# Typora 参考界面优化

本轮以原生 AppKit / TextKit 实现写作界面优化。参考 Typora 的[字体设置](https://support.typora.io/Custom-Font/)、[排版](https://support.typora.io/Typeset/)、[主题](https://support.typora.io/About-Themes/)、[快捷键](https://support.typora.io/Shortcut-Keys/)与[专注／打字机模式](https://support.typora.io/Focus-and-Typewriter-Mode/)的交互组织；不是复用其源码或 CSS 主题引擎。

## 排版与默认值

| 项目 | 初始值 | 调整入口与范围 |
| --- | --- | --- |
| 正文字号 | 16 磅 | 设置 → 写作，12–28 磅；即时编辑、预览共用 |
| 源码字号 | 15 磅 | 设置 → 写作，12–28 磅 |
| 正文／源码行高 | 1.6 倍 | 设置 → 写作，1.2–2.0 倍 |
| 最大正文宽度 | 1200 点，居中 | 设置 → 外观与预览，600–1800 点；窄窗口自动适应 |
| 主题 | GitHub | 主题菜单、设置 → 外观与预览；CSS 目录扩展 |
| 外观 | 跟随系统 | 跟随系统／浅色／深色；应用文档窗口同步 |
| 正文缩放 | 100% | 显示 → 放大／缩小／实际大小，50%–200% |
| 自动配对、语法高亮、拼写检查 | 开 | 设置 → 写作 |
| 源码自动换行／行号 | 开／关 | 显示菜单和设置 → 写作 |
| 专注／打字机模式 | 关／关 | 显示菜单，独立窗口状态 |
| 目录树／大纲 | 开／关 | 显示菜单和设置 → 工作区 |
| 链接打开 | 预览单击，编辑 ⌘+单击 | 设置 → 外观与预览，可改为仅右键菜单 |

排版、主题、外观、缩放和编辑偏好立即保存，重启继续使用；本次将历史默认宽度 760／800 点一次性升级为 1200 点，其他自定义宽度保留；升级后再次选择窄宽度会正常保存。设置提供按组和全部恢复默认。主题切换保留字号、行高与宽度的独立选择。

字体与配色从主题 CSS 读取，默认提供 GitHub、Whitey、Night、Newsprint、Pixyll、Gothic。中文使用系统字体回退。代码维持等宽，标题沿用明确的层级、段前段后留白，正文段距与字号成比例缩放。

## 菜单与编辑辅助

- 编辑：保留原生撤销、重做、剪切、复制、粘贴、查找；新增“复制为 Markdown”（⇧⌘C）和“粘贴为纯文本”（⇧⌘V）。
- 格式：粗体、斜体、删除线（⇧⌘X）、标题 H1–H6（⌥⌘1–6）、引用、列表、行内代码（⇧⌘`）、代码块（⌥⌘K）、清除格式（⌘\）。清除格式按当前选区可用性启用。
- 显示：保留三种写作视图与目录树、大纲；接入正文缩放、专注（⌃⇧⌘F）和打字机（⌃⇧⌘T）模式，以及源码换行、行号开关。写作模式不主动切换视图。
- 主题：六个 CSS 内置主题、自定义主题目录、打开目录与重新加载入口；选中状态与设置窗口共享。
- 窗口：沿用 macOS 原生窗口菜单、最小化、缩放及窗口切换行为，不新增重复命令。
- 辅助菜单：保留已有表格行列、对齐菜单，以及代码语言、复制代码、完成编辑、链接打开和重新渲染等上下文操作。

## 边界与验证

主题支持 CSS 文件扩展和常见 Typora 变量／选择器桥接，不是完整浏览器 CSS 或 Typora 专有 DOM 兼容。支持范围与示例见 [CSS 主题说明](../Themes/README.md)。PDF 仍使用固定浅色样式。专注模式主要淡化 TextKit 正文，图片、表格等覆盖视图不保证整块淡化；打字机在文档首尾受滚动范围约束。

定向验证覆盖偏好持久化与恢复默认、非法值收敛、字体／行高配置传播、CSS 输出、高对比度调色板、格式编辑、写作模式、缩放及原生渲染回归。自动化不能代替中文输入法、多窗口、系统全屏和长时间写作的人工验收。

2026-09-29 验证记录：Debug `build-for-testing` 通过；141 项定向 direct XCTest 通过；3 项真实 App 宿主测试验证格式、缩放和写作模式菜单通过；446 项测试方法与分区清单一致，`git diff --check` 通过。实际启动确认主题菜单、设置入口存在；设置标签页的完整视觉检查因 UI 自动化超时未完成，仍需人工验收。

## 渲染文字垂直对齐修复（2026-09-29）

逐项排查发现两类偏移：TextKit 将较大最小行高的额外留白主要放在字形上方；表格同一行被多行内容撑高后，短单元格的内容仍然靠上。

正文和表格共用布局代理，根据每行实际字形的上伸／下伸度量（含中文、Emoji 回退字体）调整基线，使文字在有效行框内居中。有效行框不包含段前、段后间距，因此标题、列表的结构留白保持不变；列表标记、引用条、行内代码背景继续按实际基线绘制。折叠的 Markdown 标记、覆盖视图占位和自带基线的附件保留原生布局。表格额外根据单元格内容的实际高度平分上下空间，包含换行及末尾空行；公式阅读视图的整块内容也在单元格内居中。

验证：Debug `build-for-testing`、143 项定向 XCTest、个人验收门禁分区检查、`git diff --check` 通过。新增用例遍历四个主题、三档行高，覆盖标题、段落、引用、无序／有序／任务列表、代码块，以及行高不一致的表格；原有光标、引用条、行内代码背景、表格换行和撤销测试通过。已启动修复版及临时对齐示例，但界面截图工具超时，尚未完成截图视觉复核。

## 预览留白调整（2026-09-29）

参考 Typora 的[正文宽度设置](https://support.typora.io/Width-of-Writing-Area/)，继续采用居中且可调整上限的正文区域。预览和即时编辑的默认上限从 800 点放宽到 1200 点，窄窗口的左右最小留白从 28 点缩至 24 点。以正文视口宽 1400 点为例，左右留白由各 300 点减少到各 100 点；分屏时随所在面板收缩。

设置 → 预览保留 600–1800 点的最大正文宽度滑块。旧默认值只迁移一次；PDF 保持原有固定版式，源码保留原有边距。

验证：Debug build-for-testing 通过；124 项偏好、原生渲染、Markdown 排版及写作模式相关 XCTest 全部通过；测试清单分区检查和 git diff --check 通过。

## CSS 主题扩展（2026-09-29）

主题改为不可变 CSS 快照：应用内置六份资源，首次运行安装到应用支持目录中的 `Inflow/Themes`，自定义 `.css` 文件自动加入菜单。约两秒刷新一次，文件内容变化会同时刷新已打开的原生编辑视图。选中项持久化；删除自定义主题回退 GitHub；读取错误、损坏文件不修改 Markdown 内容。

原生渲染桥接 CSS 配色、常用字体和块样式；HTML 导出嵌入同一份 CSS。六款主题为 Inflow 自行实现的对应风格，不复制 Typora 的专有页面结构或主题资产。主题文件修改不影响进行中的导出快照。

验证：Debug build-for-testing 通过；335 项 current-direct 与 18 项相关扩展用例，共 353 项 XCTest 全部通过；测试清单和 git diff --check 通过。六款主题完成原生渲染截图检查，修复了表格背景／边框／字体没有跟随当前 CSS 主题的问题。新增用例覆盖文件发现、无效文件、变量循环、层叠、修改刷新、选择持久化、删除回退、HTML 样式转义和导出快照。
