# 人工智能与连接器技术边界

> 状态：设计草案，证据 `OPEN`
>
> 更新日期：2026-08-30

## 1. 信任模型

Markdown、引用内容、网页摘录、外部服务返回值和模型输出都属于不可信数据。它们不能改变系统策略、提升权限、生成 capability token、选择额外文件或自行发起工具调用。

Core 是正文、选区、差异、撤销和用户确认的唯一所有者。高信任宿主只执行一项已授权操作，没有用户目录写权，也不持久持有正文。

## 2. AI v1：纯文本建议

首个 AI 版本只接受用户明确选择的文本和用户输入的任务说明，返回纯文本建议：

- 不读取整篇文档、工作区、剪贴板、隐藏文本或相邻文件；
- 不调用工具、函数、shell、浏览器、文件、连接器或其他模型；
- 不返回可执行 HTML、Markdown 脚本、系统 URL 或自动操作指令；
- 不自动应用正文、不创建/移动/删除文件、不连续执行后续任务；
- 模型输出由 Core 作为不可信字符串解析、限长和展示，再生成用户可审查的文本差异。

远程请求由独立签名 AI 宿主完成。Core 通过认证的一次性内存流发送精确选区；请求绑定 task ID、document version、selection hash、provider、purpose、expiry 和取消 token。任务结束或取消后销毁正文缓冲区。

### 2.1 本地 provider 和模型事实

首版 AI 可在已通过设备准入的本地 provider 与符合数据、费用合同的远程 provider 之间选择；两者都只处理用户明确选中的文本并返回纯文本建议。本地不等于把任意模型路径交给 worker：

- 独立 `ModelStore` 验证签名模型清单、精确文件摘要、格式、许可证、声明峰值内存与兼容版本，再发布到版本化、只读的内容寻址存储。
- 发布记录绑定 model ID、publisher、release sequence、manifest hash 与全部组件 hash；同一版本不得更换字节。更新先完整验证新版本，再原子切换活动指针。
- 一次性本地 AI worker 只获得已发布对象的私有只读 FD 和预期摘要，不获得用户选择的源路径、ModelStore 写权、网络、Keychain 或其他文件权限。启动前与映射后都核对发布对象身份与摘要。
- Core 始终持有精确选区、模型返回的明文、解析和差异；worker 只返回受限长度的纯文本，不直接操作编辑缓冲区。
- 本地 worker 与其他 helper 共用全局 Resource Governor。模型声明峰值、实测峰值和 worker 上限必须同时不超过物理内存的 35%，并始终为 Core 与系统保留至少 `max(4 GiB, 50% 物理内存)`。无法同时满足时，该本地模型在当前设备上不可用，不以交换或内存压力冒充支持。

ModelStore、实机峰值、强杀后清理和 8 GiB 设备准入都保持证据 `OPEN`，直到对应 target 和故障注入存在。

### 2.2 Prompt injection 边界

- 系统策略、用户任务和文档数据使用独立的结构化字段，不把文档拼接成系统指令。
- 文档中声称“忽略规则”“读取其他文件”“调用工具”或要求泄露凭据的文字只作为待处理内容。
- 提供方响应中的链接、引用、工具请求和结构化动作均不执行；只作为可见文本。
- 每次重试使用同一不可变 request envelope 和 idempotency key；用户改变选区、模型、用途或费用即创建新任务。
- 过期 document version 的结果仍可复制为独立文本，但不能直接应用到正文。

## 3. 可结算费用协议

只有同时支持权威报价、过期时间、最大消费参数或预授权，以及可幂等结算的 provider，才能被描述为受 Inflow “硬费用上限”保护。

全局账本状态：

```text
quoted -> reserved -> submitted -> settled
                     \-> released
          \-> expired
```

- `quoted`：provider 返回币种、最大金额、计费单位、税费处理、有效期和 quote ID。
- `reserved`：全局账本原子预留单次、当日和当月额度；任一不足则不提交。
- `submitted`：携带 quote ID、最大消费参数和 idempotency key 发起一次请求。
- `settled`：以 provider 权威回执结算实际金额并释放差额。
- `released`：取消、失败或 quote 过期且 provider 确认未收费时释放。

重试不得重复预留或提交；延迟回执在账本中保持未结算占用。汇率不由客户端猜测；quote 币种与用户账本币种不同且 provider 不提供锁定换算时，不提供硬上限任务。

只提供估算、最终账单不可封顶或不能幂等结算的 provider 只能显示“预算提醒”，不得通过硬上限 UAT。

“当日”和“当月”按任务开始时用户当前 IANA 时区生成自然日/月 period key；所有窗口和 provider 共享同一个串行化账本。时区变化会启用新时区的 key，但不会重置额度：仍未结束的旧时区 key 保留到其原定边界，新 key 初始化时承接所有尚未过期 key 中已结算与已预留的累计消费；新任务同时记入当时仍有效的全部 key，可用余额取这些 key 的最小值。这样无需引入第四种费用上限，也不能靠连续切换时区获得额外额度。跨周期只重置确已到达边界的 key；`reserved/submitted` 在权威结算或未收费释放前继续占用其关联 key。时钟回拨、夏令时重叠和多窗口并发不得生成第二份相同 key。

## 4. 未来 AI 工具调用门禁

工具调用不属于 AI v1。后续若开放，每次调用必须由 Core policy engine 生成独立 capability token，绑定精确工具、参数摘要、资源、document version、费用、过期时间和单次使用 nonce；调用前展示影响，产生副作用的每次调用都需要二次确认。未完成该协议和负面语料前保持禁用。

## 5. Connector v1：用户主动单向操作

首个连接器版本只提供两类独立操作：

1. **发布副本**：把用户明确选择的当前不可变文档版本发布到明列目标；不建立持续同步。
2. **获取候选副本**：从明列远端资源读取一次候选内容，在 Core 中比较；用户另存或明确应用后才改变本地内容。

不支持后台扫描、自动续传、双向同步、远端删除推断、跨文件夹队列或无交互冲突合并。本地保存永远先独立完成。

### 5.1 单次操作合同

`ConnectorOperation` 包含：

- `operationID` 与幂等键；
- `publishCopy | fetchCandidate`；
- provider、账号别名和固定 endpoint policy；
- 本地 document ID/version/hash 或远端资源 ID/version/ETag；
- 目标条件 `absent | exactRevision`；
- 内容大小、附件闭集、过期时间和取消 token。

响应逐项返回 receipt、远端 revision/ETag、实际字节、完成/未完成状态和可重试性。取消或网络失败不把未知状态标为完成。

## 6. 双向同步后续协议

双向同步属于后续阶段，必须先冻结：远端稳定身份、共同基线、put/delete/move、tombstone、条件写、幂等 receipt、顺序、部分 ACK、限流、配额、持久 dirty intent、磁盘压力、凭据轮换和崩溃恢复。完整 manifest 或逐资源 receipt 必须能证明每项状态，不能用一个“已同步”概括未知结果。

## 7. 网络策略

每个 provider 使用版本化 endpoint graph：固定 scheme/host/port，DNS/IP 限制，TLS 最低版本，逐跳重定向，跨域时清除凭据，上传/响应/解压预算，以及服务端返回 URL 的重新校验。插件不能提供任意 URL，provider 也不能通过重定向扩大 origin。

## 8. 凭据与正文所有权

- 凭据由专用凭据所有者保管，AI/Connector 宿主只获得单次操作所需的短期凭据或签名请求能力。
- Core 持有 AI 响应明文、解析结果和正文 diff；provider 宿主不写用户文件。
- Connector 宿主不把远端状态写成“已保存”；Core 分开显示本地保存与外部 receipt。
- 账号撤权、宿主崩溃或插件停用后立即停止新操作并清除短期凭据。

## 9. 必需证据

- 文档 prompt injection、隐藏指令、恶意引用和模型工具请求的负面语料；
- 过期快照、取消、重试与 idempotency 测试；
- quote/reserve/submit/settle/release 的并发和崩溃测试；
- 多窗口共享额度、冻结 IANA 时区与 period key、时区切换、DST、时钟回拨、跨周期延迟回执和无法封顶 provider 拒绝测试；
- 发布副本/候选副本的 ETag 竞态、部分失败、取消和未知状态测试；
- endpoint graph 的 DNS、重定向、压缩炸弹、超限响应和凭据清除测试。
