# 市场、生态账号与安全撤回

> 状态：设计草案，证据 `OPEN`
>
> 更新日期：2026-08-30

## 1. 市场分期

### M0：官方能力中心

- 只分发 Inflow 团队签名、免费、低风险能力；
- 不需要用户生态账号、付款或评价；
- 完整展示包版本、能力、数据边界、更新和退出影响。

### M1：免费公开市场

- 第三方发布者使用独立开发者账号完成身份、提交、审核、发布和投诉响应；
- 普通用户无需账号即可浏览和安装免费插件；
- 不提供 Inflow 收款、订阅、退费、恢复购买或用户评价；
- 下载记录只保留安全、限流和法定义务所需的最小信息，不采集文档或插件处理内容。

### M2：可选生态账号与商业市场

只有账号、会话恢复、账号删除、离线权益、支付、税费、拒付、设备迁移、评价资格和数据生命周期全部通过独立评审后，才开放交易与评价。生态账号永远不是启动、编辑、保存、恢复或本地导出的前提。

## 2. 发布记录

每个市场版本使用符合[市场发布记录 v1 机器 Schema](../../quality/extensions/market-release-record-v1.schema.json)的签名 `MarketReleaseRecord` 绑定：

- extension ID、版本和内容根摘要；
- publisher ID 与指定签名身份；
- 审核策略版本和审核等级；
- 精确能力/权限、兼容版本和 channel；
- 单调 release sequence、发布时间和撤回替代关系。

客户端只安装内容根、签名身份和 release record 完全一致的包。未知 critical 字段整条拒绝。

能力摘要使用 `manifest-capability-set-v1`：从已验签 manifest 生成符合[清单能力集 v1 机器 Schema](../../quality/extensions/manifest-capability-set-v1.schema.json)的完整 `capabilitySet`；对象字段、空数组、属性策略项形状和排序规则只以[包与运行时](./包与运行时.md)的规范算法为准。记录同时携带该对象和 `SHA256(JCS(capabilitySet))`。客户端重新构造对象、逐字节比较 JCS、重算 `capabilitySetSHA256`，并要求发布记录的 `resolvedComponents` 与 manifest 逐项一致，不能只信市场给出的对象或摘要文本。

记录正文为 UTF-8、无 BOM 的 JSON，按 RFC 8785 JCS 规范化。`market-ed25519-jcs-v1` 表示市场根密钥对以下精确字节生成分离 Ed25519 签名：

```text
"InflowMarketReleaseRecordV1\0" ||
SHA256(JCS(market-release-record.json))
```

客户端验证市场根的防回滚轮换链、记录签名、单调 `releaseSequence`、`previousRecordSHA256`、包摘要、清单摘要、内容根和发布者证书摘要。系统信任链中的任意证书、包内自带公钥或声明相同 publisher ID 均不能替代这些校验。Schema 采用闭世界字段；未知字段、未知关键字段或缺失关键字段整条拒绝。

领域能力包使用[领域包发布记录 v1 机器 Schema](../../quality/extensions/domain-pack-release-record-v1.schema.json)，由市场根对 `"InflowDomainPackReleaseRecordV1\0" || SHA256(JCS(record))` 生成分离签名。记录内嵌 host/API、catalog snapshot、solver policy 和每项有限 allowed versions 的 `resolutionInput`；`requestedComponents` 按 `(extensionID, componentID)` 的 NFC UTF-8 字节序排列且组件键唯一，`allowedVersions` 按 SemVer 2.0.0 优先级再按完整版本 NFC UTF-8 字节序排列且不重复，然后计算 `resolutionInputSHA256 = SHA256(JCS(resolutionInput))`。`resolvedComponents` 按同一组件键排序且唯一，其键集合必须与请求集合完全相等，并保存精确版本、API 版本、清单摘要及组件摘要。客户端重算输入摘要并验证无缺项、额外项或版本越界，不在安装或启动时重新求解。其输出策略固定为 Core 声明式内容树。

## 3. 发布者账号

发布者账号与普通用户账号分离。验证材料只由发布者服务持有，不进入插件包或普通客户端。主体转移需要原主体、接收主体和市场分别确认，并生成新的 release record；不能继承旧主体的敏感授权或签名身份。

## 4. 安全撤回合同

“立即撤回”精确定义为：设备**收到并验证防回滚的签名撤回清单后**，立即阻止对应版本的新任务、安装、更新、重新启用和降级恢复。离线设备在收到新清单前无法获知未来撤回，产品不得声称全球实时生效。

`RevocationManifest` 必须符合[撤回清单 v1 机器 Schema](../../quality/extensions/revocation-manifest-v1.schema.json)，并包含：

- 单调 sequence、previous manifest hash、生成时间、有效期与最低安全客户端版本；
- extension ID、版本/摘要、原因类别、影响、替代版本和用户动作；
- 市场根签名和轮换链。

客户端拒绝低 sequence、断链、过期且无法更新、签名无效或要求更高安全客户端却未满足的清单。已确认撤回是不可由用户覆盖的终态；下架和弃维不是撤回。

清单正文是 UTF-8、无 BOM 的 JSON，按 RFC 8785 JCS 规范化。`market-ed25519-jcs-v1` 对以下精确字节生成分离 Ed25519 签名：

```text
"InflowRevocationManifestV1\0" ||
SHA256(JCS(revocation-manifest.json))
```

签名密钥必须来自市场撤回根及其防回滚轮换链，不能复用发布者包内密钥。Schema 闭世界、未知字段、未知原因枚举、重复目标和不完整 `criticalFields` 均整份拒绝；运行时另验证 sequence、previous hash、时间窗口及目标唯一性。`update-required` 必须同时携带与被撤回版本不同的 `replacementVersion` 和对应 `replacementReleaseRecordSHA256`；客户端只接受同一 extension、版本精确匹配、release sequence 更高、签名有效且当前未撤回的市场发布记录。`disable` 与 `remove` 的两个 replacement 字段都必须为 `null`。

## 5. 获取策略

- M0/M1 默认仅在用户手动“检查能力更新”或应用手动检查更新时获取清单。
- 用户可选择每日或每周自动安全检查；界面说明会连接的固定服务、最后成功检查时间和离线剩余风险。
- 检查请求不包含安装插件清单、文档信息或账号，服务返回完整或增量签名清单。
- 网络失败保留上次有效清单并显示陈旧状态，不把“没有新数据”解释为“没有撤回”。

### 5.1 Market Broker

市场目录、包和撤回清单只能由独立 `MarketBroker.xpc` 访问固定官方 origin。Broker 无用户文件、无编辑器缓存和无插件运行权限；它验证 TLS、DNS/IP、逐跳重定向、响应/解压预算和服务端返回 URL。跨 origin 重定向拒绝，公共目录请求不携带用户文档、已安装插件清单或发布者凭据。

下载结果以只读私有 FD、预期长度、响应摘要和 operation receipt 交给一次性 Package Verifier；App 不根据下载路径重新打开文件。签名/内容根验证失败时整包隔离或删除，不能进入安装目录。

## 6. 商业市场前置合同

M2 需要独立可选生态账号，至少覆盖：注册/登录、会话恢复、设备迁移、账号删除、数据导出、多因素恢复、未成年人/地区限制和支持申诉。支付合同必须明确 merchant of record、币种、税费、试用、续费、取消、退款、拒付与离线权益缓存。

“已验证使用者”只能由购买/获取 entitlement 与对应版本启动的不可反推内容凭证证明；不得上传文档、文件路径、命令历史或插件输出。实现和隐私评审完成前，M1 不开放评价。

## 7. 供应链门禁

- 发布者私钥不进入构建系统或客户端；发布记录与包签名使用可轮换、可撤销的独立身份。
- 构建 provenance 绑定源提交、构建器、依赖、产物摘要和审核输入。
- 依赖漏洞和许可证策略在发布前门禁；未知依赖或摘要漂移拒绝。
- 市场服务、发布者服务和撤回签名服务分权；普通管理员不能单独伪造发布或撤回。
- 客户端保留最后有效清单、安装回执和必要审计元数据；不保留用户正文。

## 8. 必需证据

- sequence 回滚、链断裂、密钥轮换、过期和最低安全版本测试；
- 离线、代理、缓存陈旧和时钟偏移测试；
- 撤回后安装/启用/降级/旧包重放全部拒绝；
- 发布者转移、签名不匹配、内容根替换和审核策略漂移测试；
- M2 上线前完成账号删除、权益离线、退款/拒付、设备迁移和验证使用者隐私测试。
