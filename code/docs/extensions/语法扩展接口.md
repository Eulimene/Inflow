# Syntax Extension API v1

> 状态：设计草案，证据 `OPEN`
>
> 更新日期：2026-08-30

## 1. v1 范围

首个稳定语法扩展只开放两个有明确边界的结构：

1. 命名空间 fenced block：围栏 info string 为 `inflow:<extensionID>:<name>`；
2. 命名空间 block directive：`:::inflow:<extensionID>:<name> {attributes}` 至匹配的 `:::`。

不开放任意行内语法、替换 CommonMark/GFM 含义、parser hook、原始 HTML 解释、任意 LaTeX 工程或跨文档求值。未知、停用或失败的贡献始终保留原始 Markdown。

## 2. 词法与嵌套

- `extensionID` 使用清单中的 ASCII 小写反向域名标识（至少一个点、label 内部才可使用连字符），必须字节精确一致；`name` 匹配 `[a-z][a-z0-9-]{0,63}`。完整命名空间固定为 `inflow:<extensionID>:<name>`，并必须在该 syntax provider 的 `syntaxNamespaces` 中逐项声明。
- directive 起止标记必须位于独立行；前导缩进 0–3 个空格。4 个及以上空格按普通代码处理。
- 属性是严格 RFC 8259 UTF-8 JSON 对象的受限值集：字符串、有限数字、布尔值和字符串数组；不在 JSON 外增加 `\:`、`\{` 或其他私有转义。键必须由 provider 清单逐命名空间绑定、且符合[语法属性策略 v1 机器 Schema](../../quality/extensions/syntax-attribute-policy-v1.schema.json)的策略声明，未知键拒绝该贡献但保留原文。
- fenced block 内部不再识别 directive；directive 可包含 CommonMark block，但 v1 不允许同 provider 或其他 provider 的 directive 嵌套。
- directive 正文按 CommonMark block 处理，fenced body 保持不透明；反斜线只遵守其所在 CommonMark 或 RFC 8259 JSON 上下文，不定义跨上下文的额外转义。
- 未闭合、重复属性、非法 UTF-8、超出预算和语法错误都产生定位诊断，不吞掉后续文档。

CommonMark/GFM 解析优先。只有 Core 已把输入识别为上述独立结构且不处于代码、HTML、链接目标或公式排除区时，才交给 provider。

## 3. Core 所有权

Core 负责：

- Markdown 字节、UTF-8 源范围、版本和增量失效；
- CommonMark/GFM AST 与扩展节点的 discriminated schema；
- 诊断、高亮、大纲、引用和导出的最终合并；
- provider 优先级、预算、取消、过期结果拒绝和纯文本降级；
- 将受限内容树转换为平台视图或安全交付结果。

插件不能返回修改后的 AST、任意 HTML/SVG/CSS 或未绑定源范围的诊断。

## 4. Provider 请求与响应

请求字段：

- `apiVersion`、`providerID`、`contributionID`；`providerID` 固定为 `<extensionID>/<componentID>`；
- `documentVersion`、`generation`；
- `sourceRange { startByte, endByte }`；
- `kind: fenced-block | block-directive`；
- `name`、已验证属性和结构正文；
- `requestedProducts`：`diagnostics | highlights | outline | references | content-tree | export-tree` 的闭集。

响应是互斥联合：

- `success`：返回请求产品的受限结构、同一源范围摘要和预算计数；
- `unsupported`：说明稳定原因码，Core 显示原文；
- `diagnostic-failure`：返回定位诊断但不产生内容树；
- `cancelled`：无可应用结果。

请求产品名使用 kebab-case；成功响应中 `content-tree` 与 `export-tree` 分别映射到 `products.contentTree` 与 `products.exportTree`，且不能返回未请求的产品。

Core 只接受与当前 `(documentVersion, generation, sourceRangeSHA256)` 完全一致的响应。

## 5. 贡献模型

### 5.1 诊断与高亮

- 诊断包含严重度、稳定规则 ID、消息、源范围和可选纯文本修复建议。
- 高亮只能引用 Core 定义的语义 token，不提供颜色、字体或 CSS。
- 修复建议由 Core 展示差异并作为单次撤销应用。

### 5.2 大纲与引用

- 大纲贡献包含标题、层级和真实源范围，不能替换 Core 标题树。
- `ReferenceBinding` 由 `kind`、规范标识、定义范围、引用范围和可选目标组成；跨文档目标必须由 Core 在用户授权工作区内解析。
- provider 不能直接打开路径或读取第二份文档。

### 5.3 内容树

`ExtensionContentTree` 只允许[内容树 v1 机器 Schema](../../quality/extensions/extension-content-tree-v1.schema.json)中的段落、文本、强调、代码、列表、表格、数学占位、静态资源句柄和 Core 定义的布局容器。资源句柄必须来自已验证包资产或 Core 授权资源；不允许 URL、HTML、SVG 字符串、CSS、脚本或事件处理器。

Core 在接受内容树前重新遍历整棵树：`root` 计为第 1 个节点且深度为 1；每个 node object 计一个节点；`declaredUTF8Bytes` 是全部 JSON 字符串值（不含属性名）规范化为 NFC 后的 UTF-8 字节总和。Core 重新计算这三项，并要求分别等于 `declaredNodeCount`、`declaredUTF8Bytes` 和 `declaredMaxDepth`，最大深度为 32。任一声明不符、列表/表格子节点类型错误、超出 10,000 节点或 2 MiB 字符串预算时整棵拒绝，不截断后部分应用。

## 6. 多 Provider 与兼容

- 一个完整命名空间在同一用户配置中只允许一个活动 provider。多个已验证 provider 可以安装并声明同一命名空间；首次冲突时 Core 要求用户选择，记录 `namespace -> providerID + component hash`，未选择前全部保持原文。切换前展示受影响命名空间，切换后整篇按新 generation 重解析；不链式调用或合并多个结果。
- Core 语法永远优先于扩展；扩展之间没有隐式优先级或链式改写。
- 文档声明的命名空间与安装 provider 不匹配时保持原文并说明缺少能力。
- 新 API 只能通过新 `apiVersion` 增加；未知必需字段或未知 critical contribution 整项拒绝。
- 停用或卸载后重新解析为普通 Markdown，不能留下隐藏缓存事实。

## 7. Academic Pack v1

官方 Academic Pack 是 Syntax API 的首个参考实现，计划支持：

- 命名空间定理/定义/证明 block directive；
- 受控数学环境；
- `label` / `reference` 绑定；
- citation 与 bibliography 贡献；
- 纯文本、预览和导出的一致降级。

完整 `.tex` 工程、宏执行、shell escape、任意包加载和 TeX 文件系统属于独立生态工具，不进入编辑器内插件运行时。

Academic Pack 作为领域包发布时，必须提供符合[领域包发布记录 v1 机器 Schema](../../quality/extensions/domain-pack-release-record-v1.schema.json)的市场签名记录。记录固定所有语法、引用、诊断和资源组件的精确版本及摘要；运行时不重新求解依赖。所有渲染贡献只返回 `core-declarative-content-tree-v1`，PDF 由 Core 根据该内容树生成，插件不返回 PDF、任意 SVG 或 HTML。

## 8. 冻结门禁

v1 机器合同已冻结为[语法 EBNF](../../quality/extensions/syntax-extension-v1.ebnf)、[请求/响应 Schema](../../quality/extensions/syntax-api-v1.schema.json)、[属性策略 Schema](../../quality/extensions/syntax-attribute-policy-v1.schema.json)、[正反语料](../../quality/extensions/syntax-extension-corpus-v1.json)和[内容树 Schema](../../quality/extensions/extension-content-tree-v1.schema.json)。E2 实现前仍须让同版本 parser 通过 CommonMark 优先级、属性策略闭世界/预算、嵌套/转义/错误恢复、多个 provider 冲突、停用降级以及预览/诊断/大纲/导出一致性测试；当前执行证据全部为 `OPEN`。
