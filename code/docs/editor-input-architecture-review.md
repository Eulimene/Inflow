# 文本输入架构审查（2026-09-22）

结论：已证实存在导致输入丢失的架构边界缺陷。文档虽然规定 Rust Engine 是已提交正文与撤销的事实源，但原生输入、SwiftUI 绑定和展示更新没有完整遵守这一边界。当前证据支持这是反复发生交互缺陷的重要原因；无法仅凭本次审查量化所有缺陷的归因比例。

## 已复现的阻断问题

`MarkdownSourceEditor.Coordinator.update` 在每次 SwiftUI 刷新时比较绑定和 NSTextView.string。原先只保护等待 Engine 确认的普通输入，未保护尚未提交的 IME 组合输入。选区观察等无关状态变化也会触发刷新，随后用已提交的旧绑定直接重置正文。

复现序列：初始正文和绑定均为 `A` → 输入法插入 marked text `pin` → 编辑器正文为 `Apin`，绑定仍为 `A` → 执行三次相同的 Coordinator 刷新。修复前源码和即时编辑两种模式都会变回 `A`，marked 状态丢失，选区从 `{4, 0}` 退回 `{1, 0}`。新增测试修复前产生 6 个断言失败，修复后通过。

另一个时序缺口是组合期间到达的 Engine 确认直接被丢弃。若随后取消组合，原先的结束回调因文本未变而不触发，前一次普通输入的确认可能一直未发布。现在暂存此确认，提交和取消均结束输入事务；仅在确认文本仍匹配当前正文时发布，避免覆盖后续输入。取消候选不产生额外的撤销记录。

## 仍需治理的架构风险

| 范围 | 代码证据 | 影响与治理方向 |
| --- | --- | --- |
| 输入同步 | `MarkdownSourceEditorSession` 同时接受绑定刷新、原生变更、Engine 快照和外部重载 | 本次集中绑定入口并建立组合事务边界；后续将事件来源、会话版本和确认状态建成独立 InputSession，外部重载必须是显式命令。 |
| 展示属性与输入样式 | `hideRenderedMarker` 写入 0.1pt/透明属性；`syncRenderedTypingAttributes` 从同一 NSTextStorage 读取输入样式 | 存在展示属性进入输入样式的结构性风险。本次阻止组合期间改样式；后续用语义样式解析输入属性，让 Renderer 只拥有显示属性，不拥有正文或选区。此项尚未全面重构。 |
| 原生覆盖层与范围 | 表格、图片、图表需要源码范围、隐藏行、独立 NSTextView、焦点恢复和异步结果同步；表格局部编辑还需 `rebaseRenderedRanges` | 同一次编辑涉及多个对象和多组派生范围，局部修补容易漏同步。后续抽离块编辑控制器，统一版本化范围映射和选区事务，避免各渲染分支自行维护。 |
| 热路径与测试 | `canUseWritingRules` 等路径在计划过期时同步调用 `RenderedMarkdownEditor.plan(for:)`；此前输入测试主要直接操作会话再手动派生 | 单元测试没有覆盖原生输入和 SwiftUI 刷新的交错。新增 Coordinator 边界测试；后续需测试真实事件循环、慢 Engine/JS 返回、中文候选窗和长文档输入延迟。同步解析热路径尚未全部消除。 |

`MarkdownSourceEditor.swift` 已超过 5,000 行，同时包含会话同步、显示排版、输入法、撤销、剪贴板、图片与表格编辑。`MarkdownEditorView.swift` 超过 3,500 行，承担文档、派生、恢复、文件安全和界面协调。文件长度本身不证明缺陷；多个职责能直接改写相同状态、且缺少边界测试，才是本次有证据的问题。

## 本次完成与后续顺序

1. 已完成：建立从组合开始到提交/取消的原生事务状态；统一绑定回写入口；延后 Engine 确认；展示与语法高亮避开组合输入。
2. 已完成：新增三项输入边界回归，分别覆盖组合输入与 SwiftUI 刷新、确认到达后取消组合、快速输入与回车；均覆盖源码和即时编辑模式。保留原有撤销、表格、渲染和恢复回归。
3. 后续优先拆出 InputSession，使 SwiftUI 成为单向投影，明确普通输入、IME、命令、外部重载各自的入口和版本校验。
4. 再拆出 NativeRenderPresenter 与块编辑控制器，分离输入样式和隐藏样式，并统一异步结果与范围更新。
5. 最后治理逐键同步解析和派生调度，以输入延迟与真实操作场景验收，不能用通过的测试数量代替输入可靠性。

本次验证使用 AppKit 输入接口和生产 Coordinator 更新路径，覆盖跨层边界，但没有代替真实拼音输入法候选窗、真实键盘事件和长时间编辑的人工验证。当前修复解决了已复现的输入覆盖及确认丢失，不宣称上述架构风险均已消除。
