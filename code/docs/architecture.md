# Inflow 架构决策

## ADR-001：macOS 首发与 Rust 跨平台核心

- 状态：已采用
- 日期：2026-08-20

### 决策

Inflow 以 macOS 14+ 为首发平台，客户端使用 SwiftUI 与必要的 AppKit 适配。文档语义、Markdown 分析、统计、诊断与交付前检查等可复用能力放在 Rust 核心中。Swift 和 Rust 通过版本化 C ABI 交互。

### 责任边界

Rust 核心负责：

- 以同一份 Markdown 源文本为内容事实；
- 编码、换行、标题结构、统计、字面查找、渲染输入与诊断等平台无关逻辑；
- 输出带 ABI 版本的明确数据结构，不访问任意用户文件。

macOS 客户端负责：

- `NSDocument`/SwiftUI 文档生命周期、安全作用域授权与原子写入；
- 窗口、菜单、快捷键、VoiceOver 与其他平台交互；
- 按文档场景保存并路由写作视图状态；菜单、工具栏与状态栏共享同一状态，视图命令不进入 Rust 核心；
- 将核心结果呈现给用户，但不维护第二份可编辑正文。

### 安全约束

- Swift 层不直接持有 Rust 内部对象指针。
- 跨 ABI 的所有内存都由分配方释放，后续新增字符串结果时必须成对提供释放函数。
- ABI 版本号表示兼容的主版本；只新增独立函数或新结构不升主版本，已有布局、所有权或语义不兼容时必须升级。
- 文件读写不跨越 ABI，以便权限、冲突和错误始终由原生文档层管理。
- 未来 iOS、Windows 或 Linux 客户端复用 Rust 核心，不复用 macOS 文件与 UI 实现。

### 当前文档查找与替换

- Rust 核心对 UTF-8 源文本执行按源码顺序的非重叠字面匹配，并返回落在完整扩展字素边界上的 end-exclusive UTF-8 byte ranges；默认采用不区分大小写的 locale-independent Unicode folding，不会拆开组合字符或 ZWJ emoji。
- macOS 层把已校验的 UTF-8 范围转换为 TextKit 的 UTF-16 选区，负责滚动、焦点、菜单、只读状态和 UndoManager；Rust 不直接修改 NSTextView。
- 正文、查询和替换计划的快照身份按 UTF-8 bytes 精确比较，不使用 Swift `String` 的规范等价比较；规范等价但字节布局不同的文本必须使旧范围失效。
- 查找状态属于单个文档场景，不跨窗口或重启共享。后台 actor 串行执行查找，代次校验丢弃过期结果；搜索期间的下一个/上一个命令排队到最新结果，结果导航在首尾环绕，空查询不产生匹配。
- 查找与替换输入使用真正的多行 NSTextView；普通 Return 插入换行，Tab/Shift-Tab 进入键盘焦点循环，Esc 优先取消输入法 marked text、再次 Esc 关闭查找。所有智能引号、破折号、拼写纠正和自动文本替换均关闭，以保持字面输入。
- 全部替换总是先形成正文与匹配范围快照，上下文仅在预览行出现时生成。应用前正文、查询、替换词或大小写条件任一变化，旧计划都会被拒绝并刷新。
- 替换由持久 NSTextView 一次应用由已验证非重叠范围构造的最终正文，因此只发布一次正文变更并形成一个原生 undo 单元。正则、整词、选择范围和跨文档搜索不属于当前实现。

### 基础安全 HTML 导出

- Rust 核心只接收发起时冻结的 UTF-8 源文本，执行可复用的交付前检查，并生成带内联样式和严格 CSP 的完整 HTML 字节；它不读写用户文件。
- 当前垂直切片支持不依赖资源的 CommonMark 与已开启 GFM 特性。图片、公式、Mermaid、相对/本地链接和危险协议会返回可组合的阻断诊断，不生成伪完整交付物。
- macOS 层负责保存面板、安全作用域授权、目标指纹和原子写入。覆盖确认后若目标被创建或修改，旧确认立即失效；取消、检查失败和写入失败都不改变 Markdown、撤销栈或原目标。
- HTML 输出上限为 100 MiB，禁止脚本、自动网络请求、框架、对象与表单提交。PDF、资源内联、公式/Mermaid 渲染和主题选项不在本次能力范围内。
