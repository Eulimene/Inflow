# Inflow 架构决策

## ADR-001：macOS 首发与 Rust 跨平台核心

- 状态：已采用
- 日期：2026-08-20

### 决策

Inflow 以 macOS 14+ 为首发平台，客户端使用 SwiftUI 与必要的 AppKit 适配。文档语义、Markdown 分析、统计、诊断与交付前检查等可复用能力放在 Rust 核心中。Swift 和 Rust 通过版本化 C ABI 交互。

### 责任边界

Rust 核心负责：

- 以同一份 Markdown 源文本为内容事实；
- 编码、换行、标题结构、统计、字面查找、渲染输入与诊断等平台无关逻辑；
- 输出带 ABI 版本的明确数据结构，不访问任意用户文件。

macOS 客户端负责：

- `NSDocument`/SwiftUI 文档生命周期、安全作用域授权与原子写入；
- 窗口、菜单、快捷键、VoiceOver 与其他平台交互；
- 按文档场景保存并路由写作视图状态；菜单、工具栏与状态栏共享同一状态，视图命令不进入 Rust 核心；
- 将核心结果呈现给用户，但不维护第二份可编辑正文。

### 安全约束

- Swift 层不直接持有 Rust 内部对象指针。
- 跨 ABI 的所有内存都由分配方释放，后续新增字符串结果时必须成对提供释放函数。
- ABI 版本号表示兼容的主版本；只新增独立函数或新结构不升主版本，已有布局、所有权或语义不兼容时必须升级。
- 文件读写不跨越 ABI，以便权限、冲突和错误始终由原生文档层管理。
- 未来 iOS、Windows 或 Linux 客户端复用 Rust 核心，不复用 macOS 文件与 UI 实现。

### 当前文档查找与替换

- Rust 核心对 UTF-8 源文本执行按源码顺序的非重叠字面匹配，并返回落在完整扩展字素边界上的 end-exclusive UTF-8 byte ranges；默认采用不区分大小写的 locale-independent Unicode folding，不会拆开组合字符或 ZWJ emoji。
- macOS 层把已校验的 UTF-8 范围转换为 TextKit 的 UTF-16 选区，负责滚动、焦点、菜单、只读状态和 UndoManager；Rust 不直接修改 NSTextView。
- 正文、查询和替换计划的快照身份按 UTF-8 bytes 精确比较，不使用 Swift `String` 的规范等价比较；规范等价但字节布局不同的文本必须使旧范围失效。
- 查找状态属于单个文档场景，不跨窗口或重启共享。后台 actor 串行执行查找，代次校验丢弃过期结果；搜索期间的下一个/上一个命令排队到最新结果，结果导航在首尾环绕，空查询不产生匹配。
- 查找与替换输入使用真正的多行 NSTextView；普通 Return 插入换行，Tab/Shift-Tab 进入键盘焦点循环，Esc 优先取消输入法 marked text、再次 Esc 关闭查找。所有智能引号、破折号、拼写纠正和自动文本替换均关闭，以保持字面输入。
- 全部替换总是先形成正文与匹配范围快照，上下文仅在预览行出现时生成。应用前正文、查询、替换词或大小写条件任一变化，旧计划都会被拒绝并刷新。
- 替换由持久 NSTextView 一次应用由已验证非重叠范围构造的最终正文，因此只发布一次正文变更并形成一个原生 undo 单元。正则、整词、选择范围和跨文档搜索不属于当前实现。

### Markdown 语法高亮边界

- Rust 核心使用与分析、预览一致的 Markdown 配置生成语义类型和 end-exclusive UTF-8 范围；标题、强调、删除线、链接、图片、引用、列表、代码、表格、脚注、公式和原始 HTML 等可被不同平台复用，代码块内的伪标记不会被当作外层语法。
- C ABI 只暴露定宽类型标记和原始源文字节范围；Swift 会验证数量、类型、边界和 UTF-8→UTF-16 映射。快照身份按精确 UTF-8 bytes 比较，不会把规范等价但字节布局不同的文本当作同一份结果。
- 语法识别在后台 actor 内完成。AppKit 仅在当前持久 `NSTextView` 上应用系统动态颜色，每 512 个样式主动让出主线程；正文一变化就取消旧批次，防止过期范围继续回写。样式变更不发布正文变更，不登记 undo，不改变选区、文档编码或交付语义。
- 高亮默认开启，但与拼写检查、滚动同步和标题定位互相独立。关闭或核心结果不可用时回到普通单色源码，输入、选择、撤销和保存仍可继续。
- 自动换行和行号是 AppKit 显示偏好，不进入 Rust 或文档快照。关闭换行只改变 `NSTextContainer` 宽度策略并开启水平滚动；行号尺按 UTF-16 物理换行点缓存行首，视觉折行、高亮和字体变化都不会增加行号。
- 专注与打字机模式是每文档场景独立的 AppKit 呈现状态。专注模式只使用 `NSLayoutManager` 临时前景色弱化非当前段落；打字机模式只调整 `NSClipView` 垂直位置。两者都不改写 `NSTextStorage`、不登记 undo，不影响 Markdown 快照、编码、预览或交付。

### 编码与混合换行边界

- Rust 核心是 UTF-8、BOM 和换行事实的唯一解码器。新增的 `inflow_document_open` 是独立的加法式 ABI：它不改变原有严格解码函数的契约，并显式返回“需要换行选择”状态。
- 一致 LF 或 CRLF 按原样属性打开；混合 LF/CRLF 或单独 CR 被规范为内存中的 LF，但文档模型保留 BOM 事实并标记禁止写回。源码编辑、替换、格式化、插入和资源操作都从同一只读门禁取值。
- macOS 在文本上方持续展示 LF / CRLF 选择和安全说明。只有用户明确选择后，文档才解除写回禁止；编码器仍会在未选择状态拒绝生成文件字节，防止 UI 门禁失效时的静默覆盖。

### 基础安全 HTML / PDF 导出

- Rust 核心只接收发起时冻结的 UTF-8 源文本，执行可复用的交付前检查，并生成带内联样式和严格 CSP 的完整 HTML 字节；它不读写用户文件。
- 当前垂直切片支持 CommonMark、已开启 GFM 特性、安全公式子集、流程图/时序图/类图/状态图四类基础 Mermaid，以及经验证的本地静态 PNG/JPEG。图片由 Rust 输出惰性槽位，macOS 层使用导出发起时的文档目录解析、读取一次并内联 data URL；缺失、未授权、远程或安全验证失败的图片，以及相对/本地链接和危险协议会返回阻断诊断，不生成伪完整交付物。
- macOS 层负责保存面板、安全作用域授权、目标指纹和原子写入。HTML 与 PDF 共用同一目标事务：覆盖确认后若目标被创建或修改，旧确认立即失效；取消、检查失败和写入失败都不改变 Markdown、撤销栈或原目标。
- HTML 输出上限为 100 MiB，且在图片 Base64 内联后再次检查；禁止脚本、自动网络请求、框架、对象与表单提交。公式使用与预览相同的自包含 MathML，受支持 Mermaid 使用自包含 SVG，本地图片使用经内容校验的 data URL。
- PDF 只接收已通过上述预检且完成资源内联的 HTML 字节。WebKit 在禁用页面脚本的非持久数据存储中按可打印高度生成内容切片，Core Graphics 将切片组合为固定 A4 纵向、20 mm 页边距的完整页，PDFKit 在写入前复核页数和每页尺寸。首发版不提供自定义纸张、页边距或页眉页脚。

### 异常恢复保护边界

- 恢复快照是 macOS 平台生命周期与文件授权事实，保存在应用沙箱 `Application Support/Inflow/Recovery`，不进入 Rust 核心。每个活跃文档最迟每 5 秒原子写入一次，快照包含精确 UTF-8 源文、BOM/换行属性、原文件安全作用域书签、TextKit UTF-16 选区、场景视图和纵向滚动位置。
- 正常关闭文档或应用终止会取消周期任务并删除对应快照；已进入串行存储的写入在完成后会再检查会话是否已关闭，防止竞态遗留。异常退出不会触发正常清理，因而下次启动可发现孤立快照。
- 加载恢复项时会重新使用文档编码属性构造预期磁盘字节；若与当前原文件完全一致，该项立即清理而不呈现。损坏或不兼容记录被隔离保留，恢复保护故障以非阻塞横幅告知，永远不禁用用户手动保存 Markdown。
- 恢复中心只展示上次运行的孤立项，并以只读方式对比恢复源文与当前磁盘文本。“打开恢复文档”和“全部恢复”始终创建未命名 `MarkdownDocument`，不直接写原文件；“另存”复用目标指纹与原子替换事务，只在安全写入后处置恢复项。未命名及其他孤立项最长保留 30 天。

### 外部文件变化与写入门禁

- 外部修改、文件删除、权限和安全作用域是 macOS 宿主事实，不进入 Rust ABI。`MarkdownDocument` 的所有系统写回先经过共享的线程安全门禁；可见状态监控只是提示，写入门禁才是防止窗口竞态覆盖的最后保护。
- 会话保留最近成功写入的精确编码字节，并持续比对当前可编码正文与磁盘字节。Swift `String` 规范等价不能代替字节快照；BOM 和换行属性同样属于基线。
- 磁盘与基线不同时，普通保存立即失败，当前编辑仍保留；原文件消失时绝不由自动保存重建。只读文档禁用文本修改，但另存副本仍作为安全退路。
- 冲突决定同时绑定文档 URL、当前源文字节和磁盘字节。重载会建立新的撤销原点；显式覆盖必须先在同一目录原子写入带时间戳的冲突副本，再对原目标执行第二次指纹复核和原子替换。任一快照变化都使旧确认失效。

### 另存为与相对资源影响

- Rust 使用与预览一致的 Markdown 解析选项提取已解析的链接和图片目标；引用式定义会解析为真实目标，代码中的伪链接不会进入结果。C ABI 只返回引用类型和目标 UTF-8 字节，不访问文件系统。
- macOS 以文档旧目录和用户选择的新目录分别解析相对路径，显示仍指向同一资源、将指向其他位置或新位置不可用三类结果。远程 URL、文档内锚点和绝对目标不受文档目录变化影响，因此不进入相对资源清单。
- 一次确认绑定编码后的精确正文、源文档 URL、保存目标指纹，以及每个相关资源在旧位置和新位置的快照。确认到写入之间任何正文、源位置、目标或资源变化都会使决定失效；目标在另一个文档窗口中打开时不允许当前窗口接管。
- 保存面板与风险清单由 SwiftUI/AppKit 管理。最终写入仍交给 `NSDocument`：`saveAsOperation` 成功后重绑定当前窗口，`saveToOperation` 只创建副本。共享写入门禁在 FileDocument 生成 FileWrapper 前再次核对目标指纹，关闭最后的竞争窗口；普通保存继续受外部变化基线保护。

### 写作与预览外观设置

- 字号、行高、拼写检查、预览宽度、阅读缩放、外观、主题和辅助功能覆盖属于 macOS 宿主偏好，不进入 Rust 核心，也不写入 Markdown。偏好保存在本机 `UserDefaults`；旧版本或损坏的数值会收敛到公开支持范围，未知枚举回退为默认值。
- AppKit 源码编辑器在同一持久 `NSTextView` 上更新字体、默认段落样式和拼写检查。属性更新禁用 undo 登记并恢复原选区，不发布正文变化，因此不会破坏文档撤销历史、滚动或文件快照。
- 预览把已经解析和本地资源安全处理后的 HTML 与一份纯值外观配置组合。配置只能生成固定枚举和边界内数字对应的 CSS，不接收任意用户 CSS；严格 CSP、禁用脚本、禁用网络和空文件 origin 保持不变。
- HTML/PDF 导出在发起时同时冻结源文、文档目录与外观配置。平台层把同一安全 CSS 注入 Rust 生成的完整 HTML，再执行最终 100 MiB 上限检查；后续设置变化不能改变已发起交付的内容。
- 增强对比度和减少动态效果默认读取系统辅助功能状态，也可由用户明确开启或关闭。“恢复默认”只复位本组偏好，不操作文档、恢复中心记录或其他生命周期数据。

### 预览标题导航与单向滚动同步

- 标题导航与滚动同步是 macOS 视图交互，不进入 Rust ABI。Rust 分析器仍是标题级别和 end-exclusive UTF-8 源码范围的唯一事实来源；Swift 只使用与当前源文快照同步产生的分析结果注解预览标题。
- 预览 HTML 只在标题数量和级别逐项匹配时写入十进制 `data-inflow-source-start`；任何漂移都会失败关闭标注。宿主收到点击后再次确认当前分析中存在该精确字节起点，然后复用大纲的 UTF-8→UTF-16 安全定位路径。重复标题因源码起点不同而可精确区分。
- 文档页面脚本仍被禁用。唯一的桥接是应用自带、在隔离 content world 中运行的固定脚本；它只能上报已校验的数值标题位置或“用户已手动滚动”事件，不接受 Markdown 中的任意命令。
- 滚动同步只从持久 `NSTextView` 源码编辑器按可滚动高度比例驱动预览，不做双向回写，以避免循环跳动。鼠标、滚轮、触控板或键盘导致的预览手动滚动会暂停跟随，下一次源码滚动恢复。两项功能默认开启但偏好彼此独立，关闭不改变正文或撤销历史。

### 预览链接激活边界

- Rust 已解析的 Markdown 链接目标是链接事实来源；宏文本和代码中的伪链接不参与。macOS 宿主只在渲染链接数量与解析结果一致时，把原始 UTF-8 目标以有长度上限的十六进制闭集属性注入预览。这避免把 WebKit 对 `href` 的百分号或 Unicode 规范化误当成源文本。
- Markdown 页面脚本、网络和页面导航继续全部禁用。应用在隔离 content world 中的固定脚本只能上报上述十六进制属性；Swift 必须先复原有效 UTF-8，再重新用 Rust 扫描当前精确源文快照中的同一链接。过期预览、未标注节点和超长或控制字符目标都失败关闭。
- 当前文档锚点使用 Rust 标题范围定位；重复标题使用稳定后缀区分。HTTP(S) 和无查询参数的 `mailto:` 必须经过显式确认才交给系统，并禁止用户信息、密码、未知协议和控制字符。链接确认不视为网络访问，只向用户说明即将离开 Inflow。
- 本地目标是 macOS 文件授权事实，不进入 Rust ABI。计划阶段使用 `lstat` 拒绝符号链接和非普通文件，并固定设备、inode、generation、ctime、mtime 与大小；PNG/JPEG 复用图片验证器，PDF 要求可解析且至少一页。执行前正文、引用和文件快照任一变化都使旧决定失效。
- 本地 Markdown 优先聚焦已打开的文档场景，否则由 `openDocument` 打开，并以有界的进程内待处理锚点请求交付给目标场景。经验证图片和 PDF 可在确认后交给系统；其他普通附件只在 Finder 中显示，不直接执行。授权失效只允许用户重新选择同一标准化精确路径，不会改写 Markdown 或将授权转移到其他文件。

### 本地图片预览边界

- Rust 渲染器把 Markdown 图片转换为仅含十六进制 UTF-8 目标与替代文本的惰性槽位，不把原始目标写进 `src`，因此远程地址、文件地址和未验证内容都不会直接进入 WebKit 的加载器。
- macOS 资源适配器以当前 Markdown 所在目录解析相对引用；只读取当前沙箱授权可达的普通文件，并基于读取后的同一份不可变数据验证真实 ImageIO 类型、单帧、扩展名、100 MiB 上限、32,768 px 单边及 1 亿像素上限。
- 通过验证的 PNG/JPEG 转为 data URL；预览 CSP 只允许 data 图片且 WebKit 始终使用空 base URL，不取得文件系统 origin。远程、缺失、未授权、动画、伪装、过大或未命名文档中的相对图片保留源码引用并显示本地化、可访问的原位占位。
- “插入 > 图片…”只接受经同一验证器确认的静态 PNG/JPEG。未命名文档不会产生孤儿资源；已保存文档要求用户明确选择当前文档目录，并且只向其同级 `assets` 写入。
- 图片原文件名保留，Markdown 路径按 URL path component 编码。同名目标不会默认覆盖：用户必须选择显式覆盖或保留旧文件并递增名称；选择与写入间出现竞态时会停止，不覆盖突然出现的文件。
- Rust 核心只根据冻结正文、UTF-8 选区、已经平台授权流程确认的目标与默认替代文本生成并复核标准 Markdown 图片计划。macOS 层复制资源并将文本更改与资源变更注册为一个 UndoManager 分组；撤销/重做前会精确比对资源字节，外部已改变时停止资源覆盖并明确报错。
- 选择既有图片时，用户可明确保留原位置，该流程不复制、移动或登记资源撤销；同卷优先生成逐 path component 编码的相对引用，跨卷时在明确提示可移植性与本地路径隐私后才允许 `file:` 绝对引用。本次文件选择授权在当前文档场景生命周期内保留；后续无权访问时按缺失/未授权占位降级，不推测或扩大权限。
- `WindowAwareTextView` 只在剪贴板包含 PNG/JPEG/TIFF 图片时接管粘贴，非图片内容继续交给 AppKit。PNG/JPEG 使用与本地预览相同的类型、帧数、尺寸与体积验证；TIFF 只作为剪贴板输入，解码单帧后不携带原元数据转成 PNG。已保存文档经目录授权后按 `image-001` 起递增写入 `assets`；写入与 Markdown 引用共用图片资源撤销事务，取消、过期选区或竞态失败不留孤儿资源。
- 文件拖放只接管单个、扩展名声明为 PNG/JPEG 的本地 URL，在鼠标对应的 UTF-16 插入点发起与文件选择完全相同的内容验证、复制/原位选择、授权、竞态防护与撤销事务。多文件或不支持图片不会进入图片导入。
- 预览、HTML 和 PDF 共用同一本地图片内容验证边界；预览失败可原位降级，而 HTML/PDF 交付必须在写入前阻止，不允许产生少图的伪完整交付物。

### 匿名产品使用数据

- 该功能属于 macOS 客户端隐私与网络适配，不进入 Rust 文档核心。缺省状态为关闭；没有完整披露确认或没有构建时注入的可信 HTTPS 接收端时，旧偏好也会被强制收敛为关闭。
- 单条记录仅包含 Inflow 版本、macOS 主版本、界面语言、闭集功能/命令、耗时区间、闭集错误类别和计数 1。编码结构没有任意文本字段、时间戳、设备标识或用户标识，因此文档、选区、剪贴板、文件名/路径、链接、查询、凭据与插件内容无可写入通道。
- 未发送记录作为每项独立 JSON 在应用沙箱 `Application Support/Inflow/AnonymousUsage` 原子写入，通过文件系统日期实施 30 天上限，而不把时间加入载荷。损坏、过期或非普通文件会被清理。
- 传输使用无 Cookie、无缓存的短生命周期 URLSession，只接受无用户信息、查询或 fragment 的 HTTPS 目标，且拒绝跟随重定向。只有 2xx 响应才删除本地批次，其他结果保留待用户清除。
- 关闭会先增加同意代次，再取消发送与未完成记录任务；用户可选择保留或立即清空尚未发送记录。任何隐私或网络故障都不会禁用写作、文件、恢复、预览或交付功能。服务端必须另行保证事件不超过 30 天、无法回溯到用户或设备的聚合不超过 12 个月；未验证该服务前不得在发布构建中配置接收端。

### 可预测的 Markdown 格式计划

- Rust 核心接收精确 UTF-8 正文、字节选区和格式命令，返回替换范围、替换字节与操作后选区；该编辑计划不包含 AppKit 对象，可供未来客户端复用。
- 完整选中已有粗体、斜体或删除线范围时移除对应标记；普通选区排除外围空白后添加标记；空选区插入并选中可继续输入的内容位置。核心会再次解析候选结果，只在确实形成目标 CommonMark/GFM 节点时返回编辑计划。
- 选区与现有标记只部分重叠、包含混合状态、只含空白，或跨段包裹无法形成有效行内节点时，核心返回“选区语义不明确”，不猜测性改写原文。
- H1–H6 命令将选区扩展到完整源码行：混合或不同级别统一添加指定 ATX 标记，所有非空行已是指定级别时统一移除。Setext 标题的文本行与下划线作为一个块消费，改变级别时规范为 ATX。
- 标题候选结果会重新执行 Markdown 结构分析；代码围栏内等无法形成真实标题节点的选区会被拒绝。空行保留，空光标行插入最小可编辑标题模板，光标与 Unicode 选区按原内容位置恢复。
- 引用命令以完整物理行和连续 CommonMark 引用块为边界，每次统一添加或移除一层 `>`。所有行都显式包含标记时移除一层，其他情况添加一层；候选结果必须经过引用嵌套深度复核，代码围栏内的伪标记不会被写入。
- 连续引用中使用 CommonMark 懒续行时，命令会扩展到整个语义块并校验每行的实际嵌套深度；空行和完整代码围栏可作为引用块的一部分一次撤销。
- 有序、无序与任务列表命令以完整物理行为编辑单位：混合或普通行统一为目标类型，全部已是目标类型时移除一层列表标记。空行和既有缩进保持不变，任务完成状态会保留；有序源码统一写为稳定的 `1.`，由 Markdown 呈现负责连续编号。
- 列表候选结果必须重新解析为真实列表项；代码围栏中的伪标记、不能安全映射的字素选区和无法形成目标语义的缩进会被拒绝，不留下部分修改。
- 行内代码命令选择比内容中最长连续反引号多一个的定界符；当内容边缘是空格或反引号时按 CommonMark 规则加入可逆内边距。完整代码跨度可取消，部分重叠、多行或纯空白选区会被拒绝。
- 围栏代码命令以完整物理行为编辑边界，使用“内容中最长连续反引号 + 1”且至少 3 个的定界符。完整的反引号或波浪线围栏可取消，部分命中既有围栏会被拒绝；新结果必须重新解析为真实的 CommonMark 围栏代码块。
- 链接插入先固定正文快照与 UTF-16 选区，再由 Rust 生成角括号目标形式的 CommonMark 编辑计划。新链接会转义标签中的括号和反斜杠；选中完整既有链接或其完整标签时更新目标，部分重叠则拒绝。目标输入禁用系统智能引号、破折号、文本替换和拼写修正，避免 URL 被静默改写。
- 表格插入由 Rust 生成固定 3 列、1 行表头和 2 行数据的 GFM 模板。选区内的管道符与反斜杠按单元格语义转义，换行以 `<br>` 保存在首个表头内；候选结果必须重新解析为 3 列、2 个数据行的真实表格，与既有表格重叠时拒绝。
- 分隔线插入由 Rust 在当前选区末尾生成 `---` 块，保留选中的原始内容，并补足前后空行以避免被解析为 Setext 标题。候选正文必须重新解析出位于预期字节位置的 CommonMark Rule，光标随后落在分隔线后的空行。
- 脚注插入由 Rust 扫描已解析的引用与定义，选择首个未占用的 `note-N` 标识；引用追加在当前选区末尾，定义追加在文档末尾且内容占位符保持选中。候选正文必须同时重新解析出预期位置、同名的引用和定义，代码围栏等无法形成脚注语义的上下文会被拒绝。
- 公式插入由 Rust 依据选区形态选择 `$...$` 行内语法或定界符独占行的 `$$` 块语法，并重新解析确认公式节点与内容范围。渲染器把常用 TeX 上下标、分式、根式、文字、希腊字母和运算符转换为转义后的 MathML；未知命令以字面内容安全降级，不执行脚本或加载外部依赖。
- 图表插入使用长度安全的 `mermaid` 代码围栏，并要求选区先通过 Rust 的首发图表解析。渲染器只接受流程图、时序图、类图和状态图的基础节点/连接语法，生成转义后的内联 SVG；不支持或失效的单个图表输出局部错误、原因与原源码，既不执行 Mermaid JavaScript，也不影响其余文档内容。
- 清除格式只解析用户明确选择的 UTF-8 片段，并仅移除其中完整、语义有效的粗体、斜体、删除线、代码、标题、引用和列表标记。链接目标、转义后的普通符号与代码内部源码不会被二次解释；无完整标记、部分字素或空选区均不生成编辑计划。macOS 根据同一核心计划决定菜单可用性，并把最终替换作为一个原生撤销单元。
- macOS 层将 TextKit UTF-16 选区与 UTF-8 字节范围严格互转，通过持久 `NSTextView` 一次应用计划，保留原生焦点并形成一个 undo 单元。只读、输入法 marked text 或过期快照不会被修改。
- 当前垂直切片提供粗体、斜体、GFM 删除线、行内代码、围栏代码块、H1–H6、引用、有序/无序/任务列表、清除格式，以及链接、复制到 `assets` 的图片、表格、分隔线、脚注、公式和图表插入；其他资源流程按文件授权语义分别实现与验收。
