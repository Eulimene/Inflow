# Inflow：Typora 对标与差异化路线

- 文档版本：v1.0
- 更新日期：2026-08-17
- 基准产品：Typora 1.14
- 适用范围：Inflow 完整产品路线，不等同于首个 MVP

## 阅读指南

- 只需结论：读取第 1、4、5 节。
- 评估具体差距：读取第 3 节对应能力表。
- 制定版本范围：读取第 2、5、7 节。
- 本文描述竞争与路线，不替代 [PRD](./PRD.md)。

## 1. 战略结论

Inflow 采用“能力全面对标、体验重点超越”的策略：

1. 对标层解决迁移成本：Typora 用户使用的编辑、文件管理、Markdown 扩展、图片、主题、专注写作和导出能力，在 Inflow 中都应有等价路径。
2. 优势层解决 Typora 尚未充分解决的问题：源码和渲染不可同时观察、数据恢复不透明、跨渲染器兼容性难检查、资源引用容易失效、复杂文档缺少质量诊断。
3. 约束层保持产品边界：编辑器只服务本地写作与阅读，Markdown 源码始终为事实来源；CLI、自动化、发布和第三方服务由独立生态工具承担，不进入主应用。

“全面对标”是完整版本目标，不代表所有功能进入首发。首发先建立可靠编辑与渲染内核，随后逐层补齐，避免同时建设多个不稳定系统。

## 2. 对标完成标准

某项能力只有同时满足以下条件才算完成，而不是仅有菜单入口：

- 覆盖 Typora 对应能力的主要用户路径。
- 能正确读写通用 Markdown 或明确声明方言扩展。
- 支持撤销、自动保存、异常恢复和键盘操作。
- 在浅色、深色、导出和断网环境下行为一致。
- 对旧文件、异常语法和大文档有降级策略。
- 有自动化测试样例和可量化验收标准。

## 3. 完整能力矩阵

### 3.1 编辑与写作

| 能力 | Typora 基线 | Inflow 目标 | 优先级 |
| --- | --- | --- | --- |
| 即时渲染编辑 | 单栏 Live Preview | 提供等价即时渲染编辑，光标进入块时显示必要标记 | P1 |
| 源码编辑 | Source Code Mode | 原生源码编辑、增量高亮、自动换行；行号在 P1 | P0/P1 |
| 分栏预览 | 非核心路径 | 源码与预览并列、语义滚动同步、双向定位 | P0，优势 |
| 格式操作 | 菜单、快捷键、上下文工具 | P0 格式菜单与快捷键；P1 浮动工具栏和命令面板 | P0/P1 |
| 撤销与重做 | 支持 | 跨结构操作一致撤销，不能产生半成品源码 | P0 |
| 查找替换 | 当前文档 | 当前文档、选择范围、正则和结果预览 | P0/P1 |
| 拼写与语言 | 系统能力 | 系统拼写、语言选择、用户词典 | P1 |
| 专注模式 | 支持 | 淡化非当前段落，可调范围 | P1 |
| 打字机模式 | 支持 | 光标固定位置，可选仅输入时启用 | P1 |
| 字数统计 | 支持 | 字符、词、段落、阅读时长和选区统计 | P1 |
| Smart Paste | HTML 转 Markdown | HTML/富文本转 Markdown，并提供粘贴预览 | P1 |

### 3.2 Markdown 与扩展语法

| 能力 | Inflow 完整目标 |
| --- | --- |
| 基础语法 | CommonMark 与 GFM：标题、段落、强调、删除线、链接、图片、引用、列表、任务、代码和表格 |
| 长文结构 | 脚注、目录、YAML Front Matter、水平线和标题自动 ID |
| 提示块 | GitHub Alerts / Callouts，并提供方言兼容提示 |
| 行内扩展 | 高亮、上标、下标、Emoji，可分别开关 |
| 原始 HTML | P0 固定 allowlist 清洗；Core 不提供任意脚本可信模式 |
| 代码块 | 语言选择、语法着色、复制按钮、行号选项 |
| 表格 | 可视化增删行列、对齐、排序、移动与源码格式化 |
| 任务列表 | 预览和即时渲染模式可点击，准确更新对应源码 |
| 数学公式 | 行内/块级、编号、引用、复制 LaTeX 和错误诊断 |
| 图表 | Mermaid 完整稳定语法子集、主题、导出与错误定位 |

### 3.3 文件与工作区

| 能力 | Typora 基线 | Inflow 目标 | 优先级 |
| --- | --- | --- | --- |
| 单文件操作 | 新建、打开、保存 | 等价，并强化冲突检测与恢复 | P0，优势 |
| 文件夹工作区 | 文件树、文件列表 | 文件树、列表、排序、过滤、隐藏文件选项 | P1 |
| 多文档 | 窗口为主 | 原生标签页、多窗口和最近文档恢复 | P1 |
| 大纲 | 导航、折叠、搜索 | 导航、过滤、层级校验、拖动调整章节 | P1，优势 |
| 全文搜索 | 文件夹搜索 | 字面量/正则、过滤范围、替换前预览 | P1 |
| 快速打开 | 支持 | 文件名、标题和最近文档模糊搜索 | P1 |
| 文件监听 | 支持外部变更 | 冲突分支、差异查看、重新载入或另存 | P0，优势 |

工作区不是私有数据库。用户移动到其他编辑器后，文件夹和 Markdown 仍应完整可用；工作区索引可以随时删除和重建。

### 3.4 图片与资源

| 能力 | Inflow 完整目标 |
| --- | --- |
| 插入 | 文件选择、拖放、剪贴板粘贴、URL 插入 |
| 路径 | 绝对/相对路径策略、自动转义、可选 `./` 前缀 |
| 资源目录 | 按文档或工作区设置附件目录和命名模板 |
| 文件操作 | 复制、移动、重命名资源并同步更新 Markdown 引用 |
| 文档移动 | 文档移动或另存时可一并迁移资源并修复引用 |
| 资源检查 | 查找缺失文件、未引用资源、重复资源和失效远程链接 |
| 远程图片 | 默认不加载；用户授权后加载、下载为本地资源 |
| 上传 | 不进入编辑器；由独立生态工具负责，编辑器只处理上传后得到的标准 URL |

### 3.5 主题与显示

- 提供不少于 6 套高质量内置主题，并可为浅色、深色分别指定主题。
- 支持用户 CSS 主题导入、即时预览、错误回退和安全校验。
- 编辑器与导出可选择同一主题或分别指定。
- 支持正文宽度、字号、行高、段落间距和代码字体设置。
- 支持侧栏、大纲、状态栏、浮动工具栏和标签栏的显示开关。
- 支持全屏、专注模式、打字机模式和 macOS 辅助功能设置。

### 3.6 导入与导出

| 层级 | 格式/能力 |
| --- | --- |
| P0 原生 | 自包含 HTML、固定配置 PDF |
| P1 原生 | 无样式 HTML、系统打印、PNG/JPEG 长图、带大纲 HTML、PDF 页眉页脚/纸张/边距/元数据 |
| P1 增强 | PNG/JPEG 长图、可移植文档包、再次导出和默认导出目录 |
| 生态工具 | DOCX、RTF、ODT、EPUB、LaTeX 等批量转换；不打包进编辑器 |

编辑器本体只提供与“检查和分享当前文档”直接相关的原生导出，不探测 Pandoc、不调用外部命令，也不展示发布入口。跨格式批量转换属于独立生态工具。

## 4. Inflow 的领先能力

### 4.1 四态编辑工作流

Inflow 同时提供：

1. 纯源码：适合精确控制 Markdown。
2. 源码 + 预览：适合技术写作、调试语法和长文校对。
3. 纯预览：适合沉浸阅读。
4. 即时渲染编辑：适合低干扰写作。

四种模式共享同一文档模型、撤销栈和源码位置映射。用户切换模式时光标、选区和语义滚动位置保持一致。这是 Inflow 最核心的产品差异，而不是附加视图。

### 4.2 文档健康中心

在侧栏提供不修改内容的实时诊断：

- 标题层级跳跃、重复显式 ID、空标题。
- 失效链接、缺失本地图片和未使用附件。
- 未闭合围栏、无语言代码块、异常表格。
- Mermaid 与公式错误，点击诊断定位源码。
- YAML Front Matter 格式与常用字段校验。
- 当前文档在 CommonMark、GFM、GitHub、GitLab 等目标方言下的兼容性风险。

诊断规则可分组关闭，并支持对单条规则忽略。自动修复必须展示源码差异并允许撤销。

### 4.3 本地版本时间线

- 保存和关键结构修改时创建轻量本地版本，不修改用户 Git 仓库。
- 展示版本时间、摘要和字符变化，可预览差异。
- 支持恢复整个文档或复制某段旧内容。
- 版本保留期、空间上限和关闭开关由用户决定。
- 与异常恢复分离：异常恢复不能关闭，历史版本可以关闭。

### 4.4 资源管家

Inflow 维护可重建的资源索引，帮助用户安全移动文档和附件：

- 修改文件名或位置前预览受影响引用。
- 一次修复工作区内指向该资源的所有相对链接。
- 将远程资源打包为完整离线文档。
- 导出“可移植文档包”，包含 Markdown、附件和资源清单。
- 任何批量改写先显示变更列表，并作为单个操作撤销。

### 4.5 渲染配置档案

用户可以选择目标环境，例如 GitHub README、GitLab、CommonMark、静态博客或 Inflow Enhanced。编辑预览、诊断和导出使用同一配置，减少“编辑器里正常、发布后错误”的问题。

每个配置明确：支持的语法、换行规则、标题 ID、HTML 策略、公式/图表能力和资源路径规则。配置切换只改变解析与诊断，不静默改写源码。

### 4.6 可审计的隐私与可靠性

- 核心编辑、搜索、公式、Mermaid、诊断和原生导出断网可用。
- 设置中提供“网络活动”页面，列出哪些功能可能联网以及最近请求原因。
- 默认阻止远程图片、脚本和文档触发的外部请求。
- 保存前检查外部修改；冲突时提供差异视图，不静默覆盖。
- 恢复中心明确显示快照时间、来源文件和保留状态。

## 5. 版本路线

本路线只解释迁移目标；版本归属以 [PRD 第 11 节](./PRD.md#mvp-优先级) 为唯一来源。

### P0：首个可发布版本

- 原生源码编辑器、文件安全保存、恢复快照。
- `⌘1/2/3` 三模式、Markdown/GFM、公式、Mermaid。
- HTML/PDF 导出、设置基础、滚动与标题定位。
- 目标：验证原生文本系统、渲染管线和源码映射。

### P1：Typora 用户可迁移版本

- 即时渲染编辑 `⌘4`。
- 文件夹工作区、文件树、标签页、大纲、全文搜索和快速打开。
- 图形化表格、可点击任务列表、Smart Paste。
- 图片粘贴、相对路径、附件目录和资源移动。
- 脚注、TOC、YAML、Alerts、代码语法着色。
- 专注/打字机模式、字数统计、6 套主题和自定义 CSS。
- 目标：Typora 核心用户可以迁移主要日常工作流。

### P2：Typora 能力对齐版本

- 完整 PDF/HTML 配置、长图、可移植文档包和再次导出。
- 更完整数学和 Mermaid 配置。
- 目标：除 CLI、发布、上传和外部转换等明确生态边界外，Typora 的核心编辑能力均有等价路径。

### P3：Inflow 领先能力版本

- 文档健康中心、渲染配置档案。
- 本地版本时间线、冲突差异视图。
- 资源管家、可移植文档包。
- 大纲拖动重组、结构化批量编辑。
- 目标：在复杂文档可靠性、兼容性和资源管理上形成明显优势。

## 6. 产品指标

### 对标指标

- Typora 迁移测试集中，95% 的文档无需修改即可获得等价渲染。
- Top 30 高频操作均有菜单和键盘路径，迁移用户任务完成率不低于 90%。
- P2 完成时，对标矩阵不存在无说明的空白项。

### 优势指标

- 点击源码、预览、大纲或诊断项定位同一结构块的成功率不低于 99%。
- 外部文件冲突测试中静默覆盖次数为 0。
- 资源移动后的有效本地引用比例不低于 99.9%。
- 文档健康中心对标准缺陷集的召回率不低于 95%，误报率低于 5%。
- 断网环境下除用户主动加载的远程资源外，编辑器任务完成率为 100%。

## 7. 范围控制规则

- 新功能进入开发前必须明确属于“对标缺口”或“领先能力”，否则不进入路线。
- 同一基础设施优先服务多个能力，例如源码映射同时支撑滚动同步、大纲、诊断和结构化编辑。
- 编辑器本体不内置账号、云同步、多人协作、CLI、发布和图床上传。未来签名连接器扩展可以提供可选云端或 GitHub 同步，但不能把外围能力变成核心应用的默认行为，也不能替换本地保存。
- 即时渲染编辑未达到可逆、无损和可撤销标准前，不替代源码编辑器成为唯一入口。
- 生态工具必须作为独立产品和进程存在；编辑器扩展也必须运行于隔离进程。编辑器不能因为未安装任何生态工具或扩展而出现残缺入口或降级提示。

## 8. 仍需产品决策

1. 即时渲染编辑是否作为首次公开测试版的默认模式；当前建议在 P1 成熟后再设为默认。
2. 本地版本历史默认保留期限；当前建议 30 天或 500 MB，以先到者为准。

## 9. 编辑器与生态边界

### Inflow 编辑器负责

- 写作：即时渲染、源码、分栏和阅读模式。
- 理解：Markdown、公式、图表、主题和文档大纲。
- 本地组织：文件、文件夹、搜索、图片及附件引用。
- 可靠性：保存、恢复、冲突、版本历史和文档诊断。
- 单篇交付：PDF、HTML、长图和可移植文档包。

### Inflow 生态负责

- CLI 和脚本自动化。
- 批量转换、批量校验和持续集成。
- 博客、CMS、Git 仓库及其他发布渠道。
- 图床、对象存储和第三方服务连接。
- 未来可能出现的团队协作与云服务。

其中云存储与 GitHub 可在后续作为插件市场中的“连接器扩展”回接 Inflow；CLI、批量自动化和发布工具仍保持独立产品形态。

编辑器与生态只通过公开、稳定的文件格式、扩展 API 或显式协议协作。扩展可以提供用户主动调用的命令或视图，但生态能力不得以隐藏后台服务、默认联网或修改核心保存语义的方式回流到编辑器本体。
