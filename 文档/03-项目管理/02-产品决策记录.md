## 1. 目的与边界

本文保留会长期影响 Inflow 产品语义、范围、默认选择、用户保护和生态规则的关键取舍。

决策记录回答“为什么这样选”，不替代产品需求、专项设计、规格附录或验收标准。决策记录中出现的方案只在对应状态为“已批准”且主产品文档已同步时成为基线。

## 2. 决策编号

- 产品决策 ID 使用 `PD-YYYY-NNN` 格式，例如 `PD-2026-001`。
- ID 一经进入待评审即不重用；被拒绝、已取代或已撤回的 ID 仍保留。
- 一个决策只处理一个可清晰判定的取舍。多个决策可互相引用，不捆绑成无法独立复审的大项。

## 3. 决策状态

| 状态 | 含义 |
| --- | --- |
| 草稿 | 正在收集问题、证据和选项 |
| 待评审 | 推荐方案已完整，等待必要评审 |
| 已批准 | 取舍已生效，受影响产品文档已同步 |
| 已废止 | 决策已被取消或新决策取代，只供追溯 |

决策状态使用与[文档管理规范](./01-文档管理规范.md)一致的四态词汇，避免产生第二套含义相近的状态。

## 4. 决策必填内容

每条决策必须包含：

1. **决策 ID 与标题**：用结果表述，不用模糊主题词。
2. **状态、负责人与日期**：明确谁推动、谁批准、何时生效。
3. **决策问题**：说明真实用户或项目冲突，不用“竞品已有”作为唯一问题。
4. **证据与假设**：区分已知事实、研究证据、主观判断和待验证假设。
5. **候选方案**：至少记录推荐方案和主要替代方案。
6. **决定与理由**：说明用户价值、取舍、安全、可访问性、商业或时间影响。
7. **明确不做**：记录被拒绝的方案、例外和未授权范围。
8. **影响文档与行动**：列出需同步的产品设计、规格、附录、验收和用户沟通。
9. **复审触发条件**：什么新证据、故障、法规、用户反馈或产品变化会导致重新评审。

## 6. 决策详情

### PD-2026-001：定位为面向长期 Markdown 资产的本地优先写作工作台

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-19；批准日期为 2026-08-31；审批人为产品负责人；不取代既有已批准决策。
- **问题、证据与假设**：普通编辑、知识库和出版工具分别优化写入、组织或交付，长期 Markdown 用户仍需在文件所有权、连续写作和专业交付之间切换。公开市场资料支持“本地控制”和“专业交付”具有采用价值，但付费意愿与目标人群规模仍是待验证假设。
- **候选方案**：方案 A 是本地优先的长期 Markdown 工作台；方案 B 是以即时渲染为主的轻量编辑器；方案 C 是以私有资料库和关系图为主的知识管理工具。推荐方案 A，因为它能形成从接手文件到可验证交付的独立闭环，并为后续结构与生态能力提供稳定边界。
- **决定、影响与明确不做**：采用方案 A；不以复制既有编辑器、建立封闭资料库或追求功能数量作为定位。影响[产品愿景与原则](../01-产品设计/01-产品愿景与原则.md)、[目标用户与使用场景](../01-产品设计/02-目标用户与使用场景.md)、[产品功能架构](../01-产品设计/03-产品功能架构.md)、[版本路线图](../01-产品设计/06-版本规划/01-版本路线图.md)和[机会与定位结论](../02-市场研究/04-机会与定位结论.md)。产品负责人依据用户问题、产品原则、风险边界和可验收结果做批准决策；定位理解、购买理由或固定样本数研究改为产品发布后的持续验证，不是批准或发布前置。
- **复审触发条件**：用户主动反馈或后续研究否定长期资产问题、单篇可信闭环无法形成持续价值、平台范围改变，或用户主动提供的反馈与诊断材料显示主要任务与定位不符；不使用遥测作为证据源。

### PD-2026-002：统一使用五项体验支柱

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-19；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-001。
- **问题、证据与假设**：按页面或功能数量组织需求容易让可靠性、连续性和退出能力被局部功能遮蔽。现有用户任务可稳定映射到文件、写作、结构、交付和扩展五类结果；假设这五类足以覆盖当前产品周期且不会制造重复权威。
- **候选方案**：方案 A 使用“文件可信、写作流连续、结构理解、可验证交付、安全扩展”；方案 B 使用功能域名称作为价值框架；方案 C 使用竞品能力矩阵。采用方案 A，因为体验支柱能跨越功能域和版本，并可直接连接用户结果与验收。
- **决定、影响与明确不做**：冻结五项正式名称，不用近义词另建同级支柱，不以功能数量替代结果。影响[产品愿景与原则](../01-产品设计/01-产品愿景与原则.md)、[产品设计总览](../01-产品设计/00-产品设计总览.md)、[目标用户与使用场景](../01-产品设计/02-目标用户与使用场景.md)、[产品功能架构](../01-产品设计/03-产品功能架构.md)和[产品验收标准](../01-产品设计/06-版本规划/03-产品验收标准.md)。每项新能力必须说明所属支柱、避免的损害和可观察结果。
- **复审触发条件**：出现无法归类的核心用户任务、两项支柱长期无法区分，或验收实践证明某项支柱不能转化为可观察结果。

### PD-2026-003：本地 Markdown 文件是文档内容事实

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-19；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-001、PD-2026-002。
- **问题、证据与假设**：恢复、历史、同步和插件若被误认作正文事实，会造成状态混淆、覆盖和退出锁定。本地文件所有权是目标用户的重要采用因素；假设直接文件工作流可以在不建立私有内容库的情况下满足核心体验。
- **候选方案**：方案 A 以用户位置中的 Markdown 为事实，其他能力均为保护、视图或外部状态；方案 B 以内置资料库为事实并导出 Markdown；方案 C 以云端副本为事实。采用方案 A，以保证可迁移、可离线和可退出。
- **决定、影响与明确不做**：恢复内容、本地版本时间线、连接器状态和插件结果不得冒充已保存文件；不要求导入、登录或上传才可写作。影响[文档与文件](../01-产品设计/04-功能设计/01-文档与文件.md)、[首发版本范围](../01-产品设计/06-版本规划/02-首发版本范围.md)、[人工智能与连接器](../01-产品设计/05-插件生态/04-人工智能与连接器.md)及状态、默认设置和术语附录。成功以静默丢失或覆盖为零、状态理解正确和其他工具可继续打开文件判断。
- **复审触发条件**：直接文件模式无法满足经批准的核心任务、平台文件模型发生重大变化，或用户研究证明当前状态表达仍使多数用户误解事实来源。

### PD-2026-004：四种视图共享同一内容事实

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-19；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-003。
- **问题、证据与假设**：源码、分栏、阅读和即时渲染若各自保存内容或位置，会造成第二份正文、撤销分裂和上下文丢失。用户任务表明不同写作方式需要切换，但不需要不同文档事实。
- **候选方案**：方案 A 让源码编辑、实时预览、纯预览和即时渲染编辑共享 Markdown、撤销与语义位置；方案 B 为每种视图维护独立编辑模型；方案 C 只保留一种编辑方式。采用方案 A，在保留精确性与不同工作方式的同时消除内容分叉。
- **决定、影响与明确不做**：视图切换不创建隐藏富文本或第二份可编辑正文；不以视觉相似牺牲源码透明和可撤销性。影响[编辑与写作](../01-产品设计/04-功能设计/02-编辑与写作.md)、[阅读与预览](../01-产品设计/04-功能设计/03-阅读与预览.md)、[产品规格与参数](../01-产品设计/07-产品附录/附录A-产品规格与参数.md)、[默认设置](../01-产品设计/07-产品附录/附录B-默认设置.md)和[产品验收标准](../01-产品设计/06-版本规划/03-产品验收标准.md)。
- **复审触发条件**：结构化编辑无法保持标准 Markdown、跨视图定位持续失败，或辅助使用评审证明某一视图导致核心任务不可达。

### PD-2026-005：插件采用可检查、可撤权、可停用的能力租约

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-19；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-002、PD-2026-003。
- **问题、证据与假设**：开放生态可覆盖长尾任务，也会增加权限、数据、费用和退出成本。市场信号支持可选能力价值；用户是否理解“按任务授权”及其对安装转化的影响仍需验证。
- **候选方案**：方案 A 为每项插件建立能力租约与最小范围授权；方案 B 安装时一次授予全部权限；方案 C 不提供生态。采用方案 A，在保留专业扩展价值的同时维护核心独立性。
- **决定、影响与明确不做**：插件不得接管保存、恢复、撤销和冲突裁决；更新扩大权限时重新确认；撤权、停用和卸载后 Markdown 仍可读。不开放用付费换权限、静默运行或无法退出的超级插件。影响[生态战略](../01-产品设计/05-插件生态/01-生态战略.md)、[插件能力设计](../01-产品设计/05-插件生态/02-插件能力设计.md)、[插件市场与治理](../01-产品设计/05-插件生态/03-插件市场与治理.md)及生态验收与附录。

- **决定、影响与明确不做**：首个公开市场不提供付费条目、评价、Inflow 收款、订阅或购买恢复；AI 首版不调用工具、不操作文件、不自动应用，且只有能权威报价、预授权或接受最大消费参数的提供方可开始付费任务并使用硬费用上限；连接器首版不自动同步、移动或删除；设备收到防回滚的已签名撤回清单后立即停止风险版本，用户可选择明确检查周期。影响生态战略、插件能力、市场治理、AI 与连接器、路线、附录 A/B/D/E/G 与成熟版 UAT。
- **用户影响与成功指标**：每个首版都能独立解释数据、权限、结果和退出；首个市场没有隐藏商业账号依赖；文档内指令不能扩大 AI 权限；候选副本不替换本地文件；离线设备不被虚假承诺即时获知撤回。
- **复审触发条件**：免费市场不能验证发现与治理，AI 纯文本建议没有任务价值，单向连接器不能形成有用交付，提供方费用能力变化，或商业账号、同步协议和工具调用安全合同获得批准且对应专项候选 UAT 实际通过。

### PD-2026-015：首发单一编辑会话以规范路径为边界

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-30；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-003、PD-2026-012。
- **问题、证据与假设**：相同规范路径可以作为首发可观察的文件入口，但不同路径的硬链接别名可指向同一底层文件。当前候选证据只能证明身份比较和最近记录去重，不能证明两条别名路径不会产生两个活动编辑会话。
- **候选方案**：方案 A 在首发建立全局资源身份登记并用真实双打开验证硬链接去重；方案 B 只对相同规范路径保证单一会话，将硬链接别名列为公开例外与 `OPEN`；方案 C 删除单一会话承诺。采用方案 B，同时保留 A 为扩大承诺前的证据路径。
- **决定、影响与明确不做**：首发从应用、Finder 或拖放重复打开同一规范路径时回到现有会话。对不同路径的硬链接别名，不声称首发已在打开前去重，也不用身份辅助函数或最近记录测试代替真实活动文档验证。应用已检测到外部变化时仍暂停写入并进入冲突退路；这一行为不用于宣称硬链接别名或其他最终路径竞争已被排除。影响文档与文件、UAT、附录 E/G 与变更记录。
- **复审触发条件**：实现可证明所有活动打开入口都按稳定资源身份归并，或真实用户文件中硬链接别名造成不可接受的重复编辑风险时，重新评审是否转向方案 A。

### PD-2026-016：连接器断开不抹除仍待核对的外部副作用

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-30；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-005、PD-2026-008、PD-2026-014。
- **问题、证据与假设**：连接器请求在断网、超时或账号失效时可能已经对外生效，却尚未返回可确认结果。若断开账号同时删除该记录，用户会失去核对、重试或处理外部副作用的依据；假设保留少量明确标记的待核对记录，比把未知状态冒充为已取消更符合可退出和不静默修改原则。
- **候选方案**：方案 A 断开立即停止新任务并撤权，但把已完成记录与待完成、外部结果未知记录分开；后两者保留到核对完成或经专项评审批准的安全终态。方案 B 断开时允许删除全部连接器状态。采用方案 A，拒绝用方案 B 简化界面而隐藏未知影响。
- **决定、影响与明确不做**：连接设置和已完成、已确认安全结束的记录可按公开规则清理；待完成或外部副作用未知的记录不能因断开、卸载或删除设置静默消失。产品必须显示保留原因、当前状态和核对路径，但保留记录不等于继续授权或后台执行。影响人工智能与连接器、成熟版 UAT、附录 D/G 和变更记录。
- **复审触发条件**：连接器协议能够对每项任务证明无副作用的确定取消，或经安全、隐私、数据保留和服务兼容评审批准新的安全终态时，重新评审保留与删除规则。

### PD-2026-017：首发本地 Markdown 链接只打开未命名安全副本

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-30；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-003、PD-2026-012、PD-2026-013。
- **问题、证据与假设**：用户需要从 Markdown 沿本地链接阅读另一份文档，但链接被确认后，目标仍可能变化。把通过链接打开的窗口表现为原文件编辑会话，会让用户误以为后续修改会安全写回该路径。假设首发以明确、可另存的安全副本承接阅读任务，比在单篇产品中承诺持续路径所有权更容易理解和验证。
- **候选方案**：方案 A 确认当前目标后，以未命名安全副本打开确认时的内容，不继续关联或写回原文件；方案 B 持续绑定原路径并承担完整文件生命周期；方案 C 只在 Finder 中显示。采用方案 A，工作区内持续导航留到成长版。
- **决定、影响与明确不做**：首发相对及跨文档 Markdown 链接先展示固定说明，确认时明确告知将作为未命名安全副本打开；用户确认后以未命名文档打开并保持未命名，不关联或写回原文件，任何修改必须另存。副本不因原文件随后变化而改变。标题片段只解码一次并精确匹配副本内既有标题标识。影响工作区与导航、附录 A/D/G、UAT 与变更记录；不把首发链接阅读冒充为工作区持续编辑。
- **复审触发条件**：成长版工作区的单一会话、文件身份、外部变化和写入冲突合同获得批准与端到端证据，或真实用户任务证明安全副本造成不可接受的阅读中断时，重新评审持续绑定行为。

### PD-2026-018：首发保存与恢复声明不超过候选证据

- **元信息**：状态为已批准；负责人为产品团队；提出日期为 2026-08-30；批准日期为 2026-08-31；审批人为产品负责人；依赖 PD-2026-003、PD-2026-012、PD-2026-013。

## 8. 决策评审规则

- 改变产品定位、核心原则、主要用户或反目标的决策，必须由产品负责人批准。
- 涉及敏感数据、外部账号、网络、费用、删除或不可逆影响的决策，需要相应专项评审。
- 决策不能因为工期或交付便利而静默放宽已批准的用户保护底线；需要变更时必须说明用户影响和退路。
- 市场研究可作为证据，不能单独作为“其他产品已有，所以必须做”的批准理由。

## 9. 取代、撤回与复审

- 新决策取代旧决策时，新旧两条都记录双向关系，旧决策转为已废止。
- 紧急撤回可以先停止危险的产品行为，但必须在后续记录原因、用户影响、临时替代和正式决策。
- 复审不在原已批准记录中改写历史；以新决策 ID 保留时间线。
