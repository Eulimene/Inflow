## 1. 目的与边界

本文保留会长期影响 Inflow 产品语义、范围、默认选择、用户保护和生态规则的关键取舍。

决策记录回答“为什么这样选”，不替代产品需求、专项设计、规格附录或验收标准。决策记录中出现的方案只在对应状态为“已批准”且主产品文档已同步时成为基线。

## 2. 决策编号

- 产品决策 ID 使用 `PD-YYYY-NNN` 格式，例如 `PD-2026-001`。
- ID 一经进入待评审即不重用；被拒绝、已取代或已撤回的 ID 仍保留。
- 一个决策只处理一个可清晰判定的取舍。多个决策可互相引用，不捆绑成无法独立复审的大项。

## 3. 决策状态

| 状态 | 含义 |
| --- | --- |
| 草稿 | 正在收集问题、证据和选项 |
| 待评审 | 推荐方案已完整，等待必要评审 |
| 已批准 | 取舍已生效，受影响产品文档已同步 |
| 已废止 | 决策已被取消或新决策取代，只供追溯 |

决策状态使用与[文档管理规范](./01-文档管理规范.md)一致的四态词汇，避免产生第二套含义相近的状态。

## 4. 决策必填内容

每条决策必须包含：

1. **决策 ID 与标题**：用结果表述，不用模糊主题词。
2. **状态、负责人与日期**：明确谁推动、谁批准、何时生效。
3. **决策问题**：说明真实用户或项目冲突，不用“竞品已有”作为唯一问题。
4. **证据与假设**：区分已知事实、研究证据、主观判断和待验证假设。
5. **候选方案**：至少记录推荐方案和主要替代方案。
6. **决定与理由**：说明用户价值、取舍、安全、可访问性、商业或时间影响。
7. **明确不做**：记录被拒绝的方案、例外和未授权范围。
8. **影响文档与行动**：列出需同步的产品设计、规格、附录、验收和用户沟通。
9. **复审触发条件**：什么新证据、故障、法规、用户反馈或产品变化会导致重新评审。

## 6. 决策详情

### PD-2026-001：定位为面向长期 Markdown 资产的本地优先写作工作台

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品负责人评审；不取代既有已批准决策。
- **问题、证据与假设**：普通编辑、知识库和出版工具分别优化写入、组织或交付，长期 Markdown 用户仍需在文件所有权、连续写作和专业交付之间切换。公开市场资料支持“本地控制”和“专业交付”具有采用价值，但付费意愿与目标人群规模仍是待验证假设。
- **候选方案**：方案 A 是本地优先的长期 Markdown 工作台；方案 B 是以即时渲染为主的轻量编辑器；方案 C 是以私有资料库和关系图为主的知识管理工具。推荐方案 A，因为它能形成从接手文件到可验证交付的独立闭环，并为后续结构与生态能力提供稳定边界。
- **决定、影响与明确不做**：采用方案 A；不以复制既有编辑器、建立封闭资料库或追求功能数量作为定位。影响[产品愿景与原则](../01-产品设计/01-产品愿景与原则.md)、[目标用户与使用场景](../01-产品设计/02-目标用户与使用场景.md)、[产品功能架构](../01-产品设计/03-产品功能架构.md)、[版本路线图](../01-产品设计/06-版本规划/01-版本路线图.md)和[机会与定位结论](../02-市场研究/04-机会与定位结论.md)。批准前需完成定位理解与购买理由研究；成功以真实长期文件采用、核心任务完成和可退出性判断，不以竞品勾选率判断。
- **复审触发条件**：目标用户访谈否定长期资产问题、单篇可信闭环无法形成购买理由、平台范围改变，或持续使用数据显示主要用户任务与定位不符。

### PD-2026-002：统一使用五项体验支柱

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品负责人评审；依赖 PD-2026-001。
- **问题、证据与假设**：按页面或功能数量组织需求容易让可靠性、连续性和退出能力被局部功能遮蔽。现有用户任务可稳定映射到文件、写作、结构、交付和扩展五类结果；假设这五类足以覆盖当前产品周期且不会制造重复权威。
- **候选方案**：方案 A 使用“文件可信、写作流连续、结构理解、可验证交付、安全扩展”；方案 B 使用功能域名称作为价值框架；方案 C 使用竞品能力矩阵。采用方案 A，因为体验支柱能跨越功能域和版本，并可直接连接用户结果与验收。
- **决定、影响与明确不做**：冻结五项正式名称，不用近义词另建同级支柱，不以功能数量替代结果。影响[产品愿景与原则](../01-产品设计/01-产品愿景与原则.md)、[产品设计总览](../01-产品设计/00-产品设计总览.md)、[目标用户与使用场景](../01-产品设计/02-目标用户与使用场景.md)、[产品功能架构](../01-产品设计/03-产品功能架构.md)和[产品验收标准](../01-产品设计/06-版本规划/03-产品验收标准.md)。每项新能力必须说明所属支柱、避免的损害和可观察结果。
- **复审触发条件**：出现无法归类的核心用户任务、两项支柱长期无法区分，或验收实践证明某项支柱不能转化为可观察结果。

### PD-2026-003：本地 Markdown 文件是文档内容事实

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品与数据保护评审；依赖 PD-2026-001、PD-2026-002。
- **问题、证据与假设**：恢复、历史、同步和插件若被误认作正文事实，会造成状态混淆、覆盖和退出锁定。本地文件所有权是目标用户的重要采用因素；假设直接文件工作流可以在不建立私有内容库的情况下满足核心体验。
- **候选方案**：方案 A 以用户位置中的 Markdown 为事实，其他能力均为保护、视图或外部状态；方案 B 以内置资料库为事实并导出 Markdown；方案 C 以云端副本为事实。采用方案 A，以保证可迁移、可离线和可退出。
- **决定、影响与明确不做**：恢复内容、本地版本时间线、连接器状态和插件结果不得冒充已保存文件；不要求导入、登录或上传才可写作。影响[文档与文件](../01-产品设计/04-功能设计/01-文档与文件.md)、[首发版本范围](../01-产品设计/06-版本规划/02-首发版本范围.md)、[人工智能与连接器](../01-产品设计/05-插件生态/04-人工智能与连接器.md)及状态、默认设置和术语附录。成功以静默丢失或覆盖为零、状态理解正确和其他工具可继续打开文件判断。
- **复审触发条件**：直接文件模式无法满足经批准的核心任务、平台文件模型发生重大变化，或用户研究证明当前状态表达仍使多数用户误解事实来源。

### PD-2026-004：四种视图共享同一内容事实

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品与可访问性评审；依赖 PD-2026-003。
- **问题、证据与假设**：源码、分栏、阅读和即时渲染若各自保存内容或位置，会造成第二份正文、撤销分裂和上下文丢失。用户任务表明不同写作方式需要切换，但不需要不同文档事实。
- **候选方案**：方案 A 让源码编辑、实时预览、纯预览和即时渲染编辑共享 Markdown、撤销与语义位置；方案 B 为每种视图维护独立编辑模型；方案 C 只保留一种编辑方式。采用方案 A，在保留精确性与不同工作方式的同时消除内容分叉。
- **决定、影响与明确不做**：视图切换不创建隐藏富文本或第二份可编辑正文；不以视觉相似牺牲源码透明和可撤销性。影响[编辑与写作](../01-产品设计/04-功能设计/02-编辑与写作.md)、[阅读与预览](../01-产品设计/04-功能设计/03-阅读与预览.md)、[产品规格与参数](../01-产品设计/07-产品附录/附录A-产品规格与参数.md)、[默认设置](../01-产品设计/07-产品附录/附录B-默认设置.md)和[产品验收标准](../01-产品设计/06-版本规划/03-产品验收标准.md)。
- **复审触发条件**：结构化编辑无法保持标准 Markdown、跨视图定位持续失败，或辅助使用评审证明某一视图导致核心任务不可达。

### PD-2026-005：插件采用可检查、可撤权、可停用的能力租约

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品、安全、隐私与商业评审；依赖 PD-2026-002、PD-2026-003。
- **问题、证据与假设**：开放生态可覆盖长尾任务，也会增加权限、数据、费用和退出成本。市场信号支持可选能力价值；用户是否理解“按任务授权”及其对安装转化的影响仍需验证。
- **候选方案**：方案 A 为每项插件建立能力租约与最小范围授权；方案 B 安装时一次授予全部权限；方案 C 不提供生态。采用方案 A，在保留专业扩展价值的同时维护核心独立性。
- **决定、影响与明确不做**：插件不得接管保存、恢复、撤销和冲突裁决；更新扩大权限时重新确认；撤权、停用和卸载后 Markdown 仍可读。不开放用付费换权限、静默运行或无法退出的超级插件。影响[生态战略](../01-产品设计/05-插件生态/01-生态战略.md)、[插件能力设计](../01-产品设计/05-插件生态/02-插件能力设计.md)、[插件市场与治理](../01-产品设计/05-插件生态/03-插件市场与治理.md)及生态验收与附录。
- **复审触发条件**：权限理解率低于目标、发生越权或退出后内容不可读、市场治理无法阻止撤回版本，或生态使用数据显示租约模型不能支持主要任务。

### PD-2026-006：市场研究与竞品证据只作为决策输入

- **元信息**：状态为待评审；负责人为产品管理；提出日期为 2026-08-19；批准日期待产品负责人评审；不依赖外部产品持续不变。
- **问题、证据与假设**：把竞品功能表直接转成范围会制造模仿、重复权威和无用户价值的入口。公开资料能证明市场行为与迁移预期，但不能单独证明 Inflow 用户需求或优先级。
- **候选方案**：方案 A 将研究限定为问题、证据与假设输入，再由产品原则、范围和验收决策；方案 B 以竞品覆盖率决定路线；方案 C 完全不研究竞品。采用方案 A，既保留外部证据也保护原创产品判断。
- **决定、影响与明确不做**：研究文档不得创建功能、默认值或版本范围，不复制竞品界面、菜单、术语和交互顺序。影响[市场研究总览](../02-市场研究/00-市场研究总览.md)、[竞品分析](../02-市场研究/02-竞品分析.md)、[迁移兼容研究](../02-市场研究/03-迁移兼容研究.md)、[文档管理规范](./01-文档管理规范.md)和所有范围评审。新需求必须说明用户问题、支柱、结果和退出边界。
- **复审触发条件**：研究与产品权威再次混淆、无法追溯需求的独立理由，或新的研究方法能更可靠地连接证据与产品决策。

### PD-2026-007：被委托附录是对应规格字段的唯一权威

- **元信息**：状态为待评审；负责人为产品团队与项目管理团队；提出日期为 2026-08-19；批准日期待产品与项目管理评审；依赖 PD-2026-006。
- **问题、证据与假设**：默认值、范围、命令和文案散落在多份正文时会发生循环权威和无声漂移。集中附录可提升一致性，但前提是附录只精确化上位产品行为而不创建功能。
- **候选方案**：方案 A 将参数、默认、命令、文案和术语分别委托给五份附录；方案 B 在每份功能稿重复完整字段；方案 C 取消精确规格。采用方案 A，以单一责任减少冲突并保持人可阅读。
- **决定、影响与明确不做**：附录 A–E 分别负责参数、默认、命令、文案和术语；产品正文仍决定用户价值、行为、范围与阶段。附录不得提前功能、改变版本归属或放宽保护。影响[文档中心](../00-文档中心.md)、[项目管理说明](./00-项目管理说明.md)和[产品附录](../01-产品设计/07-产品附录/附录A-产品规格与参数.md)；所有重复字段应改为引用并进入变更同步。
- **复审触发条件**：同一字段出现两个权威、附录无法覆盖已批准产品行为、引用成本使读者无法完成任务，或附录开始创建上位范围。

### PD-2026-008：人工智能与连接器不成为基础产品依赖

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品、安全、隐私、费用与商业评审；依赖 PD-2026-003、PD-2026-005。
- **问题、证据与假设**：人工智能和外部连接可提升任务效率，也可能静默上传、改写、覆盖、收费或把同步状态冒充本地保存。用户愿意按任务提供上下文和连接服务是待验证假设。
- **候选方案**：方案 A 将人工智能与连接器作为成熟版高信任可选能力；方案 B 将账号、同步和人工智能作为默认主入口；方案 C 永久排除外部能力。采用方案 A，使用户可选择价值而不削弱离线核心。
- **决定、影响与明确不做**：任务前展示内容范围、去向、结果影响和费用；修改与冲突由用户确认；所有窗口共用费用上限；断开后本地文件完整。不默认上传全文、不静默解决冲突、不自动提高费用或让外部失败阻断本地保存。影响[人工智能与连接器](../01-产品设计/05-插件生态/04-人工智能与连接器.md)、[插件能力设计](../01-产品设计/05-插件生态/02-插件能力设计.md)、成熟版路线和验收。
- **复审触发条件**：发生未确认的数据发送、修改、覆盖或费用，供应商与法规边界改变，或用户研究证明现有确认与费用模型无法理解。

### PD-2026-009：文档库只保留人可阅读的产品、研究与项目管理 Markdown

- **元信息**：状态为待评审；负责人为项目管理团队；提出日期为 2026-08-19；批准日期待项目管理与产品负责人评审；不改变产品实现状态。
- **问题、证据与假设**：产品定义与技术实现、机器校验和脚本混放会让读者误判权威，并使产品范围被实现细节反向驱动。单一的人读产品库可提供稳定入口；实现与验证资料由项目其他边界另行管理，不在本库建立权威。
- **候选方案**：方案 A 让 `文档/` 只保存人读 Markdown；方案 B 在同一树中混放产品、实现、机器合同和脚本；方案 C 仅保留一份总文档。采用方案 A，以清晰分类、中文命名和文档中心维持可读性。
- **决定、影响与明确不做**：本库不收录技术实现、机器校验文件、脚本或非 Markdown 资产；不以删除历史资料冒充产品已实现。影响[文档中心](../00-文档中心.md)、[项目管理说明](./00-项目管理说明.md)、[文档管理规范](./01-文档管理规范.md)和本变更记录。迁移后需检查文件纯度、命名、链接、编号和导航覆盖。
- **复审触发条件**：人读文档无法表达必要产品合同、库内再次出现非 Markdown 或实现材料，或项目需要正式建立新的、与本库分离的资料权威边界。

### PD-2026-010：匿名产品使用数据只在用户主动开启后按公开的最小范围处理

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品、隐私、数据保护与合规专项评审；依赖 PD-2026-003，不取代既有已批准决策。
- **问题、证据与假设**：产品质量、可用性与性能改进需要了解非内容类使用结果，但默认记录、不可见字段或无法退出会破坏本地优先和用户信任。用户能在开启前理解范围并作出真实选择仍需通过隐私理解测试验证，现有产品文档只是待评审合同而非用户同意证据。
- **候选方案**：方案 A 是初始关闭，用户查看字段、用途、保留与退出规则后主动开启；方案 B 是默认开启并允许退出；方案 C 是完全不收集。采用方案 A，在不把数据选择变成核心任务前置条件的情况下保留有限的产品改进依据；方案 C 作为用户保持关闭时的完整体验成立。
- **决定、影响与明确不做**：只有主动开启后才记录与发送。允许范围限定为 Inflow 版本、macOS 主版本、界面语言、功能与命令计数、耗时区间和错误类别；永不纳入文档内容、选区、剪贴板、文件名、文件路径、链接地址、搜索词、账号凭据、插件处理内容或可识别个人的信息。数据只用于产品质量、可用性与性能改进，不用于广告、内容画像或出售。可识别单次事件的记录保留不超过 30 天，不可回溯到用户或设备的汇总保留不超过 12 个月；关闭后停止新记录与发送，并允许清除尚未发送记录，已发送数据按开启前公开的保留与删除规则到期处置。匿名产品使用数据不得成为首次写作、保存、恢复、阅读、交付或其他核心能力的依赖，保持关闭不降低功能。影响[首发版本范围](../01-产品设计/06-版本规划/02-首发版本范围.md)、[产品验收标准](../01-产品设计/06-版本规划/03-产品验收标准.md)及附录 A、B、D、E。
- **复审触发条件**：拟增加字段、用途、接收方、保留期限或身份关联，拟改变初始关闭、删除路径或核心独立性，发生禁止数据进入记录、未开启即记录或发送、超期保留，或隐私理解测试不达标时，停止扩大并重新进行产品、隐私、数据保护与合规专项评审。

### PD-2026-011：迁移归属专业版、结构洞察归属成熟版且不扩大首发范围

- **元信息**：状态为待评审；负责人为产品团队；提出日期为 2026-08-19；批准日期待产品、迁移、隐私、安全与可访问性评审；依赖 PD-2026-001、PD-2026-002、PD-2026-003、PD-2026-006。
- **问题、证据与假设**：迁移和结构洞察分别解决接手既有资产与理解长期工作区的问题，但两者都需要真实样本、清楚的退出路径和独立验收，不能因研究或竞品清单直接进入首发。现有迁移研究、功能设计和阶段验收形成了候选合同，尚不能替代真实文件与工作区证据。
- **候选方案**：方案 A 将迁移放入专业版、结构洞察放入成熟版，并保持首发范围不变；方案 B 将两项能力提前到首发；方案 C 将两项能力都延后到成熟版以后。采用方案 A，使专业版先验证可解释迁移，成熟版再基于长期工作区证据提供结构理解，同时不让后续能力反向成为首发依赖。
- **决定、影响与明确不做**：专业版承担迁移预检、来源保护、目标副本、差异说明、报告与安全退出的完整用户结果；成熟版承担基于用户所选工作区事实的关系、来源、演进与质量趋势，并将推断与用户事实清楚区分。首发不新增这两项能力的入口、承诺或退出门槛，也不以它们阻断首发验收。进入对应阶段前，迁移必须用有代表性的真实来源样本验证兼容结果、来源不变和可退出性；结构洞察必须用真实工作区验证可定位证据、错误推断可纠正、无隐藏正文修改和历史缺失时的诚实降级。影响[迁移与兼容](../01-产品设计/04-功能设计/08-迁移与兼容.md)、[工作区与导航](../01-产品设计/04-功能设计/04-工作区与导航.md)、[版本路线图](../01-产品设计/06-版本规划/01-版本路线图.md)和[产品验收标准](../01-产品设计/06-版本规划/03-产品验收标准.md)。
- **复审触发条件**：真实迁移样本不能达到来源保护或结果可解释标准，结构洞察持续产生无法纠正的误导、需要未获授权的数据或隐藏内容事实，目标用户研究否定阶段价值，后续能力成为首发依赖，或专业版、成熟版退出标准无法独立满足时，重新评审阶段归属与范围。

## 8. 决策评审规则

- 改变产品定位、核心原则、主要用户或反目标的决策，必须由产品负责人批准。
- 涉及敏感数据、外部账号、网络、费用、删除或不可逆影响的决策，需要相应专项评审。
- 决策不能因为工期或交付便利而静默放宽已批准的用户保护底线；需要变更时必须说明用户影响和退路。
- 市场研究可作为证据，不能单独作为“其他产品已有，所以必须做”的批准理由。

## 9. 取代、撤回与复审

- 新决策取代旧决策时，新旧两条都记录双向关系，旧决策转为已废止。
- 紧急撤回可以先停止危险的产品行为，但必须在后续记录原因、用户影响、临时替代和正式决策。
- 复审不在原已批准记录中改写历史；以新决策 ID 保留时间线。

- 决策只保留理由与取舍；生效的用户行为、默认值和验收仍必须写入对应产品正文或附录。
