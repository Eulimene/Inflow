## 1. 目的

本文以人能理解的方式记录项目文档基线的实质变化：改了什么、为什么改、影响哪些用户和文档、经过什么决策或评审。

本文不复制版本控制系统的文件清单，不用提交数量代表产品进度，不把文档变更误报为产品已实现或已验收。

## 2. 变更编号

- 变更 ID 使用 `CHG-YYYYMMDD-NNN` 格式，例如 `CHG-20260819-001`。
- 同一日按创建顺序递增，已取消的 ID 不重用。
- 一个变更 ID 可以覆盖一组不可分割的跨文档同步；无关主题分别记录。

## 3. 变更类型

| 类型 | 使用条件 | 是否需产品决策 |
| --- | --- | --- |
| 产品语义 | 定位、用户、原则、用户行为或反目标变化 | 需要 |
| 范围与版本 | 新增、移除、延后、提前能力或改变验收 | 需要 |
| 默认值与规格 | 默认选择、范围、选项、状态或例外改变 | 需要，除非只修复与已批准主文的明显不一致 |
| 权限、数据与费用 | 数据范围、外部去向、用户确认、费用或删除改变 | 需要，且需专项评审 |
| 权威与结构 | 文档拆分、合并、迁移、取代或附录委托改变 | 若影响权威语义则需要 |
| 编辑性修正 | 错字、格式、本地链接或无语义歧义的澄清 | 不需要，可定期汇总 |
| 紧急撤回 | 需立即停止有安全、隐私、数据或费用风险的行为 | 可先执行，但必须追加决策与复盘 |

## 4. 每条变更的必填字段

1. 变更 ID、日期、类型、状态和负责人。
2. 一句话摘要和变更背景。
3. 变更前和变更后的用户可见差异。
4. 受影响文档及其版本变化。
5. 关联产品决策、评审和已知例外。
6. 对范围、默认值、用户数据、费用、兼容、文档链接和验收的影响。
7. 需要的迁移、用户通知、后续任务和复审条件。

## 5. 变更状态

| 状态 | 含义 |
| --- | --- |
| 草稿 | 正在识别影响和关联决策 |
| 待评审 | 变更内容与同步文档已齐全，等待审核 |
| 已批准 | 变更已合并，所有受影响权威已同步 |
| 已废止 | 变更已取消或被另一变更取代 |

变更状态不代表产品交付状态。“已批准”只表示文档基线已更新，不表示功能已实现、证据已产生或版本已发布。

## 7. 本轮变更详情

### CHG-20260819-001：建立插件生态产品设计

- **元信息**：日期为 2026-08-19；类型为产品语义；状态为待评审；负责人为产品团队；关联 PD-2026-005；无已批准取代项。
- **背景与前后差异**：变更前只有“支持扩展”的方向性表述，用户无法理解插件如何发现、授权、更新、停用和退出。变更后形成能力租约、能力类型、安装与授权、修改预览、停用卸载和失败降级的完整用户闭环。
- **文档、版本与评审**：新增[生态战略](../01-产品设计/05-插件生态/01-生态战略.md)与[插件能力设计](../01-产品设计/05-插件生态/02-插件能力设计.md) v1.0，并同步路线与验收引用。需产品、安全、隐私和可访问性评审；没有允许插件接管保存或静默读写的例外。
- **影响、迁移与复审**：专业版至成熟版范围获得明确产品合同，首发范围不扩大；默认值、费用和外部数据仍由相应附录与专项设计约束。无需用户迁移；批准前完成权限理解概念测试，能力实际进入版本时在详情页和发布说明中告知权限与退出边界。若插件退出导致内容不可读、权限模型无法理解或版本范围变化，重新评审并通知受影响文档负责人。

### CHG-20260819-002：建立插件市场与治理规则

- **元信息**：日期为 2026-08-19；类型为权限、数据与费用；状态为待评审；负责人为产品团队；关联 PD-2026-005；无已批准取代项。
- **背景与前后差异**：变更前没有公开市场的信息、审核、商业、投诉、弃维和撤回合同。变更后用户在安装前能比较发布者、权限、数据、费用与退出后果，并能区分下架、弃维和不可绕过的安全撤回。
- **文档、版本与评审**：新增[插件市场与治理](../01-产品设计/05-插件生态/03-插件市场与治理.md) v1.0，并同步[状态与提示文案](../01-产品设计/07-产品附录/附录D-状态与提示文案.md)与[术语表](../01-产品设计/07-产品附录/附录E-术语表.md)。需安全、隐私、商业、退款与合规评审；付费换权限、竞价自然排名和用户绕过撤回没有例外。
- **影响、迁移与复审**：变更只进入成熟版市场，不提前改变专业版能力中心或首发。发布者和已安装用户的迁移、通知、数据导出与替代路径由市场状态决定。发生撤回绕过、误导排名、未披露费用或法规变化时立即复审。

## 9. 变更准入检查

变更进入待评审前，负责人确认：

- [ ] 不使用市场研究或竞品清单单独扩大产品范围。
- [ ] 产品正文、被委托附录、决策和验收的相关字段已同步。
- [ ] 默认值和范围仍只有一个权威位置。
- [ ] 用户数据、外部账号、网络、费用、删除或不可逆影响有专项评审。
- [ ] 受影响链接可达，取代关系双向完整。
- [ ] 变更记录说明文档已更新，不冒充为产品已实现或已验收。

## 10. 发布摘要与用户通知

- 对用户可见的变更，根据本记录编写简洁的发布摘要，不暴露无关内部细节。
- 会改变默认选择、需要新授权、导致旧内容降级、增加费用或需要用户迁移的变更，必须在生效前通知。
- 紧急撤回立即通知原因、影响、安全状态和用户需要采取的行动。
