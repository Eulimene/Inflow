# Logging Policy（冻结契约）

- policyVersion：1
- 契约状态：Frozen
- 机器事实来源：[`日志策略.json`](./日志策略.json)
- Release canary 证据：OPEN

## 原则与范围

日志只回答“哪个枚举阶段以哪个枚举结果结束、耗时/大小落在哪个 bucket”，不记录用户内容。保存、恢复、渲染、图片、PDF、本地链接、设置迁移和安全策略共用机器 allowlist；调用方不能自由拼接字典或 `localizedDescription`。

禁止字段包括 Markdown/HTML/PDF/图片字节或片段、绝对/相对路径、文件名、URL/fragment/heading、bookmark、selection/window state、prompt/response/diff、剪贴板、content/raw hash、document/workspace/session/extension/account 的稳定 ID、Keychain item、环境变量、命令行和底层错误描述。底层错误在产生日志前映射为版本化枚举 `reasonCode/outcomeCode`；映射失败使用 `unknown`，不得回退原文。

唯一相关 ID 是每次 operation 随机生成的 `ephemeralCorrelationID`，只在该次进程内用于关联，不能由文档/路径/hash 派生、不能跨启动复用。Release 遇到未知 event/field/type 时丢弃整条记录并只增加内存 counter；不得“尽量序列化”。

## 存储、容量与 TTL

app-owned operational log 位于容器 Library/Logs 的固定目录，目录 `0700`、文件 `0600`、禁止备份、无 symlink follow。上限为 10 MiB、5 个轮换文件、72 小时，以先到者为准；单条 canonical JSON line 最大 4 KiB。达到限制先删最旧完整文件，再丢新事件；日志失败永不阻塞编辑、保存、恢复或退出。

Crash breadcrumb 只在内存保留最近 200 条/256 KiB，并只含同一 allowlist 字段；正常退出清除。应用不创建第二套“debug 全量日志”。OSLog/signpost 只能使用 machine policy 中的 public 枚举、bucket 与 build role，不得把 private 标记当成允许记录正文的理由。日志不自动上传，P0 也没有遥测网络 target。

启动、每次 rotate、写入前和应用后台切换时执行容量/TTL 清理；wall clock 回拨不能延长记录寿命，同时记录 monotonic age。无法判断年龄的旧格式直接删除或隔离，不无限保留。

## Canary scanner

Release fixture 每次生成不同的高熵 canary，分别嵌入正文、路径/文件名、URL/fragment、bookmark、selection/window state、HTML/PDF、AI prompt/response 和扩展拒绝样本。完成保存/恢复/渲染/导出/强杀/crash/cleanup 场景后，scanner 扫描：

- app container 内 logs、SQLite/WAL/shm、Recovery/State/Sync/AI stores 与已过 TTL/启动清理后的 LinkOpenClones；
- 测试产生的 unified-log capture、crash report/diagnostic attachment、helper stdout/stderr；
- app 创建或可归属的 temp/replacement residue 与 PDF/print spool fixture。

匹配集合至少包含 UTF-8、UTF-16LE/BE、NFC/NFD、JSON escaped、一次/二次 percent-encoded、标准/URL-safe base64、hex 和产品实际使用的压缩 framing。Scanner 不扫描用户原始 `.md` 或用户明确选择的最终导出目标；active LinkOpenClone 可在 lease 内包含原文件字节，但 fixture 必须在 lease close/TTL/重启清理后证明零残留。

报告必须记录随机 canary 的单向 test-run identifier、扫描器/规则 hash、扫描 roots、文件/字节计数和零命中；报告本身不得保存 canary。任一无法读取的 app-owned root、scanner crash、未知压缩格式、命中或“跳过”都使门禁失败。

## 验证门槛

CI 验证 `日志策略.json` 的 event/field allowlist 与编译进各 target 的 logging facade 完全一致，源码中禁止直接 OSLog/print/stderr 的 lint 只有经过 facade 的固定模板例外。容量、TTL、损坏轮换文件、磁盘满、时钟回拨、并发写和 crash fixture 必须通过。

当前没有 Release app/container/crash/unified-log 产物，不能声称 canary 已通过。机器 policy 是实现契约；scanner 零命中报告仍为 T0/P0 开放证据。
