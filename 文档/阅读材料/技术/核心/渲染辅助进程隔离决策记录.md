# RenderHelperIsolation ADR（P0 冻结契约）

- ADR 状态：Accepted（选择 Path A）
- P0-D05 证据状态：OPEN；本 ADR 的路径选择已 Accepted，但 D05 在 Release 隔离/终止 fixture 通过前不得转 Accepted
- 被拒绝方案：Path B / `WKProcessPool` job 隔离

## 决策

Mermaid、KaTeX 及其他文档驱动的同步 JavaScript 只在 `RenderSupervisor` 启动的一次性 **非 WebKit** `RenderWorker` 进程中执行。一个 OS 进程只接收一个 job，返回最终序列化候选结果后退出；不复用 JavaScript realm、DOM、cache 或进程。

`WKWebViewConfiguration.processPool` 已不能提供可依赖的每 job 进程隔离，因此 Path B 正式 Rejected。P0 实现与测试不得再用“独占 `WKProcessPool`/non-persistent website data store”作为边界或证据。长期存活的 Preview WebView 只接收 Core 清洗后的静态 DOM patch，不执行 Mermaid/KaTeX。

## 进程与 IPC 契约

`RenderSupervisor` 是主应用外的独立签名 target，只负责调度、spawn、计量、超时和终止；不解析文档。它用公开、可发布的进程 API 为每个 job 启动代码签名已验证的 embedded worker，建立独立 process group，并记录 `{jobID, workerPID, pidStartIdentity, processGroupID, generation}`。worker 禁止 spawn；若监控发现 descendant，整个 job 立即失败并强杀进程组。

IPC 只允许：

- Main → Supervisor：typed request metadata、预算、generation 与有界输入 handle。
- Supervisor → Worker：单 job 的匿名 pipe/socketpair 或已在写入前 unlink 的 `0600 + O_CLOEXEC` FD。
- Worker → Supervisor：有长度前缀、schema version、jobID/generation 和输出 hash 的单份响应。

所有消息先验证声明长度再分配；未知字段、重复响应、错误 generation、额外 file descriptor、超时或 worker 提前退出均失败。完成、取消和失败都会关闭全部 handle。正文不进入命令行、环境变量、进程名、文件路径、日志或 crash breadcrumb。

## Runtime 与 sandbox

worker 使用随应用锁定的非 WebKit JavaScript runtime 与最小 DOM shim。精确 runtime/DOM shim 版本、license、源码 provenance、编译选项、二进制/资源 SHA-256 必须由 Release 构建写入符合 `渲染清单模式.json` 的 manifest；缺失即构建失败。本 ADR 不在没有构建产物时伪造这些值。

最终 Archive 必须证明 Supervisor/Worker：

- 没有 incoming/outgoing network entitlement，运行时也无法建立 socket、解析 DNS 或连接 loopback/Unix service。
- 没有用户文件、security-scoped bookmark、Recovery/Workspace Index/Sync/AI key、打印或任意可写目录权限。
- 只可执行 code-signed embedded worker；runtime 与 DOM 资源由 Main 以已验证只读 FD 提供，或从签名 bundle 的固定资源读取，不能按文档路径打开。
- 不加载 dylib/plugin、用户字体、环境变量指定模块或运行时下载代码。

## 明文 scratch

P0 没有命名 render scratch，也不写系统 temp。请求/响应优先留在有界内存；确需 FD 传输时，必须在写正文前创建 `0600 + O_CLOEXEC` 文件并立即 unlink，unlink 失败则不写内容并取消 job。退出路径关闭、截断并清零可控 buffer。导出 staging 与用户点击后创建的本地链接 clone 不属于 render scratch，不能被 worker访问。

## 预算、终止与公平性

每个 job 携带不可提高的 wall-clock、CPU、RSS、输入、输出、节点和尺寸预算；Supervisor 取请求值与 `SanitizerManifest` 上限的较小值。全应用并发、队列、RSS 与 generation 取消统一向 `ResourceGovernor` 注册，不能为 Render 与 Image 分别超配。一个文档同时最多占一个 running token；队列使用 round-robin document fairness，旧 generation 排队项在调度前删除。

达到任一上限时：停止读取输出 → 关闭 IPC → 对 process group 发出不可恢复终止 → `waitpid` 回收 direct child → 枚举并确认同 start identity 的关联进程已退出 → 释放 Governor 预算。只取消 Promise/connection、只杀 direct PID 或在未确认退出时启动下一 job 都不算 hard termination。

## T0 决策证据

Release fixture 必须覆盖同步死循环、微任务无限链、内存膨胀、输出炸弹、非法 descendant、worker crash、IPC 半包、取消/完成竞态和 100 次多窗口压力，并生成：

- 每个 job 的 PID/start identity/process group 生命周期与退出原因。
- worker/所有异常 descendant 的 CPU/RSS 聚合；短命 PID 也不得漏计。
- 强杀后 2 秒内进程退出、RSS/FD/token 回收且下个 job 是干净 realm 的证据。
- DNS、TCP/UDP、loopback、Unix socket、用户路径、系统 temp、Keychain 和动态加载的负面探测。
- 最终 Archive 的 codesign/entitlement/sandbox 证据以及 runtime/DOM/resource hash。

真实 hash、PID 与 Archive 证据只能由构建/运行生成。它们缺失时 Path A 仍是唯一允许实现的架构，但 P0-D05 与 T0 gate 保持 OPEN，T1 不得开始。
