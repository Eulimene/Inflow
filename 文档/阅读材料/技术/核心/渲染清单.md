## 固定组件基线

| 组件 | P0 版本/事实来源 |
| --- | --- |
| Swift Markdown / cmark | `MarkdownDialectManifest`；Release 记录 resolved commit、package checksum、编译 options 与二进制/资源 hash |
| Mermaid | 11.15.0；只从最终 app bundle 读取并记录真实 SHA-256 |
| KaTeX | 0.18.1；逐个 JS/CSS/font 记录最终 bundle SHA-256 |
| JS runtime / DOM shim | 非 WebKit、一次性 worker；精确版本、源码 provenance、license、编译选项和最终二进制 hash 由构建生成 |
| Sanitizer | `SanitizerManifest` manifestVersion、实际编译 policy allowlist hash 与通过的 evidence hash |
| Preview bridge / 主题 / 字体 | 内置资源 ID、版本、用途、最终 bundle 相对路径、长度与逐文件 SHA-256 |

文档中的版本字符串不是资源完整性证据。不存在“在 T0 手填”的 hash；只有 generator 对最终 Release 输入计算的值有效。

## Release generator

Release 构建在依赖解析、资源复制和 worker 签名完成后，枚举明确 allowlist 中的文件，拒绝 symlink、绝对路径、重复规范化路径、未登记 executable/resource 与大小写碰撞，然后生成 canonical JSON：

```text
Inflow.app/Contents/Resources/Manifests/render-manifest.v1.json
```

generator 必须：

1. 从 resolved package graph、最终 bundle 文件、最终签名 worker 和编译导出的 sanitizer policy 读取事实，不接受开发者传入任意 hash/version 覆盖。
2. 对每个 artifact 记录 package-relative path、purpose、version/source identity、byte length 和小写 hex SHA-256；目录以逐文件条目表示，不能只 hash 路径名。
3. 记录 Markdown options、heading slug contract、fragment exact-match contract、Render/Sanitizer manifest version、CSP policy version 和 worker isolation ADR version。
4. 记录 sanitizer allowlist、已执行负面 corpus evidence、golden index、Archive entitlement matrix 与 process-isolation evidence 的 hash；这些测试工件不必全部进入 app，但必须进入发布证据包。
5. 用确定性 key order/UTF-8/LF/无 BOM 编码；schema 验证失败、空/placeholder hash、未执行/跳过 case、资源缺失或 bundle 多出未登记 render executable 时非零退出。

manifest 不包含自身 hash，以避免循环；最终 `RELEASE_MANIFEST` 记录它的真实 SHA-256。应用启动时先验证 release manifest，再验证 render manifest 与实际 bundle 资源，失败则禁用 Mermaid/KaTeX/PDF/HTML 增强渲染并显示安全错误，不能回退到 CDN 或未锁定系统资源。

## 输入输出一致性

同一 `MarkdownSnapshot + RenderProfile + RenderManifestHash` 必须为预览、HTML 与 PDF 共享 typed render tree、SourceMap、heading ID、URL/Image/Export policy 和最终 sanitizer。两个接口保持分离：heading text 只进入 `heading-slug-v1`，raw fragment 只 decode/NFC 一次后精确匹配现有 DOM ID。

Golden 包含 AST、SourceMap、安全 DOM、桥消息、浅/深截图、HTML、PDF 页面与 PDF postflight 报告。任何 parser/runtime/DOM shim/主题/字体/policy/CSP/PDF postflight 变化都必须提升相应 contract version、重新生成 manifest 和完整 golden 候选，人工审核后才能替换权威 baseline。

## Golden 环境与可比性

每次 golden 运行记录 macOS build、WebKit build（仅 Preview/createPDF）、硬件架构、device scale、locale/timezone、ColorSync profile、所有字体 PostScript name/version/hash、Render/Sanitizer/Release manifest hash、fixture hash 与测试 runner hash。环境不匹配时只生成候选 diff，不得覆盖权威 golden。

截图/PDF golden 必须覆盖浅/深主题、长文档、中文/Unicode、重复 heading、fragment exact match、表格/代码/任务列表、Mermaid/KaTeX、已验证本地 PNG/JPEG、占位资源、带本地图片的性能 fixture 和所有失败降级。输出中任何绝对路径、网络请求、脚本、active PDF action 或隐私 canary 都是失败。

## T0 开放门槛

Parser/SourceMap、Editor/Preview 定位、DOM patch、PreviewBridge、非 WebKit worker 隔离、Mermaid/KaTeX、URL/local-link TOCTOU、HTML CSP/privacy、PDF postflight 与 ResourceGovernor fixture 全部通过后，才能生成 `evidenceStatus=passed` 的真实 manifest/evidence 包。

当前只冻结 schema 与生成流程；真实 bundle resources、allowlist、corpus、golden、entitlements、PID/RSS 和 PDF postflight 尚未存在，因此 T0 gate 保持 OPEN，不能据本文件判定 T0 完成或进入 T1。
