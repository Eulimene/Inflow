本目录只存放给人阅读的工程说明，回答“如何实现、模块如何协作、怎样验证和发布”。产品范围和用户语义以 [产品文档](../产品/说明.md) 为准；配套 JSON、Schema、Policy 与 Manifest 集中在 [`文档/机器校验/技术`](../../机器校验/技术/) 下。

- [产品技术方案](./技术设计.md)：Core 架构、数据流、文档生命周期、渲染、导出、性能、测试与发布的总入口。
- [Core 技术合同](./核心/说明.md)：保存与恢复、渲染隔离、内容安全、设置、数据保护及 Release 合同的可读说明。
- [扩展平台技术文档](./扩展/说明.md)：扩展 Host、IPC、语法 API、市场、同步、typed adapter 与 AI runtime。

## 工程边界

- P0 Core 采用模块化单体；本地编辑和保存不依赖扩展、AI 或网络服务。
- AppKit `NSDocument` 管理文档生命周期，AppKit/TextKit 承载编辑，受控渲染管线负责预览和导出。
- 第三方可执行能力按阶段进入独立、可审计的扩展进程体系，不提前改变 P0 的安全边界。
- 机器 Schema、Policy 和 Manifest 是可执行格式权威；Markdown 文档解释其目的和状态。

## 工程阶段

1. T0：验证编辑器、Parser、渲染隔离、`NSDocument`、Recovery 和 PDF 高风险路径。
2. T1–T3：完成并发布 P0 Core。
3. T4–T5：交付迁移能力、Typora 对标能力和领先特性。
4. T6：扩展 Host、SDK、市场、同步、AI 和连接器。

扩展文档描述的是 E1–E4/T6 目标架构。除接口预留外，不应把扩展复杂度提前引入 P0 Core。
