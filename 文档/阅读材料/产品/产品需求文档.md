## 1. 产品概述

Inflow 是一款原生、离线优先的专业 Markdown 编辑器。它以 Typora 的完整写作与文件管理能力作为产品基线，同时通过源码/渲染双工作流、本地数据安全、结构化文档检查和原生 macOS 体验形成优势。

Inflow Core 不依赖账号、云端服务或网络连接。用户始终直接操作本地文件；用户未来可主动安装可选生态扩展获得云存储、GitHub 或 AI 能力，但这些能力不成为 Core 的运行依赖。

### 1.1 产品目标

1. 用户可以在 3 秒内创建或打开一个 Markdown 文件并开始编辑。
2. 编辑、预览和文件保存均可在完全离线环境下完成。
3. 常用 Markdown 内容在编辑区易于识别，在预览区准确呈现。
4. 自动保存、恢复机制应尽可能避免非正常退出导致的内容丢失。
5. 模式切换、查找替换和格式操作符合 macOS 用户习惯。
6. 在完整产品阶段覆盖 Typora 的核心编辑、组织、图片、主题和导出能力，使 Typora 用户无需牺牲主要工作流即可迁移。
7. 在源码可控性、离线可靠性、文档质量检查和原生性能方面形成可被用户感知的领先体验。

### 1.2 非目标

Inflow Core 不内置：

- 账号、云同步、多人协作和评论；可选生态扩展可独立提供其中部分能力。
- 将专有云作为文件事实来源；系统文件与用户选择的同步盘仍可正常使用。
- 无安全边界的第三方插件或默认执行文档内脚本；受权限约束的高级扩展接口按独立规范提供。
- iOS/iPadOS 客户端。

文件夹工作区、全文搜索、所见即所得编辑和本地版本历史属于对标路线，但按版本分阶段交付。CLI、批量自动化、发布和图床上传不属于编辑器本体。编辑器为高级开发者提供受限、进程外、显式授权的扩展机制；未来可通过插件市场提供可选的云存储、GitHub 和 AI 扩展，但它们不能接管核心保存逻辑，本地文件始终是事实来源。AI 默认不内置、不强制登录、不绑定单一模型供应商。完整对标范围和差异化策略见 [Typora 对标与差异化路线](./Typora对标基准.md)，产品级扩展边界见 [Inflow 扩展能力规范](./扩展能力规范.md)，实现架构见 [扩展系统总体设计](../技术/扩展/系统设计.md)，长期生态方向见 [Inflow 扩展生态战略](./扩展生态战略.md)。

## 2. 目标用户与核心场景

### 2.1 目标用户

- 使用 Markdown 撰写技术文档、笔记、博客草稿的开发者和产品人员。
- 希望本地保存敏感内容、避免云服务的个人用户。
- 需要在编辑源码与检查渲染效果之间频繁切换的写作者。

### 2.2 核心场景

1. 新建文档，边写边预览，保存为本地 `.md` 文件。
2. 从 Finder 打开已有 `.md` 文件，修改后自动或手动保存。
3. 切换为纯预览模式进行阅读或检查排版。
4. 在长文档中查找、替换内容，并通过预览标题快速回到源码位置。
5. 编辑包含代码、表格、任务列表、Mermaid 图和数学公式的技术文档。
6. 将当前文档导出为 HTML 或 PDF，用于分享和归档。
7. 应用异常退出后，重新打开并恢复尚未落盘的内容。
8. 打开本地文件夹，通过文件树、大纲和全文搜索管理一组 Markdown 文档。
9. 在即时渲染编辑、纯源码编辑和源码/预览分栏之间按任务自由切换。
10. 粘贴、拖入、整理图片，并保持文档移动后的相对引用有效。
11. 在导出前检查断链、缺失图片、标题层级和方言兼容性。

## 3. 产品原则

- 本地优先：用户内容默认只存在于用户设备上。
- 内容安全：优先保证输入不丢失，再追求渲染性能。
- 原生一致：窗口、菜单、快捷键、文件面板和撤销行为符合 macOS 习惯。
- 渐进增强：标准 Markdown 即使不依赖扩展能力也应可读；Mermaid 和公式为增强渲染。
- 少打扰：界面服务于写作，不引入账号、推荐或运营入口。
- 兼容迁移：Typora 用户的常用语法、文件组织、主题与导出路径应有明确迁移方案。
- 可验证：任何所见即所得操作都必须产生可预测、可查看、可撤销的 Markdown 源码。

## 4. 信息架构与窗口结构

Inflow 同时支持文档窗口与工作区窗口。文档窗口直接编辑单个文件；工作区窗口以用户选择的文件夹为边界，提供文件树、全文搜索、大纲和多文档标签页。两种窗口共享同一编辑、渲染和保存管线。

窗口由以下区域构成：

- 标题栏/工具栏：文件名、模式切换、主题和导出入口。
- 可折叠侧栏：文件树、文件列表、全文搜索和文档大纲。
- 标签栏：展示当前工作区内打开的多个文档，可在设置中关闭。
- 编辑区：Markdown 源码输入及基础语法高亮。
- 预览区：渲染后的 HTML 内容。
- 查找替换条：按需显示，不长期占用空间。
- 状态信息：可选显示保存状态、字数或当前缩放，不作为 MVP 强依赖。

四种显示模式：

| 模式 | 快捷键 | 内容 | 默认焦点 |
| --- | --- | --- | --- |
| 编辑 | `⌘1` | 仅编辑区 | 编辑器 |
| 实时预览 | `⌘2` | 编辑区与预览区分栏 | 保持切换前焦点；首次进入时为编辑器 |
| 纯预览 | `⌘3` | 仅预览区 | 预览区 |
| 即时渲染编辑 | `⌘4` | 在可编辑内容中隐藏非当前块 Markdown 标记 | 即时渲染编辑器 |

P0 首次启动默认进入实时预览模式；即时渲染编辑在 P1 交付。应用记住用户最近使用的模式，并将其用于之后新开的窗口；恢复窗口时保留该窗口原模式。

## 5. 功能需求

### 5.1 文件操作

#### 5.1.1 新建

- 支持菜单“文件 > 新建”和快捷键 `⌘N`。
- 新文档初始内容为空，暂命名为“未命名”。
- 首次保存时弹出系统保存面板，默认扩展名为 `.md`。
- 若用户输入其他扩展名，应提示或自动补全 `.md`，但允许用户明确选择 `.markdown`。

#### 5.1.2 打开

- 支持菜单“文件 > 打开…”和快捷键 `⌘O`。
- 使用系统文件选择器，默认筛选 `.md` 和 `.markdown`。
- 支持 Finder 双击、拖放到应用图标，以及“打开方式”。
- P0 支持 UTF-8 和 UTF-8 BOM。新文档使用无 BOM UTF-8 与 LF；已有文档保存时保留原 BOM 状态和主换行风格（LF 或 CRLF）。检测到混合换行时，在允许首次编辑前一次性提示用户选择 LF 或 CRLF；作出选择前文档只读且自动保存暂停，选择作为文档属性保存，本次会话不再提示。
- 无效 UTF-8/UTF-8 BOM 文件不进入文本视图，也不尝试猜测编码；显示“不支持的编码”，只提供“在 Finder 中显示 / 复制原文件 / 取消”。编码识别、转换和另存为 UTF-8 在 P1 提供。
- 同一路径已在 Inflow 中打开时，聚焦已有窗口，不重复打开。

#### 5.1.3 保存与另存为

- `⌘S` 保存当前文件；未命名文档执行首次保存。
- `⇧⌘S` 另存为，成功后当前窗口切换到新文件。
- 写入采用安全保存策略：先写临时内容，再原子替换目标文件。
- 保存失败时明确显示原因并保留编辑内容。
- “另存为”改变目录时，在显示保存确认前分析相对链接和图片，并将“目标不变 / 目标改变 / 变为缺失或未授权”的项目分组列出。确认只对当时展示的源文本版本和目标目录有效；如用户在确认前继续编辑、改变目标或相关文件变化，必须重新分析。P0 不自动改写引用。
- 保存面板确认时必须同时捕获目标期望 `targetExpectation = absent | exactRevision`：目标不存在时绑定 `absent`，已存在时绑定用户确认替换的精确文件身份与 revision。进入原子写入前必须重验该期望；原本不存在的目标被创建，或已存在目标被替换、修改或身份变化时，原确认立即作废，必须重新确认替换或选择其他路径，不得静默覆盖。
- 若“另存为”目标已由另一个 Inflow 文档会话打开，不允许当前会话接管或覆盖该目标；聚焦已有窗口并要求选择其他路径。
- “另存为”成功后保留同一文档身份、窗口状态和 Undo 历史，但最近文件、恢复条目和之后的保存只指向新路径；旧路径不再是该会话的活动别名。
- 外部修改按 5.1.5 的状态机处理；不使用含义不清的“保留当前内容”。

#### 5.1.4 关闭

- 自动保存关闭时，所有 dirty 文档（包括已命名文档）关闭均询问“保存 / 不保存 / 取消”。
- 自动保存开启时，已命名 dirty 文档先等待当前或立即发起的保存完成；成功后关闭，失败后询问“重试保存 / 不保存 / 取消”。
- 未命名非空文档无论自动保存是否开启，始终询问“保存 / 不保存 / 取消”；未命名空文档可直接关闭。
- “不保存”丢弃本次会话的未保存内容并清除对应会话恢复快照；“取消”保持窗口与内容。
- 恢复快照不等于已经保存，不能使 dirty 文档绕过关闭确认。

#### 5.1.5 外部修改与删除

- 内存干净且磁盘变化时自动重新载入，并恢复光标、选区和语义滚动位置；reload 读取期间如产生本地输入或新的磁盘版本，本次 reload 必须取消，不能覆盖新输入。
- 自动重新载入或用户确认“重新载入 / 恢复至磁盘版本”后，新磁盘内容成为新的已提交基线，并清空该文档的 Undo/Redo 历史；P0 不允许通过 Undo 复活已明确丢弃的内存内容。
- 内存与磁盘均有变化时暂停自动保存，展示“最近成功保存版本 / 当前内存 / 当前磁盘”差异。
- P0 的三方差异只读展示，不提供逐块选择或编辑合并结果；交互式逐块三方合并属于 P3。
- 冲突操作固定为“保存副本 / 重新载入 / 明确覆盖”；重新载入前确认丢弃内存修改。
- 明确覆盖前必须把当前磁盘版本写为同目录带时间戳的永久冲突副本并二次确认；单文件授权不足时仅为此操作请求包含目录权限，拒绝或副本创建失败时禁止覆盖。
- 磁盘文件被删除时保留内存内容并暂停自动保存，不自动重建；只允许“另存为”或经二次确认“在原位置重建”。

### 5.2 编辑器

- 支持纯文本输入、选择、复制、剪切、粘贴和系统拼写检查；拼写检查可由用户在设置中关闭。
- 支持撤销 `⌘Z`、重做 `⇧⌘Z`，撤销栈以文档实例为单位；切换窗口或标签页不得跨文件撤销。
- 保持 Markdown 源码为唯一可编辑数据源，预览不直接编辑。
- 支持 Tab 输入与列表缩进；Shift+Tab 减少列表缩进。
- 支持设置编辑器字号，范围 12–28 pt，默认 15 pt。
- 编辑器使用等宽系统字体，首版不提供字体选择。

#### 5.2.1 基础语法高亮

高亮至少覆盖：

- 一级至六级标题。
- 粗体与斜体标记。
- 行内代码与围栏代码块。
- 链接文本与 URL。
- 引用标记。
- 有序、无序和任务列表标记。
- 表格分隔符。

高亮只改变文字样式，不修改源码。输入时应进行增量或节流刷新；10,000 行普通文本下不应因全量同步高亮造成明显卡顿。

用户可关闭语法高亮。关闭后编辑器按普通纯文本显示，但不影响 Markdown 预览和导出。

### 5.3 Markdown 渲染

P0 用户契约以 Swift Markdown 0.8.0 锁定的 swift-cmark 0.8.0 / cmark-gfm 0.29.0.gfm.13 为事实来源；`.disableSmartOpts`、精确 commit、构建选项和声明语法的零未解释偏差记录在版本化 `MarkdownDialectManifest`。CommonMark 0.31.2 只生成非阻断兼容报告。Mermaid 固定为 11.15.0，KaTeX 固定为 0.18.1。T0 验证后将全部校验值锁入 `RenderManifest`；在此之前 P0-D04 保持 Reopened。

预览支持以下语法：

- 标题与段落。
- 粗体、斜体、删除线。
- 链接与自动链接。
- 块引用。
- 有序列表、无序列表和嵌套列表。
- GitHub 风格任务列表；预览中的复选框首版只读。
- 行内代码与围栏代码块。
- 表格。
- 水平分隔线与图片。

渲染失败不能阻塞编辑；有问题的片段显示为源码或错误占位，其余内容继续展示。

### 5.4 实时预览

- 用户输入后 150 ms 左右触发防抖渲染；持续输入时可延迟，但停止输入后 300 ms 内应完成普通文档预览更新。
- 分栏模式下编辑区与预览区均可独立滚动。
- 拖动分隔条调整分栏比例，范围 25%–75%，默认编辑区占 50%。
- 记住用户设置的分栏比例。
- 切换模式不改变光标位置、文本选择或滚动位置。

### 5.5 预览主题与正文宽度

- 提供浅色、深色两套内置预览主题。
- 主题可选择“跟随系统 / 浅色 / 深色”，默认跟随系统。
- 主题切换只影响预览区，不改变文档内容。
- 预览正文最大宽度可设置为 600–1,200 px，默认 760 px；窗口较窄时自动适配。
- 代码、表格和 Mermaid 图可在正文容器内横向滚动，不能强制撑破窗口。
- P0 不加载远程图片，预览和导出统一显示占位；P1 再提供受控加载开关与隐私说明。

### 5.6 格式辅助

首版通过“格式”菜单提供以下操作；如有文本选择则包裹选择，无选择则插入模板并定位光标：

- 标题（一级至六级）。
- 粗体、斜体。
- 链接。
- 引用。
- 有序列表、无序列表、任务列表。
- 行内代码、代码块。
- 表格模板。

格式操作必须保持源码可读，不引入私有标记。

- 粗体、斜体和行内代码为 toggle：选择已由同类定界符完整包裹时移除，否则完整包裹；部分包裹不猜测。
- 多行标题取选择起始行；列表和引用对每个非空选中行执行 toggle；混合状态统一添加，全部已有时统一移除。
- 代码围栏长度为所选内容中最长连续反引号长度加一，且至少为 3。
- 默认表格为 3 列 × 3 行（含一行表头和两行数据），插入后选中第一个表头单元格。

### 5.7 查找与替换

- `⌘F` 打开查找条，支持上一个、下一个和结果数量。
- `⌥⌘F` 打开查找与替换。
- 支持替换当前项、全部替换。
- 默认区分纯文本字面值，不启用正则表达式。
- 支持区分大小写开关。
- 查找范围为当前文档源码；纯预览模式调用查找时固定切至分栏模式并在编辑器聚焦结果。

### 5.8 自动保存与异常恢复

自动保存区分两类文档：

- 已有文件：仅当文档已命名、目标可写且仍存在、无外部修改冲突时，才能在自动保存开启后于编辑停止达到用户设置的延迟时保存到原文件，默认 1 秒。应用进入后台或窗口关闭前按 5.1.4 的交互处理；不满足任一前置条件时暂停普通文件自动保存，但继续 Recovery 保护。自动保存关闭时，进入后台不得写用户文件。
- 未命名文档：只将恢复快照保存至应用容器，不创建用户可见文件、不自动弹出保存面板，也不触发普通文件自动保存。只有用户主动执行“保存”或在关闭询问中选择“保存”才进入首次保存。

恢复要求：

- 编辑过程中周期性保存恢复快照，最长间隔 5 秒。
- 快照至少包含源码、原文件路径、光标位置、选择范围、显示模式、滚动位置和最后更新时间。
- 正常保存成功后清理对应的过期快照。
- 非正常退出后，下次启动显示恢复窗口，列出可恢复文档的名称、路径与时间。
- 用户可以逐个恢复、放弃，或全部恢复；放弃前需二次确认。
- 若原文件在异常期间被外部修改，恢复内容打开为独立未命名文档，不直接覆盖磁盘文件。
- 每个会话记录 clean-shutdown 标记；仅未 clean shutdown 且快照新于最后成功保存版本的会话进入恢复中心。
- 未命名和孤立快照保留 30 天；已命名文档在最近一次成功保存并 clean shutdown 后删除过期快照。
- “另存为”成功后保留同一 document ID，并将快照书签与最近成功版本迁移到新路径。

### 5.9 源码定位与滚动同步

#### 5.9.1 点击标题定位源码

- 预览中的 H1–H6 标题可点击。
- 点击后，在分栏模式聚焦编辑器并将对应标题源码滚动到可视区域中央，同时将插入点放到标题行。
- 在纯预览模式点击标题时切换到分栏模式后完成定位。
- 重名标题按渲染时携带的源码位置精确定位，而不是按标题文本搜索。
- 用户可关闭点击标题定位；关闭后预览标题不响应定位操作，也不会触发模式切换。

#### 5.9.2 基础滚动同步

- 编辑器滚动时，预览根据邻近块级节点的源码行号进行锚点插值滚动。
- 预览滚动时不强制反向驱动编辑器，避免双向争抢；可在后续版本评估双向同步。
- 用户正在手动滚动预览时，暂停编辑器到预览的同步约 1 秒。
- 切换模式后尽量保持当前语义位置，而不是只保持绝对滚动百分比。
- 用户可关闭滚动同步；关闭后两个区域始终独立滚动，点击标题定位仍可单独使用。

### 5.10 Mermaid

- 支持围栏代码块语言标识 `mermaid`。
- 预览时将合法 Mermaid 源码渲染为 SVG。
- 所有渲染资源随应用内置，离线可用，不访问 CDN。
- Mermaid 代码只在本地受控预览环境执行；关闭外部网络加载和任意导航。
- 语法错误时显示清晰的内联错误卡片，同时保留原源码可编辑。
- 主题跟随预览主题重新渲染。
- 用户可关闭 Mermaid 渲染；关闭后 `mermaid` 围栏块按普通代码块展示。

首版目标语法覆盖由内置 Mermaid 版本决定，至少验收流程图、时序图、类图和状态图。

### 5.11 数学公式

- 支持 `$...$` 行内公式与 `$$...$$` 块级公式。
- 使用随应用内置的数学排版资源，完全离线渲染。
- 公式错误时显示原始表达式和非阻断错误提示。
- 行内公式 `$...$` 不允许跨行；开始 `$` 后和结束 `$` 前不得为空白；开始符前不得为反斜杠，结束符后紧邻数字时不解析，避免货币误判。
- `\$` 始终显示普通美元符号。代码节点、行内代码、围栏代码块、链接目的地和原始 HTML 内永不解析公式；块级 `$$` 的开始和结束定界符必须各自独占行。
- 用户可关闭数学公式渲染；关闭后公式定界符和内容按普通文本展示。

### 5.12 导出

首版支持导出：

1. HTML：生成单个自包含 `.html` 文件，内联字体、主题与代码样式、本地图片、公式及 Mermaid 结果，不含运行时脚本或外部依赖。源码中的 `data:` 仍按危险输入拒绝；只有 Core 对已通过图片策略的 PNG/JPEG 和固定 hash 内置字体按 `ExportResourcePolicy v1` 生成的 data URI 可进入最终 staging。图片重新编码必须剥离 EXIF/GPS/XMP；远程占位只显示删除 userinfo/query/fragment 后的 origin 与截断路径，不暴露完整 URL；输出禁止绝对本地路径，并固定 `default-src 'none'; base-uri 'none'; form-action 'none'; object-src 'none'; frame-src 'none'` CSP、no-referrer 与 external-link noopener/noreferrer。P0 最大输出体积为 100 MiB，预计超限时禁止写出。
2. PDF：P0 只冻结 A4、四边 20 mm、当前主题、深色背景和无内容丢失；导出正文宽度为 `min(用户正文宽度, A4 可打印 CSS 宽度)`，不承诺固定 100% 缩放或高级分页。P0 基线路径为 `WKWebView.createPDF` 与必达的 PDF postflight；postflight 必须拒绝或移除脚本、附件、URI actions、绝对本地路径和非必要隐私 metadata。`NSPrintOperation` 不是未经证据即可切换的 P0 fallback；若基线路径无法稳定满足输出契约，必须由新的已接受 ADR 证明独立分页管线或无打印机副作用的隔离 helper 后才能替代。孤行控制、页眉页脚、自定义纸张/边距、结构块整体换页等增强分页进入 P1。P0-D07 在 PDF ADR、postflight 负例与 golden fixture 通过前保持 Conditional。

导出通过“文件 > 导出”进入，使用系统保存面板。每次导出在开始时捕获当前精确 Markdown 源文本、文档版本和导出配置，并独立解析该版本；不得因预览防抖而导出更旧内容。导出不改变当前 Markdown 文件路径或保存状态。最终 staging 使用系统为目标提供的 item replacement directory；目标已存在时只能对用户确认时的精确文件修订进行协调替换，不存在时只能在仍然不存在的前提下同卷原子 rename。保存面板关闭后若目标被新建或已有目标被其他进程修改，必须重新确认替换或另选目标。无法获得同卷 staging 时终止导出，失败不产生残缺目标文件。

### 5.13 功能开关原则

以下体验增强功能由用户决定是否启用：自动保存、语法高亮、拼写检查、滚动同步、点击预览标题定位、Mermaid 渲染和数学公式渲染。

- 所有开关均提供安全、可预期的默认值，修改后立即生效并保存到本机。
- 关闭增强功能不得修改 Markdown 源码，也不得移除对应内容。
- Mermaid 或数学公式关闭时，导出结果与当前预览行为一致，按普通代码或文本处理。
- P0 预览和导出不获取远程图片，只显示占位；受控远程图片加载进入 P1。
- 异常恢复、原子保存、外部修改冲突检测和渲染安全限制属于数据安全能力，不允许关闭。

### 5.14 本地链接与跳转

Inflow 支持标准 Markdown 本地导航，不要求用户写入 Inflow 私有链接协议。

支持的目标：

- 当前文档标题：`[安装](#安装)`。
- 相对路径文档：`[配置](./configuration.md)`。
- 跨文档标题：`[主题设置](./configuration.md#主题设置)`。
- 父级或子目录文档：`[设计](../design/overview.md)`。
- 本地图片、PDF 和其他附件链接。

交互规则：

- 纯预览和分栏预览中，单击链接执行导航。
- 源码编辑与即时渲染编辑中，`⌘`+单击执行导航，普通单击仍用于定位光标。
- 当前文档锚点在当前视图内滚动，并保持返回位置。
- 指向 Markdown 文件的链接由 Inflow 打开；工作区模式默认在当前窗口新标签页打开，单文档模式在新窗口打开。
- 首次访问仅有单文件授权无法覆盖的相对资源时，请求用户授权包含目录并保存安全作用域书签；拒绝后将该目录记为“缺少目录权限”，仅保留手动授权入口，不反复弹窗。
- 标题 ID 生成和 fragment 解析是两个不可互换的产品接口。`headingText -> DOM ID` 使用版本化 `github-compatible-heading-slug-v1`，以冻结的 GitHub-compatible fixture 为准：对标题文本做 Unicode lowercase，删除 ASCII 标点（保留 `-`、`_`）并将空白替换为 `-`；中文及其他 Unicode 字母/数字保留，重复标题按文档顺序追加 `-1`、`-2`。
- `rawFragment -> existing DOM ID` 只由 URL Policy 执行一次严格 UTF-8 百分号解码和 Unicode NFC 归一化，然后与文档中已生成的完整 DOM ID 做精确匹配。该步骤不转小写、不删标点、不替换空白、不再次 slug，也不允许二次解码或容错回退。只有 Markdown 标题产生导航 ID；P0 raw HTML 不产生或保留 `id`。Parser、预览、导出和导航共享同一组冻结 fixture，但不合并这两个接口。
- Markdown、静态 PNG/JPEG 和 PDF 在权限、类型与资源身份验证后，必须从同一个已验证文件实体打开，不得回到原路径重新解析。其他非 Markdown 附件在 P0 只提供“在 Finder 中显示”；如后续允许交给系统默认应用，必须再次显式确认，且不能把旧的路径校验结果当作当前文件身份。
- HTTP/HTTPS 链接使用系统浏览器打开，并明确离开 Inflow。
- `javascript:`、可执行文件和未经授权范围的 `file:` 链接禁止直接打开。
- P0 危险或未知 scheme、多重解码后改变安全分类的链接降级为不可点击纯文本。
- 目标缺失、标题不存在或权限不足时显示非阻断错误，并提供“在 Finder 中查找”或“重新授权目录”。

导航维护每个文档窗口的前进/后退历史，记录文档 ID、标题锚点和语义滚动位置。提供“后退”和“前进”菜单操作；具体默认快捷键在交互设计阶段确定，避免与编辑快捷键冲突。

文档健康中心将检查本地断链、缺失锚点和大小写不一致路径。路径修复必须显示差异并可撤销。

## 6. 设置

设置分为全局默认、窗口状态、工作区覆盖和文档属性。本节规定用户可见语义；版本化 [Settings Schema](../技术/核心/设置规范.md) 将这些选择编码为 key、类型、序列化默认值、范围和迁移，不反向定义产品范围。全局分栏比例只决定新窗口初值，窗口保存当前比例；当前模式、滚动和侧栏属于窗口状态，工作区可覆盖编辑/渲染/资源设置，编码/BOM/主换行属于文档属性。优先级为文档属性 > 工作区覆盖 > 全局默认；窗口状态不改变内容语义。

首次启动的新窗口必须使用“实时预览（分栏）”，不是“纯预览”。用户主动切换模式后，该模式成为全局“最近使用模式”，供之后新建的窗口使用；恢复旧窗口时优先恢复该窗口自己的当前模式，不被全局最近值覆盖。P0 的可记忆值只包含编辑、实时预览和纯预览；P1 交付即时渲染编辑后才能记忆第四种模式。

| 分组 | 设置项 | 默认值 | 范围/选项 |
| --- | --- | --- | --- |
| 通用 | 自动保存 | 开启 | 开启 / 关闭 |
| 通用 | 自动保存延迟 | 1 秒 | 0.5 / 1 / 2 / 5 秒；仅自动保存开启时可用 |

| 通用 | Markdown 文件打开方式 | 新窗口 | P0 固定新窗口；P1 可选“工作区内使用标签页” / “始终新窗口”，无工作区时仍新窗口 |

字号 12–28 pt、正文宽度 600–1,200 px 和分栏比例 25%–75% 是不可越过的用户输入边界，不是建议值。语法高亮、滚动同步和点击标题定位必须是相互独立的开关；关闭任一项不得连带关闭其他两项。

P3 VersionStore 默认开启，保留 30 天或 500 MiB（先到者为准），用户可关闭或覆盖期限/容量；Recovery 不受此设置影响。

关闭自动保存时仍保留异常恢复快照；手动保存、关闭提醒和恢复机制继续生效。恢复默认设置只重置偏好，不改动文档内容、最近文件或恢复快照。

## 8. 状态与异常处理

- 保存中：标题栏显示短暂进度状态，但不阻塞编辑。
- 已保存：不持续展示强提示，可在标题栏移除修改标记。
- 保存失败：显示非模态错误提示，并提供“重试”和“另存为”。
- 文件不存在：若已打开文件被外部删除，保留内存内容并提示另存为。
- 文件无权限：以只读方式打开，允许复制或另存为。
- 预览失败：编辑器继续可用，可重试预览。
- Mermaid/公式单块失败：只影响对应内容块。
- 大文件：预览和高亮允许降级或延迟，但文本编辑和保存必须保持可用。

## 9. 非功能需求

### 9.1 平台与隐私

- 最低支持 macOS 14 Sonoma。
- 仅支持 Apple Silicon，不提供 Intel/x86_64 构建，也不通过 Rosetta 作为正式支持路径。
- 核心界面使用 SwiftUI，编辑器可按能力需要桥接 AppKit 文本系统。
- 暂不通过 Mac App Store 分发；采用 Developer ID 签名和 Apple 公证的独立安装包直接分发。
- 正式发布必须通过 Gatekeeper 校验。P0 采用官网下载安装包的手动更新并提供“检查更新”链接；签名自动更新器在首次自动更新发布前另立 ADR，不能阻塞 P0。
- 每个 P0 及之后的公开构建必须发布签名、单调递增的 release manifest，绑定版本、安装包 hash、构建 provenance、SBOM 和最低安全版本。已撤回或低于最低安全版本的构建不得被“检查更新”页面推荐；依赖漏洞门禁未通过时不得发布。
- 默认不采集文档内容、文件路径或使用数据。
- P0 Core 不因文档内容发起网络请求；帮助链接等显式外部操作仅由用户主动触发。P1 及生态联网能力必须另行授权。
- 应用沙盒化，文件访问使用系统授权和安全作用域书签。

### 9.2 性能指标

在基准设备（Apple M1、8 GB 内存）的 Release 构建上，除冷启动外的延迟类指标每项执行至少 30 次并报告中位数与 nearest-rank P95。冷启动采用 process-cold 10 次、不丢弃首次，门槛同时约束 median 与 max；reboot-cold 只作参考。测试固定 signpost 和 fixture SHA-256。内存统计 Main、WebContent、Render/Image helper 及其他 Inflow-owned 子进程整棵树的 resident peak：

- 冷启动空白窗口至可输入：median ≤ 1.5 秒且 max ≤ 2 秒。
- 已启动应用打开 1 MB / 10,000 行至可输入：median ≤ 1.5 秒且 P95 ≤ 2 秒。
- process-cold 启动并打开同一 1 MB fixture 至可输入的端到端指标：10 次 median ≤ 2.5 秒且 max ≤ 3 秒，直接验收产品 3 秒目标。
- 普通输入到预览更新：P95 不超过 300 ms。
- 模式切换：P95 不超过 150 ms。
- 连续输入过程中主线程不得出现超过 100 ms 的可感知冻结。
- 典型 1 MB 文档全进程树 resident peak 必须不超过 300 MiB；这是发布门槛，不是参考目标。复杂 Mermaid 另受 Sanitizer 全应用预算约束。
- 1 MB / 10,000 行基准必须使用完整 P0 预览和语法高亮路径，禁止进入降级模式；更大或恶意复杂文档可另行定义非发布阻断的降级策略。

### 9.3 可靠性

- 保存使用原子写入，任何失败不得破坏最后一次成功保存的文件。
- 恢复快照必须采用版本化数据结构，以支持应用升级。
- 导出和渲染任务可取消，不能阻塞关闭文档或保存源码。

### 9.4 可访问性与本地化

- 所有按钮提供 VoiceOver 标签和键盘可达能力。
- 支持系统增大对比度和减少动态效果设置。
- 浅色、深色主题下文本和关键控件对比度满足 WCAG 2.1 AA 的常用阈值。
- 首版界面支持简体中文；代码和数据结构为英文命名，为后续英文界面预留本地化资源。

## 10. 数据与技术边界

### 10.1 文档数据

Markdown 源码是文档事实来源。渲染 HTML、语法高亮结果、标题锚点和源码映射均为可重建派生数据，不写入 `.md` 文件。

### 10.2 本地持久化

- 用户文档：用户选择的位置。
- 恢复快照：应用容器的 Application Support 目录。
- 用户设置：UserDefaults 或等价偏好存储。
- 安全作用域书签：应用容器内受保护持久化。
- 渲染 scratch：P0 正文不得以明文路径文件写入系统临时目录；只能使用内存，或使用创建后立即 unlink、仅向必要进程传递的受限文件描述符，任务结束或强制终止时关闭。
- 导出 staging：系统为目标返回的同卷 item replacement directory，仅用于验证后协调替换，完成或失败后清理。

### 10.3 渲染安全

- 默认不执行 Markdown 中的任意脚本。
- P0 不渲染 raw HTML；标签和属性按源码转义显示，不产生 DOM、导航 ID 或资源请求。raw HTML allowlist 清洗和受控远程图片加载进入 P1。
- P0-D05 聚焦生成内容安全：Mermaid 必须使用严格安全配置并对最终 SVG 再清洗；禁止脚本、事件属性、外部资源、CSS、`foreignObject` 和任意导航。KaTeX 固定 `trust: false`，限制宏展开、输出节点数和尺寸。具体限额、规则与测试向量由 T0 冻结到 `SanitizerManifest`；通过前保持 Reopened。
- 预览 WebView 禁止任意导航、窗口打开和未经用户发起的下载。
- 本地图片仅在当前文档授权范围内加载；远程图片在 P0 始终占位。
- P0 本地图片只支持满足 `ImageDecodePolicy v1` 预算的静态 PNG/JPEG；本地 SVG、data URI、动画图片、MIME/魔数不一致和超大解码结果统一占位。预览、HTML 与 PDF 共用同一 `URLPolicy v1` 和 `ImageDecodePolicy v1`。
- P0 主 target 与渲染/图片 helper 不授予 outgoing-network entitlement。

## 11. 产品阶段与稳定需求 ID

统一术语：P0 为首个可发布版本，P1 为 Typora 用户可迁移版本，P2 为 Typora 能力对齐版本，P3 为 Inflow 领先能力版本。T0–T6 仅表示工程实施阶段，E0–E5 仅表示扩展生态阶段，均不得被解释为产品范围。下列 ID 是版本归属的权威索引；详细行为仍以第 5–10 节为准。

### P0：首个可发布版本

- **INF-P0-FILE-001**：新建、打开、编辑、保存、另存为、外部变更处理和多窗口文档模型。
- **INF-P0-MODE-001**：编辑、实时预览、纯预览三种模式与 `⌘1`、`⌘2`、`⌘3`，首次新窗口默认实时预览。
- **INF-P0-MARKDOWN-001**：第 5.3 节的 Markdown 基础元素、源码编辑和基础语法高亮。
- **INF-P0-THEME-001**：浅色、深色和跟随系统的内置预览主题。
- **INF-P0-SETTINGS-001**：第 6 节列出的 P0 设置语义、默认选择、开关和边界。
- **INF-P0-EDIT-001**：撤销、重做、查找、替换和格式辅助。
- **INF-P0-RECOVERY-001**：符合命名/未命名语义的自动保存、恢复保护、关闭矩阵和冲突安全。
- **INF-P0-NAV-001**：点击标题定位、编辑器到预览的基础滚动同步，以及当前文档锚点、相对 Markdown、本地图片和附件的受控导航。
- **INF-P0-EXPORT-001**：对精确源版本执行的自包含 HTML 和受 postflight 约束的 PDF 导出。
- **INF-P0-DIAGRAM-001**：Mermaid 与行内/块级数学公式的离线渲染、降级和导出。
- **INF-P0-PLATFORM-001**：沙盒权限、错误处理、基础辅助功能、独立签名分发和第 9–10 节的安全/性能门槛。

### P1：Typora 用户可迁移版本

- **INF-P1-MODE-001**：可逆、无损、可撤销的即时渲染编辑模式与 `⌘4`。
- **INF-P1-WORKSPACE-001**：文件夹工作区、文件树、标签页、大纲、全文搜索和快速打开。
- **INF-P1-EDIT-001**：双向滚动同步、代码语法着色、图形化表格、可点击任务列表和 Smart Paste。
- **INF-P1-MARKDOWN-001**：脚注、TOC、YAML Front Matter 和 Alerts 的可编辑、可预览与可导出语义。
- **INF-P1-RESOURCE-001**：图片粘贴、相对路径、附件目录和资源移动。
- **INF-P1-CONTENT-001**：用户显式开启的受控远程图片，以及通过版本化结构 allowlist 的 raw HTML；任意脚本 HTML 永久不进入 Core。
- **INF-P1-WRITING-001**：专注模式、打字机模式、行号和字数统计。
- **INF-P1-EXPORT-001**：系统打印、长图和增强 PDF。
- **INF-P1-THEME-001**：至少 6 套内置主题与受控 design token。P1 产品和 E1 生态均不接受任意 CSS、`@import`、URL、第三方字体或字体文件导入。

### P2：Typora 能力对齐版本

- **INF-P2-EXPORT-001**：无样式/带大纲 HTML、可移植文档包、再次导出和更多单篇格式。
- **INF-P2-DIALECT-001**：更完整的数学、Mermaid、图片管理和方言兼容配置。
- **INF-P2-THEME-001**：可导入的主题包只能使用机器可验证 `ThemePolicy` 允许的声明式 token 或受限样式子集；禁止任意 CSS、脚本、网络 URL 和 `@import`，主题包字体必须在隔离解码通过后才可用。
- **INF-P2-PARITY-001**：除 CLI、发布、上传、任意脚本/网络主题和外部批量转换等公开 exception 外，Typora 核心编辑能力均有等价路径。

### P3：Inflow 领先能力版本

- **INF-P3-HEALTH-001**：文档健康中心与可定位、可忽略、可预览 diff 的诊断/修复。
- **INF-P3-PROFILE-001**：渲染配置档案在预览、诊断和导出中共享同一语义。
- **INF-P3-HISTORY-001**：与 Recovery 隔离的本地版本时间线，支持查看、复制和明确恢复。
- **INF-P3-MERGE-001**：交互式逐块三方合并，任何选择不得静默覆盖并必须可撤销。
- **INF-P3-RESOURCE-001**：资源管家、大纲拖动重组和结构化批量编辑，批量改写前显示完整变更并作为单一操作撤销。

### 范围排除

- **INF-SCOPE-ECO-001**：扩展 SDK、开发者模式、权限管理、扩展故障隔离、签名市场和云/GitHub 连接器按 E0–E5 单独推进，不计入 P0–P3 DoD。
- **INF-SCOPE-AI-001**：AI 是后续可选生态能力，不进入编辑器 Core 依赖或 P0–P3 DoD。

PRD 是 P0–P3 产品语义、版本归属与 DoD 的唯一来源；[Typora 对标与差异化路线](./Typora对标基准.md)、[Typora Capability Inventory JSON](../../机器校验/产品/Typora能力清单.json) 和技术文档只能映射 requirement ID，不得另行改变版本归属。

## 12. Definition of Done

版本 DoD 是累积门槛：宣布 P1、P2 或 P3 完成时，本节中该阶段与所有早期阶段的门槛都必须在候选 Release 构建上继续通过。任何范围内 requirement ID 未验收、只有技术设计或只有手工声明，均不算完成。

### P0 DoD

1. **INF-P0-DOD-001**：在断网状态下完成新建、编辑、预览、保存、重开和导出全流程。
2. **INF-P0-DOD-002**：所有规定快捷键在编辑器聚焦时仍正确响应，且不会意外输入文本。
3. **INF-P0-DOD-003**：标准样例的标题、段落、粗体、斜体、链接、引用、列表、任务列表、代码块和表格正确渲染。
4. **INF-P0-DOD-004**：Mermaid 流程图、时序图、类图、状态图及行内/块级公式可离线渲染。
5. **INF-P0-DOD-005**：重复标题能精确定位源码；heading slug 与 raw fragment 精确匹配的独立 fixture 通过，不存在二次解码或 fragment 再 slug。
6. **INF-P0-DOD-006**：编辑区滚动跨越长文档时，预览跟随到相近语义块；用户手动滚动预览时无明显争抢。
7. **INF-P0-DOD-007**：强制终止应用后重启，可恢复最多 5 秒前的未保存内容。
8. **INF-P0-DOD-008**：模拟写入、Recovery 加密/密钥、配额和提交记录失败时，原文件完整、内存内容保留，且 Recovery 降级不会阻止用户保存自己的 `.md` 文件。
9. **INF-P0-DOD-009**：外部修改冲突不被静默覆盖；reload/revert 采纳新磁盘基线并清空 Undo。
10. **INF-P0-DOD-010**：HTML 和 PDF 导出当前精确源版本，包含主题、表格、公式及 Mermaid 结果，断网打开完整；目标并发变更时必须重新确认。
11. **INF-P0-DOD-011**：1 MB / 10,000 行基准在完整 P0 预览和语法高亮模式下满足第 9.2 节全部发布门槛，不允许降级。
12. **INF-P0-DOD-012**：VoiceOver 可读出主要工具栏控件、模式状态和错误提示。
13. **INF-P0-DOD-013**：功能开关立即生效并持久化，关闭不改写源码，恢复默认不删用户数据；Settings Schema 对首启实时预览、最近模式、文件打开方式、三个独立开关及 12–28 pt 范围的映射通过机器测试。
14. **INF-P0-DOD-014**：当前文档、相对 Markdown 和跨文档标题链接正确跳转；前进/后退恢复语义位置，越权、危险或验证后被替换的文件不会被直接打开。
15. **INF-P0-DOD-015**：自动保存开关、命名/未命名、保存成功/失败及“不保存”组合通过关闭矩阵；未命名文档只写 Recovery，快照不被误报为已保存。
16. **INF-P0-DOD-016**：UTF-8 BOM、LF、CRLF 和混合换行 fixture 保存后符合 5.1.2，非 UTF-8 文件不被直接覆盖。
17. **INF-P0-DOD-017**：外部修改与删除的每个分支均不静默覆盖或自动重建，明确覆盖前能创建冲突副本。
18. **INF-P0-DOD-018**：Save As 对新目录的相对引用影响重新分析规则、已打开目标拒绝和成功后唯一活动路径全部通过竞态测试；确认后发生的目标 `absent → created`、exact revision 变化或文件身份替换都会使 `targetExpectation` 失效并要求重新确认，静默覆盖次数为 0。
19. **INF-P0-DOD-019**：HTML 超限、远程资源占位及 PDF A4/边距/深色/无内容丢失/postflight 负例符合 5.12，失败不留残缺目标。
20. **INF-P0-DOD-020**：P0-D04、P0-D05、P0-D07 均为 Accepted；`MarkdownDialectManifest`、`SanitizerManifest`、`RenderManifest`、[Save/Recovery ADR](../技术/核心/保存与恢复决策记录.md)、Render Helper Isolation ADR 与 PDF Path ADR 已冻结并由对应 T0 fixture 验证。任何一项仍为 Reopened/Conditional 时禁止 P0 发布。
21. **INF-P0-DOD-021**：Release Archive 的 UTType/`CFBundleDocumentTypes` 支持 Finder 双击和 Open With 打开 `.md`/`.markdown`；P0 feature flag 只注册 `⌘1–3`，不暴露 `⌘4` 入口。
22. **INF-P0-DOD-022**：截图/PDF golden manifest 记录 macOS、WebKit、字体版本/hash、主题和 fixture hash；环境不匹配不能覆盖权威结果。
23. **INF-P0-DOD-023**：候选版通过依赖漏洞门禁，并发布可验证的签名单调 release manifest、安装包 hash、SBOM、build provenance 和最低安全版本/撤回信息。

4. **INF-P3-DOD-004**：资源移动后有效本地引用比例不低于 99.9%，所有批量改写在执行前展示完整变更并可作为单一操作撤销。
5. **INF-P3-DOD-005**：版本时间线的关闭、配额、恢复与删除不影响 Recovery；逐块三方合并通过并发变更矩阵，静默覆盖次数为 0。

## 13. 测试样例集合

开发阶段维护一份统一的 Markdown 验收文档，至少包含：

- 六级标题、同名标题和特殊字符标题。
- 多层列表、混合列表、已完成和未完成任务项。
- 中英文粗体/斜体、嵌套格式、链接和转义字符。
- 多语言代码块、超长代码行和反引号边界。
- 表格、超宽表格、缺失单元格和对齐方式。
- Mermaid 合法/非法示例及四类目标图表。
- 行内/块级公式、美元符号和非法公式。
- 10,000 行长文档、1 MB 文档和大量标题文档。
- 本地图片、远程图片、原始 HTML 和潜在脚本注入内容。

## 14. 关键风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 原生文本系统与增量高亮复杂 | 输入卡顿、撤销异常 | 将文本存储与样式更新解耦，先建立性能基准 |
| Markdown 渲染与源码位置映射不稳定 | 标题定位、滚动同步不准 | 渲染阶段保留 source range，并为块级节点注入稳定 ID |
| Web 预览与离线资源集成复杂 | 导出或主题不一致 | 统一预览与导出的渲染管线，所有依赖打包进应用 |
| 自动保存覆盖外部修改 | 数据损失 | 保存前校验文件版本，冲突时停止自动覆盖 |
| Mermaid 大图计算开销高 | 预览卡顿 | 后台节流、缓存相同源码结果，并允许单块失败 |
| 沙盒下相对图片访问受限 | 预览缺图 | 基于用户授权目录管理安全作用域访问 |

## 15. 后续交付顺序

PRD 确认后按以下顺序推进：

工程架构、技术选型、数据流、测试与实施阶段以 [Inflow 产品技术方案](../技术/技术设计.md) 为准。

1. 技术方案：工程架构、依赖选型、文档模型、渲染管线、源码映射与恢复机制。
2. 交互与视觉规格：窗口布局、工具栏、设置、错误与恢复流程。
3. 工程初始化：macOS 项目、测试目标、格式规范和持续集成。
4. P0 分阶段实现：文件与编辑器 → 预览 → 保存恢复 → 同步定位 → 导出和扩展渲染。
5. 自动化测试、性能测试、辅助功能检查和发布验收。

## 16. 已确认发布决策

以下决策作为产品与技术方案的正式约束：

1. Inflow 仅支持 Apple Silicon，不提供 Intel 构建。
2. 当前阶段不通过 Mac App Store 分发，使用 Developer ID 签名、公证和独立安装包。
3. PDF 导出忠实使用当前预览主题；选择深色主题时，输出保留深色背景。
