## 1. 研究目的

本组文档回答四个问题：

1. 哪些用户把 Markdown 当作长期资产，而不是临时输入格式？
2. 他们现在如何完成写作、组织、校验、交付和扩展？
3. 现有产品分别优化了什么，又留下了哪些结构性缺口？
4. Inflow 应选择什么市场位置，哪些能力值得正向设计，哪些不应进入产品？

研究结论只为产品决策提供输入，不直接创建功能。功能是否进入范围，仍须经过用户问题、产品原则、优先级与验收标准四项评审。

当前里程碑是 **个人首版（内部验证版）**，唯一产品用户为产品负责人本人。本组文档中的市场人群、访谈、兼容样本和商业验证均保留为历史研究或后续假设，不是当前用户范围；是否开展外部研究，只在本人通过个人首版验收后独立决定。

## 2. 研究范围

本轮覆盖桌面 Markdown 编辑器、知识库工具、专注写作工具、专业出版工作台和开发者编辑器五类替代方案。代表样本包括 Typora、Obsidian、iA Writer、Ulysses、Bear、Zettlr、MarkText 与 Visual Studio Code。

本轮不估算总市场规模。公开资料不足以支持可信的 TAM/SAM/SOM 数字，因而不以搜索热度、下载量或社区人数冒充付费市场规模。

## 3. 研究方法

- **桌面研究**：官方产品页、帮助中心、价格页、发布说明与官方社区目录。
- **任务拆解**：围绕接手文件、持续写作、结构理解、交付和扩展五段任务链比较产品。
- **替代方案分析**：不仅比较 Markdown 编辑器，也观察知识库、出版工具和开发者编辑器如何承接同一任务。
- **证据分级**：官方当前页面为事实；由多个产品共同呈现的方向为市场信号；用户动机和付费意愿若无访谈支持，只标为待验证假设。

资料访问基准日为 2026-08-19。价格、功能和平台支持可能变化，引用时必须保留访问日期。

## 5. 权威边界

- 市场研究描述外部事实、信号与假设，不定义产品范围。
- [产品愿景与原则](../01-产品设计/01-产品愿景与原则.md)定义长期价值取舍。
- [产品功能架构](../01-产品设计/03-产品功能架构.md)定义完整产品能力边界。
- 参数、默认值和快捷键只由产品附录定义，市场资料中的竞品数字不得直接成为 Inflow 规格。

## 6. 当前验证与后续研究

产品范围由产品负责人依据用户问题、产品原则、风险边界和可验收结果做出决策。当前先由产品负责人本人完成个人首版（内部验证版）验收；访谈数量、迁移样本数、可用性测试轮次、价格研究或概念测试都不是该里程碑的前置门槛。公共预览、对外版本号、签名公证、分发和外部研究均在本人验收后独立决定。

个人首版验证期间及后续若独立启动外部研究，研究可用于验证、挑战和调整已作出的判断：

- 个人首版由产品负责人本人记录真实任务结果，并仅在需要时主动导出本地日志；
- 后续版本可提供用户主动生成、预览、删减并自行发送的本地诊断包；
- 按真实问题选取迁移、交付、权限理解和商业模式研究，不预设固定人数、样本数或轮次；
- 将安全事件、严重失败和高频退路直接送回产品决策与版本复审。

Inflow 不使用遥测、后台使用数据发送或隐形记录代替用户反馈与研究。尚未获得的证据仍必须标为未验证，但不因此自动否定已批准的产品决策或已通过的发布验收。
