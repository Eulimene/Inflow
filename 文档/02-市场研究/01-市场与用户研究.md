## 1. 市场定义

Inflow 所处的并非单一“Markdown 编辑器市场”，而是多个相邻任务市场的交叉区域：

- 本地文件编辑与阅读；
- 个人知识与工作区管理；
- 专注写作与长文创作；
- 技术、研究和出版交付；
- 可扩展的专业写作工作流。

用户通常不会只比较编辑器功能。他们会在“简单编辑器、知识库、写作套件、代码编辑器、在线文档”之间选择能完成整条任务链的方案。

本节市场人群是历史研究与后续定位验证对象。当前里程碑是 **个人首版（内部验证版）**，唯一产品用户为产品负责人本人；在本人完成该版本验收前，不开展外部用户研究，也不把下列人群视为当前版本的实际用户范围。

## 2. 市场结构信号

### 2.1 本地文件所有权已成为明确卖点

Obsidian 以无需注册、本地存储和可选付费服务为核心承诺；Zettlr 强调无强制云同步、无遥测和本地文件；iA Writer 将 Markdown 描述为可被多种系统和应用打开的纯文本格式。这三个样本共同说明“内容可由用户直接控制”已被产品方当作明确卖点；它是否普遍影响购买与续费，仍需用户研究验证。[Obsidian Pricing](https://obsidian.md/pricing)、[Zettlr](https://www.zettlr.com/)、[iA Writer Export](https://ia.net/writer/support/preview/export-share-print?tab=export-mac)

### 2.2 市场在“少而专注”与“可组合平台”之间分化

iA Writer 以减少界面和功能干扰为卖点；Obsidian 则通过核心插件与社区插件覆盖知识管理和个性化。这些官方产品形态显示市场中同时存在“完整默认体验”和“按需组合平台”两种主张，但不能据此判断不同人群的偏好比例。[iA Writer](https://ia.net/writer)、[Obsidian Core Plugins](https://obsidian.md/help/plugins)、[Obsidian Community](https://community.obsidian.md/)

### 2.3 交付能力被多类产品作为专业价值

Ulysses、iA Writer 和 Zettlr 的官方页面都突出 PDF、Word、HTML、电子书或出版流程。由此形成一个待验证判断：对专业用户而言，写作工具的价值可能延伸到“把同一内容交付给不同接收方”，而不止于完成 Markdown 输入。[Ulysses Export](https://help.ulysses.app/export)、[iA Writer Export](https://ia.net/writer/support/preview/export-share-print?tab=export-mac)、[Zettlr](https://www.zettlr.com/)

### 2.4 扩展生态扩大覆盖面，也提出理解与信任问题

Obsidian 官方社区页面在访问日展示 6,734 个插件和 696 个主题，说明社区生态已经覆盖多个需求类别；该数量本身不证明插件质量、安全性、安装率或生态增长速度。插件发现、兼容、权限和停用后的可逆性是否构成显著障碍，仍需通过概念测试验证。[Obsidian Community](https://community.obsidian.md/)

## 3. 目标用户任务

### 3.1 长期资产维护者

他们维护技术文档、产品方案、知识资料或长期笔记。核心任务是文件可持续使用、跨工具可读、移动后引用不失效，以及外部变更时不丢内容。

### 3.2 结构化专业写作者

他们写代码示例、表格、公式、图表和多层长文。核心任务是在源文本、结构和阅读结果之间快速定位，并在交付前发现问题。

### 3.3 专注创作者

他们希望降低界面干扰，保持输入节奏，但又不能牺牲文件透明性、可恢复性和导出质量。

### 3.4 研究与出版用户

他们需要引用、脚注、长文组织、跨格式交付和严格输出。其需求强度高，但不应迫使所有用户承受复杂界面；适合由专业功能与插件按需提供。

### 3.5 受控环境用户

他们处理未公开、敏感或受组织管理的内容，关心离线可用、网络活动可见、扩展权限明确，以及停用外部能力后文件仍可用。

## 4. 购买与采用因素

| 决策因素 | 用户问题 | 研究需要验证的产品结果 |
| --- | --- | --- |
| 文件主权 | 内容是否被锁在私有资料库或账号中 | 原始 Markdown 和附件始终可直接带走 |
| 可靠性 | 保存、恢复、同步和外部修改是否容易混淆 | 状态可理解，失败不静默覆盖 |
| 上手速度 | 是否需要迁移、配置或学习大量概念 | 新建或打开后即可开始，复杂能力渐进呈现 |
| 写作连续性 | 模式、窗口和长文导航是否打断上下文 | 同一内容位置在各视图间连续 |
| 专业表达 | 公式、图表、表格、主题和导出是否稳定 | 写作到交付结果一致且可复核 |
| 生态可信度 | 插件是否值得安装、能访问什么 | 权限、来源、费用、状态和退出后果清楚 |
| 商业模式 | 是否被迫订阅或登录 | 核心产品可独立使用，付费边界透明 |

## 5. 由样本提出的机会假设

以下内容是研究命题，不直接创建 Inflow 功能或版本范围：

1. **把可靠性做成可感知体验**：市场普遍强调“本地”，但保存、恢复、外部修改和同步之间仍常被一个“已保存”状态概括。
2. **把多视图做成同一工作流**：源码编辑、实时预览、纯预览、即时渲染编辑、大纲和诊断不应是相互丢失位置的独立页面。
3. **把结构检查前移到交付前**：断链、缺图、标题层级、方言差异和导出版本应在交付前被解释。
4. **提供受控而非无限的生态**：插件价值来自按需解决专业问题，而不是最大化入口、权限和数量。
5. **让迁移成为产品能力**：先说明会保留什么、改变什么和不支持什么，再让用户决定是否执行。

## 6. 待验证假设

以下结论仍是待持续验证的市场假设，不直接创建产品需求：

- 专业 macOS 用户愿意为“可靠本地文件 + 可验证交付”支付一次性核心产品许可费用；
- 用户更愿意为可选同步、人工智能或专业插件持续付费，而非为基础编辑订阅；
- “保存状态可解释”比增加更多主题或格式按钮更能提高长期留存；
- 迁移预检和结果报告能显著降低从知识库或即时渲染编辑器迁移的心理成本；
- 插件的权限说明、审核等级和撤权后果会影响安装转化。

## 7. 研究结论

当前研究支持的定位假设是未来优先服务“把 Markdown 当长期资产、又需要专业交付”的用户，而非覆盖所有笔记和在线协作场景。当前先由产品负责人本人作为唯一用户，用真实文档完成个人首版（内部验证版）验收，并在需要时主动导出本地日志。本人验收后，再分别决定是否开展外部研究、公共预览、采用对外版本号、进入签名公证或选择分发方式；后续版本可再提供由用户主动生成、预览、删减并自行发送的诊断包，不使用遥测代替。
