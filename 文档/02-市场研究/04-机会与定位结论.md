## 1. 目标市场

Inflow 首先服务在 macOS 上维护长期 Markdown 资产、同时需要可靠本地文件和专业交付的个人用户与小型专业团队。核心人群包括技术作者、产品与工程人员、研究者、独立创作者和隐私敏感用户。

上述人群是历史研究形成的未来定位假设。当前里程碑是 **个人首版（内部验证版）**，唯一产品用户为产品负责人本人；在本人完成该版本验收前，不将这些人群作为当前用户范围，也不开展外部研究。

Inflow 不把通用笔记、在线协作、项目管理或人工智能内容生成作为首要市场。

## 2. 产品定位

**Inflow 是面向长期 Markdown 资产的本地优先写作工作台，让用户从接手文件、持续写作、理解结构到验证交付始终操作同一份可带走的内容事实，并能以可撤销的方式加入专业插件。**

## 3. 核心差异假设

1. **文件可信**：不只宣称本地存储，还让保存、恢复、外部变化和迁移状态可理解。
2. **写作流连续**：源码编辑、实时预览、纯预览、即时渲染编辑、大纲和诊断围绕同一内容位置协作。
3. **结构理解**：长文、链接、资源、公式和图表能够定位、检查并安全修改。
4. **可验证交付**：预览、检查和导出基于用户确认的同一内容，异常不静默产出旧结果。
5. **安全扩展**：插件按任务获得清晰权限，可停用、可替换，不能夺走文件所有权。

## 4. 已纳入基线、仍待验证的战略取舍

以下取舍用于组织市场验证，不直接创建功能、非目标或版本范围。

### 4.1 建议优先验证

- 一个真实 Markdown 项目的可信闭环能否先形成价值，再扩展到高级工作区和专业生态；
- 复杂能力渐进出现、默认界面保持安静，能否兼顾上手速度和专业深度；
- 迁移预检和公开降级能否减少换工具的担忧；
- 结构和交付质量是否比功能数量更能解释成熟度；
- 无账号、无网络仍能完成主要任务，是否构成明确购买理由。

### 4.2 建议不作为定位验证目标

- 不用复制任一竞品的界面、菜单、术语或主题验证产品价值；
- 不以成为通用数据库式笔记工具作为本轮市场目标；
- 不以覆盖完整 Git、内容管理系统、发布后台或实时协作为本轮定位前提；
- 不以默认执行第三方内容或自动联网换取表面便利；
- 不用私有格式制造迁移成本；
- 不让人工智能代替产品的信息架构。

## 5. 商业模式假设

当前且唯一的下一里程碑是 **个人首版（内部验证版）**，唯一产品用户和验收者为产品负责人本人。该版本不对外分发，不使用对外版本号，也不把签名、公证或分发产物作为当前门槛。本人完成内部验收后，再分别决定是否开展公共预览、采用什么版本号、是否进入签名与公证、使用何种分发方式以及是否开展外部研究：

- 个人首版不创建账号、许可证激活、试用倒计时、付款方式或价格承诺；
- 公共预览、正式桌面许可、价格、试用、退款、设备迁移与更新权益均由后续商业决策单独定义；
- 首个公开插件市场只分发免费插件；评价、Inflow 收款、订阅与恢复购买在可选生态账号及商业合同批准后再评审；
- 可选同步、远程人工智能或团队服务是否订阅仍需独立验证，不能影响核心产品；
- 不通过广告、内容推荐或出售用户数据获利。

竞品同时存在一次性购买、订阅、免费基础应用加增值服务和开源捐赠，说明市场上存在多种可持续方式，但不证明任一模式适合 Inflow。关于“用户是否愿为可靠性、专业交付和持续支持付费”的判断仍是假设，不能用人为锁定替代验证。[Typora Purchase](https://support.typora.io/purchase/)、[Obsidian Pricing](https://obsidian.md/pricing)、[Ulysses Pricing](https://ulysses.app/pricing/)

## 6. 市场验证顺序假设

1. **个人首版（内部验证版）——可信项目写作**：由产品负责人本人以一个真实 Markdown 项目验证文件夹目录树、项目内相对资源、即时渲染编辑的基础范围、手动保存与基础 PDF 交付，并在需要时主动导出本地日志。
2. **本人验收后的独立决策点**：分别决定是否开展公共预览和外部研究、采用何种版本号、是否签名公证以及如何分发。
3. **成长版——高级工作区连续性**：在已验证的轻量项目和即时渲染编辑基础范围上，继续验证跨文档搜索、多标签、项目内重命名/移动/删除等完整文件操作、资源维护、导航历史和高级结构化编辑。
4. **专业版——专业表达与迁移**：验证结构检查、引用、图表、专业交付和迁移预检能否承接高价值任务。
5. **成熟版——结构洞察与可信生态**：验证结构演进视角、插件市场、连接器和人工智能能否在不削弱核心独立性的前提下扩展价值。

以上顺序是市场验证假设，不替代产品范围或发布承诺。

后续正式版本名称、范围和验收须在本人通过个人首版验收后独立决定，并以届时批准的[版本路线图](../01-产品设计/06-版本规划/01-版本路线图.md)为准；当前路线只保留为未来产品方向。

## 7. 成功判断

以下指标用于后续外部研究，判断定位与概念是否值得继续验证；它们不适用于唯一用户为产品负责人本人的个人首版，也不替代产品验收标准。

| 目标 | 核心指标 |
| --- | --- |
| 用户信任 | 静默覆盖或静默丢失为 0；保存状态理解正确率不低于 90% |
| 写作连续 | 跨视图定位成功率不低于 95%；关键任务中断率持续下降 |
| 迁移采用 | 预检后能独立完成迁移的目标用户不低于 85% |
| 交付质量 | 导出前后内容完整率 100%；阻断问题均可定位 |
| 生态质量 | 插件权限理解正确率不低于 90%；停用后核心任务可继续完成 |

## 8. 结论

本轮研究提出的候选方向不是“做一个功能更多的 Typora”，也不是“做一个更简单的 Obsidian”，而是一种独立命题：以本地文件为事实、以可信写作链为体验骨架、以可验证交付为专业价值、以可撤销插件为扩展方式的 Markdown 工作台。当前先由产品负责人本人完成个人首版（内部验证版）验收，并在需要时主动导出本地日志；后续是否开展公共预览、版本命名、签名公证、分发和外部研究均独立决定，诊断包也后置。不使用遥测，也不把研究样本数当作批准或验收的前置条件。
