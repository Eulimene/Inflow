## 1. 研究目标

迁移的目标不是让 Inflow 长得像原工具，而是让用户能够回答：

1. 哪些内容会原样保留？
2. 哪些内容会改变但仍可使用？
3. 哪些能力不支持，有什么替代方案？
4. 原文件是否安全，迁移后能否退出？

## 2. 迁移对象

| 对象 | 典型内容 | 主要风险 |
| --- | --- | --- |
| 文档正文 | 标准 Markdown、扩展语法、原始 HTML | 方言差异、自动改写、不可逆格式变化 |
| 文件结构 | 文件夹、文件名、多文档关系 | 路径变化、重复名称、隐藏文件遗漏 |
| 链接与资源 | 相对链接、图片、附件、远程资源 | 缺失、越权、绝对路径失效 |
| 元数据 | Front Matter、标签、别名、创建时间 | 字段语义不一致、私有字段丢失 |
| 外观 | 主题、字体、导出样式 | 无法安全迁移、结果与原工具不一致 |
| 工作习惯 | 模式、快捷键、常用操作 | 入口不可发现、肌肉记忆中断 |
| 交付结果 | PDF、HTML、Word、发布内容 | 排版差异、资源未打包、版本不一致 |

## 3. 来源类型与研究关注点

### 3.1 即时渲染编辑器

代表样本：Typora、MarkText。研究重点是方言、即时编辑习惯、主题和资源路径，以及用户是否需要源文件预检和兼容说明。不得把“迁移体验相似”误解为复制原工具界面。

### 3.2 本地知识库

代表样本：Obsidian。研究重点是 wiki 链接、属性、附件目录、标签和插件生成内容，并验证用户能否理解标准内容、可映射元数据和需保留原样的专有语法之间的差异。

### 3.3 专注写作与应用资料库工具

代表样本：iA Writer、Ulysses、Bear，但三者的迁移起点不同。iA Writer 可在文件夹位置中管理纯文本与 Markdown 文件；Ulysses 的主资料库之外还支持 Markdown 外部文件夹；Bear 以笔记库组织内容并提供 Markdown、TextBundle 等导出。研究时应分别核查普通文件、应用资料库、标签、富媒体和多篇组合，不能假设所有专有组织语义都能转换。[iA Writer Organize](https://ia.net/writer/support/library/organize)、[Ulysses External Folders](https://help.ulysses.app/the-library/external-folders)、[Bear Export](https://bear.app/faq/export-your-notes/)

### 3.4 研究与出版工具

代表样本：Zettlr。研究重点是引用、参考文献、项目组合和导出样式，以及用户是否接受将专业语义交由明确的专业功能或插件承接。

### 3.5 开发者编辑器

代表样本：Visual Studio Code。通常无需搬运文件，重点是快捷操作、工作区、预览、格式检查和与现有工程目录共存。

## 4. 候选迁移体验假设

以下流程用于产品发布后组织可选的迁移研究和用户反馈，不是产品范围、默认值或发布门槛的权威。正式流程见[迁移与兼容](../01-产品设计/04-功能设计/08-迁移与兼容.md)。

1. **选择来源**：用户选择文件、文件夹或受支持的导出包；Inflow 先说明只读检查范围。
2. **生成预检**：按“原样可用 / 结果等价 / 可读降级 / 不支持”分组展示。
3. **查看影响**：列出将新增的文件、名称冲突、链接变化、资源缺失和不会迁移的设置。
4. **选择策略**：用户可选择直接打开、复制到新位置后迁移，或取消。
5. **执行迁移**：默认不修改来源；发生冲突时逐项询问或应用用户已确认的批量规则。
6. **查看报告**：展示成功、降级、跳过和失败项，并能从问题跳到目标文档。
7. **验证与退出**：用户可抽查内容和交付效果；若不满意，删除新副本即可，来源不受影响。

## 5. 研究分类框架

| 等级 | 定义 | 用户文案原则 |
| --- | --- | --- |
| 原样可用 | 无需修改即可在 Inflow 中完成主要任务 | 明确“未修改源文件” |
| 结果等价 | 表达方式可能变化，但阅读和交付语义一致 | 展示变化清单和示例 |
| 可读降级 | 内容保留为可读文本，但专有交互不可用 | 不使用“完全支持” |
| 不支持 | 无安全或可靠的转换路径 | 解释原因、提供保留或外部处理建议 |

## 6. 发布后持续验证

- 产品能力发布后，持续验证“先预检、再决定”是否降低对来源被修改的担忧；
- 需要验证用户能否区分内容兼容、外观相似和工作习惯迁移；
- 需要验证创建副本、直接打开与取消三种选择的理解成本；
- 需要观察用户是否能从降级或跳过项回到受影响内容；
- 市场样本只能揭示迁移风险，不能改变 Inflow 的产品结构。

本节不要求在产品文档批准、0.1 公共预览版或正式 1.0 前完成固定数量的迁移演练。迁移能力进入对应产品阶段时，仍须通过该阶段的发布 UAT；之后再用用户主动反馈、自愿研究和主动诊断包持续改进，不使用遥测。

## 7. 研究验证指标

以下是研究假设的判定指标，不是产品发布验收标准；产品验收以[产品验收标准](../01-产品设计/06-版本规划/03-产品验收标准.md)为准。

- 目标用户能在 5 分钟内理解预检结果并作出继续或取消决定；
- 默认流程对来源文件的修改次数为 0；
- 标准 Markdown、文件夹结构和本地资源的主要任务成功率达到 95% 以上；
- 所有降级与跳过项均有原因和目标位置；
- 迁移后用户仍可用其他文本工具打开新文件；
- 用户能在报告中找到并处理每个阻断问题。
