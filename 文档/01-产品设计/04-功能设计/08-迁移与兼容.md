## 1. 目标

让用户把已有 Markdown、文件夹或符合附录 A 规格的标准迁移包带入 Inflow 时，先理解哪些内容可直接使用、哪些会变化、哪些只能降级以及哪些暂不支持，再决定是否迁移。迁移的成功标准是内容与退出路径可信，不是界面或操作习惯与来源工具相同。

## 2. 范围

- 标准 Markdown 直接打开与需要转换的迁移流程。
- 文档、文件夹、链接、图片、附件、元数据与[附录 A](../07-产品附录/附录A-产品规格与参数.md)定义的标准 ZIP 迁移包预检。
- 内容、路径、名称、资源和目标冲突的影响说明。
- 原样可用、结果等价、可读降级和不支持四类兼容结果。
- 创建副本、查看变化、执行迁移、检查报告与放弃迁移。
- 主题、快捷键、插件和专有资料库等不能直接迁移内容的说明。

来源产品样本、用户风险和待验证问题见[迁移兼容研究](../../02-市场研究/03-迁移兼容研究.md)。研究只提供证据，不改变本文范围。

## 3. 用户故事与核心流程

### 3.1 直接打开标准 Markdown

1. 用户选择一个 Markdown 文件或现有文件夹。
2. 内容无需转换时，产品明确说明“原样可用”，直接打开用户文件。
3. 发现扩展语法、缺失资源或不兼容元数据时，保留源内容并提供迁移预检，不在打开过程中静默改写。

### 3.2 迁移预检

1. 用户选择文件、文件夹或附录 A 定义的标准 ZIP 迁移包，并看到本次检查范围。
2. 产品按“原样可用 / 结果等价 / 可读降级 / 不支持”分组展示内容与数量。
3. 用户查看名称冲突、链接变化、资源缺失、元数据差异和不会迁移的设置。
4. 每项结果可回到来源对象和受影响目标，不用汇总百分比掩盖阻断项。
5. 来源超出附录 A 的容量边界，或迁移包含有明确不支持的内容时，在创建目标前列出边界与可缩小范围的方式。

### 3.3 选择并执行迁移

1. 用户选择直接打开、创建副本后迁移或取消。
2. 需要转换时，先展示将新增、改写、跳过或降级的项目；用户可逐项排除。
3. 用户确认后如来源、目标或关联资源发生变化，原确认失效并重新预检。
4. 完成后打开新副本与迁移报告；来源内容保持不变。

### 3.4 验证、修正与退出

1. 用户从迁移报告定位降级、跳过、失败和待处理项目。
2. 可在 Inflow 中修正目标副本，也可删除副本并回到来源。
3. 用户需要再次迁移时重新预检，不复用已经过期的影响确认。

## 4. 功能规则

### 4.1 来源优先保护

- 标准 Markdown 无需迁移即可直接使用，不把“导入”设为打开文件的前置条件。
- 需要转换时按[附录 B](../07-产品附录/附录B-默认设置.md)的迁移方式起步；转换只在用户选择的目标副本上应用，不修改来源。
- 迁移失败、取消或中断不修改来源，不留下被误报为完成的目标。

### 4.2 兼容结果可解释

- 每个检查项只使用[术语表](../07-产品附录/附录E-术语表.md)中的四类兼容结果。
- “原样可用”必须说明覆盖的用户任务；不能用它暗示所有外观、插件或工作习惯都相同。
- “结果等价”必须展示变化前后；“可读降级”必须保留原内容并说明缺少的能力。
- 无法识别或无法安全转换的内容列为“不支持”，不猜测性重写或静默删除。

### 4.3 影响确认不过期

- 名称冲突、路径变化、资源缺失、覆盖和批量规则在执行前分别说明。
- 用户的确认只适用于当时看到的来源、目标和影响清单；任何一项变化后重新确认。
- 批量规则必须可查看适用范围，并允许用户排除单项。

### 4.4 报告可行动

- 迁移报告分别记录成功、变化、降级、跳过、失败和待处理项目。
- 报告从每项结果定位到目标文档和问题；不记录不必要的正文副本。
- 报告可再次打开；删除报告不删除来源、目标或用户资源。

### 4.5 来源边界

- 单个文件、现有文件夹和标准 ZIP 迁移包分别使用附录 A 定义的容量与内容边界；文件夹按实际内容计算，不借用压缩包大小判断。
- 超出边界时不创建被误报为完整的目标；用户可以缩小来源、移除不支持项或取消。
- 嵌套压缩包、可执行内容和无法识别的私有资料库只列为不支持，不继续展开、运行或猜测转换。

## 5. 异常与空状态

- **无可迁移内容**：说明所选对象为空或不含受支持内容，允许重新选择，不创建目标。
- **来源不可访问**：保留选择摘要，提供重新授权、选择其他来源或取消。
- **目标已存在**：展示名称与内容影响，允许选择其他位置或对单项作出决定，不静默覆盖。
- **预检后发生变化**：停止执行并重新检查，不使用过期确认。
- **存在阻断项**：用户可返回处理、明确跳过或取消；不会生成被冒充为完整的目标。
- **来源超出边界**：指出对应的附录 A 规格和受影响范围，允许选择较小来源或取消，不创建部分目标。
- **迁移中断**：说明已完成与未完成项目，来源不变；用户可清理目标副本或重新开始。

## 6. 验收场景

1. 标准 Markdown 可直接打开，不需要导入资料库或复制文件。
2. 含扩展语法、元数据、本地资源、远程资源和名称冲突的样本均得到逐项兼容结果。
3. 用户在执行前能说明来源是否会改变、目标会新增什么、哪些内容会降级或跳过。
4. 确认后改变来源、目标或关联资源，原迁移不继续并要求重新检查。
5. 迁移成功、部分可用、失败、取消和中断均有清楚报告，来源内容保持不变。
6. 删除迁移副本后，用户可继续使用原工具和原文件，不依赖 Inflow 才能退出。

## 7. 非范围

- 复刻来源工具的界面、菜单、主题数量或操作顺序。
- 承诺迁移第三方账号、购买记录、云端历史或无法导出的专有数据。
- 把无法验证的外观相似当作内容兼容。
- 在用户未确认时修改来源、覆盖目标或执行来源携带的脚本与联网动作。
