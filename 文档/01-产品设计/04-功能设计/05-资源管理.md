## 1. 目标

让用户能在不牺牲 Markdown 可迁移性的前提下管理图片和附件。文档移动、另存、资源重命名或导出时，用户应先看到引用影响，再决定是否修改。

当前个人首版（内部验证版）仅供产品本人使用且不公开分发，验证本地 PNG/JPEG 插入、标准相对引用，以及项目内已有相对 PNG/JPEG 图片的直接呈现。已有项目图片不会因为显示而被复制、导入或改写。资源移动、重命名、批量修复、远程资源和完整资源管家保留为后续产品方向，不阻断该版本。

## 2. 范围

- 个人首版（内部验证版）从文件选择、拖放或剪贴板插入本地 PNG/JPEG。
- 将图片复制或写入文档同级 `assets` 目录，并插入标准相对 Markdown 引用。
- 未命名文档的首次保存前置、重名处理、撤销边界和另存为警告。
- 在项目的分栏与即时渲染编辑中直接呈现项目边界内已有的相对 PNG/JPEG 图片，不复制资源、不改写引用。
- 用户主动打开普通 PNG/JPEG/PDF 文件链接时，继续使用应用管理的只读临时副本。
- 后续扩展资源移动、重命名、引用同步和资源管家。
- 支持的资源类型及安全打开方式只见[附录 A](../07-产品附录/附录A-产品规格与参数.md)。

## 3. 用户故事与核心流程

### 3.1 插入图片

1. 用户通过文件选择、拖入或剪贴板粘贴静态 PNG/JPEG；个人首版（内部验证版）不接受 TIFF、动态图或其他附件类型。
2. 当前文档尚未命名时，先要求用户保存文档。用户取消或首次保存失败时，不创建 `assets` 目录、资源文件或 Markdown 引用。
3. 文档已有路径后，将 PNG/JPEG 复制或写入文档同级的 `assets` 目录，并插入指向该文件的标准相对 Markdown 引用。若文档位于用户已经选择的项目或资源目录中，直接使用该目录及其内部路径，不再要求二次授权；确需另选目录时，系统选择动作本身即完成确认。
4. 目标文件名已存在时，自动在基本名称后递增数字后缀，直到得到未占用名称；不覆盖、替换或修改既有文件。
5. 插入作为一次可撤销的 Markdown 编辑操作。撤销只删除本次插入的 Markdown 引用，不删除已复制或写入的资源文件。
6. 文档另存为到其他目录前，提示相对资源引用可能失效；个人首版（内部验证版）不搬移或复制 `assets`，也不改写引用。

### 3.2 呈现项目内已有图片

1. 用户打开普通文件夹项目，其中 Markdown 通过标准相对图片引用使用项目内其他位置的 PNG/JPEG。
2. 分栏与即时渲染编辑以包含该引用的 Markdown 文件所在目录为基准解析路径；完成规范化和符号链接解析后，目标必须仍位于项目根目录内。
3. 合法且可读取的 PNG/JPEG 直接从原位置呈现，不复制到 `assets`、不改写 Markdown，也不将呈现行为记为资源导入。
4. 越出项目根目录、通过符号链接逃逸、目标缺失或无权限时，不读取目标；保留原引用并显示对应失败状态，不自动扩大授权范围。
5. 用户主动打开普通 PNG/JPEG/PDF 文件链接时，仍按只读临时副本规则交给系统默认应用；临时副本在文件系统中不可写，外部应用只能另存为到用户另选位置。

### 3.3 移动或重命名资源（后续）

1. 用户在资源管家中选择文件并指定新位置或新名称。
2. 执行前展示将被更新的所有 Markdown 引用和无法确认的风险项。
3. 用户确认后作为一次完整操作执行；任何目标在确认后变化时停止并重新分析。

### 3.4 修复资源问题（后续）

1. 用户按缺失、未引用、重复或远程分组查看资源。
2. 选择条目后查看引用它的文档和位置，可定位、替换、重新授权或忽略。
3. 批量修复前展示完整变更，修复后可作为单次操作撤销。

## 4. 功能规则

### 4.1 引用可迁移

- 资源引用使用标准 Markdown，不写入只有 Inflow 能理解的标识。
- 新插入图片的相对路径以当前文档位置为基准，图片统一写入该文档同级 `assets` 目录；不提供把新图片留在外部原位置或插入绝对路径引用的选项。
- 项目中已有的标准相对图片引用继续以引用所在 Markdown 文件的位置为基准，可指向项目根目录内的其他现有位置；显示这些图片不要求迁入 `assets`，也不改写引用。
- 未命名文档必须先完成首次保存，才能确定 `assets` 位置并插入图片。
- 另存为只提示相对引用影响，不搬移、复制或重写资源。移动、重命名与路径修复属于后续完整产品能力，并在执行前展示 Markdown 差异。

### 4.2 本地与远程资源

- 个人首版（内部验证版）只导入用户明确选择、拖入或粘贴的静态 PNG/JPEG；读取和复制失败时不插入引用。
- 项目内已有相对 PNG/JPEG 图片引用在分栏与即时渲染编辑中直接读取并呈现，不视为资源导入；路径规范化、符号链接解析和项目边界检查统一遵循[工作区与导航](./04-工作区与导航.md)。
- 用户主动打开普通 PNG、JPEG、PDF 文件链接时遵循[工作区与导航](./04-工作区与导航.md)的只读临时副本规则，不视为资源导入，也不写回源文件。
- 远程图片默认不请求、不下载；远程资源本地化与引用更新属于后续方向。

### 4.3 资源变更与删除

- 个人首版（内部验证版）复制资源与插入引用按顺序执行：资源写入失败时不插入引用；引用插入失败时保留已复制文件并说明结果，不自动删除文件。
- 撤销、删除引用或关闭文档都不自动删除 `assets` 中的文件；“未引用”不等于可删除。
- 后续复制、移动、重命名和引用更新必须形成用户可理解的整体，不能只完成文件移动却留下已知断链。
- 资源清单是可重建辅助信息，不是文件事实。

## 5. 异常与空状态

- **未命名文档**：插入图片前进入首次保存；取消或失败后保持原编辑状态，不创建资源。
- **资源缺失**：保留原引用并显示失败状态；定位新文件、自动修复或批量修改路径属于后续能力。
- **项目图片越界或符号链接逃逸**：不读取、不呈现目标，说明项目边界限制并保留原引用；不自动扩大授权范围。
- **插入目标目录权限不足**：不创建资源或引用，保留当前编辑并允许用户重新选择可写位置；项目内已有图片无权限时不自动扩大授权。
- **目标已存在**：自动尝试递增数字后缀，不覆盖既有文件；无法取得可用名称时停止并说明失败。
- **复制成功但引用插入失败**：保留资源文件并说明未插入引用，不进行可能误删用户文件的自动回滚。
- **远程资源失败**：保留占位和原链接，可重试或保持离线，不阻断文档。
- **不支持或可疑文件**：不直接预览或执行，提供 Finder 定位与风险说明。

## 6. 验收场景

1. 文件选择、拖放和剪贴板只接受静态 PNG/JPEG；TIFF、动态图和其他类型安全拒绝。
2. 未命名文档插入图片前必须先保存；取消或保存失败时不创建 `assets`、资源或引用。
3. 已命名文档插入图片后，文件位于文档同级 `assets`，Markdown 使用标准相对引用。
4. 同名文件已存在时自动使用递增数字后缀，既有文件内容不改变。
5. 撤销插入只删除 Markdown 引用，不删除资源文件；删除引用或关闭文档同样不会自动清理资源。
6. 文档跨目录另存前显示相对引用警告；另存完成后资源不被搬移、复制或改写。
7. 项目内已有相对 PNG/JPEG 图片引用在分栏与即时渲染编辑中从原位置直接呈现，不复制到 `assets`、不改写引用，也不产生第二份资源事实。
8. 项目内图片路径以引用所在 Markdown 目录为基准；越界、符号链接逃逸、缺失或无权限时保留原引用并显示失败，不读取目标或自动扩大授权。
9. 主动打开普通 PNG、JPEG、PDF 文件链接时只打开应用管理的只读临时副本，不把该操作当作导入或写回。
10. 资源移动、重命名、批量修复、远程资源和资源管家不作为个人首版（内部验证版）验收条件。

## 7. 非范围

- 内置图床上传、公开发布或把第三方存储设为必选步骤。
- 默认加载文档中的任意远程内容。
- 自动删除所谓“未引用”文件。
- 将附件嵌入私有容器，导致离开 Inflow 后不可访问。
- 仅为呈现项目内已有图片而复制、导入、移动或改写其相对引用。
- 个人首版（内部验证版）中的 TIFF 转换、让新插入图片保留在项目外部原位置、资源移动或重命名、批量修复和完整资源管家。
