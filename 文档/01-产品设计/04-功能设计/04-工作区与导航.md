## 1. 目标

让用户从一份文档平滑扩展到一组长期 Markdown 资产：知道文件在哪里、文档如何组织、如何找到内容，并能在文档、标题、诊断和链接之间往返而不丢失上下文。

当前个人首版（内部验证版）仅供产品本人使用且不公开分发，验证“普通文件夹即项目”的基础闭环：打开项目、浏览文件树、在明确目录中新建 Markdown、用窗口顶部原生标签保留并切换多份文档，并沿项目内相对链接和图片引用工作。项目刚打开或没有 Markdown 时可以没有当前文档；跨文档搜索、文件重命名/移动/删除、导航历史、关系视图与演进洞察保留为后续完整产品方向。

## 2. 范围

- 个人首版（内部验证版）以用户选择的普通文件夹作为项目边界，不创建私有项目文件，不导入、复制或重组项目内容。
- 用户可从应用内打开项目，也可将文件夹拖到 Dock 中的 Inflow 图标或 Inflow 应用图标；同一项目重复打开时聚焦现有项目窗口。
- 项目窗口左侧为项目目录树，右侧为当前 Markdown 的文档大纲；产品首次默认显示目录树、折叠大纲。目录树和大纲各自在栏头提供折叠按钮，折叠后在工作区对应边缘提供展开按钮；用户选择的显隐和宽度会作为应用级工作区偏好永久保留。
- 项目目录树递归展示普通目录与文件，默认不展示隐藏项；打开时读取目录树，对外部变化提供显式刷新，对应用内成功新建的文件立即更新。
- 用户可通过项目树按钮或右键菜单在目标目录新建 `.md` 或 `.markdown`；名称、重名与项目边界检查通过后才创建，不覆盖已有文件。
- 项目中 `.md` 与 `.markdown` 以窗口顶部原生标签打开；重复选择聚焦已有标签。PNG、JPEG 与 PDF 延续安全查看规则，其他文件只在树中展示、不由 Inflow 编辑。
- 单文件打开模式继续保留。
- 源码编辑、实时预览（分栏）与阅读预览共享同一 Markdown 缓冲、修改状态和保存路径；阅读预览只读，不形成私有富文本。
- 个人首版（内部验证版）由当前 H1–H6 生成基础文档大纲并返回源位置；大纲默认折叠，没有当前文档时不可操作。点击标题时正文滚动到对应标题、光标移动到标题起点并聚焦编辑器，不以查找高亮代替跳转。大纲过滤和可撤销结构重组后置。
- 后续的工作区全文搜索、结果筛选、快速打开与替换前预览。
- 个人首版（内部验证版）的标题、项目内相对文档、本地附件、已有相对 PNG/JPEG 引用和外部网页链接。
- 后续的文件重命名/移动/删除、最近项目、快速打开和导航历史。
- 成熟版的跨文档关系、来源说明、演进脉络和质量趋势洞察。

## 3. 用户故事与核心流程

### 3.1 打开项目

1. 用户选择“打开项目…”并从系统面板选择一个已有普通文件夹，或把文件夹拖到 Dock 中的 Inflow 图标或 Inflow 应用图标。
2. 产品将该文件夹直接作为项目根目录，系统面板中的选择动作同时确认当前项目访问，不再增加“允许目录访问”二次确认；产品不创建 Inflow 私有项目文件，也不导入、复制、移动或重组其中内容。同一规范项目路径已经打开时聚焦现有项目窗口。
3. 外部入口冷启动、空白窗口复用和未命名草稿保护沿用[文档与文件](./01-文档与文件.md)的统一窗口规则。
4. 项目窗口左侧在打开时递归读取并展示普通目录与文件，隐藏项默认不展示；后续外部磁盘变化由用户执行显式“刷新项目”重新读取，应用内成功新建的文件立即反映在树中。首次使用显示目录树，之后按用户最近保存的工作区偏好显示。
5. 打开完成后默认没有当前文档，因此右侧大纲不可用；用户选择 `.md` 或 `.markdown` 后才进入编辑，大纲按当前工作区偏好显示，首次使用时折叠。PNG、JPEG 与 PDF 按安全查看规则处理；其他文件仅展示在目录树中，选择后不进入 Inflow 编辑器。
6. 左侧目录树和右侧大纲在各自栏头提供折叠按钮，折叠后在工作区对应边缘提供展开按钮，同时保留工具栏与“显示”菜单入口。操作更新应用级工作区偏好，但不修改 Markdown、当前文档或撤销历史。
7. 用户关闭项目窗口时，当前文档若有未保存修改，仍进入普通文档关闭确认；关闭项目不删除或更改项目文件夹。

### 3.2 浏览、新建与切换当前文档

1. 用户从文件树选择一份 `.md` 或 `.markdown`，该原文件在窗口顶部标签中打开并成为当前编辑文档；已经打开时只切换到既有标签。
2. 用户通过项目树的“新建 Markdown 文件…”按钮或右键菜单输入名称。选中文件夹时以该文件夹为目标，选中文件时以其父目录为目标，没有选择时以项目根目录为目标。
3. 未写扩展名时自动补 `.md`，用户也可明确使用 `.md` 或 `.markdown`。空名称、以点号开头的名称、其他非法名称、其他扩展名、同名文件或目录，以及规范化并解析符号链接后位于项目根目录外的目标均被拒绝，不覆盖已有文件或目录。
4. 新建或切换文件不要求先保存当前标签；未保存修改保留在各自文档会话中。创建前重新检查目标目录存在、可写且仍位于项目根目录内，再以不覆盖方式创建空文件。目标消失、无权限或创建失败时不添加树节点、不切换当前文档，并说明原因。创建成功后立即显示在项目树并打开为新标签，无需刷新。若文件已成功创建但随后无法打开，文件和树节点保持存在，并明确提示“文件已创建但无法打开”。
5. 用户可在源码编辑、实时预览（分栏）或阅读预览之间切换；三种视图共享同一 Markdown 缓冲、修改状态和保存路径。阅读预览正确呈现常用与复杂结构，但只在源码或分栏中编辑。
6. 目标规范路径已经在另一个 Inflow 窗口中编辑时，应用只聚焦该现有窗口；项目窗口的当前文档与未保存内容不变。
7. 在目录树中切换文件只切换或新增内容标签，目录树、项目边界和窗口布局保持不变；已打开标签的预览、分析、恢复保护和文件监控在暂时不可见时保持会话，不显示整窗准备页或产生退出再进入的感觉。保存确认只在用户关闭含未保存修改的标签、窗口或应用时出现。
8. 项目中的每份文档独立遵循手动保存、外部变化提示和单快照恢复规则；项目不提供统一保存状态。
9. 个人首版使用 macOS 原生窗口标签承载项目内已打开文档并保留各自未保存状态。“文件 > 新建”或 `Command`+`N` 仍创建独立未命名单文件窗口，不在项目树内创建文件。

### 3.3 拖放入口与边界

1. 将文件夹拖到 Dock 中的 Inflow 图标或 Inflow 应用图标，等同于打开项目；将 `.md` 或 `.markdown` 拖到这些入口，等同于打开单文件。
2. 同一路径已经打开时聚焦现有文件或项目窗口；一次拖入多份 Markdown 时，每份分别打开或聚焦。
3. 将 PNG 或 JPEG 拖入编辑区仍表示在当前 Markdown 中插入图片，不解释为打开项目。
4. 项目树不接收外部文件或文件夹拖入来复制、移动或整理内容；项目内创建使用明确的项目树按钮或右键菜单。

### 3.4 寻找内容（后续）

1. 用户按文件名、标题或最近使用快速打开文档。
2. 需要查找正文时，在工作区范围搜索并按文件、路径或内容类型筛选。
3. 选择结果后打开对应文档、定位命中文本，同时记住来源位置。

### 3.5 沿链接阅读并返回

1. 用户从实时预览（分栏）或阅读预览通过明确链接操作打开当前标题、相对文档或跨文档标题。
2. 当前文档标题直接在原文中定位；指向本地 `.md` 或 `.markdown` 的链接解析到目标原文件，并形成可编辑的路径绑定。
3. 在项目模式中，相对路径以包含该链接的 Markdown 文件所在目录为基准。规范化路径并解析符号链接后，目标必须仍位于项目根目录内；越界、符号链接逃逸、目标缺失或无权限时阻止打开并说明原因，不自动扩大授权范围。
4. 项目内目标 `.md` 或 `.markdown` 通常成为同一项目窗口的当前编辑文档；若其规范路径已经在另一个 Inflow 窗口中编辑，则聚焦该窗口且项目当前文档不变。跨文档链接含标题 fragment 时，打开目标文档后按当前解析结果尝试定位；无法解析或未匹配时仍保持目标文档打开。
5. 项目内已有的相对 PNG/JPEG 图片引用在实时预览（分栏）和阅读预览中直接呈现，读取原文件但不复制、不改写引用。用户在预览中明确点击普通 PNG/JPEG/PDF 文件链接时，仍先生成应用管理且文件系统不可写的临时副本，再交给系统默认应用；副本不加入最近文档，外部应用只能另存为到用户另选位置。
6. 用户在预览中明确点击 `http` 或 `https` 链接后，直接交给系统默认浏览器；其他 URL scheme 一律拦截，不执行或转交。
7. 单文件模式继续按用户直接打开本地文件的现有规则工作，不因未打开项目而强制创建项目。
8. 成长版工作区导航可增加前进与后退历史，记录文档、标题和语义位置；该能力不阻断个人首版（内部验证版）。

### 3.6 重组长文档（后续）

1. 用户在大纲中选择标题及其子结构。
2. 拖动前显示受影响范围，拖动后将完整源文本变更作为单次操作。
3. 用户可一次撤销整个重组。

### 3.7 理解结构与演进（成熟版）

1. 成熟版用户打开结构洞察，在关系视图查看由实际链接、资源引用和来源信息形成的文档关系，并可筛选入链、出链、断链、孤立文档和来源未知项。
2. 用户选择任一关系或问题后，回到对应文件与语义位置；无法确认的关系标记为推断或未知，不冒充用户事实。
3. 演进视图结合本地版本时间线与用户明确提供的来源信息，区分内容编辑历史和外部服务状态，不把二者合并为同一种变化。
4. 质量趋势汇总一段时间内的结构、链接、资源与兼容问题变化，只呈现可解释证据，不给用户或文档打生产力分数，也不自动修改正文。

### 3.8 补充来源并纠正推断（成熟版）

1. 用户在结构洞察中选择文档，查看并新增、修改或删除来源标题、作者或机构、来源位置、日期和备注。
2. 来源信息保存前展示将写入 Markdown 的完整变化；用户确认后与正文修改使用同一保存、冲突和撤销规则，撤销或删除后不留隐藏副本。
3. 用户选择推断关系时可查看证据，并选择“在文档中添加链接”“标记为无关”或“暂时隐藏”；添加链接时，以当前选中的文档为源、推断目标文件或标题为目标，由用户选择插入位置并预览标准 Markdown 相对链接。
4. “标记为无关”和“暂时隐藏”只改变可重置的工作区显示偏好，不改写文档；用户可在隐藏项目中恢复或重新评估。

## 4. 功能规则

### 4.1 项目边界

- 项目就是用户选择的普通文件夹，不改变文件夹本身，不创建私有项目文件、内容数据库或需要 Inflow 才能读取的副本。
- 同一规范项目路径只对应一个项目会话；应用内打开或拖放重复命中时聚焦现有项目窗口，不建立平行状态。
- 只读取用户选择的项目根目录。相对路径必须以链接所在 Markdown 的目录为基准，完成路径规范化和符号链接解析后仍位于已解析的项目根目录内。
- 不递归跟随会离开项目根目录的符号链接。越界、符号链接逃逸、目标缺失或无权限均停止访问并说明原因，不静默请求或扩大到项目外目录。
- 关闭项目窗口只离开该项目，不删除文件、不改变目录，也不替代当前文档的未保存关闭确认。
- 单文件模式与项目模式并存；直接打开一个 Markdown 文件不隐式扫描其父目录或转换为项目。

### 4.2 文件树与当前文档

- 文件树在项目打开时递归读取普通目录和文件；隐藏项默认不展示。个人首版（内部验证版）以显式“刷新项目”重新读取外部变化，不要求实时监视所有目录变化；应用内成功新建的文件必须立即显示，无需刷新。
- `.md` 与 `.markdown` 可作为项目窗口顶部标签打开；项目刚打开或空项目可以没有当前文档。PNG、JPEG、PDF 采用本节既有安全查看规则；其他文件只在树中展示，不进入 Inflow 编辑器。
- 项目树“新建 Markdown 文件…”按钮与右键菜单使用同一规则：选中文件夹时使用该目录，选中文件时使用其父目录，无选择时使用项目根目录。
- 新名称没有扩展名时补 `.md`；明确的 `.md` 与 `.markdown` 保持不变。空名称、以点号开头的名称、非法名称、其他扩展名、同名文件或目录、越界或符号链接逃逸在写入前拒绝，且绝不覆盖已有文件或目录。
- 新文件打开为新标签，不要求先处理原标签的未保存修改。执行时目标消失、无权限或创建失败时不添加树节点、不切换当前文档，并明确说明原因。磁盘创建成功后立即更新树并尝试打开；若打开失败，保留已创建文件和树节点，并明确区分“已创建”与“无法打开”。
- 项目窗口中的“文件 > 新建”与 `Command`+`N` 只创建独立未命名单文件窗口；它们不是项目树新建入口。
- 文件树和项目内 Markdown 链接使用同一标签切换合同：切换不关闭原标签，也不要求处理其未保存修改。
- 目标规范路径已经在另一个 Inflow 窗口中编辑时，只聚焦现有窗口，不改变项目当前文档或创建第二份编辑状态。
- 源码编辑、实时预览（分栏）和阅读预览共享当前文档的 Markdown 缓冲、修改状态和保存路径，不生成隐藏富文本。阅读预览以完整渲染结果呈现复杂结构且不可编辑。
- 项目目录树始终位于编辑区左侧，当前文档大纲始终位于编辑区右侧。产品首次默认显示目录树、折叠大纲；任一入口的显隐操作和分隔条拖动都更新统一的应用级工作区偏好，并跨文件、窗口和应用重启保留。
- 文件重命名、移动、删除、跨文档搜索、快速打开、最近项目和导航历史不属于个人首版（内部验证版）。

### 4.3 搜索与批量变更（后续）

- 搜索结果展示文件、位置和命中上下文，选择后精确定位。
- 跨文档替换在执行前展示全部变更；目标文件发生变化后必须重新确认。
- 批量重命名、移动或结构重组不得留下部分完成且无法识别的状态。

### 4.4 链接与导航

- 使用标准 Markdown 链接，不要求 Inflow 私有链接。
- 当前文档标题在原文内定位。项目内 `.md` 与 `.markdown` 链接通常切换当前编辑文档；目标规范路径已在另一 Inflow 窗口中编辑时只聚焦现有窗口且项目当前文档不变。单文件模式下仍按普通文档流程打开原文件。
- 项目内相对路径以链接所在 Markdown 的目录为基准，并必须通过项目边界规范化与符号链接检查。检查失败、目标缺失或无权限时不打开、不切换，也不自动扩大授权。
- 个人首版（内部验证版）对跨文档 fragment 只按目标文档当前解析结果尝试定位；无法解析或未命中时仍打开目标文档并停留在默认位置，不将定位失败表示为打开失败。稳定 slug、跨版本精确匹配和重名标题消歧等长期合同后置，待[附录 F](../07-产品附录/附录F-Markdown方言与定位规则.md)后续定稿。
- 用户在预览中明确点击 `http` 与 `https` 链接后，才使用系统默认浏览器；预览渲染、后台解析或悬停不得自动打开网页。
- 除 `http`、`https` 和本节明确支持的本地文件外，其他 scheme 一律拦截。产品不把未知 scheme 交给系统执行。
- 项目内已有相对 PNG/JPEG 图片引用在实时预览（分栏）与阅读预览中直接读取并呈现，不复制资源、不改写引用；越界或无法读取时保留原引用并显示失败状态。
- 用户主动打开普通 PNG、JPEG、PDF 文件链接时，只通过应用管理且文件系统不可写的临时副本交给系统默认应用。副本不加入最近文档，外部应用只能另存为到用户另选位置，也不改变文档中的原链接。
- 临时副本存放在应用管理目录并定期清理；清理只作用于该目录中的副本，绝不移动、修改或删除源文件。清理失败可稍后重试，不阻断 Markdown 编辑。

### 4.5 关系与来源（成熟版）

- 关系视图只使用用户所选工作区内的实际文件、链接、资源引用和明确元数据，不扫描工作区外内容。
- 明确链接、用户声明与产品推断必须使用不同表达；证据不足时显示“未知”，不猜测来源或关系。
- 关系视图是可重建的辅助视图，不成为独立内容事实，也不在用户不知情时写回 Markdown。
- 用户可从每项关系、来源或问题返回实际文件与语义位置；目标缺失时保留原引用并说明缺失原因。
- 用户确认的来源信息必须按[附录 H](../07-产品附录/附录H-来源元数据合同.md)以可见、可编辑、可随文件带走的 YAML Front Matter 保存；保存前展示变化，保存后可撤销，不存入只有 Inflow 能读取的隐藏内容库。
- 推断关系默认只作为带证据的建议；用户预览并确认向当前源文档添加标准 Markdown 链接后，该链接才形成明确关系，不写入专有关系字段。否定或隐藏后可从结构洞察恢复。

### 4.6 演进与质量趋势（成熟版）

- 演进视图以本地版本时间线和用户明确来源信息为依据；缺少基线时不生成虚假趋势。
- 内容编辑历史、迁移记录与外部服务状态分别呈现，不用同步成功替代本地保存事实。
- 质量趋势仅汇总可定位的结构、链接、资源和兼容问题，不评价写作质量、工作效率或个人表现。
- 删除辅助数据后，关系与质量视图可从当前文件重建；历史基线被用户清理后，产品明确说明相应趋势不可恢复。

## 5. 异常与空状态

- **空项目**：说明当前文件夹没有可打开的 Markdown 文档，保留左侧目录树并提供“新建 Markdown 文件…”、刷新或更换项目；如当前窗口已隐藏目录树，必须保留可发现的再次显示入口。没有当前文档时不显示右侧大纲。
- **新建名称无效或目标已存在**：保留用户输入和目标目录供修正，不创建占位文件，不覆盖已有文件。
- **文件已创建但无法打开**：树中保留真实文件并明确说明“文件已创建但无法打开”，不静默删除，也不把它误报为未创建。
- **无搜索结果**：保留查询和筛选，提供清除条件，不将空结果误报为索引错误。
- **文件不可访问**：保留当前文档与未保存内容，说明不可访问原因；不自动扩大项目授权。
- **链接目标越界、逃逸、缺失或无权限**：不移动当前位置、不切换当前文档，说明具体原因并保留原链接。
- **临时副本创建失败**：不把源文件直接交给外部应用，说明未打开并保留当前位置。
- **默认应用打开失败**：保留已打开的 Markdown 上下文，说明系统未能打开副本或网页。
- **项目外部变化**：显式刷新文件树不能覆盖当前文档的本地修改；每份文档继续进入[文档与文件](./01-文档与文件.md)定义的外部变化流程。
- **切换文档失败**：保留当前标签、编辑内容和未保存状态，不显示或短暂加载目标文档。
- **洞察暂时过期**：文件刚发生变化时标记“正在更新”，旧结果不能冒充当前事实；用户仍可直接打开实际文件。
- **来源或关系未知**：显示未知原因和可补充的元数据，不自动推断作者、出处或因果关系。
- **历史基线缺失**：说明只能展示当前状态，不能生成变化趋势；不把“无历史”显示成“无变化”。
- **来源信息与外部修改冲突**：停止写入并进入文档冲突流程，不用较新的洞察界面覆盖磁盘内容。

## 6. 验收场景

个人首版（内部验证版）：

1. 从应用内选择已有普通文件夹或把文件夹拖到 Dock/应用图标后直接打开项目；文件夹中不出现 Inflow 私有项目文件，已有目录、文件、名称与位置不被导入、复制或重组。同一规范项目路径重复打开时聚焦现有项目窗口。
2. 项目打开时，项目目录树位于左侧，递归展示普通目录与文件且默认不展示隐藏项；在磁盘外部增删文件后执行显式刷新，树按当前磁盘状态重新读取；应用内新建成功的文件无需刷新即可显示。
3. `.md` 与 `.markdown` 可成为项目窗口顶部标签，打开项目后允许暂时没有当前文档；PNG、JPEG、PDF 按安全查看规则处理，其他文件只显示在树中且不能进入 Inflow 编辑器。
4. 项目树按钮与右键菜单均可新建 Markdown：选中文件夹时在该目录创建，选中文件时在其父目录创建，无选择时在项目根目录创建；无扩展名自动补 `.md`，`.md` 与 `.markdown` 均可明确使用。
5. 新建名称为空、以点号开头、非法、使用其他扩展名、与已有文件或目录重名、越界或经符号链接逃逸时不创建且不覆盖。执行时目标消失、无权限或磁盘创建失败时同样不添加树节点、不切换文档，并说明原因。
6. 新建空文件成功后立即显示在树中并尝试成为当前文档；若随后无法打开，磁盘文件与树节点仍保留，并明确提示“文件已创建但无法打开”。项目窗口中的 `Command`+`N` 仍创建独立未命名单文件窗口。
7. 从文件树或项目内 Markdown 链接切换文档时，原标签和未保存编辑保持不变，不出现保存或关闭确认。目标已打开时聚焦既有标签或窗口，不形成重复编辑会话。
8. 项目内相对链接以链接所在 Markdown 的目录为基准；正常目标可切换，路径越界、符号链接逃逸、目标缺失或无权限均被阻止并说明，且不自动扩大授权。
9. 项目内已有相对 PNG/JPEG 图片引用可在分栏与阅读预览中直接呈现，源文件与引用不被复制或改写；主动打开普通 PNG/JPEG/PDF 文件链接仍使用只读临时副本。
10. 选择当前 Markdown 后，大纲首次默认折叠；左侧目录树与右侧大纲可通过各自栏头和对应工作区边缘按钮独立折叠、展开，操作不改变 Markdown 或撤销历史。显隐、宽度和写作视图写入设置页同一工作区偏好，切换项目文件或重启应用后仍保留。
11. 点击大纲标题后，正文滚动到对应标题，插入光标移动到标题起点并聚焦编辑器；标题文本不显示查找匹配高亮。
12. 源码编辑、实时预览（分栏）和阅读预览始终使用同一 Markdown 缓冲、修改状态和保存路径；阅读预览只读且不产生私有富文本。
13. 每份项目文档独立遵循手动保存、外部变化和单快照恢复；关闭项目或刷新树不覆盖未保存内容。
14. 不打开项目时仍可直接打开单个 Markdown 文件，不扫描其父目录，也不强制转换为项目模式；拖放多份 Markdown 时每份分别打开或聚焦，拖入编辑区的 PNG/JPEG 仍表示插入图片，项目树不接收外部拖入来整理文件。
15. 用户在预览中明确点击 `http` 或 `https` 后使用默认浏览器；其他 scheme 不会被直接打开。

后续完整产品：

1. 同一文档从文件树、搜索结果、链接与快速打开进入时，聚焦同一标签页与编辑状态。
2. 全文搜索能从结果定位到正确文档和源文本，空结果与权限不足有不同反馈。
3. 大纲重组和跨文档批量替换在执行前可检查完整影响，并可以明确撤销。
4. 成熟版关系视图中的每项明确关系都能回到实际链接或元数据；推断与未知项不会显示为已确认事实。
5. 成熟版演进与质量趋势能区分内容历史、外部状态和当前问题；历史基线缺失或结果过期时给出准确降级。
6. 新增、修改或删除来源信息前可查看 Markdown 变化，确认后可撤销并随文件带走；推断可查看证据、向当前源文档的指定位置添加标准链接、撤销链接、否定、隐藏和恢复。
7. 多标签工作区可通过可发现命令一次关闭整个窗口，不需要逐个关闭标签页；关闭不会删除文件，未保存内容不会被静默放弃。

## 7. 非范围

- 将工作区转换为只能由 Inflow 读取的项目。
- 未经用户选择扫描整个磁盘或个人主目录。
- 将本地附件原文件直接交给第三方应用修改，或把临时副本的修改写回源文件。
- 云端文件库、团队权限和多人协同作为工作区的内置前提。
- 把关系视图定义为独立知识事实，或在无证据时自动补全关系、来源与因果。
- 对用户、文档或工作节奏生成生产力分数、排行榜或绩效判断。
- 个人首版（内部验证版）中的多标签、多文档并排、跨文档搜索、快速打开、文件重命名/移动/删除、最近项目、批量替换、关系视图、演进趋势和导航历史。
- 通过向项目树拖入外部文件或文件夹来复制、移动或整理项目内容。
