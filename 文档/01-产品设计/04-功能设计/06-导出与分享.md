## 1. 目标

让个人首版（内部验证版）能够把当前正在编辑的 Markdown 生成一份基础、可打开、内容可核对的 PDF。导出不改变 Markdown 文件、保存状态、撤销历史或当前位置。

## 2. 个人首版（内部验证版）范围

- 只导出单篇 PDF；HTML、长图、文档包、系统打印配置和发布平台均后置。
- 使用固定浅色打印主题；首版不提供主题、纸张、页边距、页眉页脚、分页或模板选项。
- PDF 必须来自用户发起导出时的当前编辑内容，不等待或借用可能落后的预览。
- 最终 PDF 必须能被普通 PDF 阅读器打开，文本和可用本地图片与本次源内容一致。
- 最终 PDF 不得包含用户的绝对本地路径。
- Markdown 中的 `http`、`https` 链接可在用户点击 PDF 链接时打开；`file`、脚本协议和其他自定义 scheme 不生成可执行链接动作。
- 缺失图片在导出前警告；用户继续时，PDF 在对应位置保留可见占位。
- 空文档不提供导出，导出命令预先置灰。

## 3. 用户故事与核心流程

### 3.1 导出当前内容

1. 用户在非空文档中选择“导出 PDF”并选择目标位置。
2. 产品冻结发起时的完整源文本作为本次输入；用户随后继续编辑不会改变已开始的任务。
3. 产品使用与首版预览相同的 CommonMark/GFM 与 Mermaid 范围生成固定浅色 PDF。
4. 产品检查最终文件能打开、文本与图片结果正确、且未包含绝对本地路径；通过后才显示成功并提供在 Finder 中显示或打开。

### 3.2 处理缺失图片

1. 导出前发现本地图片缺失时，产品列出安全的资源名称和源文位置，不显示完整私密路径。
2. 用户可以取消并回到文档修复，也可以明确继续。
3. 继续导出时，缺失图片位置生成可见占位；不静默删除替代文本，也不让后续内容消失或错位。

### 3.3 处理链接

1. `http` 与 `https` 链接保留显示文字，并可在 PDF 阅读器中由用户点击打开。
2. `file`、`javascript`、`data` 和其他未明确支持的 scheme 只保留可见文字，不生成可执行动作。
3. 原始 HTML 中的脚本、事件、嵌入对象、导航或网络行为不进入 PDF。

## 4. 功能规则

### 4.1 源内容与任务

- 每次导出绑定发起时的完整源文本；不从屏幕截图、旧预览或最近一次保存文件反推内容。
- 导出期间继续编辑不改变已开始任务；再次导出才使用新的当前内容。
- 取消或失败不改变 Markdown、保存状态和当前编辑。
- 首版“空文档”定义为源文本不含任何非空白字符；此时导出命令置灰。
- 首版只使用用户本次选择的目标和系统提供的基础替换确认，不承诺完整的并发目标所有权或跨进程条件替换合同。

### 4.2 PDF 呈现

- 只使用固定浅色打印主题；屏幕预览的明暗外观不改变首版 PDF。
- PDF 对基础 Markdown、图片及首版 Mermaid 的解释与[附录 F](../07-产品附录/附录F-Markdown方言与定位规则.md)一致。
- 公式、脚注、其他 Mermaid 和原始 HTML 不获得首版专用交付语义；按预览中的可读降级结果进入 PDF。
- 可用本地图片进入 PDF；缺失图片按用户确认生成占位。
- 超宽内容可以缩放、换行或保留可见溢出说明，但不得静默丢失正文。

### 4.3 基础结果检查

成功前必须对最终 PDF 完成以下检查：

1. 文件结构可由普通 PDF 阅读器打开；
2. 文本来自本次冻结的源内容，没有使用旧版本；
3. 可用本地图片出现，缺失图片使用可见占位；
4. 不包含用户的绝对本地路径；
5. 只有 `http` 与 `https` 可形成用户点击的外部链接动作；
6. `file`、脚本协议、自定义 scheme 和原始 HTML 动作没有进入交付物。

任一检查失败时不显示成功。首版保留当前编辑，并允许重试或另选位置；不以“可能可用”的文件冒充已完成 PDF。

## 5. 后续产品方向

以下能力保留为未来方向，不是个人首版（内部验证版）入口或验收门槛：

- 自包含 HTML、无样式或带大纲网页、长图和可移植文档包；
- 深色整页 PDF、多主题、纸张与方向、边距、页眉页脚、分页和专业交付模板；
- 公式、脚注、更多 Mermaid 与专业表达的完整交付；
- 公共发布级 PDF 安全负例矩阵、附件与元数据审计、跨阅读器兼容基线；
- 导出目标在多进程并发变化时的条件替换、完整所有权和恢复合同；
- 批量导出、网站发布、上传平台、多人审批和自动分享。

后续能力进入产品时不得降低“使用当前内容、失败不冒充成功、不暴露绝对本地路径”的首版基础。

## 6. 异常与空状态

- **空文档**：导出命令置灰，不生成空白 PDF。
- **缺失图片**：导出前警告；继续时在最终 PDF 中显示可见占位。
- **PDF 无法打开或结果检查失败**：不显示成功，保留当前编辑，提供重试或另选位置。
- **目标不可写或写入失败**：说明未完成，不改变 Markdown；目标最终状态无法确认时要求用户自行检查。
- **导出被取消**：当前文档与已完成的既有交付物不受影响。
- **链接协议被阻止**：保留可见文字，不生成可执行动作。

## 7. 验收场景

1. 快速修改后立即导出，PDF 使用发起时的当前编辑；导出期间继续编辑不会改变已开始任务。
2. 普通 PDF 阅读器可以打开最终文件，标题、段落、列表、代码、表格、首版 Mermaid、文本和可用本地图片均与本次源内容一致。
3. 缺失图片在导出前产生警告；用户继续后，最终 PDF 在原位置显示可见占位和替代文本。
4. `http`/`https` 链接可由用户点击；`file`、脚本协议、自定义 scheme 与原始 HTML 动作均不可执行。
5. 使用绝对路径图片或链接的样例导出后，最终 PDF 不包含用户的绝对本地路径。
6. 空文档的导出命令置灰；写入失败、检查失败或取消均不改变 Markdown，也不显示导出成功。
7. 使用深色屏幕外观导出时，最终 PDF 仍使用固定浅色打印主题。

## 8. 非范围

- 把导出文件当作当前 Markdown，或因导出改变文档保存位置。
- 在无用户操作时自行发送、上传、打印或打开交付物。
- 依赖用户未配置的外部转换工具才能完成首版 PDF。
- 用个人首版（内部验证版）的基础检查宣称已满足公共发布级 PDF 安全与兼容承诺。
