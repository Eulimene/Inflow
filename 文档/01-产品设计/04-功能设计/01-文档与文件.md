## 1. 目标

让用户始终清楚“我正在编辑哪个文件、哪些内容已保存、发生意外时如何找回”。文件位置由用户选择，Markdown 文件始终是可带走的内容事实，任何便利功能都不能以静默覆盖或锁定用户内容为代价。

当前个人首版（内部验证版）仅供产品本人使用且不公开分发，以常见 macOS 编辑器的可理解行为验证单文件与普通文件夹项目中的核心写作闭环。项目不创建私有项目文件，也不导入、复制或重组用户已有内容。自动保存、三版本比较、条件写入、完整恢复中心与版本时间线保留为后续产品方向，不作为该版本交付或批准前提。

## 2. 范围

- 普通启动后的未命名文档，以及通过“文件 > 新建”或 `Command`+`N` 创建独立未命名单文件窗口。
- 从应用内、Finder、系统“打开方式”、Dock 或应用图标拖放打开、重开 Markdown，并手动保存、另存为、关闭与在 Finder 中定位。
- 选择普通文件夹作为项目打开，在项目树中新建 Markdown，并在项目文件间切换最多一个当前编辑文档；项目刚打开或没有 Markdown 时可以没有当前文档。
- 文件被其他应用修改、移动、替换、删除或变为不可写时的基础提示与确认。
- 每份文档一个轻量恢复快照，以及异常退出后的单文档恢复选择。
- 常见 Markdown 文件的尽力打开，以及较大或无法可靠处理文件的安全降级和安全退出。
- 单文件打开模式继续保留；项目模式中的文件树、链接边界与安全查看规则见[工作区与导航](./04-工作区与导航.md)。
- 自动保存、三版本比较、条件写入、恢复中心和本地版本时间线属于完整产品后续范围。
- 文件编码、换行风格、支持类型与保留期的精确规格只见[附录 A](../07-产品附录/附录A-产品规格与参数.md)。

## 3. 用户故事与核心流程

### 3.1 新建并首次保存

1. 用户普通启动 Inflow 后，直接得到一份可编辑的空白未命名文档，不经过启动页即可开始写作。
2. 用户在任意窗口执行“文件 > 新建”或 `Command`+`N` 时，始终新建一个独立的未命名单文件窗口；即使当前是项目窗口，也不在项目树中创建文件。
3. 未选择位置前，文档保持“未命名”，只接受恢复保护，不自行创建用户可见文件。
4. 用户通过“文件 > 保存”或 `Command`+`S` 选择位置和文件名；保存成功后窗口与该文件绑定，取消或失败时仍保留未命名内容。

### 3.2 打开并继续编辑

1. 用户可从应用内打开文件，也可在 Finder 中直接打开 `.md` 或 `.markdown`、使用系统“打开方式”，或把 Markdown 拖到 Dock 中的 Inflow 图标或 Inflow 应用图标。
2. 用户可在 macOS 中自行将 Inflow 设为 `.md` 与 `.markdown` 的默认应用；Inflow 不静默更改或抢占系统默认关联。
3. 外部文件或项目请求无论在 Inflow 冷启动还是已运行时到达，都只处理用户指定的目标；冷启动不额外创建空白未命名窗口。
4. 应用先对所有目标规范化并与已打开文件或项目去重：已打开的目标只聚焦现有窗口，不消耗可复用的空白窗口。如果仍有尚未打开的目标，最多一份未修改的空白未命名窗口可承接第一个，其余目标各自新建窗口。
5. 空白未命名窗口已经输入或有其他修改时，草稿保持原样，尚未打开的目标在新窗口打开。一次打开多份 Markdown 时，每份文件均按上述顺序分别打开或聚焦。
6. 文件可正常读取时直接进入写作；存在编码、权限或换行歧义时，先让用户作出不破坏原文件的选择。

### 3.3 打开项目并切换文档

1. 用户选择“打开项目…”并选择一个已有普通文件夹，或把文件夹拖到 Dock 中的 Inflow 图标或 Inflow 应用图标；应用直接将该文件夹作为项目根目录，不创建 Inflow 私有项目文件，也不导入、复制或重组其中内容。
2. 同一规范项目路径已经打开时，应用聚焦现有项目窗口，不创建第二个项目会话。项目由外部入口触发冷启动或应用已有未修改空白窗口时，沿用 3.2 的窗口规则。
3. 项目刚打开时可以没有当前文档；用户从文件树或项目内 Markdown 链接选择 `.md` 或 `.markdown` 后，目标原文件成为项目窗口最多一个当前编辑文档，不创建标签页或第二份隐藏编辑状态。
4. 若目标规范路径已经在另一个 Inflow 窗口中编辑，应用聚焦该现有窗口，不在项目窗口创建第二份编辑状态；项目窗口的当前文档与未保存内容保持不变。
5. 其余切换中，当前文档有未保存修改时先提供“保存”“不保存”“取消”。“保存”成功后切换；“不保存”明确放弃当前未保存修改后切换；保存失败或用户取消时不切换。
6. 项目中的每份 Markdown 独立遵循手动保存、外部变化和单快照恢复规则；项目本身没有独立正文、统一保存或替代各文档保存状态的概念。
7. 用户仍可不打开项目而直接打开单个 Markdown 文件，继续使用单文件窗口与同路径聚焦规则。

### 3.4 在项目树中新建 Markdown

1. 用户通过项目树的“新建 Markdown 文件…”按钮或右键菜单输入文件名。选中文件夹时在该文件夹内创建；选中文件时使用其父目录；没有选择时使用项目根目录。
2. 未输入扩展名时自动补充 `.md`；用户也可明确使用 `.md` 或 `.markdown`。空名称、以点号开头的名称、其他非法名称、其他扩展名、同名文件或目录，以及规范化并解析符号链接后位于项目根目录外的目标均被拒绝，且不覆盖任何已有文件或目录。
3. 若新文件将替换项目窗口的当前文档且当前文档有未保存修改，先提供“保存”“不保存”“取消”。只有保存成功或用户明确不保存后才继续；取消或保存失败时不创建文件，也不改变当前文档。
4. 合法名称确认且切换条件满足后，执行前重新验证目标目录存在、可写且仍在项目根目录内，再以不覆盖方式立即创建空文件。目标消失、无权限或创建失败时不添加树节点、不切换文档，并说明原因。创建成功后立即在项目树中显示并尝试打开为当前文档，无需用户刷新项目。若磁盘文件已成功创建但随后无法打开，不静默删除文件；树中保留该文件，并明确提示“文件已创建但无法打开”。
5. 项目窗口中的“文件 > 新建”与 `Command`+`N` 不触发本流程，仍按 3.1 创建独立未命名单文件窗口。

### 3.5 保存与另存为

1. 个人首版（内部验证版）只提供手动保存，不提供自动保存。普通保存使用 macOS 标准文档保存流程（底层由 AppKit 文档框架提供）写回当前文件；未命名文档进入首次保存。
2. 另存为通过系统保存面板选择新位置。文档包含相对链接或图片引用时，确认前只提示这些引用可能失效；个人首版（内部验证版）不搬移资源、不复制资源，也不自动改写引用。
3. 保存成功后才清除未保存状态；保存失败时保留当前编辑、原路径绑定和再次保存或另存为入口。
4. 应用已观察到外部变化且用户尚未处理时，普通保存必须再次明确说明将覆盖当前磁盘内容，并在用户确认后才继续。
5. 另存为成功后，当前窗口绑定新路径并保留编辑上下文；取消或失败时仍绑定原路径。
6. 项目窗口中的当前文档若另存为到项目根目录外，成功后该窗口结束项目模式、隐藏项目侧栏，并作为绑定新路径的单文件窗口继续编辑；原项目文件夹及其中旧文件不被移动、删除或改写。

### 3.6 外部变化与重新加载

1. 已打开文件被其他应用修改、替换、移动或删除时，在编辑界面显示非模态“重新加载”提示，不抢占输入焦点。
2. 当前没有未保存内容时，用户选择“重新加载”后读取磁盘现状，并尽量恢复光标和选区。
3. 当前存在未保存内容时，选择“重新加载”必须确认将放弃当前编辑；用户取消后继续保留内存内容和提示。
4. 外部变化尚未处理时执行普通保存，必须明确确认覆盖磁盘当前内容；取消后不写入且保留当前编辑。
5. 原文件已删除或路径已失效时，不静默重建；用户可另存为，或明确确认后在原位置重新创建。
6. 个人首版（内部验证版）不提供三版本比较、自动合并、MVCC、版本令牌或 CAS 条件写入；这些属于后续并发保护能力。

### 3.7 关闭与轻量恢复

1. 有未保存内容的文档关闭时，提供“保存”“不保存”“取消”；未命名文档选择保存后进入首次保存。
2. 每份文档只保留一个应用私有的最新轻量恢复快照。快照用于异常退出保护，不表示用户文件已经保存。
3. 异常退出后发现快照时，只提供“恢复为未命名文档”和“放弃”。恢复结果不绑定或覆盖原文件，用户需主动保存。
4. 用户选择放弃后删除对应应用私有快照，不删除或改写任何用户文件。
5. 个人首版（内部验证版）不提供恢复中心、批量恢复、恢复预览比较、独立加密密钥或配额设置界面；更完整的恢复管理保留为后续方向。

### 3.8 较大文件

1. 个人首版（内部验证版）尽力打开用户的常见 Markdown 文件，不冻结文件大小数值或预设分级合同。
2. 文件较大导致解析或预览明显变慢时，优先保留完整源文本编辑；产品可提示预览较慢，并暂停大纲、诊断等非核心解析。
3. 无法可靠读取文件或维持编辑状态时，安全拒绝进入可编辑状态，保留原文件不变，并说明用户可改用其他工具处理。

## 4. 功能规则

### 4.1 文件事实与保存

- Markdown 源文本是唯一可编辑内容；源码编辑、实时预览（分栏）和即时渲染编辑共享同一 Markdown 缓冲、修改状态、保存路径与撤销历史。即时渲染编辑不是独立富文本，复杂结构可在当前位置退回局部 Markdown 源码；预览、大纲、诊断和历史都不产生第二份隐藏正文。
- 除用户在项目树中明确确认“新建 Markdown”时先创建空文件外，个人首版（内部验证版）只在用户手动保存时写入文档内容，不提供自动保存。
- 保存遵循 macOS 标准文档保存与系统文件协调行为；个人首版（内部验证版）不承诺用数据库式 MVCC、版本令牌或 CAS 消除所有路径级竞争。
- 单一编辑会话以规范路径为边界；同一路径从不同入口重复打开时聚焦现有窗口。硬链接别名不保证去重。
- 普通启动创建一份可编辑的未命名文档；外部目标冷启动不附带创建空白窗口。“文件 > 新建”与 `Command`+`N` 始终创建独立未命名单文件窗口。
- 未修改的空白未命名窗口可承接随后打开的文件或项目；已有输入的未命名草稿不得被打开操作替换或放弃，目标改在新窗口打开。
- Finder、“打开方式”和拖放入口与应用内打开使用相同的路径身份和窗口规则；应用允许用户通过 macOS 选择默认应用，但不替用户改变系统默认关联。
- 一次收到多份 Markdown 时逐份按规范路径判断：未打开的各自打开，已打开的各自聚焦，不合并为一个文档状态。
- 只有系统保存操作成功后才显示已保存；失败或取消时保留当前编辑并显示未保存状态。
- 轻量恢复快照与用户文件分开，只用于异常恢复，不能用来跳过关闭确认或冒充已保存。

### 4.2 项目中的文档会话

- 项目是用户选择的普通文件夹边界，不产生需要 Inflow 才能读取的项目清单、数据库或内容副本。
- 同一规范项目路径只保留一个项目会话；从应用内或拖放入口重复打开时聚焦现有项目窗口。
- 个人首版（内部验证版）同一项目窗口最多维护一个当前编辑文档；项目刚打开或空项目可以没有当前文档。多标签、多文档并排与后台保留多份未保存编辑状态后置。
- 文件树与项目内 Markdown 链接需要切换当前文档时，必须先完成未保存确认。保存失败或取消不得改变当前文档、路径绑定、编辑内容或未保存状态；目标已在另一窗口编辑时沿用下一条的聚焦例外。
- 目标规范路径若已在另一个 Inflow 窗口中编辑，只聚焦现有窗口，不改变项目窗口的当前文档，也不创建第二份编辑状态。
- 项目文档另存为到项目根目录外后，当前窗口转为单文件模式；项目边界不随另存为扩大。
- 项目树新建文件只接受目标目录内不重名的 `.md` 或 `.markdown`；未写扩展名时补 `.md`，空名称、以点号开头的名称、其他非法名称、其他扩展名、同名文件或目录、越界或符号链接逃逸均在写入前拒绝，不覆盖已有内容。
- 新建文件前先完成当前文档的未保存处理；取消或保存失败不得留下空文件。目标消失、无权限或磁盘创建失败时不添加树节点、不切换当前文档，并明确说明原因。磁盘创建成功后立即显示在项目树并尝试成为当前文档，不依赖显式刷新；若随后无法打开，保留已创建文件和树节点，并明确区分“已创建”与“无法打开”。
- “文件 > 新建”与 `Command`+`N` 不因项目上下文改变语义；项目内文件只通过项目树按钮或右键菜单创建。
- 每份文档的保存、外部变化提示与轻量恢复快照相互独立；关闭项目窗口时，当前文档仍按普通文档关闭规则处理。
- 项目目录树、相对路径、安全边界与显式刷新合同由[工作区与导航](./04-工作区与导航.md)统一定义。

### 4.3 外部变更

- 当前没有未保存内容时，可重新载入磁盘新版本，并尽量恢复光标、选区与语义位置。
- 外部变化使用非模态“重新加载”提示；有未保存内容时，重新加载前确认放弃当前编辑。
- 外部变化未处理时，普通保存前明确确认覆盖当前磁盘内容；未经确认不得写入。
- 重新加载后重建撤销起点；取消重新加载不改变当前编辑状态。
- 磁盘文件被删除时保留当前内容，不自动在原位置重建。
- 三版本比较、自动合并、保存副本冲突工作流与条件写入后置，不作为个人首版（内部验证版）要求。

### 4.4 轻量恢复快照

- 每份文档最多保留一个最新快照；新快照替换该文档的旧快照，不形成可浏览历史。
- 异常退出后的恢复只产生未命名文档，不直接写回原路径。
- 用户选择放弃后清除该快照；快照读取或清理失败时说明失败，不影响用户文件继续打开与保存。
- 个人首版（内部验证版）不提供恢复中心、批量操作、独立密钥管理或配额界面。

### 4.5 本地版本时间线（后续）

- 用户可查看版本时间、内容变化摘要和差异，可复制旧内容或明确恢复整份文档。
- 恢复历史版本是一次明确的文档修改，不能静默替换当前内容。
- 版本时间线可关闭或清理，恢复保护始终独立存在。保留默认与限额见[附录 A](../07-产品附录/附录A-产品规格与参数.md)和[附录 B](../07-产品附录/附录B-默认设置.md)。

### 4.6 拖放入口与编辑区边界

- 将 `.md` 或 `.markdown` 拖到 Dock 中的 Inflow 图标或 Inflow 应用图标，等同于打开单文件；将文件夹拖到这些入口，等同于打开项目，并复用同一路径聚焦规则。
- 一次拖入多份 Markdown 时逐份打开或聚焦，不创建合并文档；不支持的目标不改变已有窗口与文档。
- 将 PNG 或 JPEG 拖入编辑区仍表示在当前 Markdown 中插入图片，不解释为打开单文件或项目。
- 项目树不接受外部文件或文件夹拖入来复制、移动或整理内容；项目内创建使用明确的“新建 Markdown 文件…”按钮或右键菜单。

### 4.7 系统最近文档附带行为（非个人首版能力）

- macOS 若随标准文档框架提供“打开最近”，个人首版可以保留该系统附带入口，但不保证其存在、容量或恢复授权，也不把它计入个人首版 UAT。
- 系统附带记录只可来自用户直接打开或成功保存的 Markdown；交给默认应用打开的 PNG、JPEG、PDF 临时副本不得加入。
- CAP-FILE-005 表示由 Inflow 明确定义和管理的最近文档能力，包括容量、访问授权清理与完整管理界面；它仍属后置范围。

## 5. 异常与空状态

- **普通启动**：直接显示一份可编辑的空白未命名文档，不显示要求先选择入口的启动页。
- **外部目标冷启动**：只显示指定文件或项目；不短暂显示或留下额外空白未命名窗口。
- **空白未命名文档**：可直接关闭；一旦有内容，按未保存文档处理。
- **打开操作遇到未命名草稿**：保留草稿并在新窗口打开目标；只有从未修改的空白未命名窗口打开时才复用该窗口。
- **项目树新建被拒绝**：保留名称与目标目录供用户修正，不创建占位文件，不改变当前文档或覆盖已有文件。
- **项目文件已创建但无法打开**：保留磁盘文件与树节点，明确提示“文件已创建但无法打开”，不静默删除，也不把它误报为未创建。
- **不支持的编码**：不进入可编辑状态，只提供安全离开、复制原文件或在 Finder 中定位。
- **权限不足**：以只读方式展示可读内容，允许复制、另存为或重新授权。
- **保存失败**：保留当前编辑、未保存状态和重试或另存为入口。
- **恢复快照失败**：说明异常恢复保护不可用，但不阻止用户手动保存自己的文件。
- **外部变化或删除**：保留当前编辑并持续显示可处理提示，具体文案与按钮顺序只见[附录 D](../07-产品附录/附录D-状态与提示文案.md)。
- **项目文档切换受阻**：保存失败或用户取消时保留当前文档和未保存内容，不提前加载或短暂显示目标文档。

## 6. 验收场景

1. 普通启动后直接出现一份可编辑的空白未命名文档；用户可输入，并通过“文件 > 保存”或 `Command`+`S` 完成首次保存。未主动保存前不出现用户可见文件。
2. 在单文件或项目窗口执行“文件 > 新建”或 `Command`+`N`，都创建独立未命名单文件窗口，不在项目树中落盘。
3. Finder 直接打开、系统“打开方式”以及拖到 Dock 或应用图标均可打开 `.md` 与 `.markdown`；用户可在 macOS 将 Inflow 设为默认应用，Inflow 不静默改变该设置。
4. 外部目标冷启动时没有额外空白窗口；未修改的空白未命名窗口可被文件或项目复用，已有输入的草稿则保持不变且目标在新窗口打开。
5. 同一规范文件路径从不同入口重复打开时只有一个可编辑会话；一次打开多份 Markdown 时，每份分别打开或聚焦。硬链接别名去重不作为个人首版（内部验证版）的通过声明。
6. 打开普通文件夹项目不会创建私有项目文件，也不会导入、复制或重组其中内容；同一规范项目路径重复打开时聚焦现有项目窗口，单文件打开模式仍可独立使用。
7. 项目窗口最多有一个当前编辑文档；刚打开时可以没有。从树或项目内链接切换时，未保存文档必须先选择“保存”“不保存”或“取消”，保存失败或取消后不切换。
8. 项目树按钮和右键菜单均可新建 Markdown：选中文件夹时使用该目录，选中文件时使用其父目录，无选择时使用项目根目录；无扩展名自动补 `.md`，明确的 `.md` 与 `.markdown` 均可保留。
9. 项目树新建遇到空名称、以点号开头的名称、其他非法名称、其他扩展名、重名、越界或符号链接逃逸时不创建且不覆盖；当前文档有未保存修改时，取消或保存失败也不创建。
10. 项目树新建成功后，空文件立即存在于磁盘、显示在目录树并尝试成为当前文档，无需刷新；若随后无法打开，文件与树节点仍保留并明确提示“文件已创建但无法打开”。这不改变项目窗口中 `Command`+`N` 的独立未命名文档语义。
11. 拖放文件夹到 Dock 或应用图标会打开或聚焦项目，拖放 Markdown 会逐份打开或聚焦；拖入编辑区的 PNG/JPEG 仍插入图片，项目树不通过外部拖放复制、移动或整理内容。
12. 项目树“新建 Markdown”确认后只先创建空文件；已有或未命名文档的正文只在用户手动保存时写入。保存失败、空间不足或文件变为只读后，当前编辑和未保存状态均保留。
13. 另存为含相对链接或图片引用的文档时会给出警告，成功后绑定新路径，但不搬移资源或改写引用。
14. 外部修改发生后出现非模态“重新加载”；有未保存内容时重新加载需确认放弃，未处理提示时普通保存需确认覆盖。
15. 文件被外部删除时不会自动重建；另存为或在原位置重建都需要用户明确选择。
16. 每份文档最多保留一个轻量快照；异常退出后只能恢复为未命名文档或放弃，恢复不覆盖原文件。
17. 源码编辑、实时预览（分栏）与即时渲染编辑共享同一 Markdown 缓冲、修改状态、保存路径和撤销历史；复杂结构的局部源码退路不产生私有富文本。
18. PNG、JPEG、PDF 的应用管理临时副本不进入最近文档。
19. 使用产品本人真实文档和一个较大烟测文档验证尽力打开、较慢提示或暂停非核心解析，以及无法可靠处理时的安全拒绝；不以固定大小数值或预设分级作为通过条件。
20. 自动保存、三版本比较、MVCC/CAS、恢复中心、批量恢复、独立恢复密钥与配额界面均不阻断个人首版（内部验证版）。

## 7. 非范围

- 将云端副本设为文档事实或强制用户登录后才能保存。
- 在冲突时自动选择一方并静默覆盖另一方。
- 将恢复保护或版本时间线冒充为用户已保存的文件。
- 无选择地猜测未知编码并覆盖原文件。
- 跨文档实时多人共编。
- 个人首版（内部验证版）中的多标签、多文档并排、项目统一保存或后台保留多份未保存编辑状态。
- 个人首版（内部验证版）中的自动保存、三版本比较、自动合并、MVCC/CAS 条件写入、恢复中心和恢复配额管理。
- 由 Inflow 静默更改 `.md` 或 `.markdown` 的系统默认应用关联。
- 通过向项目树拖入外部内容来复制、移动或整理文件。
