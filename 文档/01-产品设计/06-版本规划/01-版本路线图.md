## 1. 路线图目的

本文定义 Inflow 先验证哪一个用户闭环，再决定是否扩大用户、发布范围与产品复杂度。路线图按用户价值排序，不以版本号、公开发布日期或功能数量倒推范围。

当前唯一确定的下一里程碑是 **个人首版（内部验证版）**。它只供产品负责人本人使用和验收，不是 0.1 公共预览版，不构成公开分发、支持、商业或长期兼容承诺。

## 2. 路线原则

1. **先让本人用真实项目完成闭环。** 当前验证普通文件夹中的一组真实 Markdown、相对资源和写作视图能否组成最小、可重复的本地项目任务。
2. **内部通过不等于可以公开。** 公共预览必须在本人验证通过后重新决定范围、版本号和发布合同。
3. **先保住内容，再增加便利。** 保存、外部变化、恢复和链接行为优先于自动化、复杂格式与性能指标。
4. **后续能力不得成为当前依赖。** 账号、网络、插件、同步、人工智能和公开服务都不参与个人首版。
5. **每一阶段单独验收。** 后续阶段不能用未来计划替代当前可观察结果。

## 3. 总体路线

## 4. 个人首版（内部验证版）

### 4.1 目标

让产品负责人本人在当前开发环境中，用一个包含多份 UTF-8 Markdown 与本地资源的真实文件夹项目验证 Inflow 的最小价值：

> 从普通启动、系统文件入口或应用内命令进入 → 新建独立文档或打开文件/项目 → 在项目树中按需新建 Markdown → 沿相对链接与图片理解项目 → 即时渲染写作 → 用源码或分栏核对 → 手动保存 → 处理外部变化或异常中断 → 导出基础浅色 PDF → 关闭并重新打开。

### 4.2 最小能力

- 普通启动且没有外部打开目标时，直接提供一份可编辑的未命名空白文档；“文件”菜单与 Command+N 始终新建独立未命名文档，首次手动保存时由用户选择名称与位置；
- 可从应用内打开单个或多个 Markdown、打开文件夹项目，也可经 Finder 的“打开方式”、用户主动设置的 Markdown 默认应用，以及把 Markdown 或文件夹拖到 Dock/Finder 中的 Inflow 应用图标进入；Inflow 不主动抢占系统默认应用；
- 外部目标无论在冷启动还是应用已运行时到达都只处理目标，冷启动不额外创建空白文档；先对目标规范化并与已打开文件或项目去重，再由最多一份未修改的未命名空白窗口承接第一个新目标；已经输入的草稿保留并在新窗口打开新目标，同一规范文件路径或项目目录只聚焦既有窗口；
- 把用户选择的普通文件夹直接作为轻量项目打开，不导入、不复制、不创建私有项目文件；左侧递归展示普通目录和文件，隐藏项默认不显示，并可手动刷新；
- 项目树通过按钮或右键菜单在选中目录、选中文件的父目录或未选择时的项目根目录中新建 Markdown；确认名称后立即安全创建空文件、更新目录树并以新标签打开，不覆盖既有文件，也不允许非法名称、重名或经规范化及符号链接解析后越出项目根目录；其他标签及其未保存修改保持不变，项目窗口中的 Command+N 仍新建独立未命名文档；
- 项目刚打开或空项目可以没有当前编辑文档；单一项目外壳永久承载同一个目录树实例，选择另一份 Markdown 时切换已有文档表面或把后台完成读取与校验的新会话加入应用内标签栏，只更新右侧工作区内容，不显示或切换该文档自己的窗口、不要求先保存，也不重置目录树、项目边界或窗口布局；源码可见时焦点返回目标编辑器；
- 用户选择项目目录即信任该次选择对应的精确根目录身份；项目内相对链接和图片以当前 Markdown 所在目录为基准，每次导航仍重新验证根身份、路径、符号链接边界和目标快照。验证通过的项目内 Markdown 链接无重复确认地聚焦已有标签或打开新标签，目标已在另一 Inflow 窗口中编辑时只聚焦现有窗口且项目当前文档不变；相对图片直接呈现；
- 打开、编辑、手动保存 UTF-8 Markdown，并在有未保存修改时确认关闭；
- 外部文件变化时给出简单提示：可以重新加载；需要用当前内容覆盖磁盘时再次明确确认，不提供三版本比较；
- 每份文档最多保留一个最新轻量恢复快照，异常退出后可恢复为未命名文档或放弃；
- 提供源码编辑、实时预览（分栏）和即时渲染编辑三种视图，共享同一 Markdown 缓冲、修改状态、保存路径和撤销历史；
- 即时渲染编辑可直接编辑常用结构；复杂块在当前位置提供局部 Markdown 源码退路，支持中文输入法，普通点击用于编辑、Command+点击用于打开链接；
- 呈现 CommonMark/GFM 基础内容，以及 Mermaid 的 flowchart 和 stateDiagram-v2；
- 提供当前文档查找替换、H1–H6 大纲返回源位置、基础格式命令与固定空表格模板；
- 文档首次保存后，把新增 PNG/JPEG 保存到同目录 assets 文件夹并插入相对引用；
- 本地 Markdown 链接在 Inflow 中正常打开原文件；PNG、JPEG 和 PDF 链接打开文件系统不可写的临时副本；实时预览（分栏）中的明确链接操作或即时渲染编辑中的 Command+点击可把 `http`/`https` 交给默认浏览器，其他 scheme 阻止；
- 导出基础浅色 PDF，并处理空白、缺图、绝对路径与不安全链接动作；
- 在本地保留最小诊断日志，由产品负责人主动导出并自行上传；不自动遥测或发送；
- 以基础键盘可达、焦点可见、状态不只靠颜色、异常不崩溃及一篇较大文档烟测确认基本可用性；较大文档允许明确降级或安全拒绝，不设置固定性能数值。

精确范围与判定只见[个人首版范围](./02-首发版本范围.md)和[产品验收标准](./03-产品验收标准.md)。

### 4.3 明确后置

- 自动保存；
- 多标签、项目搜索、快速打开、项目内重命名/移动/删除和导航历史；
- 完整 Typora 对等、复杂表格等完整结构化即时编辑；
- HTML 导出；
- 公式、脚注和 flowchart、stateDiagram-v2 之外的 Mermaid；
- 复杂格式命令与选择状态矩阵；
- 完整恢复中心、多快照历史和完整异常矩阵；
- 公共分发级 PDF 安全与并发合同；
- 精确性能、大文件、全设备和完整辅助使用协议；
- 公共预览、0.1 或其他版本号、Developer ID、Apple 公证、ZIP/DMG、更新、SHA-256；
- 商业、公开支持、外部反馈服务和任何面向外部用户的承诺。

### 4.4 退出标准

1. 产品负责人用一个自己的真实 Markdown 项目完成 UAT-PERSONAL-01 至 10；
2. 手动保存、外部变化、恢复和关闭路径没有造成不可理解的内容丢失或覆盖；
3. 启动、系统与应用内入口，独立新建与首次保存，项目树新建，相对链接与图片、源码编辑、实时预览（分栏）、即时渲染编辑和基础浅色 PDF 都对应本人明确选择的文件、项目或当前内容；
4. 日志只在本地生成，只有本人主动导出和上传；
5. 产品负责人记录“通过”或“退回”，并说明仍影响本人日常使用的问题。

通过以上标准只表示个人首版内部验证完成，不自动进入公共预览。

## 5. 公共预览：待独立发布决策

个人首版通过后，产品负责人再决定是否建立公共预览。该决策至少重新批准：

- 目标用户、公开范围、版本号与兼容说明；
- 支持的 Mac、macOS 与硬件范围；
- Developer ID 签名、Apple 公证、安装包形式与下载来源；
- 更新、回退、撤回、SHA-256 或其他完整性说明；
- 面向外部用户的隐私、安全、日志、反馈与支持渠道；
- 公共分发级 PDF、保存/导出并发、恢复与故障处置合同；
- 可重现性能、大文件和完整辅助使用验收；
- 免费、收费、许可、退款和维护周期。

在该独立决策批准前：

- 不使用“0.1 公共预览版”“已发布”或“正式版”称呼当前产物；
- 不把内部验收结果解释为签名、公证、分发、安全或支持证明；
- 不为公共发布提前承诺固定版本号、格式或日期。

## 6. 成长版：高级项目写作

### 版本目标

在已经验证的轻量文件夹项目和即时渲染编辑基础范围之上，提高大型、复杂项目的查找、切换、整理与结构化编辑效率。

### 重点能力

- 多标签、跨文档搜索、快速打开、项目内重命名/移动/删除与导航历史；
- 完整结构化即时渲染编辑、写作辅助和长文档高效编辑；
- 资源整理、受控远程资源与本地版本时间线；
- 最近文档与偏好设置扩展；
- 诊断与支持能力的公开合同。

该阶段只有在公共预览及其后续路线获得批准后才细化范围与 UAT。

## 7. 专业版：专业表达与质量

### 版本目标

让复杂技术、研究和出版型 Markdown 在保持标准与可迁移性的前提下，获得系统化表达、质量控制和稳定交付能力。

### 重点能力

- 公式、图表、引用、脚注、专业代码和领域表达；
- 文档健康检查、受控主题、模板和专业交付；
- 迁移预检、差异说明和安全退出；
- 第一批低风险、单一用途的可选能力与精选能力中心。

## 8. 成熟版：结构洞察与可信生态

### 版本目标

在核心写作与专业表达稳定之后，让用户理解内容如何长期演进，并安全连接外部服务、智能辅助和更丰富的领域能力。

### 重点能力

- 跨文档结构洞察、来源和质量趋势；
- 可发现、可审核、可撤回的插件生态；
- 用户主动选择的外部连接；
- 有边界的人工智能辅助；
- 围绕权限、数据、费用和可逆退出的生态治理。

### 永久边界

- 核心产品不因生态成熟而要求账号或网络；
- 本地保存与外部状态始终清楚区分；
- 外部能力不读取未授权内容，不静默修改正文；
- 生态不能把标准 Markdown 变成只有 Inflow 才能继续使用的内容；
- 撤权、停用和退出后，本地文件与核心写作仍可使用。

## 9. 跨阶段不变承诺

- 用户自己的 Markdown 是可带走的内容资产；
- 当前阶段没有批准的能力不能成为隐性依赖；
- 保存、恢复和外部变化不得在没有提示的情况下损害内容；
- 不同视图围绕同一份当前内容；
- 任何自动联网、数据发送、费用或外部副作用都需要独立批准；
- 阶段名称、内部验收、公共发布和正式长期承诺必须清楚区分。

## 10. 路线变更规则

能力跨阶段调整时，必须同步说明：

1. 它解决的当前用户任务；
2. 提前或推迟的用户价值；
3. 对当前闭环和 UAT 的影响；
4. 是否引入账号、网络、外部用户、数据、费用或发布义务；
5. 需要取代的决策与变更记录。

不得用“先放入口、后补闭环”的方式提前声明能力已交付。
