## 1. 路线图目的

本文定义 Inflow 从可信单篇写作走向成熟产品的价值顺序。路线图回答“先完成哪一个用户闭环，再扩展到哪一种复杂度”，不以竞品功能清单、界面数量或固定日期倒推范围。

四个产品价值阶段依次为：**首发版、成长版、专业版、成熟版**。当前的下一个对外里程碑是 **0.1 公共预览版**，它承载本文的“首发版”范围；正式 **1.0** 是后续的长期承诺里程碑，不与 0.1 或其他 0.x 预览版混用。每个阶段都必须形成可独立使用的用户价值，后续版本不得成为前一版本打开、保存、恢复或交付内容的前置条件。

## 2. 路线原则

1. **先建立信任，再扩大规模。** 单篇文件闭环没有成立前，不进入工作区和生态扩张。
2. **每版交付完整任务。** 不把一个核心场景拆成多个无法独立使用的半成品版本。
3. **价值递进，不做清单补齐。** 每项能力必须消除可信写作链中的明确断点。
4. **核心始终可独立使用。** 账号、网络、外部服务和可选专业能力不能成为基本写作的依赖。
5. **标准内容持续可带走。** 版本演进不能以专有内容、隐性锁定或不可逆迁移换取便利。
6. **后续能力不得稀释基础承诺。** 工作区、专业表达和生态增长不能降低文件、连续性和交付质量。
7. **以用户结果退出。** 功能存在不等于版本完成，必须通过端到端场景证明用户真正获得价值。

## 3. 总体路线

```mermaid
flowchart LR
    A["0.1 公共预览版\n可信单篇写作"] --> B["成长版\n连续写作与工作区"]
    B --> C["专业版\n专业表达与质量"]
    C --> D["成熟版\n结构洞察与可信生态"]
```

| 版本 | 核心问题 | 价值闭环 | 用户形成的信任 |
| --- | --- | --- | --- |
| 0.1 公共预览版（首发版） | 能否放心把一篇真实文件交给 Inflow | 创建/打开 → 写作 → 保存/恢复 → 检查 → HTML/PDF 交付 | 文件信任 |
| 成长版 | 能否长期维护一组相关文档 | 工作区 → 多文档写作 → 搜索/导航 → 资源维护 → 本地历史 | 规模信任 |
| 专业版 | 能否承载复杂表达和严格交付 | 专业表达 → 系统检查 → 兼容迁移 → 模板化交付 | 专业信任 |
| 成熟版 | 能否安全连接更多能力并持续演进 | 结构洞察 → 可选能力 → 外部连接/智能辅助 → 可逆退出 | 生态信任 |

## 4. 0.1 公共预览版（首发版）：可信单篇写作

### 版本目标

证明用户可以在完全离线、未启用任何可选能力的情况下，放心完成一篇本地 Markdown 从创建或接手到交付的完整任务。

### 核心用户成果

- 直接创建或打开自己的 Markdown，不经导入和登录；
- 启动后直接进入可编辑的未命名文档，需要时从“文件”菜单打开单个文件或最近文档；
- 在源码编辑、实时预览和纯预览之间连续写作；
- 保存、另存、关闭、重新打开和异常恢复时始终理解内容状态；
- 使用大纲、查找替换和基础呈现维护常见 Markdown 结构；
- 插入并查看本地图片，安全处理链接；
- 确认当前内容后交付 HTML 或 PDF；
- 通过基础设置、键盘操作和辅助使用完成核心任务。

### 重点能力

- 文件与文档的可信基础；
- 单篇写作、阅读和结构定位；
- 常见 Markdown 与本地资源表达；
- 当前内容的可验证交付；
- 离线、隐私和可访问性基本盘；
- 直接分发、手动检查更新且无需账号或许可激活的免费 0.1 公共预览版。

### 明确不纳入

- 文件夹侧栏、完整文件夹工作区、层级文件树、多文档标签和跨文档全文搜索；
- 即时渲染编辑和高级结构化编辑；
- 本地版本时间线与复杂文档关系；
- 任意主题导入、插件市场、云连接、代码托管服务和智能辅助；
- 遥测、后台使用数据发送和内置自动更新；需要诊断时由用户在后续版本主动导出本地诊断包；
- 批量交付、网站发布和多人协作。

### 退出标准

1. 新建、打开、编辑、保存、恢复、阅读和交付形成可连续完成的端到端场景；
2. 不存在静默丢失、静默覆盖或把失败表示为成功的情况；
3. 呈现和交付均对应用户当前确认的内容；
4. 完全离线时核心场景不降级；
5. 键盘和基本辅助使用方式可以完成核心闭环；
6. [首发版本范围](./02-首发版本范围.md)没有以“后续补齐”为由留下阻断性缺口；
7. 保存、恢复、外部变化、本地链接、隐私和分发来源等核心安全门槛全部通过；
8. PDF 导出属于 0.1 P0，最终 PDF 的完整安全后验通过，任一禁止项或无法完成检查都阻止发布；
9. 对外候选产物完成 Developer ID 签名、Apple 公证、ticket 装订与直接分发验收；
10. [产品验收标准](./03-产品验收标准.md)中适用于 0.1 的全部标准达到发布要求。

### 0.x 预览与正式 1.0 的承诺边界

- **0.x 公共预览版**：每一版都必须对其明列范围、核心安全、隐私、PDF 安全后验和分发产物负责，不得用“预览”豁免阻断问题。在发布说明、既有文件可带走且必要迁移路径明确的前提下，0.x 期间可调整未冻结的兼容细节、性能档位、辅助使用覆盖和发布节奏。
- **正式 1.0**：在 0.x 核心闭环之上，冻结长期兼容承诺（Markdown 方言、文件与设置迁移、降级解释）、性能承诺（基准环境、样本、阈值和降级档位）、可访问性承诺（键盘、VoiceOver、缩放、对比度和减少动态效果）以及发布承诺（支持系统、更新、撤回、安全响应和长期维护）。这些承诺改变时必须版本化、说明影响并提供兼容或迁移路径。
- 最终路径替换所有权、非协作写入者的完整并发证据、硬链接别名单一会话，以及长期性能与可访问性证据仍是正式 1.0 的入口条件；0.1 必须在自己更窄且明示的承诺下通过发布 UAT，不得宣称已获得 1.0 保证。
- 访谈、迁移样本数、可用性研究轮次和价格研究不是 0.1 或正式 1.0 的发布前置条件。发布后通过用户主动反馈、主动诊断包和可选研究持续验证，不使用遥测。

## 5. 成长版：连续写作与工作区

### 版本目标

把已经可靠的单篇写作体验扩展到一组相关 Markdown，使用户能在不改变原有文件组织的前提下长期维护项目、主题或知识域。

### 核心用户成果

- 选择现有文件夹作为工作区，不需要导入或重组；
- 在文件树、多文档和最近位置之间连续切换；
- 跨文档查找内容，并从结果回到明确位置；
- 使用即时渲染编辑处理高频写作，同时保留源内容透明度；
- 使用语法输入辅助、智能粘贴、多光标、行操作、大纲重组和轻量统计维护长文档；
- 移动、重命名或整理资源前理解相对引用影响；
- 受控查看远程图片，并可将需要长期持有的资源保存到本地；
- 查看本地版本时间线，恢复到有意义的过去状态；
- 工作区关闭后，所有文件仍可被其他工具直接使用。

### 重点能力

- 文件夹工作区与多文档组织；
- 跨文档搜索、导航和资源维护；
- 即时渲染编辑；
- 写作辅助、长文档高效编辑与专注呈现；
- 本地版本时间线；
- 用户主动导出、预览并自行发送的本地诊断包；
- 单篇与工作区之间一致的写作、保存和交付体验。

### 明确不纳入

- 需要联网的市场、同步和智能服务；
- 不受约束的自定义主题和任意内容脚本；
- 完整代码托管、项目管理或实时协作；
- 依赖专有资料库的知识管理模式。

### 进入条件

- 首发版文件信任和单篇交付标准持续成立；
- 多文档能力不会改变单篇文件的所有权和打开方式；
- 工作区价值可以通过真实的长期内容任务验证，而不只是新增侧栏和标签。

### 退出标准

1. 用户能在现有文件夹中完成打开、搜索、跨文档写作、资源维护和交付；
2. 单篇与工作区中的同一文件表现一致，不形成重复身份；
3. 即时渲染编辑产生清楚、可撤销、可迁移的 Markdown；
4. 文档移动和资源变化不会在无提示情况下破坏引用；
5. 工作区规模扩大后，核心写作和导航仍保持连续可用。

## 6. 专业版：专业表达与质量

### 版本目标

让复杂技术、研究和出版型 Markdown 在保持标准与可迁移性的前提下，获得系统化表达、质量控制和稳定交付能力。

### 核心用户成果

- 使用更完整的公式、图表、引用、脚注、专业代码和领域表达；
- 在交付前系统检查断链、资源、标题、语法兼容和表达质量；
- 从成熟 Markdown 工作流迁移时，核心内容和高频任务有清楚兼容结果；
- 使用受控主题、模板和专业交付配置建立一致成果；
- 处理专业公式、图表、引用、代码呈现和受控原始 HTML，同时保留不支持内容的可读降级；
- 对不被当前环境支持的表达看到可读降级和修复建议；
- 按需启用领域能力，而标准 Markdown 仍是核心内容。

### 重点能力

- 专业表达与领域内容；
- 文档质量诊断和交付前审查；
- 迁移兼容与差异说明；
- 受控主题、模板和专业交付；
- 系统打印，以及可配置的纸张、方向、边距、页眉页脚和分页；
- 第一批低风险、单一用途的可选能力；
- 能力中心，用于发现、启用、停用和管理精选能力，不包含公开排名、交易、付费购买或第三方自由上架；费用相关市场能力到成熟版再进入。

### 明确不纳入

- 以任意脚本和无限样式自由度破坏内容边界；
- 静默上传正文或默认连接外部服务；
- 让领域能力接管核心保存、恢复和撤销；
- 用特定竞品界面复刻替代独立产品设计。

### 进入条件

- 成长版的单篇与工作区连续性稳定；
- 专业需求拥有明确用户群、样本文档和可重复交付场景；
- 兼容性以用户迁移结果定义，而不是以界面相似度定义。

### 退出标准

1. 复杂文档能够被编辑、理解、检查和稳定交付；
2. 专业能力缺失或停用时，正文仍有清楚、可读的结果；
3. 迁移用户能够预先理解支持、差异和替代路径；
4. 主题、模板和领域表达不会制造不可解释的第二份内容；
5. 专业交付结果可以被复核并在目标环境独立使用。

## 7. 成熟版：结构洞察与可信生态

### 版本目标

在核心写作与专业表达稳定之后，让用户理解内容如何长期演进，并安全连接外部服务、智能辅助和更丰富的领域能力。

### 核心用户成果

- 看见跨文档关系、变化脉络、来源和质量趋势；
- 发现、评估和管理可信的专业能力；
- 选择性连接存储、代码托管和其他外部服务；
- 使用本地或远程智能辅助，并在应用前查看内容、费用和修改影响；
- 对每项能力回顾授权、撤销访问、停用和清理相关数据；
- 在完全退出生态能力后继续使用本地 Markdown 和核心交付。

### 重点能力

- 跨文档结构洞察和长期演进视角；
- 可发现、可审核、可撤回的能力生态；
- 第三方插件市场、发布者资料和撤回治理；首个公开市场只分发免费插件，评价、Inflow 收款、订阅与恢复购买在后续市场迭代进入；
- 用户主动选择的外部连接；首版只提供单向发布或获取候选副本，双向同步在协议与恢复合同完成后进入；
- 有边界的智能辅助；首版只处理用户明确选择的文本并输出纯文本建议，不调用工具或操作文件；
- 围绕可信、质量与可逆性的生态治理。

### 永久边界

- 核心产品不因生态成熟而要求账号或网络；
- 本地保存始终先于外部同步认知，二者对用户明确区分；
- 外部能力不读取未授权内容，不静默修改正文，不绕过用户确认；
- 生态不能把标准 Markdown 变成只有 Inflow 才能继续使用的内容；
- 付费或官方能力不获得更高的内容控制权。

### 进入条件

- 专业版已经证明复杂内容的质量与可逆性；
- 每类外部能力都有清楚用户任务、数据范围、失败退路和费用说明；
- 生态增长不会稀释首发版建立的文件信任。

### 退出标准

1. 用户能从真实文档、链接、资源和明确元数据理解跨文档关系、来源、变化脉络和质量趋势，并回到对应内容；
2. 洞察中的推断、未知和过期状态清楚，不把推断当事实，也不在用户不知情时改写内容；
3. 用户能理解每项能力读取什么、连接哪里、修改什么和可能产生什么费用；
4. 发布者能完成身份建立、版本提交、审核反馈、发布更新、主体转移和退出；首个公开市场只完成免费插件发现与获取，商业交易和评价作为后续独立退出门槛；
5. 普通插件更新遵循用户偏好，高风险变化重新确认；设备收到防回滚的已签名撤回清单后立即停止风险版本。首版付费人工智能只允许能够权威报价、预授权或接受最大消费参数的提供方开始任务，并共同受硬费用上限约束；
6. 任一能力停用或异常时，核心写作与本地文件不受阻；
7. 检测到外部变更与本地内容冲突时，暂停写入并让用户选择；不用本条宣称已排除所有最终路径竞争；
8. 首版智能辅助只处理用户明确选择的文本，纯文本建议可预览、拒绝和复制，不自动写入正文，不调用工具或操作文件；
9. 撤权、卸载和退出后，相关内容与数据有清楚处置结果。

## 8. 跨版本不变承诺

无论产品发展到哪个版本，以下承诺不得降级：

- 用户自己的 Markdown 是可带走的内容资产；
- 不登录、不联网也能完成核心单篇写作；
- 保存、恢复和外部变化不静默损害用户内容；
- 不同视角围绕同一内容事实；
- 交付结果对应用户确认的内容；
- 可选能力不能接管核心文件行为；
- 状态、风险、数据去向和费用对用户可理解；
- 辅助使用和键盘路径覆盖核心任务。

## 9. 路线变更规则

能力跨版本调整时，必须同时说明：

1. 对应的核心用户任务；
2. 提前或推迟的用户价值；
3. 对当前版本闭环完整性的影响；
4. 是否引入新的账号、网络、内容格式或退出成本；
5. 对范围文档和验收标准的同步修改；
6. 如何验证调整不是单纯追逐竞品或展示效果。

不得用“先放入口、后补闭环”的方式提前声明能力已交付。
