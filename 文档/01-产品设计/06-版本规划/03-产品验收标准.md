## 1. 验收目的

本文回答：产品负责人本人使用一篇自己的真实 Markdown 时，个人首版是否已经能完成最小闭环。

当前验收不是公开发布验收。它不检查公共版本号、签名、公证、安装包、更新、SHA-256、商业、公开支持、全设备、完整辅助使用、30 次性能协议或公共分发级安全合同。

文档状态“已批准”只表示验收方法已经确定，不表示任何实现已经通过。

## 2. 验收人、环境与样本

### 2.1 唯一验收人

产品负责人本人既是当前唯一用户，也是最终判定人。结果只使用：

- **通过**：本场景的全部预期结果成立；
- **退回**：至少一个必需结果不成立，记录问题后修正并重验；
- **未执行**：尚未实际操作，不能计为通过。

### 2.2 环境

- 使用产品负责人当前实际开发与使用的 Mac；
- 记录 Mac 型号、macOS 版本、应用构建或提交标识和验收日期；
- 验收时可以断开网络；除本人最后手工上传日志外，所有当前任务都应保持可用；
- 本阶段结论不外推到其他 Mac、系统版本或辅助使用环境。

### 2.3 一篇真实主文档

使用产品负责人本人实际会继续使用的一篇 UTF-8 .md 或 .markdown。为避免损害原稿，可先在 Inflow 外制作一个工作副本，但全部 UAT 使用这同一份主文档。

主文档应实际包含或在验收时临时加入：

- 标题、段落、粗体、斜体、删除线和引用；
- 有序列表、无序列表、任务列表、行内代码、代码块、表格；
- 一个 flowchart 和一个 stateDiagram-v2；
- 一张 PNG、一张 JPEG；
- 指向另一个本地 Markdown、PNG/JPEG 和 PDF 的相对链接。

允许另备一个被链接的 Markdown 和一个 PDF 作为链接目标；它们不是第二份主验收文档。

另备一篇比主文档明显更大的 Markdown 只做性能烟测。它不扩大语法与功能范围，也不使用固定文件大小阈值。

## 3. 当前 UAT

### UAT-PERSONAL-01 打开、编辑、手动保存与关闭

**操作：**

1. 打开真实主文档，加入一个容易辨认的验收标记；
2. 执行撤销、重做和手动保存，关闭后重新打开；
3. 文档含相对链接和图片时另存到其他目录，查看提示并检查资源与引用；
4. 再次修改并关闭，分别走“取消”“不保存”和“保存”；
5. 让目标暂时不可写，执行一次手动保存，再恢复可写并保存。

**通过结果：**

- 打开的是所选 UTF-8 Markdown 原文件；
- 撤销、重做和重新打开后的内容符合本人最后一次成功保存；
- 跨目录另存前提示相对引用可能失效；完成后不搬移资源，也不自动改写引用；
- “取消”回到当前编辑，“不保存”不写入该次变化，“保存”成功后再关闭；
- 保存失败不显示成功，当前编辑仍可继续或再次保存；
- 整个过程中没有自动保存。

### UAT-PERSONAL-02 简单外部变化提示

**操作：**

1. 主文档在 Inflow 中保持无本地修改，用另一款文本工具修改磁盘文件；
2. 在提示中选择重新加载；
3. 再让 Inflow 当前编辑和磁盘文件分别加入不同标记；
4. 执行手动保存，先取消覆盖，再次保存并明确确认覆盖。

**通过结果：**

- 外部变化出现简单提示，不静默替换当前编辑；
- 重新加载后显示磁盘当前内容；
- 双方都有变化时，保存前明确询问是否用当前内容覆盖磁盘；
- 取消覆盖后，两边各自内容仍在；
- 只有明确确认后才执行覆盖；
- 全程没有三版本比较、自动合并或未经确认的覆盖。

### UAT-PERSONAL-03 轻量单快照恢复

**操作：**

1. 主文档成功保存后加入一个未保存标记；
2. 强制结束 Inflow，再重新启动并打开恢复提示；
3. 选择“恢复为未命名文档”，检查磁盘原文件，再手动保存恢复内容；
4. 再产生一次未保存变化并异常结束，这次选择“放弃”。

**通过结果：**

- 每次只有一个最新恢复快照，没有历史列表或多版本比较；
- 恢复内容以未命名文档回到编辑区，不关联原路径，也不在用户保存前覆盖磁盘原文件；
- 手动保存后磁盘得到恢复内容；
- 明确放弃后，对应快照不再出现；
- 恢复不可用或被放弃都不阻止正常打开和手动保存。

### UAT-PERSONAL-04 源码、分栏、查找格式与两类 Mermaid

**操作：**

1. 在源码与分栏之间反复切换，临时隐藏并恢复编辑栏，再继续编辑同一段内容；
2. 由当前 H1–H6 生成大纲，依次点击标题回到对应源位置；
3. 用查找、上一个/下一个匹配、替换和全部替换处理真实内容，并验证全部替换可作为一次操作撤销；
4. 对真实内容使用粗体、斜体、行内代码、H1–H6、引用、无序/有序/任务列表和链接格式命令，并插入一次固定空表格模板；
5. 在源码中编辑删除线、围栏代码和图片内容，确认它们可以预览，但没有把它们当作格式命令；
6. 查看 CommonMark/GFM 基础内容、flowchart 和 stateDiagram-v2；
7. 加入含脚本、样式、事件、表单、嵌入或网络动作的原始 HTML 样例；
8. 临时破坏一个 Mermaid 块，再修复。

**通过结果：**

- 源码、分栏与临时隐藏编辑栏始终使用同一份当前内容，没有第二份正文；隐藏状态不形成独立持久模式；
- 大纲只来自当前 H1–H6，点击后回到相应源位置；不以本项承诺大纲重组、跨视图精确语义滚动或长期 slug/fragment；
- 查找和替换回到正确匹配，全部替换可一次撤销；
- 格式命令只包含当前明列项目且只改变本人操作的内容，结果可撤销；表格只插入固定空模板；
- 删除线、围栏代码和图片内容通过源码编辑与预览成立，图片新增仍走资源插入；
- CommonMark/GFM 基础结构和两类 Mermaid 可读；
- 原始 HTML 以可读源码或安全转义文本保留，不执行脚本、样式、事件、表单、嵌入、导航或网络动作；
- 单个 Mermaid 失败时保留可读源文，只降级该块，不阻止其他正文编辑和保存；
- 没有把公式、脚注、其他 Mermaid 或复杂格式矩阵冒充为当前能力。

### UAT-PERSONAL-05 图片与本地链接

**操作：**

1. 在已保存的主文档中通过文件选择、拖放和剪贴板分别加入图片，覆盖 PNG 与 JPEG，并让其中一个目标文件名预先存在；
2. 检查 assets 文件夹和 Markdown 引用，随后撤销一次图片插入；
3. 先打开被链接的 Markdown，再从主文档点击指向同一路径的链接；随后在目标文档中修改并手动保存；
4. 分别点击 PNG/JPEG 和 PDF 链接；打开后再用外部工具改变原目标；
5. 明确点击 http、https 链接，再点击 file、脚本和一个自定义 scheme 链接；
6. 关闭这些临时副本，并观察应用后续的周期清理行为。

**通过结果：**

- 新增图片位于主文档同目录的 assets 文件夹，正文使用相对引用；同名资源使用递增后缀且不覆盖既有文件；
- 文件选择、拖放和剪贴板均只接收静态 PNG/JPEG，不支持的图片类型不创建资源或引用；
- 撤销只移除 Markdown 引用，不删除已经写入 assets 的图片；
- 本地 Markdown 链接打开原文件，修改可手动保存回该原路径；同一路径只聚焦现有可编辑窗口，不创建第二份状态；
- PNG/JPEG 和 PDF 打开的是点击时内容的只读临时副本；
- 临时副本不自动写回、不随原目标变化；关闭后由 Inflow 管理并定期清理，不把关闭视图表示为立即删除；
- http/https 只在本人点击后交给默认浏览器；file、脚本和自定义 scheme 均被阻止，预览刷新不自动打开链接；
- 临时副本不进入最近文档；
- 目标缺失或无法读取时显示原因，不猜测打开；
- 在未保存文档中尝试添加图片时，必须先保存；取消保存不创建图片或引用。

### UAT-PERSONAL-06 基础浅色 PDF

**操作：**

1. 在主文档末尾加入一个当前内容标记；
2. 确认空白文档不能导出；再在主文档加入一张缺失图片并尝试导出，先取消，随后选择继续；
3. 在主文档加入 http、https、file、脚本和自定义 scheme 链接，导出到新的 PDF；
4. 检查文本、PNG/JPEG、缺图占位、flowchart、stateDiagram-v2、分页、浅色页面与链接动作；
5. 再导出到同名目标，先取消覆盖，再确认覆盖；
6. 模拟一次导出失败。

**通过结果：**

- 空白文档的导出入口保持禁用；
- 缺失图片先得到警告；选择继续后，PDF 对应位置有可见占位；
- PDF 包含导出时的当前标记，不使用旧内容，并且可完整打开、不显示本地绝对路径；
- 本阶段支持的文字、图片和两类 Mermaid 清楚可读，页面使用基础浅色样式；
- http/https 链接可点击；file、脚本和自定义 scheme 没有可执行动作；
- 已有目标在覆盖前得到简单确认，取消不会替换目标；
- 成功后可以打开或在 Finder 中显示结果；
- 失败时不显示成功，主文档和当前编辑仍可使用；
- 没有要求 HTML、深色主题、专业页面设置或公共分发级完整安全后验。

### UAT-PERSONAL-07 本地最小日志与无自动遥测

**操作：**

1. 触发一次可控的打开、保存或 PDF 失败；
2. 正常继续写作，关闭并重开一次；
3. 主动导出日志到本人选择的位置并打开检查；
4. 由本人使用 Inflow 之外的方式手工上传，或决定不上传。

**通过结果：**

- 未经主动导出，Inflow 不上传日志、使用数据或正文；
- 导出内容只覆盖当前会话与上一会话，只含时间、应用版本、操作类别和错误代码；
- 日志不含正文、文件名、完整路径、选区、剪贴板、链接、搜索词、账号、凭据或恢复内容；
- 导出位置由本人选择，Inflow 不自动打开上传渠道，也不保留隐藏导出副本；
- 日志失败不影响打开、编辑、手动保存或 PDF。

### UAT-PERSONAL-08 一篇真实文档端到端与基础烟测

**操作：**

1. 主要使用键盘，用同一篇真实主文档连续完成：

> 打开原文件 → 源码编辑 → 分栏检查 → 用大纲返回源位置 → 查找替换与基础格式命令 → 加入图片 → 手动保存 → 处理一次外部变化 → 恢复一次未保存快照 → 打开 Markdown 原件和 PNG/JPEG/PDF 临时副本 → 导出基础浅色 PDF → 带关闭确认退出 → 重新打开核对。

2. 在当前闭环中逐项确认焦点可见，修改、保存、外部变化、恢复、警告与失败状态不只靠颜色表达；
3. 触发一个可控的解析、资源、保存、恢复或导出异常，确认应用不崩溃且仍可继续编辑；
4. 打开一篇较大的烟测 Markdown，观察它是继续提供输入、查找、分栏与手动保存，还是明确降级非核心解析或安全拒绝；记录环境、明显停顿和失败，不计固定毫秒、不要求固定大小或 30 次重复。

**通过结果：**

- 整个旅程由产品负责人本人完成，不需要账号、插件、云服务或自动遥测；
- 主文档最后内容、分栏、图片引用、被打开的本地目标和 PDF 结果符合本人每一步的明确选择；
- 没有静默内容丢失、未确认覆盖、保存或导出失败却显示成功；
- 当前闭环的基础操作可用键盘到达，焦点清楚可见，重要状态含非颜色表达；
- 可控异常没有导致应用崩溃；较大文档可以继续编辑，或在无法可靠处理时明确降级/安全拒绝，且不损坏原文件、不虚报成功；验收记录包含环境、实际结果与本人观察；
- 本人认为该闭环已经足以进入真实日常使用，并记录“通过”；否则记录“退回”。

## 4. 判定规则

出现以下任一结果，对应 UAT 直接“退回”：

- 手动保存、关闭、重新加载、恢复或链接操作造成本人无法理解的内容损失；
- 外部变化在没有提示或确认时覆盖任一方内容；
- 恢复快照在本人确认保存前覆盖磁盘原文件；
- 源码与分栏出现不同正文；
- 本地 Markdown 链接没有打开原件，或 PNG/JPEG/PDF 临时副本能够写回原件；
- 空白文档仍可导出，缺图继续后没有占位，PDF 使用旧内容、无法打开、暴露绝对本地路径、允许 file/脚本/自定义 scheme 动作，或失败却显示成功；
- Inflow 自动发送日志、遥测或正文；
- 当前闭环无法由键盘基本到达、焦点不可见、重要状态只靠颜色、可控异常导致崩溃，或较大烟测文档既无法继续操作也没有安全拒绝且保护原文件；
- 任一必需步骤无法完成。

不影响内容与任务完成的轻微视觉问题可记录后由产品负责人判断是否退回。风险不能用其他项目的通过结果抵消。

## 5. 最小验收记录

每轮只需记录：

| 字段 | 内容 |
| --- | --- |
| 日期 | 实际验收日期 |
| 环境 | Mac 型号、macOS 版本 |
| 构建 | 应用构建或提交标识 |
| 主样本 | 本人真实文档的内部标识 |
| 烟测样本 | 较大 Markdown 的内部标识；不要求固定大小 |
| UAT 结果 | UAT-PERSONAL-01 至 08 的通过、退回或未执行 |
| 问题 | 影响、复现方式和复验结果 |
| 最终结论 | 产品负责人签署“个人首版通过”或“退回” |

不要求公共证据包、30 次运行统计、外部用户签字、签名公证产物或发布说明。

## 6. 个人首版完成条件

只有 UAT-PERSONAL-01 至 08 全部实际执行并通过，且产品负责人最终签署“个人首版通过”，才可认为内部验证完成。

该结论不表示：

- 产品已经公开发布；
- 存在 0.1 或任何公共版本号；
- 已通过 Developer ID、Apple 公证、ZIP/DMG、更新或 SHA-256 验收；
- 已满足公共分发级 PDF、保存/导出并发、完整恢复、安全、性能或辅助使用合同；
- 已承诺商业、公开支持或长期维护。

## 7. 公共预览前的独立验收决策

如果本人验证通过后决定面向外部用户，必须先创建新的产品决策与范围，再建立公共预览 UAT。至少重新决定：

- 目标用户、版本号、支持系统与设备；
- 安装、签名、公证、下载、完整性、更新、回退与撤回；
- 外部用户数据、反馈、日志、隐私和支持渠道；
- 公共分发级保存、恢复、PDF、安全、并发、性能、大文件与辅助使用标准；
- 免费、收费、许可、退款和维护承诺。

这些项目当前均不是个人首版 UAT，也不能因个人首版通过而自动标为通过。

## 8. 后续阶段验收继承

成长版、专业版和成熟版的下列专项 UAT 保留为长期产品方向。它们不参与个人首版判定；对应阶段进入实施或发布前，必须结合届时范围、公共发布决策和已批准规格重新确认。

后续阶段不得降低已经由个人首版证明的本地 Markdown 所有权、手动保存、明确外部变化、恢复不自动覆盖、视图同源和无自动遥测原则。

## 9. 成长版专项验收

### UAT-GROWTH-01 现有文件夹成为工作区

**步骤：** 使用附录 A 定义的基准工作区，完成打开、浏览文件树、搜索、编辑、保存和打开多个标签页；先关闭一个标签页，再通过附录 C 的整窗命令一次关闭工作区窗口并再次打开。

**通过结果：**

- 不要求导入、复制或重组原文件夹；
- 文件树与用户实际文件保持一致，未授权位置不被扫描；
- 同一文件从系统入口或工作区打开时仍是同一文档，不形成重复修改；
- 关闭标签页只影响对应文档视图；关闭整个窗口不需要逐个关闭标签页，未保存内容不会被静默放弃；
- 关闭工作区后，文件仍可由其他工具直接使用；
- 首次可浏览、搜索、变化可见和同时打开文档能力达到附录 A 的工作区规格。

### UAT-GROWTH-02 多文档搜索与导航

**步骤：** 在工作区中按文件名、正文和结构条件查找，打开多个结果，再使用前进、后退、快速打开和标签页切换。

**通过结果：**

- 每个结果都回到正确文件与语义位置；
- 文件变化后过期结果不冒充当前事实；
- 键盘可完成搜索、打开、切换与返回；
- 关闭或移动文件时，导航历史给出清楚降级而不跳到无关内容。

### UAT-GROWTH-03 即时渲染编辑

**步骤：** 在即时渲染编辑中修改标题、列表、任务、表格、链接、公式和图表，并反复切换到源码编辑。

**通过结果：**

- 当前结构的必要 Markdown 可查看，不产生私有富文本；
- 每次结构修改都可理解并完整撤销；
- 切换视图后内容、选区、语义位置与撤销边界连续；
- 不支持或有歧义的结构保留源文本，不猜测性重写。

### UAT-GROWTH-04 资源整理与本地版本时间线

**步骤：** 移动文档和资源、下载一项远程资源、重命名附件，再浏览和恢复本地版本时间线。

**通过结果：**

- 执行前展示受影响引用，确认后变化会使原确认失效；
- 资源操作与引用更新作为一个可理解的整体成功或退出；
- 恢复历史版本形成一次可撤销的当前编辑，不静默替换用户文件；
- 关闭本地版本时间线不关闭异常恢复保护。

### UAT-GROWTH-05 用户主动导出诊断包

**步骤：** 生成包含可用错误、性能和环境信息的诊断包，预览并删除一项，再保存到用户选择的位置；随后取消一次生成并模拟一项信息不可用。

**通过结果：**

- 只有用户主动发起才生成，逐项内容可见、可删减，只保存到用户选择位置；
- 文档正文、文件名、路径、选区、剪贴板、链接、搜索词、账号凭据和恢复内容始终不存在；
- Inflow 不自动发送、不打开外部发送渠道、不保留隐藏副本；
- 取消或部分信息不可用时不留下残缺包，也不影响核心写作。

### UAT-GROWTH-06 最近文档容量设置

**步骤：** 在已有记录超过新容量的情况下，将最近文档容量降低到附录 A 最小值，再提高容量并继续打开文件。

**通过结果：** 降低后最旧超限记录及其访问授权立即移除，提高容量时旧记录不会重新出现；之后只由新打开的文件按时间顺序补充空余名额，设置始终表示物理保留上限而非显示数量。

### UAT-GROWTH-07 写作辅助与长文档高效编辑

**步骤：** 在中文、英文和混合内容中分别使用括号与围栏辅助、缩进与列表自动延续、拼写检查和智能粘贴预览；再以多光标、行操作和大纲重组修改一篇长文档，并切换行号、字数/字符数、专注模式和打字机模式。覆盖输入法标记文本、只读内容、混合结构、取消智能粘贴和一次完整撤销。

**通过结果：**

- 辅助只作用于用户当前输入或明确选择的范围，不在输入法标记期间改写内容，也不把富文本或不可信结构静默写入 Markdown；
- 多光标由用户明确创建；行操作只执行整行上移、下移、复制、删除、缩进或反缩进；智能粘贴和大纲重组在执行前显示完整影响；所有成功修改可按一次可理解的文档操作撤销，歧义结构保持原文；
- 拼写、行号、统计、专注和打字机模式只改变提示或呈现，不改变源文本、保存结果与交付语义；
- 取消智能粘贴、关闭拼写/行号/统计，或退出专注和打字机模式后，基础输入、选择、撤销和保存仍连续可用。

成长版只有在以上场景及全部继承门槛同时通过后，才满足版本验收。

## 10. 专业版专项验收

### UAT-PRO-01 专业表达与交付

**步骤：** 使用附录 A 定义的专业表达样本、渲染配置、交付格式和专业交付模板，完成编辑、检查、预览与交付；所有初始选择均按附录 B 验证，不在本文重复默认值。

**必测矩阵：**

| 验收组 | 必须覆盖 |
| --- | --- |
| 公式与图表 | 附录 A 列出的全部增强公式环境与增强图表类型，以及各一项可定位失败样本 |
| 引用与参考文献 | 附录 A 列出的全部参考文献样式、缺失来源和重复引用键；Markdown 脚注作为独立基础内容验证，不当作参考文献样式 |
| 渲染配置 | 附录 A 列出的全部渲染配置；同一源文档分别进入预览、诊断和交付 |
| PDF 与打印 | 附录 A 列出的纸张、方向、页边距边界、页眉页脚和分页选项，并覆盖超宽与不可完整分页内容 |
| 专业导出变体 | 长图的全部格式与边界、全部网页变体、可移植文档包的正常结果、缺失资源和超出边界结果 |
| 专业交付模板 | 附录 A 列出的全部内置模板、从内置模板复制出的本地模板，以及模板含不再支持选项的降级结果 |

**通过结果：**

- 支持内容符合附录 A，缺失能力有可读降级；
- 文档健康中心能定位断链、资源、结构和表达问题；
- 每种渲染配置下，预览、诊断和交付物使用同一解释，没有无说明差异，也不改写 Markdown；
- 每种参考文献样式都只改变呈现与交付，缺失来源可定位；Markdown 脚注继续按自身语义呈现；
- 纸张、方向、边距、页眉页脚、分页、主题和专业导出变体均产生符合附录 A 的可复核结果；
- 专业交付模板的初始行为符合附录 B，应用前可见全部选项变化；应用、复制、重命名或删除模板不改变 Markdown 与已完成交付物。

### UAT-PRO-02 迁移与退出

**步骤：** 分别使用单个文件、处于附录 A 边界内的现有文件夹和标准 ZIP 迁移包完成预检、创建副本、迁移、查看报告和放弃副本；再逐项使用超出附录 A 各容量边界的来源，以及含嵌套压缩包、可执行内容和无法识别私有资料库的样本。

**通过结果：**

- 每项内容归入原样可用、结果等价、可读降级或不支持；
- 用户能在执行前理解来源、目标和变化；
- 单个文件、现有文件夹和标准 ZIP 分别使用附录 A 对应边界；文件夹按实际内容判断，不借用压缩包大小；
- 每项超出边界的来源都在创建目标前停止并指出可缩小范围的方式；不支持内容不被展开、运行或猜测转换；
- 来源或目标变化后重新预检，不使用过期确认；
- 来源保持不变，删除目标副本后仍可完整退出。

### UAT-PRO-03 精选能力中心

**步骤：** 从能力中心评估、启用、使用、撤权、停用和卸载外观、诊断及单次文本修改能力；核对附录 B 的全局更新偏好，为两个插件分别保留全局值和设置逐插件覆盖，再模拟边界不变更新、权限扩大更新与安全撤回；同时按附录 A 的样本与计算规则，在实际启用确认界面完成可选能力边界理解测试。

**通过结果：**

- 能力中心不出现公开排名、交易或第三方自由上架；
- 专业版能力中心不出现购买或付费流程；费用理解在成熟版有费用的能力中验收；
- 启用前能理解来源、用途、读取、修改、外部连接、停用和清理影响，理解正确率达到附录 A 的专业版门槛；
- 文本修改在应用前可查看，应用后可撤销；
- 停用、卸载或异常不影响本地保存、恢复和标准 Markdown 可读性；
- 更新偏好的全局值、逐插件覆盖与实际生效来源可见；只有边界不变更新可按偏好自动安装，权限扩大仍需确认；撤回检查周期与最近状态可见，设备收到有效清单后风险版本无条件停止。

### UAT-PRO-04 首批领域内容边界

**步骤：** 使用两个不同命名空间的块级指令或围栏内容，分别模拟提供者可用、停用、缺失、渲染失败和两个能力争用同一命名空间。

**通过结果：**

- 首批只接受有命名空间的块级表达，原始 Markdown 在能力缺失或失败时可读；
- 单块错误不影响其他正文、保存或交付；
- 同一命名空间有多个提供者时保持源文并让用户选择，不按安装顺序猜测；
- 内联学术语法、完整 LaTeX 工程和改变基础 Markdown 优先级不冒充首批能力。

专业版只有在以上场景及全部成长版继承门槛同时通过后，才满足版本验收。

## 11. 成熟版专项验收

### UAT-MATURE-01 结构洞察与演进

**步骤：** 在包含明确链接、断链、孤立文档、附录 H 来源元数据和多次本地版本变化的工作区中查看关系、来源、演进与质量趋势；新增、排序、删除并撤销一项来源信息，分别打开含既有未知字段、无效 YAML、重复来源 ID 与未知更高版本的样本；从推断向当前源文档的指定位置添加标准相对链接并撤销，再否定和恢复另一项错误推断，最后删除一部分历史基线并修改一个目标文件。

**通过结果：**

- 明确关系、用户声明、产品推断和未知状态能够区分，每项结果可回到实际文件与语义位置；
- 内容历史与外部服务状态分开呈现，不用外部状态替代本地保存事实；
- 文件变化后旧洞察标记为过期，历史基线缺失时不生成虚假趋势；
- 来源信息按附录 H 写入可见、版本化的 YAML，写入前可查看变化，确认后可撤销并随 Markdown 带走；既有未知字段保持不变，无效、重复或未知版本不被猜测性改写；推断形成明确关系时只添加用户预览的标准相对链接，可撤销并被其他 Markdown 工具读取；错误推断可查看证据、否定、隐藏和恢复；
- 未经用户确认的洞察结果不修改 Markdown；结构洞察不扫描工作区外内容，也不生成生产力分数或个人评价。

### UAT-MATURE-02 插件市场与治理

**步骤：** 在首个公开市场中搜索、比较并获取不同信任等级的免费插件，再模拟权限增加、弃维、下架、设备离线、手动/周期检查撤回清单，以及收到有效撤回清单后的状态。

**通过结果：**

- 排名与精选清楚区分，权限、数据和免费状态在安装前可理解；
- 市场中不存在付费插件、评价、Inflow 收款、订阅、退费或恢复购买入口；
- 权限或数据去向扩大时不会自动生效；
- 下架、弃维和已撤回状态清楚不同；
- 离线期间准确说明尚未获知新的撤回；设备收到防回滚的有效清单后，已撤回版本不能重新启用或通过降级绕过。

### UAT-MATURE-03 人工智能任务与费用

**步骤：** 只选择一段含普通文字、隐藏指令、工具调用要求、文件路径与权限升级要求的文本，分别使用本地/免费能力、能权威报价或预授权的付费提供方完成解释、改写与总结，并尝试使用不能约束最高费用的付费提供方；覆盖三项上限未设置、额度不足、取消和删除记录。

**通过结果：**

- 发送前只包含用户明确选择的文本，处理方、用途、保留与费用清楚；隐藏指令不能扩大上下文、调用工具、读取凭据或操作文件；
- 对收费能力的计费、停止计费、上限和取消理解正确率达到附录 A 的成熟版门槛；
- 结果与事实声明分开，只输出可复制或关闭的纯文本建议；正文、文件和外部服务均未被修改；
- 三项上限未全部设置时，符合准入的付费任务不能开始，界面不提供无上限选项；
- 所有窗口和符合准入的提供方共同受单次、每日和每月上限约束；不能权威报价、预授权或接受最大消费参数的提供方不显示“硬上限”，首版也不能由它们开始付费任务；
- 取消、失败、删除记录或停用能力不影响本地文档。

### UAT-MATURE-04 连接器冲突与退出

**步骤：** 连接一个外部服务，先取消一项尚未提交的发布，再提交另一项发布并在外部尚未确认时请求取消，然后从外部获取候选副本；分别测试目标已变化、断网、账号失效、失败、比较候选副本和断开账号。另在一次外部响应未知时断开账号并尝试删除连接设置、已完成记录和该未知结果记录。

**通过结果：**

- 本地保存与外部状态分开显示，外部失败不延迟本地保存；
- 发布完成只表示本次明列项目完成，不建立持续同步；候选副本不会替换本地 Markdown；
- 首版没有双向、自动移动、自动删除、共同基线合并或后台重试入口；
- 尚未提交的任务取消后直接移出待发布列表，不创建外部任务或保留外部任务记录；已提交任务只能显示“请求取消”，在外部服务明确确认前保持待核对状态，不冒充已取消；
- 断网、账号失效和服务停止时，本地内容保持完整；
- 断开立即停止新任务并撤销账号与内容访问；连接设置、已完成或已确认安全结束的记录可按规则删除，外部数据删除有单独路径；
- 待完成或外部副作用未知的记录不会因断开、卸载或删除设置而静默消失，在核对或到达经批准的安全终态前持续显示状态、保留原因和下一步。

### UAT-MATURE-05 生态退出后的核心独立

**步骤：** 对本次成熟版迭代实际纳入的市场插件、人工智能或连接器逐项撤销授权、停用并卸载，然后断网完成单篇写作与交付；尚未纳入的后续能力不参与本轮。

**通过结果：**

- 本地 Markdown、附件和已完成交付物不丢失；
- 缺失领域能力的内容仍以原文和可读说明呈现；
- 核心写作、保存、恢复、预览和交付不要求账号、网络或插件；
- 权限、费用和相关数据都有可检查的最终状态。

### UAT-MATURE-06 发布者与版本生命周期

**步骤：** 新发布者在开发者中心建立身份，分别提交公开资料与私密验证资料；创建一个免费插件版本，经历提交、审核反馈、修改、复审、通过和发布；再提交一次改变权限或数据范围的免费更新，随后把发布者主体转移给另一个已核对主体，最后分别演练主动下架单个插件与退出整个市场。

**通过结果：**

- 身份通过前不能公开发布，普通用户只看到必要公开资料，不看到私密验证资料；首个公开市场没有价格、购买、订阅、评价或恢复购买入口；
- 每次提交绑定明确版本、免费状态、权限、数据、兼容与退出影响，审核反馈可定位、可修正、可申请复审，未通过更新不改变已发布版本；
- 权限、数据或主体变化必须重新审核并在生效前通知受影响用户，不继承或扩大既有授权；
- 主体转移明确原主体、新主体、支持与数据责任，用户可查看影响并选择停用或卸载；
- 主动下架与退出计划覆盖支持期、用户通知和数据出口，不删除用户本地文档、附件或已完成交付物。

### UAT-MATURE-07 后续商业市场

本项属于成熟版后续商业市场，不阻断首个公开免费市场，也不属于当前阶段验收门槛。进入后续商业市场决策前必须先批准可选生态账号合同。

**步骤：** 让未获取插件的用户尝试评价，再让已获取并实际使用对应版本的用户提交、修改、删除、举报和申诉评价；分别购买一次性插件和订阅插件，明确开启后再关闭自动续费，演练付款失败、退费通过、退费未通过和恢复购买，并尝试恢复一个已撤回版本。

**通过结果：**

- 未验证使用者不能获得“已验证使用”标识；每位用户对同一插件只保留一条当前评价，修改、删除、举报和申诉状态清楚；
- 评价发布前提示排除文档正文、路径、凭据和他人个人信息，操纵评分、付费买评与报复性下架不改变自然排名或投诉处理；
- 购买前显示收费方、总价、税费、适用范围、期限、自动续费、取消和退费规则，购买不会自动安装、授权或运行插件；
- 自动续费只有明确开启后生效，关闭不缩短已付费期限；付款、退费与使用权状态分别可查，商业争议不影响本地文件；
- 恢复购买只恢复核对成功的使用权，不自动安装、授权、连接账号或恢复已撤回版本。

成熟版按迭代验收：每次只执行本次纳入能力的专项场景及全部继承门槛。首个公开市场必须通过 UAT-MATURE-01、02、05、06；首版人工智能与首版连接器分别增加 UAT-MATURE-03、04；UAT-MATURE-07 只在后续商业市场进入时成为门槛。任何后续迭代都不得用尚未纳入的商业、同步或工具调用场景阻断更早的完整闭环，也不得借分期削弱继承门槛。
