## 1. 0.1 公共预览版定义

0.1 公共预览版是 Inflow 的下一个对外里程碑，也是本文所称的“首发版”。它只承诺一个完整且可信的核心价值：

> 用户无需账号和网络，可以直接创建或打开自己的本地 Markdown，在源码编辑、实时预览和纯预览之间连续完成写作，安全保存与恢复，并把当前内容交付为 HTML 或 PDF。

首发不是完整产品架构的缩小展示，也不是从每个未来方向挑选少量功能。它必须把“可信单篇写作”做完整，把工作区、即时渲染编辑和专业生态留给后续版本。“预览版”只表示尚未冻结正式 1.0 的长期兼容、性能、可访问性和发布维护承诺，不豁免本版明列的核心安全、隐私、PDF 和分发门槛。

当前文档及其依赖文档均为“待评审”，因此当前工作区只能称为 **0.1 公共预览候选实现**，不能称为已批准产品基线、已发布 0.1、正式 1.0 或已经完成签名公证的分发版本。只有在文档批准、0.1 UAT 与候选证据闭环、Developer ID 签名、Apple 公证和官方直接分发验收都完成后，才可对外使用“0.1 公共预览版”。

## 2. 首发目标用户

首发优先服务：

- 需要创建、接手和长期保存单篇 Markdown 的写作者；
- 需要同时看见源码与阅读效果的技术、产品和专业内容作者；
- 在本地处理未公开内容、希望完全离线写作的用户；
- 需要把当前 Markdown 稳定交付为 HTML 或 PDF 的用户。

首发不以多人团队、跨文档知识管理或第三方能力重度用户为主要对象。

## 3. 首发核心场景

| 场景 | 用户起点 | 用户终点 | 必须成立的价值 |
| --- | --- | --- | --- |
| 新建并交付 | 没有现有文件 | 获得本地 Markdown 与可分享交付物 | 从零开始到交付全程离线可用 |
| 接手并修改 | 已有 Markdown 与本地资源 | 原文件安全更新并可重新打开 | 不导入、不改成专有格式、不破坏原内容 |
| 异常后恢复 | 存在未保存内容或意外中断 | 用户明确选择继续使用哪份内容 | 已保存文件不受损，未保存内容有处置路径 |
| 外部变化处理 | 打开的文件被其他工具改变 | 用户理解差异并作出选择 | 检测到双方修改时暂停写入，不覆盖磁盘版本 |
| 长文档检查 | 多层标题与常见复杂结构 | 定位问题并完成阅读检查 | 源码、结构和呈现可以相互定位 |
| 当前版本交付 | 文档仍在编辑且目标可能已存在 | HTML/PDF 对应用户最终确认的内容 | 不导出旧内容，检测到目标变化时不沿用旧覆盖同意 |

## 4. 纳入范围

### 4.1 文件与文档

首发必须支持：

- 新建空白 Markdown，并在选择保存位置前持续保护未保存内容；
- 打开用户选择的 `.md` 与 `.markdown` 文件；
- 手动保存、另存为、保存副本和关闭前处理未保存修改；
- 保存与另存为在开始前复核本次内容和目标，系统报告完成后再复核目标；不一致时不显示已保存，并保留当前编辑的比较与保存副本退路；
- 对已有、可写文件提供符合用户预期的自动保存；
- 显示可理解的修改、保存、失败和只读状态；
- 重新打开最近文档；
- 处理文件不存在、不可写、权限变化和保存目标已被占用；
- 检测到外部内容变化且双方都有修改时，暂停写入，只提供比较、保存副本和重新载入三条安全路径；首发不提供覆盖磁盘版本；
- 在异常中断后发现可恢复内容，说明它与已保存文件的关系，并允许恢复、另存或放弃；
- 另存到新位置前，提示相对链接和本地图片可能受到的影响。

### 4.2 写作与编辑

首发必须支持：

- 源码编辑；
- 源码与阅读结果并列的实时预览；
- 纯预览；
- 三种视图之间清楚切换，并保留当前语义位置和焦点预期；
- 撤销、重做、选择、复制、剪切、粘贴和全选；
- 查找、上一个/下一个匹配、替换和全部替换；
- 标题、强调、删除线、引用、无序/有序/任务列表、分隔线；
- 行内代码、代码块、链接、图片、表格和脚注的基础编辑；
- 常用格式入口和平台惯用快捷方式；
- 中文、英文与混合输入；
- 当前文档内稳定、可撤销的格式与插入命令；各选择状态行为由[编辑与写作](../04-功能设计/02-编辑与写作.md)统一定义。

首发不包含即时渲染编辑；用户不会在隐藏大部分 Markdown 标记的可编辑阅读界面中直接改写内容。

### 4.3 阅读与基础表达

首发必须正确呈现：

- 段落、标题、强调、删除线、引用和分隔线；
- 有序、无序和任务列表；
- 行内代码、代码块和基础代码配色；
- 表格、链接、脚注与本地图片；
- Inflow Markdown 1.0、首发公式子集和 Mermaid 四类基础语法子集的结果；精确方言与定位合同见[附录 F](../07-产品附录/附录F-Markdown方言与定位规则.md)，图表产品边界见附录 A；
- 中文、英文和混合排版；
- 浅色、深色和跟随系统的内置外观。

呈现等待或个别复杂内容失败时，用户仍能继续编辑，并能看见清楚的降级说明。

### 4.4 结构与导航

首发必须支持：

- 从当前文档标题生成大纲；
- 点击大纲回到对应源位置；
- 在阅读结果中点击标题回到对应源位置；
- 分栏滚动同步，并允许用户关闭；
- 查找结果显示匹配数量和当前位置；
- 识别缺失本地图片和无法打开的链接；
- 对本地文件链接提供清楚、安全的打开或显示位置选择。

首发不包含文件夹侧栏、工作区、层级文件树、多文档标签、文件夹内编辑管理、快速打开索引、跨文档全文搜索、反向链接或文档关系图。用户通过系统文件选择、Finder、“打开最近”和拖放接手单篇文件。

### 4.5 图片与链接

首发必须支持：

- 通过文件选择或拖放添加静态 PNG/JPEG；从剪贴板粘贴 PNG/JPEG/TIFF，其中 TIFF 在用户确认后转换为 PNG；
- 对粘贴、新建或选择复制的图片，在文档目录或用户选择的相对资源目录中保存，并插入可理解的相对引用；
- 对用户明确选择保留原位置的既有外部图片，不复制或移动原文件；可以形成相对路径时使用相对引用，否则在说明可移植性影响后保留绝对引用；
- 允许为两类图片引用维护替代文本；
- 预览本地图片并清楚标记缺失资源；
- 区分网页链接、文档内标题和本地文件链接；
- 对外部网页链接在离开应用前遵循用户明确操作；
- 文档另存到其他目录前说明相对资源风险。

首发保存、预览与导出只生成或包含静态 PNG/JPEG；完整来源矩阵与失败行为只见附录 A。

首发不包含图床上传、图片在线搜索、复杂素材库或批量图片管理。

### 4.6 HTML 与 PDF 交付

首发必须支持：

- 从当前精确内容导出单篇 HTML；
- 生成可离线打开、包含必要样式的 HTML；
- 从当前精确内容导出单篇 PDF；
- PDF 导出是 0.1 P0，不得改为可选功能、已知限制或发布后补齐项；
- 在交付前说明缺失图片、异常链接和可能影响结果的问题；
- 选择目标位置，并在覆盖已有交付物前确认；
- 若在最终替换前检测到目标变化，暂停交付并重新要求用户决定；
- 目标复核不代表已排除其他应用在复核与最终替换之间的竞争；真实目标条件替换与非协作写入者并发证据是正式 1.0 候选的 `OPEN` 阻断；
- 交付完成后显示结果位置，并允许打开或显示该交付物；
- 不在交付物中无说明地暴露本地绝对路径或私人编辑信息；
- 对最终 PDF 执行完整安全后验，证明不含脚本、嵌入附件、可启动外部程序或访问网络的动作、本地绝对路径和不必要的隐私元数据，并验证文件结构可完整打开；
- 安全后验发现任一禁止项、结构不完整或无法完成检查时，必须判定导出失败，不替换最终目标、不报告成功，且阻止 0.1 发布。

首发不包含批量导出、发布网站、上传平台、自定义脚本模板或多人审批。

### 4.7 离线、隐私与核心独立性

首发必须满足：

- 首次启动、创建、打开、编辑、保存、恢复、阅读和交付均不需要账号；
- 完全断网时，所有首发核心场景保持可用；
- 不因推荐、统计、内容分析或在线服务默认发送正文；
- 用户能清楚理解打开网页链接等主动联网行为；
- 不记录或发送匿名产品使用数据，不依赖遥测、统计接收端或后台网络服务；
- 未安装或未启用任何可选能力时，产品体验完整；
- 错误提示和交付物不无意显示完整私人内容或本地路径。

用户主动导出本地诊断包属于成长版后续能力：导出前可预览和删减，产品只保存到用户选择的位置，由用户决定是否以及如何发送；它不反向成为首发依赖。

### 4.8 设置与可访问性基本盘

首发设置界面只提供以下可配置项，精确选项和初始值只见[附录 B](../07-产品附录/附录B-默认设置.md)：

- 自动保存；
- 编辑器字号；
- 预览正文宽度；
- 外观；
- 新窗口分栏比例；
- Markdown 语法高亮、编辑器到预览滚动同步、点击预览标题定位源文本三个独立开关。

新建未命名文档、打开已有文档和恢复窗口的视图起点采用附录 B 的三类上下文矩阵，本文不重复默认值。除此之外，首发必须提供：

- 最近文档与打开方式的固定、可理解行为，但不将其作为首发设置项；
- 平台常见菜单、快捷方式和窗口行为；
- 仅用键盘完成新建、打开、编辑、查找、保存、切换方式和交付；
- 清楚的键盘焦点与辅助阅读名称；
- 放大字号、高对比度、减少动态效果后的可用性；
- 状态和错误不只依赖颜色表达。

## 5. 明确排除范围

以下能力不属于首发承诺：

| 排除项 | 计划去向 | 首发替代体验 |
| --- | --- | --- |
| 文件夹侧栏、完整文件夹工作区、层级文件树和多文档标签 | 成长版 | 通过系统文件入口、Finder、拖放和最近文档处理单篇文件 |
| 跨文档全文搜索、反向链接和关系图 | 成长版及成熟版 | 当前文档查找与大纲 |
| 即时渲染编辑 | 成长版 | 源码编辑、实时预览和纯预览三种视图 |
| 本地版本时间线 | 成长版 | 当前文件保存与异常恢复 |
| 任意 CSS、脚本和字体导入 | 正式例外，不进入产品计划 | 首发使用内置标准主题；后续只评审受控视觉参数和主题包 |
| 插件、领域能力包和市场 | 专业版至成熟版 | 首发内置常见 Markdown 表达 |
| 云同步、代码托管与其他外部连接 | 成熟版 | 直接使用本地文件或用户现有同步文件夹 |
| 智能写作与人工智能 | 成熟版 | 人工编辑、查找替换和结构检查 |
| 批量导出、网站发布、图床上传 | 不属于首发，是否进入后续另行评审 | 单篇 HTML/PDF 交付 |
| 多人实时协作、评论审批 | 非核心方向 | 通过交付物与现有协作工具流转 |
| 移动端、命令行与自动化平台 | 非首发产品范围 | 原生 macOS 单篇写作体验 |
| 匿名遥测与后台使用数据发送 | 不进入首发；未来若重提需独立决策 | 成长版提供用户主动导出的本地诊断包 |

排除项不应在首发界面中以不可用入口、诱导注册或“即将推出”占用核心注意力。

## 6. 首发体验基线

### 首次使用

- 用户启动后直接得到可编辑的未命名 Markdown，不先弹出 Finder 文件选择器；首次保存时再选择文件名与位置；
- 新建未命名文档、打开已有文档与恢复窗口按[附录 B](../07-产品附录/附录B-默认设置.md)的三类上下文矩阵确定视图状态；
- 打开单个文件和最近文档从 macOS 顶部“文件”菜单进入，不在编辑区复制文件操作按钮；
- 不强制登录、选择套餐、连接云端或完成冗长引导；
- 空白状态解释 Markdown 文件归用户所有，并提供清晰下一步。

### 日常使用

- 高频操作可以通过菜单和快捷方式发现；
- 正常保存保持安静，异常状态及时且明确；
- 写作区域优先，不展示推荐内容、市场入口或无关动态；
- 关闭并重新打开后，恢复合理的窗口和写作方式。

### 风险情境

- 不用单一含混提示同时表示本地保存、恢复保护或其他状态；
- 用户作出的保存副本、重新载入或放弃决定只适用于当时看见的内容；
- 无法确认目标结果时，不把本次操作表示为成功；保留当前修改，重新检查目标并提供保存副本退路，不虚构目标仍是旧内容；
- 任何错误都提供可继续写作、另存或取回内容的明确路径。

## 7. 范围完整性检查

首发范围评审必须回答“是”：

1. 核心用户能否不借助后续版本完成一篇真实文档？
2. 新建文件和已有文件是否都有完整路径？
3. 正常保存、保存失败、外部变化和异常恢复是否都有明确结果？
4. 源码编辑、实时预览和纯预览是否围绕同一当前内容？
5. 基础结构、本地图片、大纲和链接是否足以完成常见专业文档？
6. HTML/PDF 是否来自用户当前确认的内容？
7. 离线、键盘和基本辅助使用是否覆盖同一核心闭环？
8. 所有排除项是否有清楚边界，而不是隐藏依赖？

任一答案为“否”，首发范围仍未闭环。

## 8. 范围变更规则

### 新增范围

新增项必须证明：

- 它解决首发核心场景的阻断问题；
- 现有范围无法提供安全替代；
- 不会以牺牲文件信任、连续性或交付确定性换取展示价值；
- 同时补充对应的产品验收标准。

### 移出范围

移出项必须证明：

- 核心用户仍能独立完成端到端任务；
- 有清楚、不误导的替代路径；
- 不会把风险留给用户或假装由后续版本解决；
- 同步更新场景、路线图和验收标准。

任何范围变更都应将本文状态恢复为“待评审”，经产品负责人批准后才成为新基线。

## 9. 0.1 公共预览版完成条件

0.1 公共预览版可进入对外发布决策的前提：

- “愿景—场景—功能—首发范围—默认值—验收”最小产品链及本轮关联决策、变更均已批准；
- 本文所有纳入项都有完整、连贯、可理解的用户体验；
- 所有核心场景通过[产品验收标准](./03-产品验收标准.md)；
- 不存在静默内容损失、静默覆盖、错误成功状态或旧内容交付；
- 恢复保护的加密、容量、备份排除、密钥失效隔离、降级不阻止保存和全部清除合同已通过 0.1 候选验收；候选记录明确这不等于完整真实崩溃恢复已经闭环；
- 本地 Markdown、图片和 PDF 链接的 0.1 安全路径通过真实替换目标验收，不在检查后按旧路径直接打开已替换内容；
- 最终 PDF 通过完整安全后验及内容、页面背景和隐私负例验收；未通过时不得发布 0.1；
- 保存/另存与导出目标的最终条件替换所有权、非协作写入者的完整并发证据、硬链接别名单一会话，以及强制退出、恢复交接中再次崩溃、密钥受限与系统恢复关系的完整真实证据，仍为正式 1.0 候选阻断；0.1 只能按文档中更窄的前后复核、核心恢复保护、失败不报成功和安全退路承诺对外说明；
- 排除项没有成为核心场景的隐性依赖；
- 已知限制以用户能理解的方式说明，并有安全退路；
- 候选产物完成 Developer ID 签名、Apple 公证、ticket 装订与官方直接分发验收；
- 产品负责人确认范围、用户结果和发布说明一致。访谈数量、迁移样本数、研究轮次和价格研究不列为 0.1 或正式 1.0 的发布前置条件。

本文处于“待评审”不表示上述条件已经通过。

## 10. 0.1 分发与商业边界

- 0.1 公共预览版只通过 Inflow 官方直接渠道提供 Developer ID 签名、Apple 公证并装订 ticket 的 ZIP；DMG 容器和 Mac App Store 不属于首发渠道。
- 首发只提供用户主动执行的“检查更新”，不在后台下载或安装更新；离线时不影响任何核心任务。
- 0.1 公共预览版免费使用，不要求账号、许可证激活、试用倒计时、付款方式或周期联网。
- 当前不定义首发价格、退款、设备迁移或付费更新权益。任何收费版本必须以新的产品决策、商业合同和用户通知进入评审，不能把 0.1 使用记录自动转为付费承诺。价格研究只影响未来收费决策，不阻断 0.1 或正式 1.0 的产品质量批准。
- 直接分发渠道只定义用户获得、安装和检查更新的产品合同；签名、公证与候选证据是否有效仍需在每个发布候选中独立验证。
