## 1. 当前里程碑

个人首版只服务一位用户：**产品负责人本人**。它用于回答一个问题：

> 我能否从普通启动、Finder 或应用内命令进入，用独立未命名文档或自己的真实文件夹项目开始写作，在项目树中安全新建 Markdown，沿相对链接与图片完成即时渲染写作、源码或分栏核对、手动保存、外部变化与恢复处理，并导出基础浅色 PDF？

个人首版不是 0.1 公共预览版，不公开分发，不承诺公共版本号、安装包、更新、商业、公开支持或长期兼容。本人验收通过后，是否进入公共预览必须另行决策。

## 2. 验收用户与材料

- 唯一验收用户：产品负责人本人；
- 唯一主样本：本人实际使用并会继续维护的一个普通文件夹项目，不使用只为演示制作的理想样例；
- 项目至少包含两份位于不同目录的 UTF-8 Markdown、PNG、JPEG、PDF、一个默认隐藏项，以及能覆盖 `./`、`../` 和符号链接边界的相对路径；
- 主 Markdown 应包含常见文字结构、两类 Mermaid、项目内相对图片，以及指向另一份 Markdown、PNG/JPEG 和 PDF 的相对链接；
- 项目中另备一篇比主 Markdown 明显更大的文档做一次性能烟测，不要求固定大小；
- 验收环境：当前实际开发与使用的 Mac；本阶段不外推到全部 Apple Silicon 设备或全部受支持系统；
- 验收方式：本人按照[产品验收标准](./03-产品验收标准.md)完成真实操作并记录“通过”或“退回”。

## 3. 个人首版最小闭环

### 3.1 文档入口、新建与轻量文件夹项目

个人首版必须支持：

- Inflow 普通启动且没有收到外部打开目标时，不显示启动页，直接在编辑区创建一份可编辑的未命名空白文档；该文档在首次保存成功前不创建或写入用户文件，应用私有恢复快照仍按轻量恢复规则处理；
- “文件”菜单中的新建命令和 Command+N 始终创建一份独立未命名文档；即使当前位于项目窗口，Command+N 也不在项目树中创建文件；
- 未命名文档可立即编辑；用户首次执行“文件”菜单中的保存或 Command+S 时选择名称与位置，取消选择不创建或写入用户文件、不绑定用户路径且保留当前内容；保存成功后文档才绑定该路径，后续仍由用户手动保存；
- 应用内可打开单个或一次选择多个 UTF-8 `.md`、`.markdown` 原文件，也可选择一个普通文件夹作为项目打开；一次打开多个 Markdown 时，每个目标分别在自己的单文件窗口打开，已经打开的目标改为聚焦既有窗口；
- Inflow 注册为 `.md`、`.markdown` 的可选编辑应用，使用户可在 Finder 使用“打开方式”打开，也可由用户通过 macOS 把 Inflow 设为这些类型的默认应用后双击打开；Inflow 不主动更改、抢占或反复提示更改系统默认应用；
- 用户可把一个或多个 `.md`/`.markdown`，或一个文件夹，拖到 Dock 中或 Finder 中的 Inflow 应用图标；Markdown 沿用打开文件行为，文件夹沿用打开项目行为；多文件夹或文件与文件夹混合拖放不在个人首版承诺中；
- 外部文件或文件夹请求无论在 Inflow 冷启动还是已运行时到达，都只处理收到的目标；冷启动不额外创建未命名空白文档。应用先对目标规范化并与已打开文件或项目去重：重复目标只聚焦既有窗口，不消耗可复用空白窗口；最多一份未修改的未命名空白窗口可承接第一个尚未打开的目标，其余目标各自新建窗口；
- 空白未命名窗口已经输入或有其他修改时必须保留草稿，并在新窗口打开尚未打开的目标；同一规范文件路径或同一规范项目目录不创建第二份编辑状态或项目窗口，硬链接别名去重仍不属于个人首版；
- 用户选择一个普通文件夹后直接把它作为项目打开，不导入、不复制、不重组原内容，也不创建 Inflow 私有项目文件；
- 左侧目录树递归展示项目中的普通文件夹和文件；以点号开头或被系统标记为隐藏的项目项默认不显示；
- 项目内容在 Inflow 外发生新增、删除或改名后，由用户执行手动刷新重新读取目录树；个人首版不承诺实时监听整棵目录树；
- 项目树提供“新建 Markdown 文件…”按钮和右键菜单；选中目录时在该目录中创建，选中文件时在其父目录中创建，没有选择时在项目根目录创建；
- 新建名称为空、以点号开头、为 `.` 或 `..`、包含路径分隔符、带 `.md`/`.markdown` 之外的显式扩展名或不符合文件系统要求时拒绝；名称没有扩展名时自动补 `.md`，显式 `.md` 与 `.markdown` 保持不变；
- 创建前对目标目录和目标文件重新做路径规范化与符号链接解析；结果越出项目根目录、同名文件或目录已经存在时拒绝，不读取项目外内容，也不覆盖、截断或改写既有文件或目录；
- 当前项目文档有未保存修改时，在创建并切换到新文件前提供“保存”“不保存”“取消”：保存成功后继续，不保存则放弃当前未保存修改后继续，取消或保存失败均不创建文件并留在当前文档；
- 名称确认、边界校验和必要的当前文档处理完成后，执行时再确认目标目录存在、可写且仍位于项目根目录内，再立即以不覆盖方式在磁盘创建空 Markdown 文件，使它成为项目当前文档并即时更新目录树，无需手动刷新；之后写入的新正文仍须手动保存；
- 执行时目标目录消失或无权限、或空文件在落盘前创建失败时，不添加目录树节点、不切换当前文档，并明确说明原因；
- 空文件已经成功落盘、但随后无法打开或绑定为当前文档时，目录树仍保留并显示该真实空文件，明确提示“文件已创建但无法打开”及原因，当前文档保持不变；Inflow 不静默删除文件，也不把它虚报为未创建；
- 项目内最多保留一个当前编辑文档，不提供标签页；项目刚打开或没有 Markdown 时可以没有当前文档，选择 .md 或 .markdown 后才进入编辑；
- 当前文档有未保存修改时，切换前提供“保存”“不保存”“取消”：保存成功后切换，不保存则放弃该次未保存修改后切换，取消则留在当前文档；保存失败时不切换；
- 目标规范路径已经在另一个 Inflow 窗口中编辑时，只聚焦该现有窗口，不改变项目当前文档或创建第二份编辑状态；
- 打开用户选择的 UTF-8 .md 或 .markdown 原文件；
- 编辑源文本，撤销与重做；
- 由用户主动执行手动保存；
- 保存成功后，重新打开得到最后一次成功保存的内容；
- 保存失败时不显示成功，并保留当前编辑供再次保存；
- 另存到其他目录前，如果文档含相对链接或图片引用，提示引用可能失效；个人首版不搬移资源或改写引用；
- 项目文档另存为到项目根目录外并成功后，当前窗口结束项目模式并作为绑定新路径的单文件窗口继续编辑；原项目及旧文件保持不变；
- 关闭含未保存修改的窗口时，提供“保存”“不保存”“取消”；
- 未修改文档可以直接关闭。

Finder、“打开方式”、用户主动设置默认应用和拖到 Inflow 应用图标属于当前入口；macOS 可能附带的“打开最近”不计为 Inflow 管理的最近文档能力。本阶段不承诺自动保存、Inflow 管理的最近项目或最近文档、硬链接别名去重、精确大文件分级、标签页、项目搜索、快速打开、项目内重命名/移动/删除或导航历史。

### 3.2 外部变化

文件在 Inflow 外被修改时：

- Inflow 显示简单外部变化提示，不静默替换当前编辑；
- 用户可选择重新加载磁盘内容，或暂不处理并继续查看当前编辑；
- 当前编辑也有未保存修改时，手动保存前必须再次明确询问是否用当前内容覆盖磁盘；
- 用户取消覆盖后，当前编辑与磁盘文件都保持各自现状；
- 用户明确确认覆盖后，才用当前内容执行手动保存；
- 不提供三版本比较、自动合并或完整并发写入保证。

### 3.3 轻量单快照恢复

- Inflow 为每份文档最多保留一个应用私有的最新本地恢复快照；
- 新快照替换旧快照，不形成恢复历史或版本时间线；
- 异常退出后再次打开时，用户可选择“恢复为未命名文档”或“放弃”；
- 恢复内容以未命名文档回到编辑区，不自动关联或覆盖已保存的 Markdown；用户仍需手动保存；
- 成功保存或明确放弃后，清除对应快照；
- 快照不可用时给出说明，但不阻止正常打开与手动保存。

完整恢复中心、多快照比较、重复崩溃、密钥受限、系统恢复关系和完整真机异常矩阵不属于个人首版。

### 3.4 三视图与即时渲染编辑

- 提供源码编辑；
- 提供源码与预览并列的分栏模式；
- 提供可直接写作的即时渲染编辑视图；个人首版只承诺本文列出的基础范围，不把它实现为独立富文本文件或第二份正文；
- 源码编辑、实时预览（分栏）和即时渲染编辑共享同一 Markdown 缓冲、修改状态、保存路径和撤销/重做历史；切换视图时回到同一语义块，不承诺逐像素或逐字符位置完全一致；
- 段落、H1–H6 标题、粗体、斜体、删除线、引用、有序/无序/任务列表、行内代码和链接文字可在即时渲染编辑中直接编辑；
- 表格、围栏代码、Mermaid、图片目标与属性、原始 HTML、复杂嵌套以及解析有歧义或尚未支持的结构，在当前位置显示局部 Markdown 源码供编辑；退出局部源码后能解析则重新渲染，不能解析则保留源码与当前输入，不猜测性改写或丢弃；
- 中文输入法的标记文本在组合完成前不被提前提交、重排或套用格式；
- 即时渲染编辑中普通点击链接用于放置光标或选择文字，Command+点击才执行链接打开；
- 文本、RTF 与 HTML 粘贴只写入纯文本；剪贴板中的 PNG/JPEG 位图载荷按第 3.6 节的图片插入流程处理；
- 由当前 H1–H6 生成文档大纲，点击标题可返回对应源位置；
- 提供选择、复制、剪切、粘贴、全选、撤销与重做；
- 保留当前文档的查找、上一个/下一个匹配、替换与全部替换；
- 格式命令只包括粗体、斜体、行内代码、H1–H6 标题、引用、无序列表、有序列表、任务列表和链接；
- 表格只提供插入固定空模板，不承诺结构化表格编辑；
- 删除线、围栏代码和图片内容可在源码中编辑并在预览中查看；图片新增使用第 3.6 节的资源插入路径，不属于格式命令；
- 有选择内容时，格式命令只作用于选择内容；没有选择内容时，插入可继续输入的基础语法，不猜测复杂结构。

个人首版不包含独立持久的纯预览模式、完整 Typora 对等、复杂表格等完整结构化即时编辑、大纲重组、跨视图逐像素定位、长期 slug/fragment 合同、多光标或完整选择状态矩阵。

### 3.5 Markdown 与 Mermaid

个人首版呈现以下内容：

- CommonMark 基础：段落、标题、强调、粗体、引用、有序/无序列表、行内代码、代码块、链接和图片；
- GFM 基础：删除线、任务列表和表格；
- Mermaid：flowchart 与 stateDiagram-v2。

某个 Mermaid 块失败时，只降级该块并保留可读源文，不阻止其余正文编辑与保存。

原始 HTML 只以可读源码或安全转义文本呈现；脚本、样式、事件、表单、嵌入、导航和网络动作均不执行。

公式、脚注、其他 Mermaid 图形、原始 HTML 的完整兼容和复杂格式组合不属于个人首版。

### 3.6 图片

- 只有文档已经成功保存并拥有目录后，才能新增图片；
- 未保存文档首次添加图片时，先要求保存文档；用户取消保存则不创建资源文件或引用；
- 支持从文件选择、拖放或剪贴板添加静态 PNG/JPEG；
- 新增图片复制到文档同目录的 assets 文件夹，并插入相对 Markdown 引用；
- 同名文件使用递增数字后缀，不覆盖既有文件；
- 撤销图片插入只移除 Markdown 引用，不删除已经写入 `assets` 的图片文件；
- 预览缺失图片时显示清楚占位，不影响正文编辑和手动保存。
- 项目内既有相对图片以当前 Markdown 所在目录为基准解析，并在不越出项目根目录时直接呈现；它与点击图片文件链接后打开只读临时副本是两种不同动作。

拖放目标不复用同一种语义：拖到 Dock/Finder 中的 Inflow 应用图标按第 3.1 节打开 Markdown 或项目；拖入编辑区的 PNG/JPEG 仍表示向当前文档插入图片；项目树不接收外部拖入来复制、移动或新建文件。Markdown 或文件夹不会在编辑区被当作正文或图片插入，PNG/JPEG 也不会因为拖入编辑区而被当作项目打开。

TIFF 转换、远程图片、图床、资源管家、批量整理和删除孤立资源不属于个人首版。

### 3.7 本地链接

项目内相对路径以当前 Markdown 所在目录为基准；Inflow 先消解 `.`、`..`，再解析符号链接，并以项目根目录的规范位置为边界。规范化或解析符号链接后的目标一旦越出项目根目录即阻止，不读取或展示项目外内容。

用户在实时预览（分栏）明确打开链接，或在即时渲染编辑中使用 Command+点击时，Inflow 在打开前重新读取当前目标；即时渲染编辑中的普通点击只用于编辑：

- 项目内 .md、.markdown：通常切换为当前编辑文档，作为可编辑且可手动保存回原路径的文档；若目标已经在另一个 Inflow 窗口中编辑，则只聚焦该窗口且项目当前文档不变；
- 切换前沿用第 3.1 节的“保存”“不保存”“取消”处理；同一规范路径不创建第二份可编辑状态；跨文档标题 fragment 只按当前解析结果尝试定位，失败仍保持目标文档打开；
- .png、.jpg、.jpeg、.pdf：打开执行链接操作时内容的文件系统不可写临时副本；
- 只读临时副本不关联源文件、不自动写回、不进入最近文档；外部应用只能另存为到用户另选位置，其生命周期由 Inflow 管理并定期清理，关闭视图不等于立即删除副本；
- 原目标随后变化时，已经打开的临时副本不跟随变化；
- 用户在实时预览（分栏）明确打开或在即时渲染编辑中 Command+点击 http 或 https 链接时交给默认浏览器；预览刷新不会自动打开，file、脚本和其他自定义 scheme 一律阻止；
- 目标缺失、类型不支持或无法读取时，显示原因，不猜测打开。

个人首版不提供项目外相对文件访问、本地链接三版本比较、跨项目身份归并或对所有文件类型的内置预览。

### 3.8 基础浅色 PDF

- 从用户发起导出时的当前编辑内容导出单篇 PDF；
- 使用内置浅色页面、基础排版和固定默认布局；
- 支持本阶段的文字结构、本地 PNG/JPEG，以及 flowchart 和 stateDiagram-v2；
- 空白文档不允许导出，导出入口保持禁用；
- 存在缺失图片时先警告；用户选择继续后，最终 PDF 在对应位置显示可见占位；
- 用户选择目标；已有同名 PDF 时简单确认是否覆盖；
- 最终 PDF 必须可完整打开，不显示本地绝对路径；
- http/https 链接可点击；file、脚本和自定义 scheme 不得形成可执行动作；
- 导出成功后可以打开或在 Finder 中显示结果；
- 导出失败时不显示成功，Markdown 与当前编辑保持可用。

个人首版不包含 HTML、深色 PDF、纸张/边距/页眉页脚设置、批量导出、打印合同、最终文件完整安全后验或非协作写入者并发保证。

### 3.9 本地最小日志

- 不记录或发送产品使用遥测；
- 只在本地保留当前会话与上一会话的最小故障日志；
- 日志只包含时间、应用版本、操作类别和错误代码；
- 日志不得包含正文、文件名、完整路径、选区、剪贴板、链接、搜索词、账号、凭据或恢复内容；
- 只有产品负责人主动操作时才导出到本人选择的位置；
- 导出后由本人查看并使用自己选择的外部方式手工上传；Inflow 不自动上传、打开上传渠道或保留隐藏导出副本。

### 3.10 基础可用性与性能烟测

- 当前闭环的基础操作可用键盘到达，当前焦点清楚可见；
- 修改、保存、外部变化、恢复、警告和失败状态不只依赖颜色表达；
- 打开、预览、格式解析、图片、链接、保存、恢复、PDF 或日志遇到异常时，不导致应用崩溃；
- 性能只用本人真实项目、主 Markdown 和一篇较大的烟测文档观察打开项目、刷新目录树、输入、即时渲染、查找、分栏和保存；较大样本可以降级非核心解析或安全拒绝，但不得崩溃、损坏原文件或虚报成功；
- 验收记录环境、实际结果与本人观察到的停顿或失败，不设置固定毫秒、文件大小阈值，也不执行 30 次协议。

完整键盘命令矩阵、VoiceOver、系统缩放、高对比度、减少动态效果、全部设备与可重现性能协议仍属于后续独立合同。

## 5. 完成条件

个人首版完成仅需同时满足：

1. 本文列出的最小闭环已经实现；
2. 产品负责人用同一个真实 Markdown 项目完成 UAT-PERSONAL-01 至 10；
3. 普通启动、Finder、应用内与拖放入口，独立新建和首次保存，项目树新建、文档切换、相对路径边界、三视图、手动保存、外部变化、恢复、链接和 PDF 的结果可理解，未发生重复编辑状态、越界读取、静默内容损失或未确认覆盖；
4. 日志只在本地生成，只有本人主动导出和上传；
5. 基础键盘、焦点、中文输入法、非颜色状态与异常不崩溃通过，真实项目与较大文档性能烟测已经完成并记录；
6. 产品负责人记录最终结论为“通过”。

本文获批只表示范围已经确定，不表示实现或 UAT 已经通过。个人首版通过也只表示内部验证完成，不表示产品已公开发布。
