## 1. 使用规则

- 能力 ID 一经进入待评审不再复用；能力拆分时创建新 ID 并保留取代关系。
- “阶段”只做映射，版本归属仍由路线图与首发范围决定。
- “默认值来源”只链接附录 B；没有用户默认的能力写“不适用”。
- 本表列明的能力方向、阶段和当前已经定义的边界已随 2026-08-31 产品文档基线获得批准；显式标为后续专项合同或前置合同的部分不在本次批准范围。“候选 UAT 状态”只记录对应端到端产品验收是否已经执行并通过。`OPEN` 表示尚未通过候选验收，不能据此宣称已交付或可发布。
- 正文中可独立延期、采用不同默认值或需要独立验收的能力必须拥有不同 ID；只有阶段、权威正文与 UAT 完全相同的细项才可归入同一能力行。
- 0.1 产品定义已经批准；当前实现和发布产物仍只是 **0.1 公共预览候选**。只有全部适用的 0.1 候选 UAT（包括核心安全与 PDF 完整后验）均已执行并通过，且 Developer ID 签名与 Apple 公证均已完成、对应候选分发验收已经通过，才可称为“0.1 公共预览版”。“产品定义已批准”不得被解释为“候选 UAT 已通过”。
- 能力目标、阶段、边界与 UAT 由产品正文正向定义，不因当前工程状态、已有入口或现存限制而增删或收窄。状态只由对应候选 UAT 结果及产品批准/发布记录更新，不从产品文档之外的材料推定。

## 5. 当前开放验收状态

以下项目阻止对应产品合同被判定为已验收或可发布：

1. 最小产品文档基线已于 2026-08-31 获批；该状态只关闭产品定义评审，不关闭任何候选 UAT 或发布证据。
2. 0.1 公共预览的端到端候选 UAT 仍为 `OPEN`，尤其是恢复核心安全层、外部冲突、本地链接、大文件、当版键盘/辅助使用与性能档位、深色 PDF 完整页面以及最终 PDF 安全后验；后验未完整通过时直接阻止 0.1 发布。
3. 最终保存/另存与交付目标条件替换、非协作写入者完整并发、硬链接别名单一会话，以及强制退出/交接中再次崩溃/系统恢复关系的完整候选 UAT，仍是正式 1.0 候选阻断与 `OPEN`。
4. 0.1 候选 UAT 与候选发布验收记录尚未逐项绑定支持系统、验收样本、完成签名公证的分发产物及验收结果。
5. 后续生态能力只是产品阶段合同；尚未形成的专项合同须先获得批准，对应候选 UAT 须实际执行并通过，才能宣称相关阶段通过验收；发布仍须满足该阶段的全部发布门槛。

## 6. 验收场景

1. 产品功能架构与专项功能设计中每组可独立延期或验收的能力都能映射到一个稳定 ID、权威正文、明确阶段和至少一个明确绑定的候选 UAT；候选 UAT 执行状态只能按实际结果记录为 `OPEN` 或“已通过”，当前全部为 `OPEN`。
2. 附录 B 中的每个默认值都能映射到已存在能力，不能由本表反向创建功能。
3. 候选 UAT 执行记录或证据缺失时保持 `OPEN`；只有对应端到端产品验收实际通过后才可更新为“已通过”。
4. 能力延期、拆分、取代或增加正式例外时，同步更新路线、范围、UAT、决策和变更记录。

## 7. 非范围

- 工程设计、工程验证资产或发布流水线资料。
- 用能力数量或 `OPEN` 数量代表产品进度。
- 在没有候选 UAT 执行记录与证据的情况下变更候选 UAT 状态。
