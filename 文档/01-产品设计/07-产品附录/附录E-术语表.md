## 1. 目标

让产品、设计、客服与用户在讨论文档、保存、恢复、视图、资源和导出时使用同一语言。术语必须表达用户可感知的事物，不把内部实现名称暴露给用户。

## 2. 范围

- 文档、文件、内容版本与保存状态。
- 视图、预览、项目、工作区、大纲、诊断和导航。
- 资源、引用、授权、渲染配置和主题。
- 导出、交付物、恢复保护和本地版本时间线。
- 插件生命周期、市场信任、人工智能、连接器和外部状态。
- 个人首版、后续公共预览、正式 1.0、本地日志、诊断包与 Markdown 边界。
- 不在用户文案中使用的模糊表达。

## 3. 用户故事与使用流程

1. 编写产品文档或界面文案时，先从本表选择标准术语。
2. 新概念无对应术语时，先补充用户可感知的定义、与现有术语的区别及反例，再进入其他文档。
3. 术语调整时，同步检查菜单、提示文案和功能文档，不保留两个同义权威词。

## 4. 功能规则与术语定义

### 4.1 文档与保存

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 文档 | 用户当前正在阅读或编辑的一份内容及其工作状态 | 文档可以尚未命名；不等同于已存在的磁盘文件 |
| Markdown 源文本 | 文档中唯一可编辑的 Markdown 内容 | 预览、大纲和诊断是它的视图，导出从它生成交付物 |
| 用户文件 | 保存在用户选择位置的 Markdown 文件 | 只有成功写入后才能说“已保存” |
| 规范路径 | 将用户选择的文件路径消除 `.`、`..` 和冗余分隔后得到的精确位置 | 不搜索或猜测替代文件，也不用它证明两条不同路径的硬链接指向同一底层文件 |
| 硬链接别名 | 与另一条不同路径指向同一底层文件的文件入口 | 个人首版不建立特殊去重或并发承诺；按用户实际打开的路径处理 |
| 未命名文档 | 尚未选择用户文件位置的文档 | 可有一份最新轻量恢复快照，但不是已保存文件 |
| 未改动的空白未命名文档 | 源文本为空、尚未选择保存位置且用户没有输入或执行其他内容修改的文档 | 可在打开文件或项目时复用其窗口；一旦已有输入或其他修改，就保留该文档并为目标另开窗口 |
| 默认应用 | macOS 为某类文件记录、在 Finder 双击时优先使用的应用 | 用户可把 Inflow 设为 `.md`、`.markdown` 的默认应用；不等于 Inflow 会静默接管系统选择 |
| 只读临时副本 | 为查看 PNG、JPEG 或 PDF 而在应用临时位置创建、文件系统不可写的副本 | 不加入最近文档、不与原件绑定；外部应用只能另存为到用户另选位置，并由 Inflow 定期清理 |
| 命名文档 | 已与一个用户文件位置绑定的文档 | 位置可通过另存为改变 |
| 当前编辑 | 用户在窗口中正在使用的最新内容 | 可能尚未保存；不使用模糊的“保留当前内容”作为冲突操作名 |
| 最近成功保存版本 | 最近一次确认完整写入用户文件的内容 | 用于判断修改状态以及重新加载或覆盖保存，不等同于恢复内容 |
| 磁盘版本 | 当前从用户文件读取到的内容 | 可由其他应用修改，不一定等于最近成功保存版本 |
| 文档版本 | 为一次比较、预览或导出固定下来的当前内容状态 | 后续编辑不会混入已开始的任务；不等于另一份可编辑正文 |
| 有未保存更改 | 当前编辑与最近成功保存版本不同 | 面向用户使用这个说法，不使用内部状态缩写 |
| 自动保存 | 在用户不主动执行保存命令时，将命名文档的当前编辑写回用户文件 | 不属于个人首版；后续启用前需重新评审外部变化行为 |
| 手动保存 | 用户主动要求写入当前文档 | 恢复保护降级不能禁止它 |
| 另存为 | 将当前文档保存到新位置，成功后当前窗口转向新位置 | 不是“导出”；会改变之后的保存目标 |
| 外部变更 | 用户文件在 Inflow 当前编辑之外发生的修改、替换、移动或删除 | 不假定变更来自哪个具体应用 |
| 覆盖保存 | 检测到外部变化后，用户明确要求用当前编辑替换磁盘内容 | 个人首版只在普通确认中提供；不得静默发生 |

### 4.2 恢复与历史

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 轻量恢复快照 | 为意外退出保存的每个文档最新一份未保存源文本及最小关联信息 | 不等于已保存，不提供版本时间线或批量恢复 |
| 恢复为未命名文档 | 将轻量恢复快照打开为未绑定路径的新文档 | 不自动改写原文件，用户检查后自行保存 |
| 本地版本时间线 | 用户为阅读、复制和明确恢复旧内容而使用的长期历史 | 可关闭或清理；不影响恢复保护 |

### 4.3 视图与结构

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 源码编辑 | 只显示 Markdown 源文本的视图 | 不简写为“编辑模式”；不表示一份不同文档 |
| 实时预览 | 同时显示源文本与预览的分栏视图 | 不简写为“预览”而与纯预览混淆 |
| 即时渲染编辑 | 在同一 Markdown 中直接编辑安全渲染结果、弱化非当前块标记，并让复杂块聚焦时回退局部源码的稳定视图 | 属于个人首版；不称“可编辑预览”，不产生私有富文本、HTML 或隐藏正文 |
| 局部 Markdown 源码块 | 即时渲染编辑中为一个复杂、错误、歧义或未知结构原位显示的可编辑源码范围 | 只替代对应块的可视编辑，不复制正文、不改写其他块，也不表示整篇已切换到源码编辑 |
| 独立只读纯预览 | 只显示阅读结果、不能编辑正文的独立视图 | 不属于个人首版；不得用隐藏编辑栏的临时布局或即时渲染编辑冒充 |
| 预览 | 由当前 Markdown 和渲染配置得到的可阅读结果 | 是可重建视图，不是可单独保存的正文 |
| 语义位置 | 文档中某个标题或结构块及其内部相对位置 | 用于视图切换、导航和返回，比绝对滚动百分比更稳定 |
| 大纲 | 从当前 Markdown 标题得到的文档结构视图 | 大纲重组会明确改写 Markdown，纯导航不改写 |
| 文档健康中心 | 展示结构、链接、资源、语法与交付问题的可操作视图 | 诊断本身不修改内容；修复前展示差异 |
| 渲染配置 | 预览、诊断和导出共享的目标语法与呈现选择 | 切换配置不静默修改 Markdown |
| 主题 | 控制预览与交付物视觉呈现的受支持方案 | 不改变文档内容或语法 |
| 个人首版 Markdown 基线 | 当前解析器支持的 CommonMark/GFM 基础以及 `flowchart`、`stateDiagram-v2` | 只服务内部真实文档验证，不冻结长期自有方言或跨版本 slug 合同 |
| fragment | Markdown 链接中 `#` 后用于尝试定位标题的片段 | 个人首版沿用当前解析器结果；无法定位时仍可打开文档 |

### 4.4 工作区、导航与资源

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 文档窗口 | 直接打开和编辑一份文档的窗口 | 可不属于项目或工作区 |
| 项目 | 以用户主动选择的普通文件夹为根目录、通过目录树组织多份 Markdown 与资源的个人首版环境 | 不创建 Inflow 私有项目文件；已打开 Markdown 使用 macOS 原生标签组，文件操作仅包含明确的新建 Markdown，不包含跨文档搜索、高级标签管理、重命名、移动或删除 |
| 项目窗口 | 在左侧承载可显示或隐藏的项目目录树，并以原生标签组编辑项目 Markdown 的窗口 | 刚打开或空项目可以没有当前文档；目录树、大纲与窗口布局在标签切换时保持，保存与撤销仍以各文档为边界 |
| 项目侧栏 | 在项目窗口左侧承载项目目录树和项目命令的导航区域 | 可显示或隐藏；首版提供新建 Markdown 文件，不提供搜索、重命名、移动、删除或高级标签管理 |
| 项目目录树 | 项目侧栏中按磁盘结构展示项目目录与文件的树形区域 | 选中目录、文件或无选择时分别为项目内新建推导目标目录；不接受外部项目拖入、复制、移动或整理 |
| 项目内新建 Markdown 文件 | 通过项目目录树按钮或右键菜单，在推导出的项目内目录立即创建并打开空白 `.md` 或 `.markdown` 用户文件 | 与 `⌘N` 在独立单文件窗口创建未命名文档不同；首版不接受会被默认隐藏的点号开头名称，不覆盖重名文件或目录，不允许越出项目根目录或经符号链接逃逸；创建成功后即使打开失败也保留磁盘文件与树节点 |
| 刷新项目 | 重新读取项目根目录下当前可访问的目录和文件结构 | 不改写 Markdown、不执行文件操作，也不放弃当前文档的未保存更改 |
| 工作区 | 在项目基础上扩展跨文档搜索、快速打开、高级标签管理和文件管理能力的后续环境 | 不把文件导入私有容器；个人首版已有目录树、大纲与原生文档标签 |
| 工作区窗口 | 包含文件树、跨文档搜索、大纲、快速打开与高级标签管理的后续窗口 | 基于个人首版原生标签继续增强；每份文档仍保持独立保存和撤销边界 |
| 导航历史 | 用户沿标题、链接、搜索和诊断移动时的前进/后退记录 | 记录文档、目标和语义位置 |
| 资源 | Markdown 通过链接或图片语法引用的本地或远程文件 | 资源不自动成为文档内容 |
| 附件 | 除了视觉图片外，用户通过 Markdown 链接关联的本地文件 | 未受支持的类型不默认直接打开 |
| 相对引用 | 以当前 Markdown 文件位置为基准的文档、图片或附件路径 | 文档或资源移动时需要重新分析 |
| 资源管家 | 查看缺失、未引用、重复与远程资源及引用影响的视图 | 辅助清单可重建，不代替实际文件 |
| 授权 | 用户明确选择 Inflow 可以访问的文件或文件夹范围 | 拒绝后不反复弹窗；保留手动重新授权入口 |

### 4.5 结构洞察

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 结构洞察 | 成熟版中用于理解文档关系、来源、演进和质量趋势的工作区视图 | 只解释用户所选工作区，不成为独立内容事实 |
| 关系视图 | 按明确关系、推断和未知状态展示文档之间联系的结构洞察页面 | 每项明确关系可回到实际链接或来源信息 |
| 来源信息 | 用户为文档明确记录的来源标题、作者或机构、来源位置、日期和备注 | 以可见 Markdown 元数据保存，可编辑、撤销、删除和带走 |
| 推断关系 | 产品根据可见证据提出、但尚未由明确链接确认的关系建议 | 必须展示为推断，可查看证据、标记为无关或暂时隐藏；如要成为明确关系，用户必须从当前源文档选择插入位置，预览并确认标准 Markdown 相对链接 |
| 演进视图 | 区分内容历史、迁移记录和外部服务状态的结构洞察页面 | 缺少历史基线时只显示当前状态，不生成虚假趋势 |
| 质量趋势 | 一段时间内可定位的结构、链接、资源与兼容问题变化 | 不评价写作质量、效率、用户表现或个人生产力 |

### 4.6 导出与交付

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 导出 | 根据当前精确 Markdown 版本与配置生成一份新交付物 | 不改变当前 Markdown 位置或保存状态 |
| 交付物 | 通过导出生成、用于阅读、分享、打印或归档的文件或文档包 | 不是当前可编辑 Markdown |
| 成果 | 泛指用户通过写作获得的内容或价值 | 指具体导出文件时必须使用“交付物” |
| 导出配置 | 本次导出使用的格式、主题、渲染配置与页面选择 | 与发起时的源文本一起确定本次交付物 |
| 自包含 | 交付物不依赖未随交付物提供的本地或网络资源 | 远程占位不等于已嵌入远程内容 |
| PDF 基础检查 | 对个人首版最终 PDF 执行的可打开性、正文、图片和本地绝对路径检查 | 失败时不报告成功；不等同于公共分发级完整安全后验 |
| 可移植文档包 | 包含 Markdown、必要本地资源与清单的交付物 | 不把资源转换为 Inflow 私有形式 |

### 4.7 迁移与兼容

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 迁移预检 | 在改变任何内容前，说明来源、兼容结果、冲突和目标影响的检查 | 预检不修改来源，也不表示迁移已经完成 |
| 原样可用 | 无需改变内容即可在 Inflow 中完成该项主要任务 | 必须说明覆盖的任务，不写“完全兼容” |
| 结果等价 | 表达方式发生可见变化，但约定的阅读与交付语义保持一致 | 变化必须可查看并由用户接受 |
| 可读降级 | 原内容被保留为可阅读文本，但部分交互或专业呈现不可用 | 不把降级项计为原样支持 |
| 不支持 | 当前没有安全、可解释的使用或转换路径 | 保留来源并提供跳过或外部处理建议 |
| 迁移报告 | 汇总成功、变化、降级、跳过、失败和待处理项目的用户记录 | 可再次打开，并能定位目标文档与问题 |

### 4.8 插件生态

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 插件 | 用户按任务安装、授权、停用和卸载的一项可选专业能力 | 不接管本地保存、恢复、撤销或冲突裁决 |
| 能力租约 | 插件只在用户理解的任务、内容范围和时间内参与工作的产品关系 | 安装不等于获得全部权限；租约可以被缩小、撤回或结束 |
| 能力中心 | 用户查看精选可选能力、已安装能力、权限和状态的入口 | 专业版只提供受控低风险能力，不等于公开市场 |
| 插件市场 | 用户发现、比较和获取第三方插件的公开产品 | 成熟版开放；首个公开版本只分发免费插件，商业市场后续进入 |
| 开发者中心 | 发布者建立身份、提交版本、处理审核反馈、发布更新、转移主体或退出市场的入口 | 成熟版开放；进入入口不等于已经通过身份验证或获得发布资格 |
| 权限中心 | 用户查看、缩小或撤销可选能力授权的入口 | 授权记录不展示文档正文 |
| 发布者身份 | 对插件责任主体、公开资料、联系方式和支持责任的市场记录 | 私密验证资料不向普通用户公开；主体变化必须重新核对并通知受影响用户 |
| 发布者身份状态 | 资料草稿、需补充资料、验证中、未通过、已验证、转移中或已退出中的一项当前事实 | 身份结果不替代插件版本审核；“未通过”不表示插件已被判定为不安全 |
| 插件提交版本 | 发布者送交审核的一份明确插件版本及其产品资料 | 每次提交独立说明权限、数据、费用、兼容和退出影响，不能借旧审核扩大边界 |
| 插件提交版本状态 | 草稿、已提交、审核中、需修改、已通过、已拒绝、已发布或已撤回中的一项当前事实 | 提交结果不静默改变上一已发布版本；已撤回的原风险版本不能恢复分发 |
| 审核反馈 | 市场针对一次提交给出的通过、需修改、拒绝及逐项理由 | 发布者可修正或申请复审；反馈不静默改变已发布版本状态 |
| 发布者主体转移 | 将插件责任、支持与商业关系从一个已核对主体转给另一个主体 | 不自动转移用户授权或扩大权限；生效前公开影响并允许用户退出 |
| 已验证使用评价 | 后续商业市场中，实际获取并使用过对应插件版本的用户提交的评分与说明 | 不属于首个公开免费市场；可修改、删除、举报和申诉 |

### 4.9 人工智能、连接器与使用数据

| 标准术语 | 定义 | 使用边界 |
| --- | --- | --- |
| 人工智能辅助 | 用户主动发起、可预览上下文与结果的机器辅助能力；行业材料中可说明简称 AI | 正式产品名称使用“人工智能”；结果不冒充原文、已验证事实或用户已接受的修改 |
| 人工智能建议 | 人工智能生成或辅助生成的独立纯文本结果 | 首版只可查看或复制，不自动应用、不调用工具、不操作文件 |
| 人工智能任务状态 | 进行中、结果待决定、部分完成、已取消、失败和已完成六种相互区分的任务事实 | 不用一个“完成”涵盖未应用建议、部分结果、失败或费用结算 |

## 5. 异常与空状态

- 同一概念出现两个候选词时，在本附录完成评审前保留已有标准词，不在其他文档并行创建新权威词。
- 界面空状态不使用“无数据”这类无对象说法；应说明没有文档、资源、搜索结果、诊断或恢复内容中的哪一种。
- 术语在中英文之间无一一对应时，用中文用户语义作为界面权威，不直译内部名称。

## 6. 验收场景

1. 受控产品概念、状态含义和分类术语都能在本附录找到统一定义；具体命令名称、菜单位置和快捷键以[附录 C](./附录C-菜单与快捷键.md)为权威，提示标题、按钮文案与展示条件以[附录 D](./附录D-状态与提示文案.md)为权威。

3. 个人首版的源码编辑、实时预览和即时渲染编辑名称在菜单、帮助与功能文档中完全一致；不使用“可编辑预览”或其他旧称。

5. 只阅读用户界面文案的人不需要了解任何内部组件即可理解文档处于哪个状态。
6. 发布者身份、提交版本、审核反馈、主体转移、评价、购买使用权、续费、退费和恢复购买在市场、文案与验收中使用同一含义。
