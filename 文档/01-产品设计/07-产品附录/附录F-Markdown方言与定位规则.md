## 1. 目标

让用户能够准确回答“一段 Markdown 在 Inflow 中会怎样解释、链接会跳到哪里、离开 Inflow 后哪些表达仍可读”。本文以版本化的人读合同取代“常见 Markdown”“兼容大多数工具”等不可验收说法。

## 2. 方言版本

首发版冻结为 **Inflow Markdown 1.0**，由三层组成：

1. CommonMark 0.31.2；
2. GFM 0.29-gfm 中的表格、删除线和任务列表扩展；CommonMark 尖括号自动链接保持有效，GFM 的无定界自动链接不在首发合同中；
3. Inflow 1.0 扩展：脚注、首发公式子集和附录 A 规定的 Mermaid 基础子集。

同一文档只按一个明确的方言版本解释。后续新增或改变语法时必须增加 Inflow 方言版本、说明旧内容结果和迁移方式，不以应用版本号暗中改变含义。

原始 HTML 在首发版保持可读源文，不作为可执行或增强呈现内容。任意 CSS、脚本和远程资源不属于 Inflow Markdown 1.0。

## 3. 首发公式子集

### 3.1 定界与上下文

- 行内公式使用 `$...$`；起止符位于同一段，未闭合时按普通文本显示，不生成公式，也不生成问题标记。
- 块级公式使用独占行的 `$$` 开始与结束；未闭合时保留原文并标记问题。
- 反斜线可转义美元符；代码、行内代码、围栏代码、链接目标和原始 HTML 中不解析公式。
- 首发不支持用户自定义宏、外部资源、命令定义或会改变文档其余部分解释的全局指令。

### 3.2 支持内容

| 类别 | 首发支持 |
| --- | --- |
| 基础结构 | 数字、普通 Unicode 字符、`+ - = < > / *`、括号、逗号、分号、冒号、竖线、分组与上下标 |
| 分式与根式 | `\frac`、`\sqrt` |
| 大型符号与极限 | `\sum`、`\prod`、`\int`、`\lim`、`\infty`；可组合上下标 |
| 常用函数 | `\sin`、`\cos`、`\tan`、`\log`、`\ln`、`\exp`、`\max`、`\min` |
| 希腊字母 | `\alpha`、`\beta`、`\gamma`、`\delta`、`\theta`、`\lambda`、`\mu`、`\pi`、`\sigma`、`\phi`、`\omega`，以及 `\Gamma`、`\Delta`、`\Theta`、`\Lambda`、`\Pi`、`\Sigma`、`\Phi`、`\Omega` |
| 运算与关系 | `\times`、`\cdot`、`\pm`、`\le` / `\leq`、`\ge` / `\geq`、`\ne` / `\neq`、`\in`、`\notin` |
| 箭头与括号 | `\to` / `\rightarrow`、`\leftarrow`、`\leftrightarrow`、`\langle`、`\rangle`、`\left`、`\right` |
| 公式内文本 | `\text{...}`；文本仅作为公式的局部可读内容，不解释标记 |

`\dfrac`、`\tfrac`、字体与修饰命令、`\begin...\end` 环境、矩阵、多行对齐、公式编号和跨公式引用均不属于首发子集；其中经产品评审的环境从专业版开始。未知命令、超出子集的环境和语法错误只让对应公式降级，不影响文档其余内容。

## 4. 标题标识生成

“标题可见文本 → 标题标识”使用以下唯一顺序：

1. 取标题的可见纯文本；链接只取显示文字，格式标记不进入标识。
2. 使用 Unicode 15.1.0 的规范化数据将文本转换为 NFC。
3. 使用 Unicode 15.1.0 Default Case Conversion 的完整小写映射转换文本，不应用用户地区特例；转换后再次规范化为 NFC。
4. 去除首尾空白；把 Unicode 15.1.0 `White_Space` 属性中的一个或多个连续字符替换为一个连字符 `-`。
5. 只保留 Unicode 15.1.0 `General_Category` 为字母类 `L*` 或十进制数字 `Nd` 的字符，以及 ASCII 连字符 `-` 和下划线 `_`；移除其余字符。
6. 连续连字符合并为一个，移除首尾连字符；结果为空时使用 `section`。
7. 文档内第一次出现使用基础标识；后续重复项按源文顺序追加 `-1`、`-2`、`-3`。

例：`你好，Inflow!` 得到 `你好-inflow`；第二个同名标题得到 `你好-inflow-1`；只有标点的标题得到 `section`。

Unicode 数据版本是 Inflow Markdown 1.0 合同的一部分。操作系统或运行库升级不得静默改变既有标题标识；升级 Unicode 数据必须提升 Inflow Markdown 方言版本，并提供旧标识兼容与迁移说明。

## 5. fragment 定位

“原始 fragment → 已有标题标识”与标题标识生成是两套独立产品规则：

1. 去掉 URL 中用于分隔的第一个 `#`，但不把后续字符当作新的片段。
2. 按 UTF-8 百分号解码一次；非法编码不导航并显示目标不可用。
3. 将解码结果规范化为 NFC。
4. 与文档已经存在的标题标识进行区分大小写的精确匹配。
5. 不再次解码、不重新生成 slug、不猜测大小写、标点或重复标题序号。

当前文档与跨文档标题链接使用同一规则。外部工具生成的 fragment 若不能精确匹配，Inflow 可打开目标文档并说明标题未找到，但不得跳到猜测的标题。

## 6. 版本化正反样例

| 样例 ID | 输入 | 预期结果 |
| --- | --- | --- |
| DIALECT-1.0-001 | `# Hello World` | 标识为 `hello-world` |
| DIALECT-1.0-002 | 两个 `# 重复标题` | 标识依次为 `重复标题`、`重复标题-1` |
| DIALECT-1.0-003 | fragment `%E9%87%8D%E5%A4%8D%E6%A0%87%E9%A2%98-1` | 解码一次后精确命中第二个标题 |
| DIALECT-1.0-004 | fragment `%2520` | 只得到 `%20`，不再次解码为空格 |
| DIALECT-1.0-005 | 未闭合 `$formula` | 作为普通文本保留，不生成公式或问题标记 |
| DIALECT-1.0-006 | 公式中的未知命令 | 保留原公式，其他段落继续呈现 |
| DIALECT-1.0-007 | 原始 HTML 中的脚本或样式 | 保留可读源文，不执行也不扩大能力 |

发布候选必须保存本轮实际使用的全部正向、反向和跨工具样例及结果。只证明一个理想样例不能宣称整个方言或 fragment 合同通过。

## 7. 兼容与演进

- “支持 Inflow Markdown 1.0”只表示本文列出的语法与降级结果，不表示与任意第三方产品完全相同。
- 未支持扩展优先保留原文并给出可读降级；不得为视觉相似而不可逆改写。
- 方言升级必须说明旧版本、目标版本、差异、用户选择、回退与交付影响。
- 任意 CSS 导入是正式产品例外，不属于 Markdown 方言、主题兼容或迁移承诺。

## 8. 验收场景

1. CommonMark、GFM 与 Inflow 扩展分别有正向、歧义和错误样例，且结果可定位。
2. 首发公式只接受第 3 节子集；未知命令、未闭合定界和排除区域结果符合合同。
3. 标题标识对 Unicode、标点、重复标题和空结果具有确定结果。
4. fragment 只解码一次并精确匹配，不经过标题 slug 流程。
5. 同一方言版本在源码、预览、诊断与交付中没有无说明差异。

## 9. 非范围

- 宣称兼容完整 TeX、完整 Mermaid、任意 GFM 扩展或某个第三方编辑器方言。
- 用实现组件名称代替用户可理解的方言版本。
- 在不增加方言版本的情况下改变既有文本解释。
