## 1. 目标

让用户记录的来源标题、作者、机构、位置、日期和备注真实写入 Markdown 文件，在其他工具中仍可查看、复制和保留；同时避免隐藏数据库、重复字段和无说明覆盖。

## 2. 文档表达

来源信息使用文档顶部既有或新建的 YAML Front Matter，并放入唯一命名空间 `inflow`。首个合同版本为 `sourceSchema: 1`。

```yaml
---
inflow:
  sourceSchema: 1
  nextSourceOrdinal: 2
  sources:
    - id: source-001
      title: "示例来源"
      authors:
        - "作者甲"
      organization: "示例机构"
      url: "https://example.com/source"
      file: "references/source.md"
      published: "2026-08-01"
      accessed: "2026-08-30"
      note: "用户写下的来源说明"
---
```

产品保存前必须展示完整 Markdown 变化。来源信息与正文共享同一保存、冲突和撤销规则，不另建隐藏内容事实。

## 3. 字段合同

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `sourceSchema` | 正整数 | 当前只接受 `1`；未知更高版本保持原文且只读展示 |
| `nextSourceOrdinal` | 正整数 | 必填；始终大于本文档曾使用的最大来源序号，只递增、不回退，用于保证删除后的 ID 不被重用 |
| `sources` | 来源列表 | 可为空；顺序就是用户看到的顺序 |
| `id` | 文档内唯一字符串 | 必填，格式为 `source-NNN`；创建时使用 `nextSourceOrdinal` 并将其递增，删除后不重用 |
| `title` | 单行文本 | 可选；不解析为 Markdown |
| `authors` | 单行文本列表 | 可选；按用户输入顺序保留，不拆分或猜测姓名 |
| `organization` | 单行文本 | 可选；不与作者自动合并 |
| `url` | 单个网页地址 | 可选；只接受明确的 `https` 或 `http` 地址，不包含账号凭据 |
| `file` | 相对文件路径 | 可选；以当前 Markdown 位置为基准，不保存绝对本地路径 |
| `published` | `YYYY-MM-DD` | 可选；日期不完整时由用户放入 `note`，产品不猜测 |
| `accessed` | `YYYY-MM-DD` | 可选；只在用户提供或确认时记录 |
| `note` | 文本 | 可选；保留换行，不自动变成正文、标签或关系 |

每条来源除 `id` 外至少有一个非空字段；所有内容字段都可单独修改或删除。最后一个内容字段被清空时，产品建议删除整条空来源，不保留不可见占位。

## 4. 既有 Front Matter 与未知字段

- 文档已有合法 Front Matter 时，只在现有内容中新增或更新 `inflow` 命名空间，不重排、重命名或删除其他顶层字段。
- 已有 `inflow` 命名空间但没有来源字段时，只新增 `sourceSchema`、`nextSourceOrdinal` 与 `sources`，保留其他未知字段。
- 未知的 `inflow` 子字段保持原文；产品不声称理解，也不因编辑一条来源而删除。
- 文档存在多个 Front Matter、无效 YAML、重复 `inflow`、重复来源 ID、序号不大于既有最大值或类型不符时，停止结构化写入，定位问题并允许用户编辑源码。
- 不把同名的第三方顶层字段自动迁移进 `inflow`，也不把 Inflow 字段复制到多套命名空间。

## 5. 冲突与重复

- 外部修改与来源信息编辑同时发生时，进入统一文档冲突流程；不做隐藏字段级合并。
- 来源 ID 重复时，保留源文本并标记每个重复位置；只有用户确认修复后才生成新 ID。
- URL 与相对文件同时存在是允许状态，表示同一来源的两种位置；产品不自动判定两者内容一致。
- 两条内容相同但 ID 不同的来源不自动合并；可向用户提示候选重复并展示差异。
- 删除来源信息与删除外部网页或文件无关，不发起网络或文件删除。

## 6. 迁移与交付

- 直接打开或迁移 Markdown 时，合法的 `inflow.sourceSchema: 1` 原样保留；未知版本按可读降级处理。
- 其他工具不理解命名空间时，仍可把它作为普通 YAML 查看与保留；工具删除 Front Matter 会丢失来源信息，但正文不受影响。
- Markdown 与可移植文档包保留完整来源元数据。HTML、PDF 和长图不自动把 Front Matter 内容显示为正文；用户要展示来源时，应先将所需信息明确写入正文。
- 删除结构洞察辅助数据不能删除本合同写入 Markdown 的来源信息。

## 7. 验收场景

1. 新增、修改、排序和删除来源前可查看完整 Markdown 差异，确认后可一次撤销。
2. 既有 YAML 与未知字段在来源编辑后逐字保持，除用户确认的来源变化外不发生改写。
3. 无效 YAML、重复命名空间、重复 ID、未知版本与类型错误均保持原文并给出可定位问题。
4. 外部修改发生后不沿用过期确认写入来源信息。
5. 在不使用 Inflow 的普通文本工具中，来源信息仍可阅读和复制；删除插件或结构洞察辅助数据后仍存在于 Markdown。
6. Markdown 和可移植文档包保留来源信息，HTML/PDF/长图不在用户不知情时披露元数据。

## 8. 非范围

- 在不可见数据库或 sidecar 中保存唯一来源事实。
- 自动抓取网页、推断作者或补齐日期。
- 把来源元数据当作版权、真实性或引用正确性的证明。
- 在未修改方言版本和迁移合同的情况下增加必填字段或改变已有字段含义。
