## 1. 目标

为全部产品文档提供唯一的精确规格来源。功能文档只说明为什么和如何使用，不重复本附录中的数值、范围、格式清单或保留周期。

## 2. 范围

- 平台、文件、编码和换行规格。
- 编辑、预览、即时渲染、轻量项目与内容支持范围。
- 响应时间、基准文档与恢复保留参数。
- 图片、链接、导出格式、页面与体积边界。
- 可配置项的初始值不在本文重复，统一见[附录 B](./附录B-默认设置.md)；文件与交付格式的固定基准仍由本附录定义。

## 3. 用户故事与使用流程

- 作为用户，我希望在选择文件、调整字号、导出或等待恢复时，看到稳定、不相互矛盾的产品边界。
- 作为产品与设计人员，我在功能稿中遇到数值或支持清单时，必须引用本附录，而不是创建第二个版本。
- 规格变更时，先在本附录完成产品评审，再检查所有引用文档的用户语义是否需要同步调整。

### 4.1 平台与文件

| 规格项 | 产品规格 |
| --- | --- |

| 公开平台范围 | 未冻结；在个人验证通过并进入公开预览决策时另行定义，不由当前内部版本推导 |
| 当前分发状态 | 不分发；从本地开发环境运行，不提供安装包、签名、公证、更新或商业合同 |

| Markdown 文件扩展名 | `.md`、`.markdown` |
| 普通启动 | 没有来自 Finder、系统或用户操作的待打开目标时，创建一份可直接编辑的空白未命名文档并聚焦编辑器；不显示启动页，也不先要求选择文件或目录 |
| 新建独立文档 | “文件 > 新建”或 `⌘N` 始终在独立单文件窗口创建未命名 Markdown 文档；即使从项目窗口执行也不在项目目录树中创建文件，首次保存时再选择名称和位置 |

| 多目标与去重 | 先规范化目标并与已打开文件或项目去重：重复目标只聚焦现有窗口，不消耗可复用空白窗口；最多一份未改动的空白未命名窗口承接第一个尚未打开的目标，其余 Markdown 各自新建窗口；同一规范文件路径或项目根目录始终不创建第二份编辑状态或项目窗口 |
| 可直接编辑编码 | UTF-8、UTF-8 BOM |
| 新文档编码 | UTF-8，无 BOM |
| 新文档换行 | LF |
| 已有文档保存 | 保留原 BOM 状态与主换行风格（LF 或 CRLF） |
| 混合换行 | 编辑前一次性请用户选择 LF 或 CRLF；未选择时只读且不自动写回 |
| 不支持编码 | 不猜测、不进入文本编辑、不覆盖原文件 |

个人首版同时保留单文件打开与项目打开。项目只是用户选择的普通文件夹，不创建清单、数据库或隐藏正文；完整边界见 4.5.1。

| 专业版增强写作内容 | 目录、YAML Front Matter、Alerts；未启用对应能力时保留原文 |
| 代码围栏 | 至少 3 个反引号；选区包含更长连续反引号时，围栏长度为最长连续长度加 1 |
| 内置表格插入模板 | 3 列 × 3 行，包含 1 行表头与 2 行数据；插入后选中第一个表头单元格 |
| 个人首版 Mermaid | 只验证当前仓库实际使用的 `flowchart` 与 `stateDiagram-v2`；失败时显示原代码围栏和局部错误，不执行脚本或网络动作 |
| 即时渲染直接编辑 | 段落、H1–H6、粗体、斜体、删除线、行内代码、引用、无序/有序/任务列表和普通链接文字 |
| 即时渲染局部源码 | 围栏代码、表格、Mermaid、图片目标或属性、原始 HTML、复杂嵌套和未知语法；聚焦编辑时只显示对应 Markdown 源范围 |
| 即时渲染保真 | 只修改用户实际操作的最小源范围，不整篇重新序列化；未操作与不支持内容逐字保留，解析失败时原位保留局部源码 |
| 即时渲染输入与链接 | 中文输入法标记文本提交前不重建当前块；普通点击用于定位编辑，`⌘`+点击才执行链接导航；文本/RTF/HTML 只粘贴纯文本，PNG/JPEG 位图载荷走图片插入流程 |
| 后置表达 | 公式、脚注、`sequenceDiagram`、`classDiagram`、其他 Mermaid 类型及长期兼容合同均不属于个人首版 |
| 字数 | 中日韩文字每个计为一字；连续拉丁字母或数字按由空白和标点分隔的词计数；空白与标点不计入字数 |
| 字符数 | 按用户可见字符计数；分别提供“含空格”与“不含空格”，换行不计入 |

| 规格项 | 产品规格 |

### 4.4 保存、恢复与历史

| 规格项 | 产品规格 |
| --- | --- |
| 自动保存 | 个人首版不提供；用户使用 `⌘S` 手动保存，关闭有修改的文档时使用系统式保存确认 |
| 保存完成判定 | 使用 macOS 标准文档保存流程（底层由 AppKit 文档框架提供）的结果；失败时保持当前编辑和修改标记，不把恢复快照表示为已保存 |
| 外部变化 | 检测到后显示“重新加载”；有未保存内容时在放弃前确认，未处理变化时保存到原路径需要一次明确覆盖确认；不提供三版本比较或自动合并 |
| 轻量恢复快照 | 每个打开文档只保留一个最新快照；异常退出后可“恢复为未命名文档”或“放弃”，恢复不会自动写回原路径 |
| 恢复范围 | 保存源文本及恢复所需的最小关联信息；不提供恢复中心、批量恢复、独立版本时间线、密钥生命周期或容量管理界面 |
| 恢复失败 | 不得阻止用户手动保存当前 Markdown；无法读取的快照不冒充可恢复内容 |
| 项目内切换文档 | 项目刚打开或空项目可以没有当前文档；选择新目标时加入同一原生标签组，选择已打开目标时直接聚焦原标签；切换不关闭其他文档、不要求先保存，每个标签的修改与撤销独立保留 |
| 本地版本时间线保留范围 | 成长版起：1–365 天、100 MiB–5 GiB；同时设置时以先达到者为准，用户可关闭 |
| 系统“打开最近” | macOS 实际提供时可附带显示，但不保证存在、容量或授权恢复，也不参与个人首版 UAT；由 Inflow 管理容量与授权的 CAP-FILE-005 后置 |

### 4.5.1 个人首版轻量项目

| 规格项 | 产品规格 |
| --- | --- |
| 项目定义 | 用户明确选择的一个普通文件夹；不创建 Inflow 私有项目文件，不导入、复制或重组原内容 |
| 项目目录树 | 递归显示项目中的普通目录与文件，隐藏项默认不显示；`.md`/`.markdown` 可编辑，PNG/JPEG/PDF 使用当前支持动作，其他文件仅展示 |
| 编辑会话 | 一个项目窗口使用 macOS 原生标签组保持已打开文档；刚打开或空项目可以没有当前文档；每份文档保持独立缓冲、撤销、预览和保存边界 |
| 目录更新 | 打开项目时读取目录树，并提供显式“刷新项目”重新读取；项目内新建成功后目录树立即显示新文件，不要求用户刷新；个人首版不以其他实时目录监听作为通过条件 |
| 相对路径基准 | 始终以链接或图片引用所在 Markdown 的目录为基准，不以项目根目录替代 |
| 根目录边界 | 路径规范化并解析符号链接后必须仍位于项目根目录；越界、符号链接逃逸、缺失或无权限目标均阻止并说明，不自动扩大授权 |
| 项目内 Markdown | 从目录树或相对链接选择时聚焦已有标签或新建标签；不关闭原标签，也不因切换要求处理原标签的未保存修改；跨窗口同路径使用下一条例外 |
| 跨窗口同路径 | 目标规范路径已经在另一个 Inflow 窗口中编辑时聚焦现有窗口，项目当前文档保持不变，不创建第二份编辑状态 |
| 项目内新建入口 | 只通过项目目录树的“新建 Markdown 文件…”按钮或右键菜单发起；`⌘N` 仍创建独立未命名文档，不作为项目内新建入口 |
| 项目内新建目标 | 选中目录时在该目录创建；选中文件时在其父目录创建；未选择目录树项目时在项目根目录创建 |
| 项目内新建名称 | 输入不含扩展名的名称时自动补 `.md`；显式 `.md` 或 `.markdown` 均保留；空名称、以点号开头的名称、路径分隔符、`.`、`..`、其他扩展名及平台不允许的名称不创建，避免新文件被首版默认隐藏 |
| 项目内新建保护 | 写入前同时确认目标仍在项目根目录内且解析符号链接后未逃逸；同名文件或目录已存在、目标越界、符号链接逃逸、无权限或创建失败时拒绝且不覆盖任何现有文件或目录 |
| 项目内新建提交 | 无需放弃或保存其他标签的修改；用户确认文件名后立即在磁盘创建 UTF-8 无 BOM 的空文件、在目录树中显示并以新标签打开 |
| 项目内新建后打开失败 | 磁盘空文件已成功创建但编辑器随后无法打开时，不静默删除或回滚该文件；目录树保留并显示它，明确说明“文件已创建但无法打开”，允许重试打开或在 Finder 中显示 |
| 项目内图片 | 项目根目录内的相对 PNG/JPEG 可直接呈现，不复制、不改写引用；用户要求外部打开时仍使用只读临时副本 |

## 6. 验收场景

1. 全库搜索精确数值、默认值、快捷键和状态文案时，分别只能在对应附录找到权威定义。
2. 文件编码、换行、三种当前视图、轻量项目、恢复、资源和导出的边界在各功能流程中可被引用，不出现第二套值。
3. 超出每个数值边界时，界面拒绝无效值并保留最近有效值。
4. 对所有支持格式与不支持格式、项目内与项目外路径、直接可视编辑与局部源码结构各有正向与降级验收场景。
5. 插件发布、评价、交易与更新状态覆盖完整正向和退出路径；人工智能付费任务同时受三项有限上限约束，不存在无上限或无法封顶仍执行的路径。
6. 普通启动、Finder 与“打开方式”、默认应用、菜单打开、`⌘N`、多 Markdown、单文件夹和拖放入口遵守同一窗口路由；目标先去重、再由最多一份未改动空白窗口承接第一个新目标，外部冷启动不产生额外空白窗口。
7. 项目内新建在三种目录树选择状态下都创建到正确位置；未保存更改、非法或重名名称、越界、符号链接逃逸和写入失败均不会覆盖现有文件；完整成功后目录树立即更新并打开新文件，磁盘创建成功但打开失败时则保留文件与树节点并明确提示。
