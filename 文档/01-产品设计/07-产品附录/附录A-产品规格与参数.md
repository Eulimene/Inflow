## 1. 目标

为全部产品文档提供唯一的精确规格来源。功能文档只说明为什么和如何使用，不重复本附录中的数值、范围、格式清单或保留周期。

## 2. 范围

- 平台、文件、编码和换行规格。
- 编辑、预览、分栏和内容支持范围。
- 响应时间、基准文档与恢复保留参数。
- 图片、链接、导出格式、页面与体积边界。
- 可配置项的初始值不在本文重复，统一见[附录 B](./附录B-默认设置.md)；文件与交付格式的固定基准仍由本附录定义。

## 3. 用户故事与使用流程

- 作为用户，我希望在选择文件、调整字号、导出或等待恢复时，看到稳定、不相互矛盾的产品边界。
- 作为产品与设计人员，我在功能稿中遇到数值或支持清单时，必须引用本附录，而不是创建第二个版本。
- 规格变更时，先在本附录完成产品评审，再检查所有引用文档的用户语义是否需要同步调整。

### 4.4 保存、恢复与历史

| 规格项 | 产品规格 |
| --- | --- |
| 自动保存延迟选项 | 0.5 / 1 / 2 / 5 秒 |
| 保存完成判定 | 开始前复核本次精确内容与目标；系统报告完成后再读取目标，只有与本次确认内容一致时才显示成功；不一致时保留当前编辑并提供比较、保存副本或继续编辑的退路 |
| 最终路径竞争边界 | 首发只承诺上述前后复核，不宣称排除复核与最终路径替换之间的所有外部变化；完整最终替换所有权与真实并发证据是正式 1.0 候选阻断，当前为 `OPEN` |
| 恢复保护最长间隔 | 5 秒 |
| 恢复内容 | 源文本、原路径、光标、选区、显示视图、滚动位置与最后更新时间 |
| 单个当前恢复项上限 | 每个文档最多保留一个唯一当前恢复项，单项最多 64 MiB；达到上限时明确进入恢复保护降级，不把未受保护的修改表示为可恢复 |
| 本机恢复保护总容量 | 最多 512 MiB；空间不足时先清理已过期项和可替代的旧记录，不因历史配额删除某个文档唯一的当前恢复项；仍无法容纳时保留已有唯一当前项并明确进入恢复保护降级 |
| 正常恢复项保留 | 未命名、孤立及其他尚待用户处理的正常恢复项保留 30 天；用户已保存、恢复或放弃的内容按其明确选择退出恢复中心 |
| 隔离恢复材料保留 | 无法验证、无法解读或因旧保护密钥失效而不能恢复的材料单独隔离 7 天；不把它显示为可恢复内容，到期后清除 |
| 存储或保护密钥异常 | 磁盘空间不足、恢复区域损坏或本机恢复保护密钥失效时，显示“恢复保护暂时不可用”；旧的不可读材料进入隔离，并重新建立后续恢复保护；任何一种异常都不得阻止用户保存自己的 Markdown 文件 |
| 备份边界 | 应用私有的恢复内容、隔离材料和中间状态不进入系统或云端备份；用户自行保存的 Markdown 与资源仍按其所在位置的备份规则处理 |
| 0.1 恢复安全边界 | 加密、容量、备份排除、密钥失效隔离、降级不阻止保存与全部清除规则必须在 0.1 候选中通过；只约束 Inflow 恢复中心管理的材料，不猜测系统其他恢复材料已消失 |
| 正式 1.0 恢复证据 | 真实强制退出、恢复交接中再次崩溃、密钥受限及系统其他文档恢复材料的完整关系尚无候选证据；未完成前不批准正式 1.0 候选，当前为 `OPEN` |
| 清除全部恢复内容 | 用户明确确认后，清除全部正常恢复项、隔离材料、未完成中间状态及与其关联的本机恢复保护密钥；后续产生新修改时建立新的保护；不删除或改写任何用户 Markdown 文件、资源或已导出交付物 |
| 本地版本时间线保留范围 | 成长版起：1–365 天、100 MiB–5 GiB；同时设置时以先达到者为准，用户可关闭 |
| 最近文档容量 | 5–50 项的本机物理保留上限；降低后立即移除超限最旧记录及其访问授权，不保留隐藏记录；文件不存在时仍占一个名额，允许用户移除且不自动扫描其他位置 |

### 4.5 链接与资源

| 规格项 | 产品规格 |
| --- | --- |

| 本地 Markdown 标题片段 | 只解码一次并与目标内既有标题标识精确匹配；不重新生成标识或猜测目标 |
| 成长版工作区导航 | 相对 Markdown 与跨文档标题按工作区导航、单一会话及历史规则打开 |
| 可直接预览的本地图片 | 静态 PNG、JPEG |
| 图片文件选择与拖放 | 只接受内容确认为静态 PNG 或 JPEG 的文件；扩展名与内容不一致或其他类型不进入候选 |
| 图片剪贴板 | 接受 PNG、JPEG、TIFF；PNG/JPEG 保留原格式，TIFF 在确认前明确转换为 PNG |
| 图片保存、预览与导出 | 只使用静态 PNG/JPEG；不把 TIFF、SVG、动画图片或未知类型写入资源目录或交付物 |
| 可受控打开的本地类型 | Markdown、静态 PNG/JPEG、PDF |
| 其他附件 | 默认只在 Finder 中显示；交给外部应用前需要当次明确确认 |
| 远程图片 | 成长版起：用户明确开启后可受控加载；可下载为本地资源 |
| 不支持的本地预览 | SVG、动画图片、类型与内容不一致的文件；显示占位或 Finder 定位 |
| 新建或复制的附件位置 | 必须位于当前文档同级目录或用户选择的工作区相对目录，不进入 Inflow 私有位置；具体选项与默认见附录 B |
| 引用既有外部文件 | 用户可明确选择保留原位置；能形成相对路径时优先使用相对路径，否则保留绝对引用并在确认前提示可移植性影响；该选择不复制或移动原文件 |
| 附件命名 | 选择已有文件时保留原名；重名时在写入前让用户选择替换、保留原位置或使用递增后缀；剪贴板图片使用 `image-001` 起的递增名称 |
| 未命名文档资源 | 在首次保存时连同目标目录与引用影响一起确认；取消保存时不在用户目录留下未确认附件 |

推断本身不是关系事实。只有用户预览并确认标准 Markdown 链接后，才按该链接形成明确关系；不写入专有关系字段。

## 6. 验收场景

1. 全库搜索精确数值、默认值、快捷键和状态文案时，分别只能在对应附录找到权威定义。
2. 文件编码、换行、视图尺寸、恢复、资源和导出的边界在各功能流程中可被引用，不出现第二套值。
3. 超出每个数值边界时，界面拒绝无效值并保留最近有效值。
4. 对所有支持格式与不支持格式各有正向与降级验收场景。
5. 插件发布、评价、交易与更新状态覆盖完整正向和退出路径；人工智能付费任务同时受三项有限上限约束，不存在无上限或无法封顶仍执行的路径。
